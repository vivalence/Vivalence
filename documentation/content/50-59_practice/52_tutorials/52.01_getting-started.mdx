# 52.01 · Getting Started

Bare machine to running language-learning instance in 5 minutes. Every command shown
with the output you should see. Sharp edges flagged inline; ledger at the bottom.

## 0. The model (read once)

Three nouns. Internalize these and the rest is obvious.

| noun | what it is | where it lives |
| --- | --- | --- |
| `registry` | catalog of installable modules — variants, daemons, modes… | `<repo>/registry/` |
| `system` | per-machine coordinator. ledger of instances, locks, logs. | `$VIVA_SYSTEM_MOUNT` (`~/.viva`) |
| `instance` | a cloned variant materialised on disk + its running children | anywhere on disk you cloned to |

A **variant** (e.g. `@vivalence/variant/localhost`) is the recipe in the registry.
`instance/clone` copies it to a dir on disk; `instance/init` wakes it up
(boots runtime + kajuit, signs you up); `instance/run` keeps it running in
foreground; `system` tracks every instance you've ever booted.

## 1. Prerequisites

- `deno` v2.7+ — `deno --version`
- POSIX shell (zsh / bash)
- macOS or Linux. (Detached background processes have a known macOS gotcha — see §Sharp edges.)

## 2. Repo

```sh
git clone https://github.com/vivalence/vivalence.git
cd vivalence/code/vivalence
deno task dependencies
```

Root holds `deno.jsonc` (workspace), `systems/`, `subsystems/`, `registry/`.

## 3. Environment

Edit `testament/.env` at repo root. Used by everything that runs through
`deno task`:

```sh
VIVA_SYSTEM_MODE=DEVELOPMENT
VIVA_SYSTEM_ROLE=SUDO

# usually inferred — set only if defaults don't fit:
# VIVA_REPOSITORY_MOUNT=/abs/path/to/code/vivalence
# VIVA_SYSTEM_MOUNT=~/.viva
# VIVA_REGISTRY_MOUNT=$VIVA_REPOSITORY_MOUNT/registry
```

`VIVA_VARIANT_MOUNT` is **not** set by hand — ghost detects a variant by
scanning your shell cwd for a `.viva.js` marker on every invocation.

## 4. Two ways to invoke

Two equivalent entry points. Both run `systems/ghost/mod.js` with the same args.

### A. Dev — `deno task ghost/run` (recommended while iterating)

No install. Runs straight from the repo.

```sh
deno task ghost/run /system/doctor
```

Works from any directory — `deno task` walks up to find the repo's
`deno.jsonc`. Your shell cwd is preserved in `INIT_CWD`; ghost reads that
(not `Deno.cwd()`) for any user-relative path.

### B. Installed — `viva` (after `deno task install`)

```sh
deno task install   # ? DOES IT ?? writes ~/.config/viva/env + symlinks ~/.deno/bin/viva
viva system/init
```

The `viva` wrapper sources `~/.config/viva/env` then execs deno with the
right config. `viva` with no args exits silently (no usage banner).
Ensure `~/.deno/bin` is on `PATH`.

**Note**: `viva` global does NOT source `testament/.env`. If your shell rc has
no `VIVA_*` exports, only what `~/.config/viva/env` holds (and what
`ghost/install.sh` wrote there) is in scope.

For the rest of this guide we use `deno task ghost/run`.

### Useful flags (work on every command)

| flag | does |
| --- | --- |
| `--json` | dump the effect (handler result) as JSON to stdout |
| `--buffer` | render in an alt-screen Chrome (press `enter` to exit) |

## 6. Initialise the system (one-time)

```sh
deno task ghost/run /system/init
```

Three-phase wizard:
1. **how** — embedding method: `.config` (writes `~/.config/viva/env`) /
   `manual` (prints `export VIVA_SYSTEM_MOUNT=...` for your shell rc) / `abort`
2. **where** — path for `$VIVA_SYSTEM_MOUNT` (default `~/.viva`)
3. **manual** — only on manual choice: shows the export line, `enter` to confirm

What it does after the wizard:
- pins `paladin.scope.system` to the chosen dir
- scaffolds `<system>/logs/` + `<system>/locks/`
- probes that `repository` and `registry` scopes resolve (`integrity check stub`)

You can re-run it any time — it's idempotent.

## 7. Clone a variant

Materialize a variant from the registry onto your disk.

```sh
cd ~/projects                                                # or wherever
deno task ghost/run /instance/clone                          # interactive
# OR
deno task ghost/run /instance/clone localhost ./brazilian    # explicit
```

Three-step wizard (if interactive):
1. **variant?** — pick from the registry's `type:"variant"` entries
2. **path?** — where to put it (default `./<slug>`)
3. **proceed?** — preview of source/target, `yes` to copy / `no` to abort

What it copies: the variant's directory tree from the registry — manifest
(`*.viva.js`), `environment/`, `mountpoint/`. Skips `.logs/`, `.git/`,
`.jj/`, `node_modules/` (configurable in `clone.js`).

Effect:

```jsonc
{
  "variant": { "owner": "@vivalence", "type": "variant", "slug": "localhost", "version": "0.0.1" },
  "source": "/.../registry/wafers/@vivalence/variant/localhost",
  "target": { "relative": "./brazilian", "absolute": "/Users/you/projects/brazilian" }
}
```

## 8. Wake the instance

cd into the cloned dir — ghost detects the variant marker there.

```sh
cd ./brazilian
deno task ghost/run /instance/init
```

Interactive 4-phase wizard:

| phase | what |
| --- | --- |
| boot | spawns runtime + kajuit (piped); awaits `Status:ALIVE` beacon |
| create | admin form (`username` / `password` or `skip`) |
| install | `POST /auth/signup` against the lighthouse |
| ready | per-process status + admin echo; `enter` → teardown + exit |

What you see (the Chrome wraps it):

```text
╭───────────────────────────────────────────╮
│ ✦ V I V A  L E N C E              ready   │
│ language learning OS                      │
│                                           │
│ ╭─────────────────────────────────────╮   │
│ │ variant up                          │   │
│ │ admin beef  ·  •••••••••••••••      │   │
│ │ next steps                          │   │
│ │   1. enter to stop + exit           │   │
│ ╰─────────────────────────────────────╯   │
│                                           │
│ ● auth/signup  SUCCESS  019e70d6-…        │
│ ● runtime  exited (code 0)                │
│ ● kajuit   exited (code 0)                │
│                                           │
│ enter → stop + exit                       │
╰───────────────────────────────────────────╯
```

After exit, the instance is registered with `$VIVA_SYSTEM_MOUNT/instances.json`.

The kajuit web UI was live on `http://localhost:1794/` during `ready`.
Bookmark for next boot.

## 9. Day-two lifecycle

From inside the variant dir:

```sh
deno task ghost/run /instance/run        # foreground attached (Ctrl-C stops both)
deno task ghost/run /instance/run runtime  # only the runtime child
```

That's the workhorse. Logs stream to your terminal.

For just the runtime or just kajuit, pass `runtime` or `kajuit` as the target.

## 10. Inspect a running instance

```sh
deno task ghost/run /instance/doctor    # prints paladin.variant
```

Currently this is a seed — dumps the resolved variant object (daemons, services,
clients, runtime). Future: per-instance locks + processes + log files.

For the wider view:

```sh
deno task ghost/run /system/doctor      # all scopes, all variants, all locks
deno task ghost/run /system/doctor --json | jq '.processes'
deno task ghost/run /system/doctor --buffer
```

After everything above:

## Sharp edges

### `/instance/start` + `/instance/stop` — partially broken

`/instance/start` prints `ghost: started temp (runtime=PID kajuit=PID)` and
writes lock files, but the children die within milliseconds. Use `/instance/run`
or `/instance/init` for now. See `.ikiro/known-issues.org`
`detached-process-die-on-parent-exit`.

### `deno task` rewrites `Deno.cwd()`

`deno task` chdirs to the repo root before running the task. Your actual shell
cwd is in `Deno.env.get("INIT_CWD")`. Handlers that resolve user-relative paths
(`instance/clone` etc.) already use the right fallback chain
(`INIT_CWD ?? PWD ?? Deno.cwd()`). If you write a new handler that takes a
relative path, do the same.

### `viva` global ≠ `testament/.env`

The installed `viva` wrapper only sources `~/.config/viva/env`. If you change
`testament/.env`, either also update `~/.config/viva/env` or use
`deno task ghost/run` (which reads `testament/.env` directly).

### Slug = last segment of variant dir

`instance/target.js` derives the slug from
`basename(VIVA_VARIANT_MOUNT)`. Two cloned variants with the same dir name will
collide on locks. Marked `@beef ugly and stupid` in the source — to be replaced
with manifest lookup.

### `paladin.scope overwrite` warning

Fires every invocation. Cosmetic — ghost intentionally re-registers
`scope.variant` from the detected cwd. Will be silenced when paladin learns
about idempotent overwrites.

### `viva` with no args = silent exit

No usage banner. List commands by reading `systems/ghost/trajectories/index.js`
or running `deno task ghost/run /system/doctor` (the trajectory registry isn't
yet user-facing).

## Cheat sheet

```sh
# inspect
viva /system/doctor                       # all scopes + registry overview
viva /system/doctor --json | jq           # machine-readable
viva /system/doctor --buffer              # fullscreen

# bootstrap
viva /system/init                         # one-time, idempotent

# clone + init
cd ~/projects && viva /instance/clone localhost ./brazilian
cd ./brazilian && viva /instance/init

# run (from variant dir)
viva /instance/run                        # foreground; preferred today
viva /instance/run runtime                # just the runtime
# viva /instance/start                    # BROKEN — see known-issues
# viva /instance/stop                     # BROKEN — see known-issues
viva /instance/doctor                     # variant dump
```

(Substitute `deno task ghost/run` for `viva` if you skipped `deno task install`.)
