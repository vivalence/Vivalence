# 46.13 · Contexts

## the four contexts
- Table — symbol · deck file · owns · ship-metaphor:
  - LIGHTHOUSE · `decks/lighthouse.js` · auth / identity / daemons · the tower
  - QUARTERS · `decks/quarters.js` · terminals repository · the workspace
  - BRIDGE · `decks/bridge/` · layout / view / paneSize (localStorage) · the helm
  - MAIN · `decks/main.js` · active terminal→thread→daemon→mode · the pivot
- [TODO: confirm BRIDGE store inventory against `decks/bridge/bridge.js` before publish.]

## MAIN — the pivot (deep)
- Renamed from THREAD (ikiro stale). `new Main(quarters, lighthouse)`.
- ONE primary store: `$terminal` (the active Terminal entity; persisted as `terminal.id` under
  localStorage `viva.main.terminal`). `$thread` is **derived** — `activeThread($terminal)` flattens the
  active terminal's `$thread`, re-switching when the terminal changes; emits only entity threads
  (`thread?.id ? thread : null`). No `$active` id-store, no duplicate `$current`.
- queue lifecycle is a subscription on `$thread`: on switch, `prev.queue.deactivate()` →
  `next.queue.activate()`. No wrapped setter.
- accessors: `terminal` `thread` `daemon` (thread?.daemon) `mode` (thread?.mode).
- methods: `activate(id)` `close(id)` `set(thread)` `clear()` `hydrate()`. Creation lives on
  `quarters.spawn(slug)` — main never creates, only selects.
- `hydrate()`: walks terminals, merges each thread off its owning daemon into `terminal.thread`
  (`$thread` reflects it through the flatten). Runs on `lighthouse.$daemons` change. `set/clear`
  write the terminal; no manual thread re-sync.

## consumption pattern (the one law)
- Components call `getContext(MAIN)` etc., then subscribe to atoms or read accessors.
- Right: `{#if $current.thread}` / subscribe. Wrong: component resolves its own entity.

## deck surface (read/written props; $nano collapsed)

Source-derived, exhaustive. `$store` collapsed to `{store,value,read,write}`.
inspector + box are deck **modules**, not contexts; box is unmounted (commented in +layout).
