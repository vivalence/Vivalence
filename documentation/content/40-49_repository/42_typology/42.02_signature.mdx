# 42.02 · Signature — the path grammar

*everything in the system routes on a Signature. one prototype, five heirs: `Pattern` declares a route, `Signal` dispatches against it, `Path`/`Filepath`/`Url` carry the filesystem and the network.*

`subsystems/typology/prototypes/signature.js` is the root (213 lines). It holds no routing logic — it is a **linked node**: a `nature` (this segment's name), a `trace` (its parent), and `gauges` (its children). Everything else is traversal over that chain.

```
Signature            nature · trace · gauges          the chain
  ├─ Pattern         + filter · apply()               DECLARE — one of four segment types
  ├─ Signal          + flags · tokenize()             DISPATCH — a path being walked
  ├─ Path            normalized filesystem path
  ├─ Filepath        + extension/basename handling
  └─ Url             + origin
```

The chain is walked by generators, not arrays: `heritage()` climbs to the root, `finn()` descends to the tip, `array` splices both into one ordered list. `absolute` is that list mapped to natures.

## the two faces

A `Pattern` and a `Signal` are the same grammar pointed in opposite directions. This is the distinction the whole spine rests on:

## four segment types

`Pattern` probes each segment against a `patternmap` (`pattern.js:63`) — first match wins, `literal` is the catch-all:

```
"*"          wildcard     matches any one segment
"(.*)"       remainder    matches every remaining segment
":name"      parameter    matches one, binds it to `params.name`
anything     literal      matches only itself
```

A remainder does **not** produce one joined string. Each surplus segment binds to its own indexed parameter — `/files/(.*)` against `/files/a/b/c` yields `{0:"a", 1:"b", 2:"c"}`.

## Signal parses flags

`Signal`'s tokenizer (`signal.js:5–70`) is why `deno task ghost/run /system/doctor --json` works: the same prototype that routes HTTP also parses a command line. Rules:

```
--key value      → flags.key = "value"      (next token consumed, if not a flag)
--key            → flags.key = true
-v               → flags.v = true           (single short)
-abc             → flags.a = flags.b = flags.c = true    (cluster expands)
--               → terminator; everything after is a SEGMENT
-                → passthrough; this token is a segment
```

Flags attach to the **last** segment. A flags-only signal (`--json`) has a `nature` of `null` — it addresses the root, which is what makes `open("/")` reachable from a bare flag invocation (see [[42.03_vector]]).

### where this pays off

`ghost` is the whole reason. It takes argv, coerces it into a `ShellSignal`, and dispatches it against a Vector of trajectories (`systems/ghost/mod.js:60`):

```js
ctx.call = (args) => {
  const signal = args instanceof ShellSignal ? args : new ShellSignal(args)
  return steer.dispatch.invoke(trajectory, signal, strategy)(new ShellContext({ signal }))
}
```

So `deno task ghost/run /system/doctor --json` is not a CLI parser feeding a router. It is *one* Signal: `/system/doctor` routes, `--json` rides along on the tip segment, and the trajectory reads it off the context. The same prototype that matches an HTTP path matches a command line, because a command line **is** a path with flags.

## the other three heirs

`Pattern` and `Signal` get the attention, but the filesystem and network heirs carry more call sites than either — 36 `new Path(` and 46 `new Url(` against 12 `new Signal(`.

- **`Path`** — normalized filesystem paths. Almost entirely **paladin's** (`subsystems/paladin/lifecycle/populate.js`, five sites): the registry scan resolves every module mount as a `Path`. The runtime uses it for daemon mounts and `APPLICATION` view resolution.
- **`Filepath`** — `Path` plus extension/basename handling, for the bundler and freight catalogs.
- **`Url`** — `Path` plus an origin, plus `.with(query)` and `.scheme()`. Every `Connection` holds one; `transmitter.multiplex` uses `.scheme(secure ? "wss" : "ws")` to derive the socket address from the HTTP origin (`transmitter.js:29`).

One law worth stating because it is easy to violate: **`Path` overrides `absolute` to be heritage-only.**

```js
// signature.js:76 — base: heritage AND descendants
get absolute() { … for (const t of this.heritage()) array.unshift(t)
                   for (const t of this.finn())     array.push(t) … }

// path.js:30 — Path: ancestors only, concatenated
get absolute() { for (let p = this; p; p = p.trace) nature = p.nature + nature }
```

So a `Path`'s `absolute` is *where this node is*, never *where its children go*. Build paths with `branch()`; never concatenate strings against `absolute` and never assume a child's path is reachable from the parent's. `Path` also implements `Symbol.toPrimitive` (`path.js:55`), so string interpolation yields `absolute` — convenient, and the reason the mistake is easy to make.
