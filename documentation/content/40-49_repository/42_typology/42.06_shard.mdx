# 42.06 · shard — the middleware belt

*if `shape` is what a Vector becomes and `steer` is how it is walked, `shard` is what rides inside it. fifteen namespaces of `(ctx, next)` middleware — the payload of every `.use()` in the system.*

`subsystems/typology/gestalten/shard/`, ~1500 lines. Shards are the least visible layer, because they never appear in a route declaration — they wrap one. A leaf can be read in isolation; what actually happened to `ctx` before it got there is entirely a question of which shards are mounted above.

## the two mount points

A shard is koa-style middleware, so it mounts wherever a `carry` exists — and there are exactly two carries in the system:

```js
// systems/kajuit/src/typology/entities/daemon/dossier.js:52
new Connection(url, shard.transmitter.retry(multiplex, { maxRetries: 2 }))
  .use(shard.track.span(…, ctx.telemetry))
  .use(shard.track.request())
  .use(shard.track.fault())
  .use(shard.connection.timeout(8000))
```
</Fragment>
</Tabs>

Note the asymmetry in the client chain: `retry` is **not** a `.use()`. It wraps the transport at the bottom, because koa's `compose` forbids calling `next()` twice — a retry loop has to own the inner call rather than re-enter the onion (`transmitter.js:164`).

Read the distribution, not the list. Three things fall out of it:

- **`context.bind` is the workhorse** (16 sites). It is how the daemon, the mode, and the thread reach a leaf that never asked for them. Every trait installer opens with it.
- **`datamap` is a third of all shard usage** (30 sites) and is the only namespace registry modules mount directly — `registry/education/domain/aperture/index.js:61` builds its repositories out of `datamap.repository` + `datamap.reactive` exactly the way the runtime does.
- **`track.*` is client-only.** The server's tracing goes through `Span` directly (`shape.http` emits a `server-timing` header from `ctx.span.records`, `http.js:57`); the client mounts `track.span/request/fault` as shards. Same records, two mount styles.

## the law

**Never raw-fetch in a Connection.** The transport chain is what carries auth, retry, timeout, tracing, and multiplexing — a bare `fetch` silently drops all of it. `Connection.call` exists so the chain cannot be bypassed; if a call must skip a shard, remove the shard, don't route around it.

`shard.transmitter.multiplex` makes the stakes concrete: it holds **one WebSocket per origin**, lazily established and shared by every call to that origin (`transmitter.js:9`). A raw fetch doesn't just lose auth — it opens a connection the pool was built to avoid.

## the testing dual

`shard.transmitter.inline(handler)` swaps the socket for a direct call into a `shape.http` handler (`transmitter.js:192`). It still builds a real `Request`, still serializes the body, still reads `content-type` off the response — so the **full** context path runs with no port open. Every runnable example in this category uses it, and so does the daemon's own integration seam (`systems/runtime/daemon/lifecycle/integration.js:5`), which is why an in-process daemon call and a networked one traverse identical code.

## current state — honest

This page is an inventory with a usage map, not a per-shard reference. Specifically untraced here: what `datamap.reactive` subscribes to, what `nano.transient` evicts, what `hal.voice` expects on `ctx`.

Two namespaces — `ambient` and `receiver` — have **no call sites outside tests**. They are either pre-wiring or dead; nothing in this repo currently proves which. Treat them as unsupported until something mounts them.

Test coverage is partial: `tests/gestalten/shard/` covers `batch`, `cors`, `datamap`, `serve`, and `websocket`. The remaining ten namespaces are exercised only indirectly through runtime and kajuit tests.
