* Intent

Oak provides URL pattern matching, middleware composition, and HTTP serving. Vector
already does the first two better. ~Deno.serve~ does the third natively. Oak is a
middleman.

The ~http~ compiler compiles a Vector into a ~(Request) => Response~ handler. Same
pattern as the object compiler (~Vector → callable~), proxy compiler (~Vector → Proxy~),
and oak compiler (~Vector → Oak middleware~). Different execution target: native HTTP.

The Context prototype is the unified container for all execution paths. It replaces the
ad-hoc ~{ input, output, state, params, request, response }~ objects scattered across
compilers, transports, and lifecycle code. Lives in typology alongside Request, Response,
Connection, Url.

** Relationship to vector-aperture-compiler.workpackage.org

That workpackage introduced ~dispatch~ (shared traversal), ~compileInvoke~ (Connection
transport), and ~compileOak~ (Oak HTTP). The http compiler replaces ~compileOak~. The
~dispatch~ function from ~shared.js~ is reusable — the http compiler calls ~traverse~
and aggregates params the same way. ~compileInvoke~ remains for internal invocation until
the Connection vector transport is built (separate work).

** Design Constraints

- The compiler returns a handler ~(Request) => Response | Promise<Response>~. It does not
  call ~Deno.serve~. The caller owns server lifecycle (port, hostname, signal, onListen).
- Context is a passive container. No methods that "do" anything. No ~finalize()~, no
  ~invoke()~. Things are done TO contexts, not BY them.
- ~ctx.input~ / ~ctx.output~ are getter/setter aliases for ~ctx.request.body~ / ~ctx.response.body~.
  No copy-then-sync. They ARE the same slot.
- Handler arity convention (0/1/2 args) is handled in the compiler's execution terminal,
  not on Context, not on Vector, not on the controller.
- CORS is a middleware/shard concern, not a compiler concern. The handler returned by
  ~http(vector)~ does not handle CORS. The caller adds CORS middleware to the vector
  or wraps the handler.
- The compiler owns: body parsing, traversal, params aggregation, execution (carry +
  terminal with arity dispatch), response serialization, error handling (NotFound → 404).

** Future Constraints

~ctx.output~ is untyped. Binary (~Uint8Array~), streams (~ReadableStream~), and JSON
objects all flow through the same slot. The ~respond~ function discriminates on type
at the HTTP boundary. Streaming requires no changes to Context or Vector — the respond
function branches on ~instanceof ReadableStream~.

* Context Prototype

** Location: ~typology/prototypes/context.js~

#+begin_src js
import { Request } from "./request.js";
import { Response } from "./response.js";

export class Context {
  constructor(request) {
    this.request = request instanceof Request ? request : new Request(request);
    this.response = new Response();
    this.state = {};
    this.params = {};
  }

  get input() { return this.request.body; }
  set input(v) { this.request.body = v; }

  get output() { return this.response.body; }
  set output(v) { this.response.body = v; }
}
#+end_src

When a handler does ~return { success: true }~, arity dispatch does ~ctx.output = result~,
which IS ~ctx.response.body = result~. No mapping step. No finalize. Same slot.

When middleware does ~ctx.input.injected = true~, it mutates ~ctx.request.body~ directly.
Same object. No drift.

** Response.type

One addition to the existing Response prototype: a ~type~ property for content-type.
Handlers set ~ctx.response.type = "audio/mpeg"~ and the compiler reads it during
serialization. Default is ~"application/json"~.

* HTTP Compiler

** Location: ~vector/compiler/http.js~

Compiles a Vector into a ~(Request) => Response~ handler. The handler:

1. Parses the native Request body (JSON, catch to null)
2. Creates a Context from the parsed request
3. Traverses the Vector with a Signal from the URL pathname
4. Aggregates params from traverse steps onto ~ctx.params~
5. Runs the carry chain with a terminal that does arity dispatch
6. Catches ~NotFound~ → 404, other errors → 500
7. Serializes ~ctx.response~ into a native Response via ~respond~

#+begin_src js
import { Signal, Context } from "@vivalence/typology";
import { traverse } from "@vivalence/vector/controller";
import { NotFound } from "@vivalence/vector/typology";

export function http(vector) {
  return async (req) => {
    const body = await req.json().catch(() => null);
    const ctx = new Context({
      body,
      url: req.url,
      method: req.method,
      headers: req.headers,
    });

    try {
      const signal = new Signal(ctx.request.url.pathname);
      const [effect, carry, steps] = traverse(vector, signal);
      if (!effect) return respond(ctx, 404);

      ctx.params = Object.assign(
        {}, ...steps.map(s => s.parameters).filter(Boolean)
      );

      await carry(ctx, async (c) => {
        if (effect.length === 0) c.output = await effect();
        else if (effect.length === 1) c.output = await effect(c);
        else if (effect.length === 2) c.output = await effect(c.input, c);
      });
    } catch (e) {
      if (e.code === "NOT_FOUND") return respond(ctx, 404);
      console.error(e);
      return respond(ctx, 500);
    }

    return respond(ctx);
  };
}

function respond(ctx, status) {
  const body = ctx.response.body;
  const s = status || ctx.response.status || (body != null ? 200 : 404);
  const type = ctx.response.type || "application/json";

  if (body instanceof Uint8Array || body instanceof ReadableStream) {
    return new Response(body, { status: s, headers: { "content-type": type } });
  }

  return new Response(
    body != null ? JSON.stringify(body) : null,
    { status: s, headers: { "content-type": type } },
  );
}
#+end_src

** Scenario 4: Re-entrant Vector Call (Daemon Pattern)

This tests the production pattern from ~daemon/lifecycle/population.js~ where middleware
injects a ~ctx.call~ method that re-enters the same vector tree. The middleware closures
over the vector and does its own traverse+execute — no magic from the compiler.

#+begin_src
Vector:
  .use(middleware that injects ctx.call — closures over vector + traverse)
  .use(middleware that sets ctx.auth = "token-123")
  /lookup/:id → { id, auth: ctx.auth }
  /aggregate (input, ctx) →
    a = await ctx.call("/lookup/1")
    b = await ctx.call("/lookup/2")
    return { results: [a, b], auth: ctx.auth }

Tests:
  GET /lookup/5  → { id: "5", auth: "token-123" }
  GET /aggregate → {
    results: [
      { id: "1", auth: "token-123" },
      { id: "2", auth: "token-123" }
    ],
    auth: "token-123"
  }
#+end_src

The ~ctx.call~ injected by middleware does its own traverse+execute cycle:
- Creates a fresh Context for the inner call
- Traverses the same vector
- Aggregates params
- Runs carry + terminal
- Returns the inner ctx.output

This proves: re-entrant traversal, independent Context per call, middleware runs for
inner calls (auth propagates), params resolve independently per traversal.

#+begin_src js
// The middleware that injects ctx.call — closures over vector
function withCall(vector) {
  return async (ctx, next) => {
    ctx.call = async (path, body) => {
      const signal = new Signal(path);
      const [effect, carry, steps] = traverse(vector, signal);
      if (!effect) throw new NotFound(signal);
      const inner = new Context({ body, url: `http://internal${path}`, method: "POST" });
      inner.params = Object.assign({}, ...steps.map(s => s.parameters).filter(Boolean));
      await carry(inner, async (c) => {
        if (effect.length === 0) c.output = await effect();
        else if (effect.length === 1) c.output = await effect(c);
        else if (effect.length === 2) c.output = await effect(c.input, c);
      });
      return inner.output;
    };
    await next();
  };
}
#+end_src

* Open Spaces

** Connection vector transport (separate work)
Replaces ~compileInvoke~ for internal invocation. Connection transport that traverses
the vector directly. Uses Context. Not part of this workpackage.

** CORS shard
CORS as a vector middleware or as a handler wrapper. Preflight (OPTIONS → 204) needs
to short-circuit before traversal. Either the vector has a catch-all middleware that
handles it, or the caller wraps the http handler.

** Streaming
~respond~ already branches on ~ReadableStream~. When streaming effects arrive, they
flow through ~ctx.output~ unchanged. SSE would need ~text/event-stream~ type and a
ReadableStream body. Additive.
