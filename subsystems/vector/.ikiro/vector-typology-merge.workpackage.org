#+TITLE: Vector → Typology Merge — Work Package
#+AUTHOR: Vivalence

* Intent

Vector merges into typology. The routing engine was always a gestalt over
typology's Signature hierarchy — controller is computation over Pattern/Signal,
compiler is compilation of Vector trees into external targets (Oak, LLM tools,
ORM events, callable objects). Two packages for one type system creates import
indirection and forces consumers to juggle =@vivalence/vector= and
=@vivalence/typology= for tightly coupled code.

After merge: =@vivalence/vector= ceases to exist. All consumers import from
=@vivalence/typology=. Controller and compiler become first-class gestalt
categories alongside is/cast/not/fromm/belt/shard.

** Design Constraints

- Controller and compiler are gestalten: =gestalten/controller/=, =gestalten/compiler/=
- Vector prototypes join the prototype family: =prototypes/vector.js=, =prototypes/context.js=
- Vector errors nest into =prototypes/errors/vector.js=: Long, Short, NotFound
- Both =shard/secure.js= kept — vector's becomes =shard/secure.vector.js=
- Aperture .ts/.js files stay as-is — Deno handles mixed extensions
- Oak/aperture compiler requires =index.client.js= exclusion — Oak unavailable on client
- =subsystems/vector/= moves to =subsystems/vector.bak/= after merge
