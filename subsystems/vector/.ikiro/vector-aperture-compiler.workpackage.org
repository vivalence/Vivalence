* Intent

The Aperture was a thin wrapper around Oak's Router. ~open()~, ~use()~, ~branch()~
mutated the Oak router directly. Two compilation paths existed: ~compose()~ for
internal ~Connection.call()~ invocation and ~serve()~ for HTTP. These paths diverged
in middleware application, param extraction, and 404 handling. The result was chaotic:
params sometimes appeared, sometimes didn't; middleware ran in different orders depending
on invocation mode; 404 behavior was ad-hoc.

The migration: Aperture extends Vector. IS the routing trie. Compilation into Oak HTTP
and internal callable is handled by dedicated external compilers that both call the same
~traverse()~. One code path for matching, one for middleware, one for param extraction.

** Design Constraints

- Aperture extends Vector, does not contain one.
- ~branch()~ returns Apertures (via ~this.constructor~ in Vector).
- All Vector consumers work on Aperture unchanged: ~traverse~, ~walk~, ~invoke~, ~Agentic~, ~Subscriber~.
- ~ctx.input~ / ~ctx.output~ for internal semantics. ~ctx.request~ / ~ctx.response~ for external/HTTP.
  This delineation is intentional: one request can be responsible for multiple invocations
  with different inputs/outputs while maintaining the original request context.
- Handler arity convention preserved: 0-arg (pure value), 1-arg (ctx), 2-arg (body, ctx).
- Compilers are external to the Aperture class. The Aperture is pure data structure + builder.

** Future Constraints: Streaming

~ctx.output~ is untyped. If an effect returns an ~AsyncGenerator~ or ~ReadableStream~,
the carry chain doesn't care — it already ran. The compiler layer discriminates:

- ~compileOak~: async iterable → SSE (~text/event-stream~), value → JSON body.
- ~compileInvoke~: pass through on ~ctx.output~, Connection handles it.
- Future ~compileSSE~ or ~connection.subscribe()~ requires no aperture/vector changes.

The vector pipeline is: signal → traverse → carry → effect → output. Nothing assumes
output is a single value. Streaming is a compiler concern, not a routing concern.

** Future Constraints: Shared Realtime Entities

Shared bidirectional entities (sessions, chats, collaborative state) do NOT live in the
aperture. The aperture handles "what happens when a signal arrives" — reactive to
invocation, not persistent across time.

A ~SharedEntity<T>~ primitive is needed separately:

#+begin_src
SharedEntity<T>
  .id         — identity
  .state      — current value
  .patch(op)  — apply mutation (either side)
  .subscribe()— AsyncIterator<Patch>
  .snapshot() — current full state
#+end_src

The aperture's role is transport:
- ~open("/session/:id", ctx => session.snapshot())~ — initial state, normal dispatch
- ~open("/session/:id/stream", async function* (ctx) { yield* session.subscribe() })~ — SSE
- ~open("/session/:id/patch", (body, ctx) => session.patch(body))~ — client mutations

Client-side: ~connection.subscribe("/session/abc/stream")~ returns ~AsyncIterator~,
~connection.call("/session/abc/patch", op)~ is a normal call. The bidirectional illusion
comes from a local ~SharedEntity~ on each side syncing via these two channels.

The architecture needs one extension point eventually: effect return type discrimination
in ~dispatch~:

#+begin_src js
ctx.output = await effect(ctx);
ctx.streaming = isAsyncIterable(ctx.output);
#+end_src

Each compiler then branches on ~ctx.streaming~. This is additive, not structural.

* Source: aperture.js

:END:

The entire Aperture. ~30 lines of logic. Constructor overloading: string first arg
is path metadata, otherwise delegate to Vector. ~open()~ wraps handler arity so the
stored effect is always ~async (ctx) => ...~. ~slurp()~ is path-aware ~set()~.

#+begin_src js :tangle compiler/aperture/aperture.js
import { Vector } from "@vivalence/vector/typology";

const wrap = (handler) => {
  const n = handler.length;
  if (n === 0) return async () => handler();
  if (n === 1) return async (ctx) => handler(ctx);
  return async (ctx) => handler(ctx.input, ctx);
};

export class Aperture extends Vector {
  constructor(first, second) {
    if (typeof first === "string" || first == null) {
      super(null, second);
      this._path = first || null;
    } else {
      super(first, second);
    }
  }

  open(signature, handler) {
    return super.open(signature, wrap(handler));
  }

  slurp(other) {
    if (other._path) this.branch(other._path).set(other);
    else this.set(other);
    return this;
  }

  get json() {
    const path = this._path || "/";
    const effects = [...this.effects.keys()].map((p) => p.nature);
    const trajectories = [...this.trajectories.entries()].map(([p, v]) => {
      const child = Object.create(Aperture.prototype);
      Object.assign(child, v);
      child._path = p.nature;
      return child.json;
    });
    return { [path]: [...effects, ...trajectories].filter(Boolean) };
  }

  [Symbol.for("nodejs.util.inspect.custom")]() {
    return `Aperture ${JSON.stringify(this.json, null, 2)}`;
  }
}

* Source: shared.js
:PROPERTIES:
:ID: aperture-shared
:END:

The single traversal point. Both compilers call ~dispatch~. Signal is constructed
from the path string, ~traverse~ resolves effect + carry chain, params are extracted
from steps. This is where parity comes from: one function, two callers, identical behavior.

Note: ~traverse~ returns ~[effect, carry, steps, position]~. The carry is already
composed via ~chain~ across all trie levels the signal passed through. Params accumulate
from Pattern ~apply()~ at each step — parameter patterns return ~{ parameters: { key: val } }~.

#+begin_src js :tangle compiler/aperture/shared.js
import { Signal } from "@vivalence/typology";
import { traverse } from "@vivalence/vector/controller";
import { NotFound } from "@vivalence/vector/typology";

export const params = (steps) =>
  steps.reduce(
    (acc, step) => (step?.parameters ? { ...acc, ...step.parameters } : acc),
    {},
  );

export const dispatch = async (aperture, path, ctx) => {
  const signal = new Signal(path);
  const [effect, carry, steps] = traverse(aperture, signal);

  if (!effect) throw new NotFound(signal);

  ctx.params = params(steps);

  await carry(ctx, async (ctx) => {
    ctx.output = await effect(ctx);
  });

  return ctx;
};

import { dispatch } from "./shared.js";

export function compileInvoke(aperture) {
  return async (ctx) => {
    const path =
      ctx.request?.url?.pathname ||
      (typeof ctx.request?.url === "string"
        ? new URL(ctx.request.url, "http://internal").pathname
        : null) ||
      ctx.request?.path ||
      "/";

    ctx.input = ctx.input ?? ctx.request?.body ?? {};
    ctx.state = ctx.state || {};

    try {
      await dispatch(aperture, path, ctx);
      ctx.response.body = ctx.output;
      if (ctx.response.status === 0 || ctx.response.status === 404)
        ctx.response.status = 200;
    } catch (e) {
      if (e.code === "NOT_FOUND") {
        ctx.response.status = 404;
        ctx.response.body = { error: { code: "NOT_FOUND" } };
      } else {
        ctx.response.status = 500;
        ctx.response.error = e;
      }
    }
  };
}

export function context(path, body, options = {}) {
  return {
    input: body,
    output: undefined,
    state: {},
    params: {},
    request: {
      body,
      url: new URL(path, "http://internal"),
      method: options.method || "POST",
      headers: new Map(),
    },
    response: {
      body: undefined,
      status: 0,
      headers: new Map(),
    },
  };
}

* Source: oak.js — Oak HTTP Compiler
:PROPERTIES:
:ID: aperture-oak
:END:

Replaces the old ~serve()~ method. Registers a single catch-all Oak route that
delegates to ~dispatch~. Oak is now an HTTP shell: parse body, build ctx, hand off
to vector traverse. Params, middleware, 404 — all handled identically to invoke.

The old code scattered params across Oak's own router matching (which used its own
pattern syntax, independent of Vector's Pattern) and the Aperture's internal routing.
Now there's one pattern system: Vector's ~Pattern~ with its ~patternmap~ (literal,
parameter, wildcard, remainder).

#+begin_src js :tangle compiler/aperture/oak.js
import { Router } from "@oak/oak";
import { dispatch } from "./shared.js";
import parser from "./parser.js";

export function compileOak(aperture, options = {}) {
  const prefix = options.prefix || "";

  const handler = async (oakCtx, next) => {
    const pathname =
      oakCtx.request.url.pathname.replace(new RegExp(`^${prefix}`), "") || "/";

    const body = await parser(oakCtx);

    const ctx = {
      input: body,
      output: undefined,
      state: oakCtx.state,
      params: {},
      request: oakCtx.request,
      response: oakCtx.response,
    };

    try {
      await dispatch(aperture, pathname, ctx);
      oakCtx.response.body = ctx.output;
      if (oakCtx.response.status === 404) oakCtx.response.status = 200;
    } catch (e) {
      if (e.code === "NOT_FOUND") {
        oakCtx.response.status = 404;
        oakCtx.response.body = "Not Found";
        return;
      }
      oakCtx.response.status = 500;
      oakCtx.response.body = { error: e.message };
    }
  };

  const router = new Router();
  if (prefix) router.all(`${prefix}/(.*)`, handler);
  else router.all("/(.*)", handler);

  return {
    router,
    routes: () => router.routes(),
    allowedMethods: () => router.allowedMethods(),
    handler,
  };
}

export default async function parseBody(ctx) {
  const { method, body, headers = {} } = ctx.request;

  if (method === "GET") return ctx.request.query || {};
  if (!body) return {};

  try {
    switch (true) {
      case typeof body.json === "function":
        return await body.json();
      case typeof body === "object":
        return body;
      case typeof body === "string":
        try {
          return JSON.parse(body);
        } catch {
          return { rawBody: body };
        }
      default:
        return {};
    }
  } catch (error) {
    console.error("[aperture/parser]", { error, method });
    return {};
  }
}

    headers: { "Content-Type": "application/json" },
    body: method === "GET" ? undefined : JSON.stringify(body),
  });
  return { status: res.status, body: await res.json().catch(() => null) };
};

** Streaming dispatch (future)
~ctx.output~ is untyped. When streaming arrives, ~dispatch~ gains:
#+begin_src js
ctx.streaming = isAsyncIterable(ctx.output);

Each compiler branches on it. No aperture/vector changes.

** SharedEntity primitive (future)
Lives outside the aperture. Uses aperture for transport (snapshot, stream, patch).
Needs ~connection.subscribe()~ alongside ~connection.call()~.

** compileSSE (future)
A third compiler. Receives the same aperture, same traverse. Outputs SSE responses
for streaming effects. Additive, not structural.

** Connection.subscribe (future)
Counterpart to ~Connection.call~. Opens persistent channel. HTTP side: SSE via fetch.
Internal side: direct async iterator from ~compileInvoke~.
