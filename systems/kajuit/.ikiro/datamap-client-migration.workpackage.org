* Intent

The runtime exposes entity repositories through hand-rolled aperture routes
with mismatched client/server contracts. The client's entity system is
hardcoded per entity type with no generic layer. This work replaces both
sides with a unified =shard.datamap= that controls exposition, security,
errors, and reactive subscriptions — and migrates the client to use
=RemoteRepository= from typology with schema-driven entity discovery.

Five phases. A through E. A fixes the runtime. B migrates the client.
C adds schema exchange for dynamic entity awareness. D applies the
pattern to lighthouse. E wires reactive subscriptions end-to-end.

** What Exists (Typology — Done)

The typology layer is built and tested (40 tests, 165ms):

*** shard.datamap — three composable shards

Each returns an Aperture. Compose via =.slurp()= on the consumer's branch:

#+begin_src javascript
aperture.branch("/entities/literal")
  .slurp(shard.datamap.repository(repos.literal))
  .slurp(shard.datamap.reactive(repos.literal, entities.twitch))
  .slurp(shard.datamap.ingest(repos.literal))
#+end_src

- =shard.datamap.repository(repo)= — wraps a MikroORM repository as an
  Aperture with typed routes: find, findOne, findOneOrFail, findAndCount,
  count, create, upsert, ensure (if available), update, remove. Options
  sanitization (whitelist: populate, orderBy, limit, offset, fields,
  exclude). Error middleware: NotFoundError→404, ValidationError→400,
  UniqueConstraintViolation→409, else→500. Body: ={code: "NOT_FOUND"}= etc.

- =shard.datamap.reactive(repo, twitch)= — outbound entity subscriptions.
  Opens handlers on the =twitch= Vector for create/update/delete events.
  When an entity mutates, the handler serializes it and pushes to an internal
  Broadcaster. Exposes =/subscribe= GET endpoint that serves the Broadcaster
  as SSE via =response.publish()=. Entity name derived from
  =repo.getEntityName().toLowerCase().replace("entity", "")=.

- =shard.datamap.ingest(repo)= — inbound entity mutations. Exposes
  =/ingest= POST endpoint that consumes incoming SSE via
  =ctx.request.subscribe()= and applies each event to the repo (create,
  update, delete). Enables daemon-to-daemon sync, client-driven streaming,
  offline reconnection.

- =shard.datamap.scope(ctx => patch)= — middleware that sets =ctx.scope=.
  Route handlers merge scope into =where= (reads) or =data= (writes).

- =shard.datamap.errors()= — middleware. Shared by repository and ingest.

*** shape.subscriber(vector) — MikroORM EventSubscriber

Function (not class) that takes a Vector and returns a MikroORM-conforming
POJO with lifecycle methods (afterCreate, afterUpdate, afterDelete, etc.).
When MikroORM fires an entity event, the subscriber builds a Signal from
the entity name + event type (e.g. ="literal/create/after"=) and uses
=steer.shine= to fire ALL matching effects at the terminal node.

=getSubscribedEntities()= returns =[]=. MikroORM fires events for all
entities regardless — Signal routing handles filtering. No timing dependency
on when handlers are added to the Vector.

Registered on the EM once, early. The twitch Vector is populated over the
daemon lifecycle (datamap setup, mode traits, domain code). Effects added
later are picked up automatically.

*** steer controllers — shotgun, shine, spray

Three multi-effect variants of =steer.traverse=:

- =steer.shotgun(vector, signal)= — fires effects at EVERY level during
  traversal. =v.open("/a", f).branch("/a").open("/b", g)= + signal ="/a/b"=
  → fires both =f= and =g=. Hits everything along the way.

- =steer.shine(vector, signal)= — fires only direct hits at the terminal
  node. Same example → fires only =g=. Used by =shape.subscriber= for
  precise entity event routing.

- =steer.spray(vector, signal)= — navigates to a position using the signal,
  then harvests ALL effects in the entire subtree below. =spray(v, "/a")=
  collects everything under the =/a= branch.

All three share =steer.strategy= from invoke. Each returns an array of
=async (input) => output= callables. =steer.spread= preserves the old
shotgun behavior (flatmap scope across multiple signals at one level).

*** Other typology pieces

- =RemoteRepository= — client-side generic repository. =$entities= nanostore,
  CRUD methods mirroring shard API over Connection. =subscribe(where)=
  returns =unsubscribe()=. =merge()= upserts into store. =_hydrate()=
  resolves cross-repo relations via =_schema=.

- =Broadcaster= — async pub/sub. =subscribe(filter, {timeout})= returns
  ={iterable, unsubscribe}=. Timeout option prevents infinite iterator hangs.
  =push(event, entity)= checks =object.match= per subscriber.

- =tests/scenarios/datamap.js= — in-memory SQLite scenario with concrete
  entity schemas, seed data, repos. =@vivalence/typology/scenarios=.

** Design Decisions (Settled)

1. Per-entity branches. Each entity gets its own aperture branch with its
   own middleware stack. No more =/:entity/:method= param-dispatched handlers.
2. =.post()= for all CRUD routes. =.get()= for =/subscribe=.
3. Scope is a function: =scope(ctx => ({user: ctx.user.id}))=.
4. Auto-flush on every write. No batch mode.
5. Error responses are data: ={code: "NOT_FOUND", message: "..."}=.
   Client acts on code. Message carries diagnostic detail (2026-03-23).
6. =findOneOrFail= for update/remove. Error middleware translates to 404.
7. Three separate composable shards (repository, reactive, ingest), not
   one monolith with options flags.
8. Reactivity flows through the twitch Vector, not inline MikroORM
   subscribers. One =shape.subscriber(twitch)= on the EM routes all
   entity events. Reactive handlers and domain reaction handlers coexist
   as multiple effects on the same Vector paths.
9. Entity name normalization: =getEntityName().toLowerCase().replace("entity", "")=
   because MikroORM returns class names like "LiteralEntity", and the
   subscriber strips "entity" from =args.entity.constructor.name=.
10. Custom repositories (DataRepository.ensure) aren't inherited through
    MikroORM's EntitySchema =extends=. The shard checks
    =typeof repo.ensure === "function"=.

// systems/kajuit/src/typology/entities/daemon.js
import { Connection, Path, RemoteRepository } from "@vivalence/typology";
import { Mode } from "./mode.js";
import { Intent } from "./intent.js";

export class Daemon {
  manifest = null;
  mount = null;
  connection = null;
  entities = {};
  cargo = {};

  constructor(connection) {
    this.connection = connection;
  }

  getAsset(asset) {
    if (!this.cargo || !asset) return null;
    if (asset.path) return this.cargo[asset.path] ?? null;
    if (asset.slug) {
      const entry = Object.entries(this.cargo)
        .find(([k]) => k.endsWith("/" + asset.slug) || k.startsWith(asset.slug));
      return entry?.[1] ?? null;
    }
    return null;
  }

  toJSON() {
    return {
      slug: this.slug ?? this.manifest?.slug ?? null,
      mount: this.mount?.nature ?? null,
      manifest: this.manifest,
    };
  }
}

export const prototype = Daemon;

export async function lifecycle(daemon) {
  daemon.manifest = await daemon.connection.call("/manifest");
  daemon.slug = daemon.manifest.slug;
  daemon.call = daemon.connection.call.bind(daemon.connection);
  daemon.mount = new Path(`/daemon/${daemon.slug}`);

  daemon.entities = {
    mode: new RemoteRepository(Mode)
      .connect(daemon.connection.branch("/entities/mode")),
    intent: new RemoteRepository(Intent)
      .connect(daemon.connection.branch("/entities/intent")),
    session: new RemoteRepository()
      .connect(daemon.connection.branch("/userspace/entities/session")),
  };

  const modes = await daemon.entities.mode.find();
  for (const mode of modes) {
    mode.intents = new Set();
    mode.daemon = daemon;
    mode.mount = daemon.mount.branch(`/mode/${mode.type}/${mode.slug}`);
    mode.connection = daemon.connection.branch(mode.mount.nature);
    mode.call = mode.connection.call.bind(mode.connection);
    mode.manifest = await mode.connection.call("/manifest");
    if (mode.implements("VIEWABLE")) mode.view = await mode.connection.call("/view");
    if (mode.implements("SELFEVIDENT")) mode.link = mode.mount.rebase("/viva");
  }

  daemon.cargo = await daemon.connection.call("/cargo");

  const intents = await daemon.entities.intent.find({}, { populate: ["symbols", "literals"] });
  for (const intent of intents) {
    intent.symbols = intent.symbols ?? [];
    intent.literals = intent.literals ?? [];
    intent.mode = await daemon.entities.mode.findOne({ id: intent.mode?.id ?? intent.mode });
    if (intent.mode && intent.implements("SELFEVIDENT")) {
      intent.link = intent.mode.mount.branch(`/intent/${intent.slug}`).rebase("/viva");
    }
    if (intent.mode) intent.mode.intents.add(intent);
  }
}

export function projectSchema(orm) {
  const result = {};
  for (const meta of orm.getMetadata().getAll().values()) {
    if (meta.abstract) continue;
    result[meta.name] = {
      name: meta.name,

** EntityStore (Client)

#+begin_src javascript
class EntityStore {
  constructor(schema, connection) {
    this.schema = schema;
    for (const [name, meta] of Object.entries(schema)) {
      const key = name.toLowerCase().replace("entity", "");
      const repo = new RemoteRepository();
      repo.connect(connection.branch(meta.path));
      repo._schema = { ...meta, _stores: this };
      this[key] = repo;
    }
  }
}

* Phase E — Reactive Subscriptions End-to-End — INFRASTRUCTURE DONE (2026-03-26)

Wire the full subscription path:
MikroORM entity mutates → =shape.subscriber= catches it → =steer.shine=
routes through twitch Vector → =reactive()= handler pushes to Broadcaster
→ Broadcaster =/subscribe= SSE endpoint → =Connection.subscribe()= on
client → =RemoteRepository.subscribe()= drives =$entities= nanostore → UI.

** Server Side (Done in Typology)

=shard.datamap.reactive(repo, twitch)= opens handlers on the twitch
Vector. When an entity event fires, =shape.subscriber= routes through
the Vector, the reactive handler serializes and pushes to a Broadcaster,
the =/subscribe= endpoint serves the Broadcaster as SSE.

Phase A wires this into the runtime. Adding =.slurp(shard.datamap.reactive(...)=
to session and buffer branches enables subscriptions for those entity types.
Literal/symbol get reactive too for domain-level event propagation.

Multiple effects coexist: the reactive broadcaster handler and any
domain-specific handlers (mode traits, domain reactions) all fire via
=steer.shine= on the same twitch paths.

** Client Side (Done in Typology)

=RemoteRepository.subscribe(where)= calls =connection.subscribe("/subscribe")=,
iterates the async generator, drives =merge()= or =_drop()= on =$entities=.
Returns =unsubscribe()=.

** Ingest — Reverse Flow (Done in Typology)

=shard.datamap.ingest(repo)= exposes =/ingest= endpoint. Consumes incoming
SSE via =ctx.request.subscribe()=. Each event applied to repo (create,
update, delete). The transport primitives are symmetric:

- Forward: server → =Response.publish()= → SSE → =Connection.subscribe()= → client
- Reverse: client → =Connection.publish()= → SSE → =Request.subscribe()= → server

This enables:
- Daemon-to-daemon entity sync (daemon A publishes, daemon B ingests)
- Client-driven mutation streaming (offline queue, reconnection flush)
- Service-to-service entity replication (lighthouse → daemons)

*** Subscription lifecycle

*** Backpressure

Broadcaster queue grows if events arrive faster than SSE can send.
