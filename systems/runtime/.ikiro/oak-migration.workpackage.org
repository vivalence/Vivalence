#+TITLE: Oak Migration — Work Package
#+AUTHOR: Vivalence

* Intent

The runtime uses Oak (~Application~, ~Router~, ~compose~) for HTTP serving. With the
~http~ compiler (see ~vector/.ikiro/http-compiler.workpackage.org~), Oak is redundant.
~Deno.serve~ replaces ~Application.listen~. Vector ~traverse~ replaces ~Router~. The
http compiler handles body parsing, response serialization, error boundaries.

This workpackage covers the runtime-side migration: replacing Oak infrastructure in
lifecycle code with the http compiler and ~Deno.serve~.

** Dependencies

- Context prototype in typology (from vector http-compiler workpackage)
- ~compiler/http.js~ in vector (from vector http-compiler workpackage)
- Response.type on Response prototype (from vector http-compiler workpackage)

* Migration Plan

** Phase 1: Swap imports (~Aperture~ → ~Vector~)

Mechanical. Every ~import { Aperture } from "@vivalence/vector/aperture"~ becomes
~import { Vector } from "@vivalence/vector"~. Every ~new Aperture()~ becomes
~new Vector()~. The API is identical: ~.open()~, ~.use()~, ~.branch()~, ~.slurp()~.

Files: ~daemon/daemon.js~, ~daemon/lifecycle/population.js~, ~daemon/lifecycle/resolution.js~,
~lifecycle/populate.js~, ~runtime/runtime.js~.

** Phase 2: Replace ~compose~ + ~serve~ with http compiler

~lifecycle/resolve.js~ currently does:

#+begin_src js
// compose()
runtimeDie.good.server
  .use(mw.cors)
  .use(mw.notFound)
  .use(async (ctx, next) => {
    ctx.input = await parser(ctx);
    await next();
    ctx.response.body = ctx.output;
    // ... status handling, error handling
  });
runtimeDie.good.server.use(runtimeDie.good.aperture.compose(true));

// launch()
runtimeDie.good.server.listen({ port, hostname, signal });
#+end_src

Becomes:

#+begin_src js
import { http } from "@vivalence/vector/compiler";

// compose()
const handler = http(runtimeDie.good.vector);
// CORS: either as vector middleware or handler wrapper (TBD)

// launch()
runtimeDie.listening = Deno.serve({
  port: url.port,
  hostname: url.hostname,
  signal: runtimeDie.abort.signal,
  onListen: ({ hostname, port }) => console.log(`listening on ${hostname}:${port}`),
}, handler);
#+end_src

~Application~ disappears from ~runtime.js~. The ~server~ property becomes the
~Deno.HttpServer~ returned by ~Deno.serve~.

** Phase 3: Replace daemon Connection transport

~daemon/lifecycle/integration.js~ currently does:

#+begin_src js
const composed = await die.good.aperture.compose(true);
die.connection = new Connection(new Url("http://internal"), async (ctx) => {
  ctx.input = ctx.input || ctx.request.body;
  await composed(ctx);
  ctx.response.body = ctx.output;
  // ... status/error handling
});
#+end_src

Short-term (using ~compileInvoke~ from aperture workpackage):

#+begin_src js
import { compileInvoke } from "@vivalence/vector/aperture";
die.connection = new Connection(new Url("http://internal"), compileInvoke(die.good.vector));
#+end_src

Long-term (Connection vector transport — separate workpackage):
The Connection transport traverses the vector directly using Context. No compilation
step. This is separate work.

** Phase 4: CORS

Currently ~mw.cors~ is Oak middleware in ~vector/compiler/aperture/mw.js~. Needs to
become either:

a) A vector middleware that short-circuits on OPTIONS
b) A wrapper around the http handler
c) A shard

Decision deferred. CORS logic (~15 lines) is straightforward to extract regardless
of where it lands.

** Phase 5: Remove Oak

Once all phases complete:
- Remove ~@oak/oak~ from ~deno.jsonc~ imports
- Remove ~vector/compiler/aperture/~ directory
- Remove ~compiler/oak.js~
- Update ~vector/compiler/index.js~ exports

* What Does NOT Change

- Endpoint handler functions (~daemon/aperture/datamap.js~, ~userspace.js~, ~modes.js~, ~freight.js~)
  — they call ~die.good.aperture.open()~ which becomes ~die.good.vector.open()~. Same API.
- Mode trait functions — they call ~mode.aperture.open/use~ which becomes ~mode.vector.open/use~.
- The middleware that injects ~ctx.daemon.call~ — same pattern, closures over connection.
- ~lifecycle/resolve.js~ attach/expose logic — same ~.branch().use().open().slurp()~ calls.
- Test structure — tests hit HTTP endpoints, don't care about Oak vs Deno.serve underneath.

* Open Spaces

** Property rename: ~.aperture~ → ~.vector~

~daemon.aperture~, ~mode.aperture~, ~runtime.aperture~ all become ~.vector~. Grep shows
~30 sites. Mechanical but touches many files. Could be done incrementally or all at once.

** CORS strategy

Needs decision before Phase 4. Cleanest is probably a handler wrapper since CORS
should intercept OPTIONS before any vector traversal.

** ~Deno.serve~ shutdown

~Deno.serve~ returns ~Deno.HttpServer~ with ~.finished~ Promise and ~.shutdown()~ method.
Currently ~runtimeDie.listening~ stores the ~app.listen()~ promise. Needs minor adjustment
for the new shutdown semantics (~server.shutdown()~ instead of abort controller,
or keep abort controller via ~signal~ option).
