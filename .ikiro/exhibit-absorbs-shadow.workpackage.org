#+TITLE: Exhibit absorbs Shadow — recite as a style of present
#+AUTHOR: Vivalence
#+DATE: 2026-04-22
#+STATUS: DESIGN

* Intent

Collapse the ~shadow~ game mode into ~exhibit~ as a stylistic variant.

Today these are two top-level modes with overlapping shape: ~exhibit~ /presents/
literals (table / pattern / contrastive layouts, no input), ~shadow~ /presents
then tests/ a literal (timed memorize phase, then typed recall, per-token
scoring). Read pedagogically, ~shadow~ is "exhibit, then echo it back" — the
presentation is the same; the only addition is a follow-up recall stage with
optional timer.

The two modes already share their ~Desk~ surface, the same TRANSLATED literal
contract, and the same daemon-level ~/pick/literal/feed~ fallback. ~shadow~'s
unique surface is ~75 lines of phase + timer state — not enough mode to
justify standing alone.

After this workpackage:

- ~game/shadow~ no longer exists as a mode in the registry.
- ~exhibit~ gains a ~data.style~ enum: ~BROWSE~ (default, current behavior) and
  ~RECITE~ (new, absorbs shadow's two-phase machine).
- ~exhibit~ gains an ~/emit/recite~ route + a ~recite~ intent.
- All four shadow call sites in tactics (~clinic/routine.js~,
  ~survival/buildup.js~, ~survival/exercise.js~, the ~clinic.api.shadow~
  primitive) point at ~game.exhibit.emit.recite(...)~ instead.
- The two daemon manifests that import ~"@vivalence/game/shadow"~
  (~testament~ + ~multiplayer/server~) drop the line.
- Tests at ~runtime/tests/mode/emitters.test.js~ and
  ~runtime/tests/daemon/integration.test.js~ retarget the shadow case onto
  ~exhibit/recite~.

* Why

| Today                                                               | After                                                       |
|---------------------------------------------------------------------+-------------------------------------------------------------|
| Two modes, same ~Desk~ surface, same TRANSLATED contract            | One mode (~exhibit~) with two styles                        |
| ~shadow.svelte~ (458 lines) — only novelty is timer + 2-phase       | ~Exhibit.svelte~ branches on ~data.style~; novelty in one place |
| Tactic call sites split between ~game.shadow~ and ~game.exhibit~    | All "present + maybe recite" routed through ~game.exhibit~  |
| Two daemon registry entries for one pedagogical idea                | One                                                         |
| Shadow's ~MASKED.batch~ key dead — handler reads ~ctx.input.limit~  | Recite intent uses canonical ~MASKED.limit~                 |
| "Style" axis on a presentation mode does not yet exist anywhere     | ~data.style~ joins ~data.layout~ / ~data.gameplay~ as a discriminant |

The compositional argument: ~exhibit~ is the *presentation primitive* of the
mode set. Recite is the *presentation primitive followed by an active recall
stage*. That is one mode with two styles, not two modes.

* Vocabulary

Settled (in use):

- *exhibit* — game mode that presents structured knowledge.
- *layout* — already on exhibit (~TABLE~ / ~PATTERN~ / ~CONTRASTIVE~). Controls
  /how literals are arranged/ inside the presentation.
- *recall* — direction of the question, established across modes:
  ~LEARNING~ / ~KNOWN~ / per-literal array / omitted (random per literal).
- *speed* — preset object ~{rate: FAST | NORMAL | SLOW}~ or custom
  ~{base, multiplier}~. Established on shadow + judge.
- *forgiving* — boolean toggle for diacritic + punctuation tolerance during
  evaluation. Established on Write / Listen-TYPE / Shadow.
- *gameplay* — discriminant axis on ~listen~ (~PICK~ / ~TYPE~), ~match~
  (~TRANSLATE~), ~cloze~ (~PICK~ / ~TYPE~). Mode-internal interaction shape.

Introduced:

- *style* — new discriminant on ~exhibit~. Controls /what kind of
  presentation/ this buffer is.
  - ~BROWSE~ (default) — current exhibit behavior. Renders all literals in
    one of the layouts. Single "Got it" advance.
  - ~RECITE~ — absorbs shadow. Steps through literals one at a time, each as
    a memorize → typed-recall → feedback card. Optional timer (~speed~).
- ~/emit/recite~ — new route on exhibit. Accepts explicit ~literal~ or
  ~literals~ input, OR (when neither given and ~where~ is present) auto-fetches
  via ~daemon.entities.literal.feed~. Returns a buffer with ~data.style:
  "RECITE"~.
- *recite* (intent slug) — new dataset intent on exhibit, mounting
  ~/emit/recite~. Supersedes shadow's ~feed~ intent.

Deprecated:

- ~game/shadow~ mode — deleted.
- ~api.shadow~ on ~clinic/emitter/shards/routine.js~ — renamed ~api.recite~.

* Architectural directives

- *D1 — One mode, two styles.* Exhibit's data schema gains ~style~ as the
  primary discriminant. ~layout~ stays a sub-discriminant scoped to
  ~style: "BROWSE"~. ~recall~ + ~speed~ are sub-discriminants scoped to
  ~style: "RECITE"~. Wrong-style fields are ignored, not defended against —
  data shape encodes intent.

- *D2 — Style is presentation-shape, not interaction.* The ~style~ axis is
  about /what the buffer does/ (browse vs recite), parallel to how ~layout~
  is /how items lay out/ within browse. It is *not* a synonym for
  ~gameplay~ (PICK vs TYPE vs ...). Future styles can grow here without
  collision: ~COVER~ (reveal-on-click), ~TIMED_BROWSE~ (auto-advancing
  carousel), ~DICTATION~ (audio in, type out — when VOCALIZED matures).

- *D3 — Single ~/emit/recite~ route, polymorphic on input.* Shadow shipped
  two routes (~/literals~, ~/feed~). Exhibit's ~/recite~ collapses them: if
  ~literal~ / ~literals~ is given, use it; else if ~where~ is given,
  ~daemon.entities.literal.feed~ it. The intent mounts ~/emit/recite~ with
  no literals → auto-fetch branch. Tactics pass ~literal~ → explicit branch.

- *D4 — Tactic call sites change shape, not intent.* Every shadow call
  becomes a recite call against ~exhibit~. The ~api.shadow~ helper in
  ~clinic/emitter/shards/routine.js~ is renamed ~api.recite~ and the
  pedagogical guard inside ~api.contextualizeSentence~ stays
  (~needsShadow~ → ~needsRecite~ — local rename, same condition).

- *D5 — No backwards-compatibility shim.* Per project convention, no
  ~game/shadow~ stub re-exporting from exhibit. Delete the directory.
  Callers are updated in the same diff.

- *D6 — Manifest version bump records the merge.* ~exhibit.viva.js~ goes
  ~0.1.0~ → ~0.2.0~. Description updates to reflect both styles.

* Design

** Data schema (new exhibit buffer)

#+BEGIN_SRC js
v.buffer({
  data: {
    style: v.string({ default: "BROWSE" }),

    // BROWSE-only fields
    layout: v.string({ default: "TABLE" }),
    title: v.string({ default: "" }),
    subtitle: v.string().optional(),
    template: v.string().optional(),

    // RECITE-only fields
    recall: v
      .union([v.string(), v.array(v.string())], {
        description: "RECITE only — LEARNING, KNOWN, per-literal array, or omit for random",
      })
      .optional(),
    speed: v
      .object({})
      .desc("RECITE only — {rate: FAST|NORMAL|SLOW} or custom {base, multiplier}")
      .optional(),
  },
})
#+END_SRC

~forgiving~ stays implicit. Shadow currently exposes it as a Svelte prop
defaulting ~true~ but no caller ever sets it. We do the same in the new
component (default ~true~, no data field). If it ever needs to be tunable
per-buffer, add it then.

** Buffer view branching

~Exhibit.svelte~ becomes a single component with a top-level branch on
~data.style~. The ~BROWSE~ arm is the existing render tree verbatim. The
~RECITE~ arm is shadow's two-phase machine, plumbed onto the same ~Desk~.

#+BEGIN_SRC text
Exhibit.svelte
├─ {#if style === "BROWSE"}
│   ├─ meta (lang label, layout)
│   ├─ title / subtitle
│   ├─ TABLE | PATTERN | CONTRASTIVE
│   └─ controls: "Got it"
│
└─ {#if style === "RECITE"}
    ├─ {#if phase === "show"}
    │   ├─ progress bar (countdown)
    │   ├─ meta (memorize, type, position, time, speed, forgiving)
    │   ├─ answer (large)
    │   └─ translation
    │   controls: "I'm ready"
    │
    └─ {#if phase === "recall"}
        ├─ meta (recall, type, speed, forgiving)
        ├─ translation
        └─ {#if submitted} feedback (signal, expected, per-token tokens)
        controls: text input + Check / Next →
#+END_SRC

The two arms share nothing in the template — they only share ~Desk~ as the
chrome. CSS is partitioned into a ~/* ── browse ── */~ section (existing)
and a ~/* ── recite ── */~ section (lifted from shadow). The mobile
breakpoints are merged.

#+BEGIN_SRC svelte
<script>
  import { Asset, Desk, Keyboard, ViewportLock } from "@vivalence/drapes";

  const { terminal, buffer, forgiving = true } = $props();

  const data = buffer.data ?? {};
  const style = data.style ?? "BROWSE";

  // ─────────────────────────────── BROWSE state ─────────────────────────────
  const layout = data.layout ?? "TABLE";
  const title = data.title ?? "";
  const subtitle = data.subtitle;
  const template = data.template;

  let literals = $state(buffer.literals ?? []);
  let loading = $state(!literals.length);

  if (style === "BROWSE" && !literals.length) {
    terminal.daemon.call("/pick/literal/feed", { limit: 6 }).then((lits) => {
      literals = lits ?? [];
      loading = false;
    });
  }

  function personLabel(literal) {
    const symbols = literal?.symbol ?? {};
    if (symbols["word.person.first"] && symbols["word.number.singular"]) return "eu";
    if (symbols["word.person.second"] && symbols["word.number.singular"]) return "tu";
    if (symbols["word.person.third"] && symbols["word.number.singular"]) return "ele/ela/você";
    if (symbols["word.person.first"] && symbols["word.number.plural"]) return "nós";
    if (symbols["word.person.second"] && symbols["word.number.plural"]) return "vós";
    if (symbols["word.person.third"] && symbols["word.number.plural"]) return "eles/elas/vocês";
    return null;
  }

  function known(literal) { return literal?.trait?.TRANSLATED?.known; }
  function learning(literal) { return literal?.trait?.TRANSLATED?.learning; }

  function getAudio(literal) {
    const reference = literal?.trait?.VOCALIZED?.asset;
    return reference ? terminal.daemon.getAsset(reference) : null;
  }

  function parseTemplate(templateString) {
    if (!templateString) return [];
    const parts = templateString.split(/(\{[^}]+\})/g);
    return parts.map((part) => {
      const match = part.match(/^\{(.+)\}$/);
      if (match) return { type: "slot", label: match[1] };
      return { type: "text", value: part };
    });
  }

  const templateParts = $derived(template ? parseTemplate(template) : []);

  function contrastiveGroups(items) {
    const middle = Math.ceil(items.length / 2);
    return [items.slice(0, middle), items.slice(middle)];
  }

  const groups = $derived(layout === "CONTRASTIVE" ? contrastiveGroups(literals) : []);

  function browseAdvance() {
    buffer.release();
  }

  // ─────────────────────────────── RECITE state ─────────────────────────────
  let keyboard;
  const speed = data.speed ?? {};
  const queue = buffer.literals ?? [];

  function recallFor(index) {
    const direction = data.recall;
    if (!direction) return Math.random() > 0.5 ? "KNOWN" : "LEARNING";
    if (Array.isArray(direction)) return direction[index] ?? (Math.random() > 0.5 ? "KNOWN" : "LEARNING");
    return direction;
  }

  let currentIndex = $state(0);
  let activeRecall = $state(recallFor(0));
  let literal = $state(queue[0] ?? null);
  let reciteLoading = $state(style === "RECITE" && !literal);
  let phase = $state("show");
  let input = $state("");
  let submitted = $state(false);
  let result = $state(null);
  let elapsed = $state(0);
  let timerInterval = $state(null);

  const total = $derived(queue.length);
  const position = $derived(currentIndex + 1);

  const isWord = $derived(literal?.symbol?.word);
  const knownText = $derived(literal?.trait?.TRANSLATED?.known);
  const learningText = $derived(literal?.trait?.TRANSLATED?.learning);
  const prompt = $derived(activeRecall === "KNOWN" ? learningText : knownText);
  const answer = $derived(activeRecall === "KNOWN" ? knownText : learningText);
  const answerLabel = $derived(activeRecall === "KNOWN" ? "English" : "Português");

  const SPEED_PRESETS = {
    FAST: { base: 1200, multiplier: 80 },
    NORMAL: { base: 2400, multiplier: 120 },
    SLOW: { base: 3600, multiplier: 180 },
  };

  const resolvedSpeed = (() => {
    const preset = SPEED_PRESETS[speed.rate] ?? SPEED_PRESETS.NORMAL;
    return {
      base: speed.base ?? preset.base,
      multiplier: speed.multiplier ?? preset.multiplier,
    };
  })();

  const timeMs = $derived.by(() => {
    if (!answer) return resolvedSpeed.base;
    return resolvedSpeed.base + answer.length * resolvedSpeed.multiplier;
  });

  const progress = $derived(Math.max(0, 1 - elapsed / timeMs));

  const normalize = forgiving
    ? (text) =>
        text
          .toLowerCase()
          .normalize("NFD")
          .replace(/[̀-ͯ]/g, "")
          .replace(/[?.!,;:'"'´`~\-—]/g, "")
          .trim()
    : (text) => text.toLowerCase().trim();

  function evaluate(rawInput, currentLiteral, currentRecall, word) {
    const expected =
      currentRecall === "KNOWN"
        ? currentLiteral.trait.TRANSLATED.known
        : currentLiteral.trait.TRANSLATED.learning;
    if (word) return evaluateWord(rawInput, expected);
    return evaluateSentence(rawInput, expected, currentLiteral.trait.ANNOTATED?.tokens, currentRecall);
  }

  function evaluateWord(rawInput, expected) {
    const alternatives = expected
      .split("/")
      .map((alternative) => alternative.replace(/\(.*?\)/g, "").trim())
      .filter(Boolean);
    const match = alternatives.some((alternative) => normalize(rawInput) === normalize(alternative));
    return { signal: match ? "SUCCESS" : "MISTAKE", tokens: null };
  }

  function evaluateSentence(rawInput, expected, tokens, currentRecall) {
    const match = normalize(rawInput) === normalize(expected);
    if (!tokens) {
      return { signal: match ? "SUCCESS" : "MISTAKE", tokens: null };
    }
    if (currentRecall === "KNOWN") {
      const signal = match ? "SUCCESS" : "MISTAKE";
      return { signal, tokens: tokens.map((token) => ({ ...token, signal })) };
    }
    const remaining = normalize(rawInput).split(/\s+/);
    const results = tokens.map((token) => {
      const parts = normalize(token.form).split(/\s+/);
      const found = parts.every((part) => {
        const index = remaining.indexOf(part);
        if (index === -1) return false;
        remaining.splice(index, 1);
        return true;
      });
      return { ...token, signal: found ? "SUCCESS" : "MISTAKE" };
    });
    const correct = results.filter((token) => token.signal === "SUCCESS").length;
    const total = results.length;
    const signal = correct === total ? "SUCCESS" : "MISTAKE";
    return { signal, tokens: results };
  }

  function review(outcome) {
    terminal.daemon.call("/review/literal", {
      signal: outcome.signal,
      scope: { literal: literal.id },
    });
    if (outcome.tokens) {
      for (const token of outcome.tokens) {
        if (!token.literal) continue;
        terminal.daemon.call("/review/literal", {
          signal: token.signal,
          scope: { literal: token.literal },
        });
      }
    }
  }

  function skipToRecall() {
    clearInterval(timerInterval);
    phase = "recall";
  }

  function startTimer() {
    clearInterval(timerInterval);
    elapsed = 0;
    timerInterval = setInterval(() => {
      elapsed += 50;
      if (elapsed >= timeMs) {
        clearInterval(timerInterval);
        phase = "recall";
      }
    }, 50);
  }

  function begin(card) {
    literal = card;
    reciteLoading = false;
    phase = "show";
    startTimer();
  }

  if (style === "RECITE") {
    if (literal) {
      begin(literal);
    } else {
      terminal.daemon.call("/pick/literal/feed", { limit: 3 }).then((cards) => {
        if (cards?.length) {
          for (const card of cards) queue.push(card);
          begin(queue[0]);
        } else {
          reciteLoading = false;
        }
      });
    }
  }

  function submit() {
    if (!input.trim() || submitted) return;
    submitted = true;
    result = evaluate(input, literal, activeRecall, isWord);
    review(result);
  }

  async function next() {
    clearInterval(timerInterval);
    if (currentIndex + 1 < queue.length) {
      currentIndex++;
      activeRecall = recallFor(currentIndex);
      input = "";
      submitted = false;
      result = null;
      begin(queue[currentIndex]);
    } else {
      buffer.release();
    }
  }

  let inputElement = $state(null);

  $effect(() => {
    if (style !== "RECITE") return;
    if (phase === "recall" && inputElement) {
      inputElement.focus();
    } else if (phase === "show" && keyboard) {
      keyboard.focus();
    }
  });

  function handleKey(event) {
    if (style === "BROWSE") {
      if (event.target.closest("input,textarea")) return;
      if (event.key === "Enter" || event.key === " ") {
        event.preventDefault();
        browseAdvance();
      }
      return;
    }
    if (event.key === "Enter") {
      if (phase === "show") return skipToRecall();
      if (!submitted) submit();
      else next();
    }
  }
</script>

* Open questions

- *Recall direction for RECITE* — shadow always called with
  ~recall: "LEARNING"~ in production. Should RECITE *enforce* LEARNING
  (drop the union from the schema) or stay polymorphic for future use
  (e.g. a /known-recall/ exercise mode)? Lean keep polymorphic — costs
  nothing, and the union mirrors what shadow shipped.
- *Single ~/recite~ vs split ~/recite~ + ~/recite-feed~* — proposal
  collapses to one polymorphic route. ~/feed~ stays split for BROWSE
  because it already exists and changing it is out of scope. Eventually
  ~/present~ + ~/feed~ on BROWSE could collapse the same way; that is a
  separate consistency pass.
- *Enum vs emergence* — could omit ~data.style~ entirely and dispatch on
  presence of ~data.recall~. Rejected: the established convention in
  ~listen~ (~gameplay~) and ~exhibit~ (~layout~) is explicit enum
  discriminants. ~style~ joins that family.
- *Naming the new style ~RECITE~ vs ~SHADOW~* — chose RECITE to describe
  the user action (they recite the answer back). SHADOW is the deleted
  mode's name; carrying it forward as an enum value would conserve the
  history at the cost of clarity. If the historical reference matters
  more than I think, swap to ~SHADOW~ — it is a one-token change.
