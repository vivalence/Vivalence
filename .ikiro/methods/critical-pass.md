# the critical pass — hardening a staged artifact without touching the gated worktree

beef: *"do a ciritcal pass against that quest. improve it. fix anything in need of fixing"* · *"do the same check and critical pass against m33."*

A quest can carry an executable artifact as an attachment — a package tree (`quests/m32-memoriter/memoriter/`), a patch (`quests/m33-dictation/dictation.patch`) — authored outside the session, against some past model of the codebase. Everything under `.ikiro/` is mine, so the ARTIFACT can be improved in place; the repo it targets stays gated (apply/land only on `go`). The pass makes the artifact TRUE against HEAD before beef ever applies it.

## the shape (both passes followed it; write it once)

1. **base facts first.** Which commit does the artifact claim? Is it local (`git cat-file -t`)? How does it relate to HEAD (`git merge-base`; `git diff --stat <claimed> HEAD -- <touched files>`)? Does it dry-apply (`patch -p1 --dry-run -N` — never `git apply`, the guard is right to block it)? m33 claimed a sibling commit; the diff between the sibling and HEAD on every patched file was EMPTY, so "applies clean there" ⇒ "applies clean here" — a fact, not a hope.
2. **sandbox, not worktree.** `rsync` the code containers to the scratchpad (exclude `node_modules .git .jj`, kajuit `static/`+`build/`, corpora freight, `*.db`), symlink `node_modules` and `testament` in, stub missing workspace members with their `deno.jsonc`. ~250 MB, two minutes. This is where patches get applied and suites run — the worktree is never touched, no VCS is touched, beef's live watchers keep running (runtime tests use `:memory:` datamaps; check `ps aux | grep deno` anyway).
3. **baseline before patch.** Every suite the artifact could reach, unpatched — real repo is fine for a read-only run — then patched in the sandbox. Report the numbers side by side; the artifact's own "green" claim is the author's, not evidence. (m33's report claimed "identical pre-existing snapshot failures"; the baseline was clean.)
4. **grep every terrain claim.** Especially the ABSENCE claims — *"no typology distance util exists"*, *"CONVERSATIONAL is dead"*, *"nobody parses the upstream body"*. Both artifacts contained one; both were false (`belt/string.js:53 levenshtein`, `Mode.ts:19`). Absence is the claim that rots fastest and does the most damage when trusted; it is also the cheapest to check.
5. **read the CONSUMER side of every new seam.** Tests pass by construction (they encode the author's model); the defects live where the artifact meets code it did not write. m32: the client hydrates `buffer.literals` with `populate: ["literals","symbols"]` only (`focus.js:13`), so `literal.retention` could never reach the tablet — status had to ride `buffer.data`. m33: `cortex.findOne` is squared-euclid nearest in tune-space (`belt/array.js:52`), so "multi is the default" was decided by a vector the author never computed — English won. Find the mechanism behind every "by default", and compute it.
6. **compare against ≥1 live sibling.** m32 = the education domain frozen two renames back (memory → engram → retention) plus a hallucination API that never existed (`configure().context.system()`); the live sibling (`Retention.ts`, francesca/aprende `harness.js`) is the oracle. Anything the sibling does that the artifact fabricates is a fix; anything the artifact adds beyond the sibling's scope is a flag.
7. **scope against the artifact's own words.** m33's quest said *"dictation only — no full voice mode"* and shipped a barge-in arbiter with tests. Tested completeness makes creep look earned. Park (`quests/<name>/deferred/`), never delete; one `mv` re-adds.
8. **wiring sections are the least trustworthy part.** They describe the environment the author imagined: `localhost.viva.js` (does not exist — `test.viva.js`), a hand edit of `registry.json` (m31 says `/ledger/tap`), `SECRET_DEEPGRAM` (it is `SECRET_VIVA_DEEPGRAM_API_KEY`, and deepgram was already mounted in all three daemons). Re-derive wiring from `testament/variant/` + docs every time.
9. **fix in the sandbox, re-run, REGENERATE.** Never hand-edit a patch. Fresh pristine base copy → fix in the sandbox → `git diff --no-index --src-prefix=a/ --dst-prefix=b/ base sandbox` (read-only git, allowed) → **whitelist to the intended file set** (beef edits live; a fresh base captures his concurrent changes and kajuit's `.svelte-kit/` regenerates) → normalize prefixes → dry-apply on the real tree → record the new stat in the quest.
10. **the quest carries the delta.** Status line rewritten with the real numbers; a `* critical pass` section (method · verification table · claims that held · defects fixed · parked · design↔build drift · stale text · residue); stale sentences annotated inline `/(pass: …)/` rather than rewritten — build reports are verbatim records. Frontier line updated, under its char limit.

## what it is not

Not a review that ends in prose. Not `git apply` on the worktree. Not "tests are green so the claims are true". Not applying the artifact — that is beef's `go`, per op.
