#+AUTHOR: Vivalence

* Intent

Define the html client's layout system from the ground up. Not a CSS
framework — a set of named, addressable, composable *panels* arranged
into a *T-bone* (structural skeleton) with a draggable controller — the
*viket* — at the junction. Mobile-first; viket is the primary input
device. All layout state is a serializable JSON blob (saveable, JSON-
patchable, hot-swappable). Themed exclusively through dapper's per-
skeleton color sets — never raw hex, never tailwind utility classes.

The terminal-first client plugs into this layout: terminals render in
panel E, modeline in A or H, REPL is one phase of E.

* Terminology

| Term         | Definition                                                                          |
|--------------+-------------------------------------------------------------------------------------|
| T-bone       | Structural skeleton: crown + spine + viket. Always visible.                         |
| Crown        | Horizontal bone perpendicular to stem direction. Passes through viket.              |
| Spine        | Stem of the T. Extends from viket in the orientation direction.                     |
| Viket / pincer | Square at junction of crown and spine. Draggable. Layout controller. The *position* is =pincer=; the *component* is =viket=. |
| Panel        | A content region. A, B, C are primary; D/E/F live inside C; G/H are overlays.       |
| Bone         | Structural separator between panels. 4-bone model: shoulder, crown, pincer, spine.  |
| Orientation  | Stem direction: 0/90/180/270. Selected via long-press radial.                       |
| Snap grid    | Fibonacci-ish percentages =[0,13,21,34,50,66,79,87,100]=, 28px gravity.             |
| Layout blob  | Serializable JSON object holding viket position, orientation, panel state.          |
| Skeleton     | Self-contained color universe (5 of them, 0-4). 27 scalars, flat. Per-pane.         |

Panel inventory: A=header/nav, B=left rail, C=stage (D=inspector, E=work
surface, F=aux/preview), G=system tray (overlay), H=dev console (overlay).

* Architecture

** T-bone

Crown + spine = sk1-surface bones with theme-primary borders, always
visible. Viket = square at junction (size = bone thickness), sk1
surface, primary border, vinca-viket pictogram, sharp corners. Panels
A/B/C fill area around bones; collapse to 0 when viket reaches edge.

** Layout blob

#+begin_src json
{
  "viket": {"x": 540, "y": 320, "snap": null},
  "previous": {"x": 200, "y": 240},
  "standard": {"x": 540, "y": 320},
  "orientation": 0,
  "panels": {"a": true, "b": true},
  "stage": {"ratio": "1 3 1", "d": {"show": true, "orient": "tree"},
            "e": {"phase": "repl"}, "f": {"show": false, "orient": "map"}},
  "overlays": {"g": false, "h": true},
  "bones": {"notch": true}
}
#+end_src

Engine emits CSS variables on the document root from this blob. One
source of truth.

** Viket gesture state machine

#+begin_src
idle ──hold──→ longpress ──release-far──→ idle (commit orientation)
                  │
                  └──release-near──→ sticky ──tap-spoke──→ idle (commit)
                                       │  ──tap-outside──→ idle (cancel)
                                       │  ──hold-viket──→ longpress
                                       └──drag-viket──→ idle (sticky cancelled)
#+end_src

Tap actions (idle): 1=jump to standard, 2=swap with previous, 3+=mark
current as standard. Pointer events unified, =setPointerCapture= on
pointerdown, =touch-action: none= to suppress browser gestures.

** Dapper skeleton model

5 skeletons (0-4), each a flat populated set of 27 scalars:
- structural: surface, contrast, boundary (1 state)
- emphasis: primary, secondary, accent (3 states each: base/hover/active)
- semantic: info, success, warning, danger (3 states each)
- error: box triplet (surface, contrast, boundary)
- font: heading, body, code

10 root ramps (IRON, DEEP, GOLD, AQUA, INDIGO, MOSS, AMBER, RUST, SLATE,
PINK), 12 stops each (=50,100,...,950=). Skeletons hand-pick ~12 anchors;
=skeleton({...})= factory + =interactive= / =box= helpers fan out the
rest. ~60 numbers parameterize the whole 5-skeleton system.

CSS naming: explicit, always. =--colors-skeleton-1-primary-base=, never
shorthand. Grep-able, predictable.

Skeleton → pincer region: 0=T-bone+H, 1=panel A, 2=B+E, 3=D+F, 4=G+frame.

** Context architecture (4 symbols)

3 structural (set once at boot) + 1 navigational (reactive).

| Symbol     | Set by      | Lifecycle                  | Provides                             |
|------------+-------------+----------------------------+--------------------------------------|
| LIGHTHOUSE | layout init | once                       | auth, identity, daemons Map          |
| QUARTERS   | layout init | once                       | terminal LocalRepository, $active    |
| BRIDGE     | layout init | once                       | layout store + view store + geometry |
| THREAD     | layout      | reactive (follows active)  | thread entity, daemon/mode accessors |

DAEMON and MODE consolidated into THREAD on 2026-04-11 (single
navigational context; =thread.mode= and =thread.mode.daemon= are
accessors). Old =$client= still exports DAEMON/MODE — pending removal.

State is data; lifecycle is functions over data. No boot vectors
(wafers) on the client. Lighthouse: =verify/populate/boot=. Daemon:
=construct/populate/resolve=. Classes stay pure state containers.

Context store directory at =systems/html/src/typology/stores/=:
=store.js= (factory), =quarters.js=, =bridge.js=, =thread.js=.

* Open Questions (Finn decisions)

- Per-route layout state vs global localStorage blob — currently global
  by default; per-route is more natural for users (different layout per
  mode) but more complex.
- Panel A/B/C/D/E/F/G/H are placeholder letters; need real names
  (mode-bar, left-rail, stage, inspector, etc.) before production.
- Modeline location: panel A or H? (Phase 5 wiring decision pending.)
- D/E/F orientation modes (tree, icons, list, map) not enumerated.
- Notch behavior (crown notch above B collapse when viket left-aligns)
  not implemented; may be deferred indefinitely.
- Keyboard interface to viket — if layout is the OS shell, shortcuts
  are eventually mandatory.
- DAEMON / MODE symbols still exported from =$client= post-M4
  consolidation; pending removal.
- Old wafer files retained as reference but no longer invoked from boot;
  delete?

- Viket drag broken under real mouse (Phase 12 followup; agent can't

- No skin for =directed= signature (the original stamp consumer).

* Decisions

| Decision | Choice | Rationale |
|----------+--------+-----------|
| Layout primitive name | T-bone | Crown + stem visual metaphor; "Layout" too generic. |
| Junction controller | Viket (component) / pincer (position) | Brand element with existing pictogram. The junction IS the pincer. |
| Bones as DOM siblings | Yes | Addressable, animatable, themable per-segment. Borders-on-panels rejected. |
| Bones color | sk1-surface + theme-primary-boundary | Modeline material from screenshot ref. |
| Viket shape | Square (no radius) | User explicit. Modeline button feel. |
| Panel collapse to 0 | Yes | Allows full-screen single-panel modes. |
| Snap grid | Fibonacci-ish percentages, 28px gravity | Combines dominant points (0/50/100) with golden-ratio secondaries. |
| Sticky hold | Yes | Long-press → release → menu stays. |
| H as panel, G as overlay | Yes | H is 50px top bar; G slides in from right. |
| Layout state | Flat JSON blob | Serializable, JSON-patchable, transportable. |
| Token namespace | =--colors-...= raw form | No tailwind utility classes for colors. |
| Mobile-first | Pointer events + =touch-action: none= | Unified gesture handler set. |
| Context count (M4) | 4 — LIGHTHOUSE, QUARTERS, BRIDGE, THREAD | Down from 6; DAEMON/MODE consolidated into THREAD. |
| Context internals | =store() + domain commands= | Uniform internal model. |
| Terminal state | Minimal ={id, slug}= | Thread holds daemon/mode/intent/phase. |
| Quarters backend | =LocalRepository= (Map-backed) | Map IS identity map; same CRUD as RemoteRepository. |
| Color model | Flat scoped skeletons (5×27 scalars) | Per-skeleton populated sets fix legibility across panes. |
| CSS var naming | Explicit, always (=-base= included) | Grep-able, predictable. |
| Value pickup | Factory + middleware (~60 anchors total) | =skeleton({...})= + =interactive=/=box= helpers. |
| Root palettes | 10 (IRON/DEEP/GOLD/AQUA/INDIGO/MOSS/AMBER/RUST/SLATE/PINK) | 12-step ramps. Vibe: dark scandinavian, nordsee + concrete. |
| Lifecycle on client | Functional — data + standalone fns | Boot vectors retired; classes stay pure state. |
| Stamp output | =nature= outside signature; arrays; =children= on branches | Identity vs metadata; duplicate natures preserved; consumer doesn't care effects/trajectories distinction. |
