** Bug 1 — EntityManager cast recursion on cyclic schemas

While forcing middleware on cold-restored threads via =await daemon.entities.thread.merge(local)=, hit:

#+begin_src

    cast entity-manager.js:144
    integrate entity-manager.js:103

    resolve entity-manager.js:125
    cast entity-manager.js:141

Cycle: thread.mode → mode.intents → intent.mode → mode (already in identity) → recurse.

=integrate= was gating only the install hook (=installed= Set) but =cast= ran unconditionally on every re-sight. The =installed= Set's documented purpose ("nested integrate on the same id observes the parent as already-installed and does not re-fire") only protected the integrator, not the cast walk.

Identity invariant was *not* the issue — same Thread instance returned every time via =merge=. Recursion was in the *walk*, not in duplicate instantiation.

*** Fix — extract Tab.svelte that subscribes per-entity

New file =systems/kajuit/src/routes/pincer/bones/crown/widgets/Tab.svelte=. Subscription chain via =$effect= + =atom.subscribe= → local =$state=:

#+begin_src svelte

let thread = $state(null);
let label = $state({});
let traits = $state([]);
let conversation = $state(null);
let conversationState = $state(null);

$effect(() => {
  if (!terminal?.$thread) { thread = null; return; }
  return terminal.$thread.subscribe((value) => { thread = value ?? null; });
});

$effect(() => {
  if (!thread || typeof thread !== "object" || !thread.$label) { label = {}; return; }
  return thread.$label.subscribe((value) => { label = value ?? {}; });

=crown.svelte= reduces to a slim wrapper that iterates terminals and mounts =<Tab terminal={t} isActive={t.id === activeId} onactivate={...} onclose={...} />= per terminal. The 500ms tick interval and =tabLabel= / =tabDescription= / =tabFlags= / =tabConversation= functions were all dropped.

=$effect= teardown returns the unsubscribe; effect re-runs cleanly when =terminal= or =thread= reference changes.

** Pattern (keep for next session)

For any list-rendered component that needs to reactively reflect entity-internal atom state:

1. Pass the *entity reference* as a prop, not a derived field.
2. Inside the component, =$effect= chain: subscribe to entity =$X= atoms → write to local =$state=.
3. Each subscription returns the unsubscribe so =$effect= teardown handles cleanup on prop changes.
4. =$derived= reads off the local =$state=, never the getters on the entity directly.
5. When mutating an entity in place (without going through =repo.update=), call =repo.refresh()= so =$entities= fires and any list components that depend on the array reference re-render.

The Svelte-5-vs-nanostores gap (=feedback_svelte5_rune_props=, =project_svelte_class_state_gap=) only matters when you skip the explicit subscription. Convention: =class field $X = atom(...)= + prototype getter =get X() { return $X.get(); }= for ergonomic non-reactive reads; consumers that need reactivity subscribe to =$X= directly.

** Pre-existing latent bug not fixed

=Entity.toJSON= still serializes atom-as-plain when an entity is passed to =JSON.stringify= without a class-specific =toJSON=. Currently no entity hits that path. If a new entity class needs persist + has =$X= fields, either give it an explicit =toJSON= (collapse atoms via the getter form) or upgrade =Entity.toJSON= per the getter-walk pattern above.
