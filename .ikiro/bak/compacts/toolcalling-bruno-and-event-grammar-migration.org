** Event-name grammar discussion

After test summary used =turn.open / turn.close= etc, user:
#+BEGIN_QUOTE
the naming is inconsistent. whats teh scope here? what's inside the semantic space here? and whats our range of expression? we can do turn.open obviously. turn_open should work too. what about turn/open?
#+END_QUOTE

Laid out grammar:

Scope — bounded:
| Axis | Today | Plausible future |
|------+-------+------------------|
| Subject | turn, part | tool, maybe thread |
| Action | open, delta, close | error, abort (per channel-grammar in toolcalling wp: server emits packet/close/error/abort) |

6 events today.

Range of expression — three valid separators, each load-bearing elsewhere in viva:
| Sep | Meaning | Where else | Reads as |
|-----+---------+------------+----------|
| =.= | namespace.method | JS access, current packet style | =turn.open= |
| =_= | name-component join | =agentic=-compiled tool names (=learner_state=) | =turn_open= |
| =/= | path / address | Signal pathname, vector nature, aperture (=/harness/dialogue/stream=) | =turn/open= |

Argument for =/=: aligns with Signal/Url/vector-nature world. =/turn/open= IS valid Signature. Single grammar end-to-end. =_= is workaround for Anthropic, not primitive. =.= keeps packets in own corner forever.
