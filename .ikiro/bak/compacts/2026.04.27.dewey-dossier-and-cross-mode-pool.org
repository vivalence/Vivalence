* Arc
Four threads over one session, after the morning's re-mode-ilization compact. Mostly infrastructure: making modes aware of state and surviving small mobile/desktop layout regressions.

First — a dock geometry bug. =systems/html/src/routes/pincer/panels/a.svelte= had a =.panel= flex container that read =geometry.size=, =geometry.vertical=, and =geometry.side= but never applied =geometry.direction=, so flex-direction defaulted to =row= and only =side="right"= visually worked. =top=, =bottom=, =left= all dumped the dock to the right edge regardless. One-line fix: added =style:flex-direction={geometry.direction}= on the panel. The =flexDirection()= helper in =a/dock.geometry.js= already returned the correct row/row-reverse/column/column-reverse — it just wasn't read.

Second — the survival/buildup tactic was emitting zero buffers at first activation despite 452 word literals matching =proficiency.survival=. Started runtime/watch, added 5 logs at junctions in =buildup.js= + 1 in =clinic/emitter/pronouns.js=, fired =pull= via the live UI through Chrome automation. Trace showed buildup found 452 literals, scored 8 valid theme buckets, picked 3 weakest, fired all 3 delegates with =hasTarget: true= — and ended with BUFFERS=0. Root cause: =await ctx.daemon.modes.tactic.clinic.emit[route](...)= runs through the EMITTER trait wrapper in =systems/runtime/daemon/traits/emitter.js=, which spins up a fresh =ctx.pool= per call, drains it, and returns =ctx.output = {condition: "NOMINAL", buffers: [...]}=. Buildup awaited the call but threw the return away, so the inner pool's buffers never reached buildup's outer pool. Fix: =ctx.pool.add(target({...}))=. =Pool.add= already understands promises and =condition/buffers= envelopes (=subsystems/typology/prototypes/pool.js:23=), so adding the unawaited promise also parallelizes the delegates as a bonus. Verified with a fresh pull through the UI — BUFFERS went 0 → 19 IDLE.

Third — Dewey began as a thin =/dialogue= middleware that pulled 20 traces + 20 due literals and concatenated them into a learner-state prompt. Finn rejected the first cut ("no this is shit. i want the modes to know more than that") then redirected ("right idea, wrong bucket. for now we keep that in the mode. set it up such that we can use it as a toolcalling tool later and as a middleware now"). Lifted into =registry/modes/@vivalence/teacher/dewey/dossier.js=, colocated with the mode rather than the kernel, with =gather(ctx, where = {ontology: "word"})= returning ={histogram, weak, recent, due, mistakes, toPrompt(), toJSON()}=. Histogram showed UNTOUCHED=0 first because Memory entities only exist after first review — Finn flagged this ("untouched doesnt exist technically. its literals without memories given user"), fixed by adding =daemon.entities.literal.count(where)= and computing =UNTOUCHED = totalLiterals - memories.length=. Weak section showed UNTOUCHED items because =byStrength= orders NULL-strength literals first; fixed by pulling 20, filtering to memory-having, slicing 5. Then "cut this down to 50% but keep info" — dropped slug prefix (redundant with learning/known), English example sentence (gloss covers it), default UNKNOWN status, verbose section headers. Lines went from ~110 chars to ~52. Added chat etiquette to Dewey's persona ("you live inside vivalence, a language-learning system... small chat box on screen... no markdown, no bullets, no bold, no headings, no asterisks. Just sentences").

Fourth — mobile keyboard regression in =Listen.svelte= TYPE mode. Between reviews, soft keyboard closed/reopened, jarring on phone. Cause: Check/Next buttons had =onmousedown preventDefault= but iOS Safari doesn't fire =mousedown= on touch (or fires it after =touchstart= resolves), so the focus-shift block never landed. Tap stole focus from the hidden =<Keyboard>= drape that parks focus, mobile keyboard closed, then advance() remounted the input and reopened it. Fix: added =ontouchstart preventDefault= to both buttons, mirroring the pattern already on the pick-option buttons (line 314). Then a theory thread: same root cause for the audio button, but Asset's inner button isn't ours to edit. Sketched =preserveFocus= as a Svelte action with capture-phase listeners on a wrapper, generalizable across all game modes — Finn confirmed scope ("this would apply generally to all modes") and proposed land it in drapes. Not applied yet.

** memory: feedback_emitter_delegation_via_pool.md — NEW
Logged the buildup bug pattern: when a tactic emitter delegates to another mode's emitter via =mode.emit.X(input)=, the call returns a fresh-pool drained envelope. Bare =await target(...)= drops it on the floor. Always wrap in =ctx.pool.add(target(...))=.

* Decisions
- Dossier lives in the mode (=teacher/dewey/dossier.js=), not the kernel. Finn: "right idea, wrong bucket. for now we keep that in the mode"
- Dual-use shape: =gather()= returns ={...data, toPrompt, toJSON}=; =tool(ctx)= factory exported for later. Same assembler powers middleware now and LLM tool later
- UNTOUCHED in histogram = literals-without-memory, computed via negative space — Memory rows only exist post-first-review, so the status enum's UNTOUCHED is structurally unreachable from memory queries alone
- Default scope =gather(ctx, {ontology: "word"})= — covers words + conjugation forms; modes can narrow (e.g. ={symbols: ["proficiency.survival"]}=)
- Prompt format ~50% shorter by dropping slug-prefix (redundant), English example (gloss covers), default UNKNOWN status, verbose headers
- Pool.add(promise) over =await + add(result)= — promises collected and resolved at drain time, parallelizes the delegated emits
- Dewey gets chat-channel context and explicit "no markdown" directive in persona — markdown was leaking through as literal asterisks in the chat box
- =ontouchstart preventDefault= over =onmousedown preventDefault= for mobile-tap focus preservation; the latter doesn't fire reliably on iOS Safari
- Theme labels in buildup remain hardcoded for v1 (still in the morning compact's open list); broken =functional.time/degree/discourse= symbols still silently drop their themes from bucket scoring — three of ten themes never select, but unrelated to the zero-buffer bug
