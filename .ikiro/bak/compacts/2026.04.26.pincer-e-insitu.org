* Learnings · future

** Trait reactivity is a real gap, not a hand-wave
The pattern of =trait config (durable JSON) → install-time finalizer → runtime artifact= captures state at install and never rebinds. AIMED's =thread.pull= is the canonical example. Today the fix is per-controller manual rebind. Long-term: per-trait atom subscription, with teardown contracts on finalizers. The quest is the contract for that work.

** Class instances vs plain objects in Svelte 5 $state
Svelte 5's =$state= deep-proxies plain objects + arrays but treats class instances as opaque. =Thread= and =Terminal= are classes, so any UI that reads =terminal.session= or =thread.trait.X= via =$state= won't re-render on field mutation. Workaround: use atoms (=$dock=, =$thread=, =$state=, =$entities=) for any field that needs UI reactivity. Anything assigned with =instance.field = newValue= is a black hole for the dashboard.

** Hardening JSON renderers pays off immediately
=Json.svelte= with depth/type guards meant MASKED-display worked the moment we threw arbitrary trait config at it. Same renderer becomes useful for other display panels (panel-d trait dump already uses raw JSON.stringify; could swap).

** Dewey hallucinator says "I am Claude"
The system prompt sent through =ctx.hallucination.add([...])= is not enough to override the model's identity. The agent introduced itself as Claude / Anthropic regardless of dewey's persona instruction. Worth investigating cortex faculty wiring + harness composition order — and whether the prompt is being eclipsed by API-level system messages.

** Strategic logging is cheap; HMR noise is not
=[INSITU]= logs at every state transition made the un-gutting a 5-minute verify (engage → opening → moin → packets). Worth keeping in. The cost was HMR's stale-module noise after deletes (vite tries to reload removed files); reload clears it but it briefly drowned the signal. Future: prefer rename over delete during HMR-sensitive iteration, or full reload sooner.

** "Display only first, then editing" is a good cadence
MASKED started as a malformed editor with invented chips. Stripped to display-only via Json. That single move forced the question: what's actually in the trait? Once we could see it, the editor's shape became obvious. Apply this pattern to other trait controllers when they start guessing.

** Consolidate engage/release before the second consumer asks
The Dock and the Session controller both wanted to start a session. The first cut wired engage logic only into the panel-e button; the Dock's "open" was a UI flag. The user's "message received no answer ever comes" exposed it. Lifting =engage(thread)= / =release()= onto =Terminal= unified the two paths in one short edit. Small refactor, big clarity.

** Naming caused a misread
Calling the WS layer "P · port" read as "the dock". Finn flagged it: "i confused dock with port". The fix was renaming + content clarification. The =port= card was eventually replaced by session introspection, which carries both the WS readyState and the rehydrated send/inbound shapes — better signal density than a single-purpose port card.

** "do your research" → DB schema dive paid for itself
The MASKED/AIMED/QUEUEING ontology research (sqlite schema → datamap shard → entity-manager → trait functions → sample data) became the entire foundation for everything that followed. Without that pass the controllers would still be guessing. Future controller work should start with the same dive.
