* Intent

Collapse two naming fault lines in the cortex before more code lands:

1. Faculty type *=conversation=* is wordy and bleeds into the already-taken
   *CONVERSATIONAL* mode trait. Rename the faculty to *=dialogue=*, matching
   =mode.dialogue= / =mode.cake.dialogue= which already exist. One word, one
   meaning, wherever it shows up in the cortex stack.
2. The planned STT faculty was going to be *=transcription=* — too long, and
   Finn prefers *=verbatim=*. Since no live code registers a =transcription=
   faculty yet, this lands as a fresh slot in the FacultyType union plus orb
   sketch alignment.

Apply both in a single, coherent rename pass. Routes, faculty type strings,
client-side getters, server-side resolver calls, tests, and the orb Sketch 2
all move together.

** Desired end state

- =cortex.resolve("dialogue", ...)= returns what =cortex.resolve("conversation", ...)=
  returned yesterday. Same for =.stream= / =.render= via
  =hallucinate.dialogue.*=.
- =cortex.resolve("verbatim", ...)= is a valid call shape — resolves to empty
  faculty list today, waits for a provider to populate.
- FacultyType union reads: =dialogue | object | speech | verbatim | call=.
- No remaining live reference to =conversation= as a faculty type anywhere in
  =subsystems/typology= or =systems/runtime=. (Trait name =CONVERSATIONAL=
  stays intact.)
- No remaining live reference to =transcription= as a faculty type. Only the
  one surviving mention is in =registry/modes/@vivalence/game/listen/listen.viva.js=
  description string, which is pedagogical — kept.
- Orb Sketch 2 routes use =/dialogue/*= / =/speech/*= / =/verbatim/*=. Socket
  state slots mirror: =socket.state.{dialogue,speech,verbatim}=.
- All existing cortex + hallucinate + trait tests pass unchanged in behavior;
  only strings updated.

* Vocabulary

** Settled (existing, respected)

- *cortex* — faculty table. =resolve(type, {tune, via})= lookup.
- *faculty* — a capability slot: ={type, tune, context, channels, via}=.
- *hallucinate* — the cortex spawn — per-invocation envelope binding turns,
  tools, config to faculty calls.
- *CONVERSATIONAL* — mode trait. Name stays. Wires =mode.dialogue=,
  =mode.aperture.branch("/dialogue")=, and (pending M4.0) the session vector.
- *tune* — 3-vector for tier selection across faculties; gains a latency dim
  in longdistance work (orthogonal to this rename).

** Introduced / renamed

- *dialogue* (faculty type) — text in, turn packets out. Was =conversation=.
  Chosen because =mode.dialogue= already exists and means the same thing;
  unifying collapses a distinction that was never meaningful.
- *verbatim* (faculty type) — audio in, text turn out (STT). New slot. Replaces
  the planned =transcription= name.
- =/verbatim/*= (socket route family) — audio soma packets in, =/verbatim/close=
  finalizes the buffered audio and routes the transcribed text into dialogue.

* Architectural directives

** D1. Faculty type = one word, matches the capability

=conversation= was a sentence; =dialogue= is the thing. =transcription= was a
noun-form of a verb; =verbatim= names what you get back (text exactly as
spoken). Faculty types become canonical keys exposed to the client via
=/herald/cortex=; short, distinctive words keep the herald table legible.

** D2. Route family slot matches faculty type, one-for-one

The socket route family slot is the faculty type exactly. =/dialogue/*= ⇔
=dialogue= faculty. =/speech/*= ⇔ =speech= faculty. =/verbatim/*= ⇔ =verbatim=
faculty. One vocabulary, three layers (cortex table / route / socket state).

** D3. Trait name stays CONVERSATIONAL

The trait composes many capabilities (dialogue + speech + verbatim + session
lifecycle); its name is intentionally broader than any one faculty. Don't
conflate. Explicit user directive.

** D4. Verbatim faculty lands additive

No live provider ships =verbatim= today. The rename adds the type string to
the =FacultyType= union and the hallucinate constructor getter so calls
resolve cleanly to an empty list until a provider registers. Enables orb /
herald / INSITU UI to reason about the slot before an implementation lands.

** D5. Pedagogical use of "transcription" in learning modes is unrelated

=registry/modes/@vivalence/game/listen/listen.viva.js= uses the word
"transcription" in a human-facing description ("Pick or type the
meaning/transcription"). That's linguistic vocabulary, not a cortex faculty
reference. Out of scope.
