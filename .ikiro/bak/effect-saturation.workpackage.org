#+TITLE: Effect Saturation — identity-gated install, single integrate verb
#+AUTHOR: Vivalence
#+DATE: 2026-04-22
#+STATUS: DONE 2026-04-22 — install fires exactly once per unique identity. Browser verified: 20 modes + 18 threads = 1×/id (was 40 + 36 = 2×/id). Two sequential fixes: pre-merge race in =em.cast= + double-populate memoization in =lighthouse.populate=.

* Intent

Structural setup effects must not fire at data-merge cadence. The client re-ran the full hydrate pipeline (trait install, connection aim, =/buffered= fetch, subscriptions) every time =em.merge= touched an entity — which was every relation traversal during =em.cast=. Mode use[] was observed firing 50+ times per scene.

** Desired end state

- Structural setup runs exactly once per identity. Fetch =/buffered= once. Install traits once. Subscribe once.
- Data merge runs every time a raw POJO lands — no ceremony, just field copy.
- Relation resolution is pure identity-map lookup; never triggers install on entities already in the map.
- The identity map =em.identities= is the system-wide cadence gate.
- One call path: =repo.merge(raw) → em.integrate(name, raw, kind) → em.cast + install-if-fresh=. No back doors.
- Two args at the install boundary: =(entity, raw)=. Context via closure, not envelope.

* Vocabulary

- *integrate* — identity-gated install. Runs install exactly once per =(name, id)=. Subsequent calls cast-and-merge only. =em.integrate(name, raw, kind)= is the single entry point.
- *install* — the dossier-derived side-effect closure compiled from =dossier.use[]=. Trait application, connection aim, subscriptions. Receives =(entity, raw)=.
- *integrator registry* — =em.integrators[name]= holds the compiled install fn per registered name. Populated via =em.register(name, repository, integrate)=. Replaces the =repo.integrate= field on managed repos.
- *merge* — field-level copy from incoming POJO into the identity-mapped entity. Re-sight semantic.
- *resolve* — relation-field normalization. Pulls from identity map; triggers integrate on unseen ids.
- *cast* — EM method that walks relations, resolves each, then merges the root. Defines =$collection= for =1:m= + =mappedBy=. Called by integrate on every sight.
- *restore* — =LocalRepository.restore()=. Reads localStorage, synchronously populates identities + reactive store, returns a promise for the async integrate pass. Called by =Quarters= after the integrate fn is wired. No entity-level bridge state.
- *hydration ctx* — =ctx = { entity, raw, dossier, repository, dataspace | quarters, daemon }=. Seeded by =shard.context.attach= middlewares (Dataspace/Quarters attach dossier/repository/self; daemon seed attaches =daemon=). Middleware reaches through =ctx.daemon.mount= / =.connection= / =.link=.
- *seed* — =Dataspace= constructor option: =(vector) => void= hook that layers caller-scoped attaches on top of Dataspace's own seed middlewares. =daemon.js= passes =seedDaemon(daemon)=.
- *effect saturation* — the bug class this workpackage dissolves. Setup effects (install, fetch, subscribe) firing at data-merge cadence because hydrate-on-read ran them on every relation traversal.

* Architectural directives

** D1. Identity map is the cadence gate

The EM's =identities= map distinguishes first-sight from re-sight. Install effects gate on =!identity(name, raw)=; merge does not. Structural invariant.

** D2. integrate is the single entry for install

=repo.merge(raw)= routes through =em.integrate(name, raw, kind)=. =em.integrate= calls =em.cast= (relation walk) then fires the registered integrator on first-sight only. =repo.cast= is a synonym of =repo.merge= — both land on =em.integrate=. No back door.

** D3. EM owns the integrator registry

Compiled install lives at =em.integrators[name]=, populated by =em.register(name, repo, integrate)=. Repos don't carry the fn. Whoever owns the identity map owns dispatch. =LocalRepository= is its own identity owner, so it keeps its own =.integrate= field.

** D4. shard.context.attach is the canonical seed primitive

Dataspace/Quarters seed middleware uses =shard.context.attach(key, value)= — the typology idiom (also used by CHAOSMONKEY). No bespoke per-site =use(async (ctx, next) => { ctx.x = y; await next(); })=.

** D5. Attach objects, not fields

=daemon.js= seed is one line: =vector.use(shard.context.attach("daemon", daemon))=. Middleware reaches =ctx.daemon.mount= / =.connection= / =.link=. No shadow vars (=ctx.mount=, =ctx.link=, =ctx.connection=) — they dilute the ctx without adding information.

** D6. (entity, raw) signature — no envelope

=integrate(entity, raw)=. Everywhere. Closure carries context (dossier, repository, dataspace, daemon) via the compiled vector. The envelope =({raw, em, name})= was redundant with what the closure already had.

** D7. Inline, don't abstract

=shard.invitro= (the brief compile helper namespace) deleted. Dataspace + Quarters each inline their own =strategy()= + compile loop. Two call sites, visible structure, no indirection.

*** =subsystems/typology/prototypes/entity-manager.js=

#+begin_src js
this.integrators = {};  // name → compiled install fn

register(name, repository, integrate = null) {
  if (!this.stores[name]) this.stores[name] = atom([]);
  repository.manage(this, name);
  this.repositoryMap[name] = repository;
  this.integrators[name] = integrate;
  return repository;
}

async integrate(name, raw, kind) {
  if (!raw?.id) return raw;
  const fresh = !this.identity(name, raw);
  const entity = await this.cast(name, raw, kind);
  if (fresh) {
    const install = this.integrators[name];
    if (install) await install(entity, raw);
  }
  return entity;
}

async disintegrate(name, id) { this.drop(name, id); }
#+end_src

#+begin_src js
restore() {
  if (!this.storageKey) return Promise.resolve();
  let rawList = null;
  try {
    const stored = localStorage.getItem(this.storageKey);
    if (stored) rawList = JSON.parse(stored);
  } catch {}
  if (!rawList) return Promise.resolve();

  const pending = [];
  for (const raw of rawList) {
    if (!raw?.id || this.identities.has(raw.id)) continue;
    const entity = this.kind
      ? Object.assign(new this.kind(), { ...raw })
      : { ...raw };
    this.identities.set(raw.id, entity);
    this.$entities.set([...this.$entities.get(), entity]);
    pending.push({ entity, raw });
  }
  if (!this.integrate) return Promise.resolve();
  return (async () => {
    for (const { entity, raw } of pending) await this.integrate(entity, raw);
  })();
}
#+end_src

=cast= gates install to =!existing= (fixes the original saturation on LocalRepo re-cast).

*** Investigation log — 2026-04-22 evening

Three-round root-cause hunt after the rotation. Each round ruled out one layer and surfaced the next.

**** Round 1 — pre-merge await race in =em.cast= (partial cause)

Browser trace shows =thread.js:74= install middleware firing ~40× per page load (=console.trace()= on every hit). The identity gate is not closing. No =ctx.mount is undefined= errors — install is working, just firing too often.

**** Stack shape (uniform across all 40 hits)

Every call follows the same spine:

#+begin_src

Two distinct upstreams feed this spine:

1. *ThreadContext.resolve path* — =findOne remote-repository.js:87 → resolve thread-store.js:30 → ThreadContext thread-store.js:17= (under =populate lighthouse.js:253= via =boot= and =unsubscribePopulate +layout.svelte:68=).
2. *Panel D navigation path* — =find remote-repository.js:76 → find remote-repository.js:76 → compose navigation.js:15 → D d.svelte:22=. =find= appears *twice* in the stack — either =find= recurses, or one =find= awaits another.

**** Evidence interpretation

- =populate lighthouse.js:253= fires from both =boot lighthouse.js:226= AND =unsubscribePopulate +layout.svelte:68=. The subscribe-notify-set-populate loop is active: every populate triggers a =notify= → =set= → =subscribe= callback → =populate= again. Each populate re-walks the lifecycle pipeline.
- =find → find= in the Panel D path (d.svelte:22 navigation compose) indicates =find()= entering itself — consistent with =remote-repository.find= doing =Promise.all(results.map(raw => this.cast(raw)))= where each cast re-enters find via some relation (or the vector registered two copies of the find effect).
- Every entry into =em.integrate= ends with =fresh === true=. Either:
  - The identity map write is racing with concurrent integrate calls on the same id (pre-merge awaits in =cast=), OR
  - The subscribe/populate loop is running the *same raw* through integrate many times within one microtask — all see empty map, all install.

**** Hypothesis — pre-merge await race

=em.integrate= captures =fresh = !identity(name, raw)= BEFORE =em.cast= completes. =em.cast= awaits =Promise.all(raw[field].map(resolve))= across 1:m relations BEFORE calling =merge=. A 1:m field whose children back-reference the parent via m:1 will nest back into =integrate(name, raw)= for the *same id* — the outer merge hasn't run yet, so nested calls see =fresh=true=.

**** Fix applied

Moved =this.merge(name, raw, kind)= to the *top* of =em.cast=, synchronous before any await. Walk relations reading =raw[field]= for inputs, assigning results to =entity[field]=.

**** Failing test that drove the change

Added =back-reference race= describe block to =subsystems/typology/tests/entity-manager.integrate.test.js= — registers mode + intent repos, integrates a mode whose =intents= array has children back-referencing the mode via =m:1=. Pre-fix: =modeInstalls = 2=. Post-fix: =modeInstalls = 1=.

**** False trail — walking =entity[field]= on the nested call

First attempt walked =entity[field]= (rather than =raw[field]=) after synchronous merge. Caused infinite recursion: on the nested back-ref cast, the canonical entity still holds its original =intents= array, so the 1:m walk re-dispatches all children, each re-enters the parent, each re-walks. =InternalError: too much recursion=. Backed out — kept reading =raw[field]= so nested cast receives a bare =\{id\}= ref with no relations.

**** Round 2 — post-fix, symptom changed

After race fix shipped: browser still showed install firing 2× per unique identity. Not the recursion any more. Test case in typology passed (closed the synthetic reflected-ref race) but browser showed a different path.

**** Fix applied

Memoized =populate= with an in-flight promise:

#+begin_src js
export async function populate(lighthouse) {
  if (lighthouse.$populating) return lighthouse.$populating;
  if (lighthouse.daemons.size) return;
  // bootOneDaemon defined above...
  lighthouse.$populating = (async () => {
    lighthouse.manifest = await lighthouse.connection.call("/manifest");
    const daemons = await lighthouse.connection.call("/entities/daemon/find");
    await Promise.all(
      daemons.map(async (pojo) => {
        if (lighthouse.daemons.has(pojo.slug)) return;
        const daemon = await bootOneDaemon(pojo);
        lighthouse.daemons.set(daemon.slug, daemon);
      }),
    );
    lighthouse.$daemons.set([...lighthouse.daemons.values()]);
  })();
  try { await lighthouse.$populating; }
  finally { lighthouse.$populating = null; }
}
#+end_src

Post-fix browser verification: second populate sees =inflight= true=, awaits the first's promise, returns. One EM, one install-per-id. 20 modes + 18 threads.
