#+AUTHOR: Vivalence

* Overview

The Vivalence view system already speaks a framework-agnostic mount protocol:
=module.default(dom, context) → { destroy }=. This means any framework that
can mount to a div and clean up after itself slots into the existing
=Frame.svelte= → =pack()= → =view-bundler= pipeline with zero changes to the
client shell.

This document adds React as a second renderer target alongside Svelte.

* New Files

** pack-react.js

React equivalent of =@vivalence/drapes= =pack()=. Same contract:
=(dom, context) → { destroy }=.

#+begin_src js :tangle pack-react.js
import { createElement } from "react";
import { createRoot } from "react-dom/client";

export const pack = (Component) => (dom, context) => {
  const root = createRoot(dom);
  root.render(createElement(Component, context));
  return { destroy: () => root.unmount() };
};
#+end_src

** view-bundler-react.js

Parallel esbuild pipeline to =svelte()= in =view-bundler.js=. Handles JSX
via esbuild's automatic transform. Externalizes =react= / =react-dom= so
they're loaded once on the client via importmap, not bundled per-mode.

#+begin_src js :tangle view-bundler-react.js
import { dirname } from "@std/path";
import esbuild from "esbuild";

import { mapimports } from "./view-bundler.js";

export async function react(entry, isDev) {
  const bundle = await esbuild.build({
    entryPoints: [entry],
    minify: false,
    bundle: true,
    sourcemap: false,
    write: false,
    format: "esm",
    target: "es6",
    treeShaking: true,
    outdir: dirname(entry),
    jsx: "automatic",
    jsxImportSource: "react",
    external: ["react", "react-dom", "react-dom/client", "react/jsx-runtime"],
    plugins: [mapimports()],
  });
  return bundle.outputFiles;
}
#+end_src

const pool = [
  ...words.map((w) => ({ ...w, type: "word" })),
  ...sentences.map((s) => ({ ...s, type: "sentence" })),
];

const generate = () => {
  const t = pickOne(pool);
  const d = Math.random() > 0.5 ? "l1l2" : "l2l1";
  const same = pool.filter((x) => x.type === t.type && x.slug !== t.slug);
  return {
    target: t,
    direction: d,
    options: shuffle([t, ...pick(same, 3)]),
    selected: null,
  };

  const answerLang = direction === "l1l2" ? "Português" : "English";

  const select = useCallback(
    (slug) => {
      if (answered) return;
      setState((s) => ({ ...s, selected: slug }));
    },
    [answered],
  );

  const next = useCallback(() => setState(generate), []);

  return (
    <div className="bsp-node" style={{ gridTemplateRows: "1fr auto" }}>

          </div>

            {prompt}
          </p>

          <div style={styles.options}>
            {options.map((option) => {
              const isThis = selected === option.slug;
              const isAnswer = option.slug === target.slug;
              const style = answered
                ? isAnswer
                  ? styles.optCorrect
                  : isThis
                    ? styles.optWrong
                    : styles.optDimmed
                : styles.opt;

* Why This Works

The =pack()= contract is a framework adapter boundary:

#+begin_example
(dom: HTMLElement, context: Object) → { destroy: () → void }
#+end_example

=Frame.svelte= calls =module.default(dom, context)= and expects ={ destroy }=
back. It has no knowledge of what framework produced the module. The view
bundler compiles framework-specific code into ESM bundles that conform to this
contract. The VIEWABLE trait just needs to know which bundler to invoke.

This is, by accident, a micro-frontend runtime. The same protocol would work
for Solid, Preact, vanilla DOM, or anything else that can mount to a div and
clean up after itself.
