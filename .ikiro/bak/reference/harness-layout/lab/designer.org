#+title: brief — the harness map: tools and primer, added and removed by reference
# writer: agent · limit: 16000 chars · for: a designer, no repo access needed

* what this is

vivalence is a language-learning OS. A conversation with a model happens on a *thread*. The thread sits in a *mode* (a language tutor, a typing game, an operator console). Two things decide what the model can do and knows:

- *tools* — functions the model may call (read a file, deal a drill, play a typing game)
- *primer* — sections of system-prompt text (who the tutor is, grammar notes)

Every tool and every primer section has an address, a *reference*: an absolute path.

#+BEGIN_SRC text
/runtime/runtime/mode/harness/runtime/fs/read
└─host──────────┘    └─type──┘└slug──┘└path──┘
/daemon/education/mode/teacher/francesca/drill
#+END_SRC

Each reference is in exactly ONE of three states:

| state | glyph | means |
|---+---+---|
| eager | ● | in the request: the model has it now |
| lazy | ◇ | listed by name and one sentence; the model can pull it in |
| none | ○ | not there |

The *mode* offers a default (its own tools eager, its own primer as authored). The *thread* stores only a *delta* on top: a small map of reference → state. The delta wins; a load never downgrades. The user AND the model edit the same delta — the model through its own tools, the user through this UI.

Your component: let a person SEE the resolved map and ADD / REMOVE references to it, for tools and for primer, in four places. The hard part, in the owner's words: /"how do i navigate these tree*maps ? add and remove from maps via tree."/

** the cost

Everything eager lands in every request. Width costs context: the next request in the sample is ~980 tokens; loading all of =/runtime= adds ~600. Show the cost of a change before it is made.

* the commands — every gesture is one of these

| command | does | to the delta |
|---+---+---|
| =/tool/load <ref> [<ref> …]= | load, eager | writes =eager= |
| =/tool/preload <ref> …= | list, pullable | writes =lazy=; skipped where already eager |
| =/tool/unload <ref> …= | remove | deletes the key and every key under it; if a parent key still brings it in, writes =none= |
| =/primer/load <ref> …= | load a section in full | writes =eager= |
| =/primer/preload= · =/primer/unload= | the same for primer | NOT RULED yet — design them, mark them |
| =/mode <ref>= | move the thread to another mode | the delta stays; names change |

Many references at once. A branch reference takes the whole subtree. An unknown reference is REFUSED with text: =matches nothing: /nowhere=. A change that changes nothing says so (=already so=). Every load is also written into the conversation as a turn — the journal shows it.

The UI is domain-blind: every click, key and tick produces one of these commands as text, a *signal*. The pending signal IS the state of an edit in progress.

* the panes — one sentence each: shows what, from where

| pane | shows | from |
|---+---+---|
| sidebar · harness section | the RESOLVED tree, tools and primer, foldable; a picked node offers load · preload · unload | mode default + thread delta |
| harness widget | the DELTA itself — the keys the thread stores, each removable; =+ load …= | thread delta |
| inspector | tree · one node in depth (state · which key decides it · offered by the mode · the model's name · input · output · examples · primer text) · the journal entries that touched it | all three |
| repl | a signal field with completion and pickers; a preview of what would change before Enter | the catalog of references |
| ghost (terminal twin) | the same four, in a monospace terminal grid | same |

| row kind | looks like |
|---+---|
| =sub= | a sub-heading with a count, foldable |
| =item= | mark glyph · label · quiet sub-text · status dot |
| =keys= | a row of small key buttons, one may be lit |
| =choice= | label + inline chips, one latched |
| =chips= · =tags= | toggle chips |
| =value= | dot · label · value, may fold |
| =meter= | label · bar · text |
| =stepper= | label · − value + |
| =check= | ● / ○ · label · value |
| =filter= · =more= · =note= | filter field · "more" link · quiet note |

Today's harness section: tier (choice) · model (value, folds into items) · tune · effort · rounds (stepper) · context (meter) · then =primer= and =tools= sub-headings folding into the mode's DEFAULT tree with marks =● ◇ ◉(open)= and folders =▸ ▾=. It shows no delta and cannot edit.

** harness widget — exists today as a popover

The bottom modeline has segments (entity · activity · harness · display …). The harness segment shows =tier · effort · context %=; a click opens a 320px popover (max 2/3 viewport tall) holding a section of the same rows as the sidebar. The new segment needs the counts (e.g. =7● 3◇ · primer 2●=) and a popover on the delta.

** inspector — exists today

A floating panel, three columns: tree (filter field · lens tabs with counts · indented nodes: fold sign · name · quiet text · =!= flag) | entity (kind · title · reference · action buttons · breadcrumbs · key/value rows grouped in sections, rows may carry inline edits: choice · select · step · field) | trace (a timeline of spans). Narrow: the trace column hides.

** repl — exists today, too simple

A single field with a fuzzy list of commands below; a command with fixed options opens a chooser. No path completion, no multi-select, no tree. This is the open ground.

* what the lab tried — =testament/prototypes/harness-ui/=

A working playground with the sample data above, every pane, and three repl shapes writing ONE signal:

| shape | gesture |
|---+---|
| A · the field | type a path; Tab completes ONE segment; ↑↓ pick; many references space-separated |
| B · columns | Finder-like columns host → mode → path; click a name descends, a box ticks a reference; ▣ = covered by a ticked parent; ticked references collect as chips |
| C · sift | fuzzy text over every path; matches shown WITH their ancestors as an indented tree; Space ticks |

All three share a preview: =/tool/unload …/fs= → =would change · 5= with each leaf =● eager → ○ none=. Use it as behaviour reference, not as the look.

* states that must ship

- empty delta — only the mode's default; say "nothing changed from the mode"
- a branch fully eager · fully none · MIXED (counts)
- a leaf covered by a parent key vs decided by its own key (which key decides it must be visible)
- a key whose state equals what the default gives (redundant)
- pending edit: the preview, before → after, the cost delta
- refused: unknown reference, with the text
- no-op: =already so=
- after =/mode=: same references, new names
- a mode with no primer · with no tools · with 40 tools
- unruled commands (=/primer/preload= · =/primer/unload=): visibly provisional
- the model edited the delta (a journal turn arrives) while the user looks
