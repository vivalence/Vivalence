The tools vanish because of how the daemon populates a mode at boot. When the runtime resolves hello-world it builds the mode record from the manifest, then stagger walks the declared traits and asks each trait module to install itself against the mode and the daemon. The TOOLING trait is the one that reads the mode's tools vector, rolls it up into ToolCall shapes and registers each of them on the harness so the hallucinator sees them as callable. Since the manifest no longer declares TOOLING, stagger never reaches the tooling installer, so the tools vector is built (the slurps of doctor, web and research still run at module load) but nothing ever consumes it — the vector is inert, arming() in the harness finds an empty tool table, and the thread's model is never offered web_search. The aperture and the application are unaffected because they ride their own traits. This is also why nothing throws: an undeclared trait is simply skipped by the optional call, and the harness treats an empty tool table as a valid configuration, so the failure is silent by design rather than a crash. Restoring the trait declaration restores the whole chain.
