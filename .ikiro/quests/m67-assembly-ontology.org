The capabilities — what the system can do to an assembly or a component. Each is reached by harness and App alike; a tool verb is how one is called, never what it is.

| capability | what it does |
| intake | take a model file into the editor and interpret it into staged nodes — not rows |
| embed | turn a staged node into a component row and its freight file |
| mint a component | create a component with no staged geometry — parametric, from a generator and params |
| round-trip through Blender | write a component out as =.blend=, take the edit back on return |
| mint an assembly | open a new assembly, optionally referencing an existing one |
| place | put a component or an assembly into an assembly at a transform |
| join | record that a fastener holds named nodes together |
| open | put an assembly on the operator's screen |

Harness: the current buffer (staged nodes, the open assembly resolved with meshes omitted, the bin, the kinds and families) in the system prompt on every call — =ctx.hallucination.system.<key>=, m54's =system.file= shape.

Buffer: rows through the dataspace, =resolve= the domain's pure function, the threlte tree a template over it.

* usd textbook — read 09-21

Pixar =Kitchen_set= (openusd.org/files/Kitchen_set.zip) · ASWF =usd-wg/assets= (OpenChessSet; =RelationshipEncapsulationTests/SublayeredInternalReferenceTest/hardware.modeling.usda= — a Blender-exported bolt + washer assembly). Scratchpad =usd/= this session; re-download by URL.

Patterns, verbatim from the files:

- a component is THREE files: =X.usd= (interface: =kind=, =assetInfo{identifier,name}=, a =payload=) → =X_payload.usd= → =X.geom.usd= (binary crate).
- an assembly: =def Xform (kind="assembly")= → nested =Xform (kind="group")= → =def "Name" (references = @asset@) { xformOp… }=. The reference carries NO kind of its own; placement = its xformOps. =Kitchen_set_instanced.usd= differs by one word per reference: =instanceable = true=.
- =class Scope "Prototypes"= holds abstract components, =def=s reference them by path (hardware). Kitchen_set does without it.
- =modelingVariant= on a component (Nail A/B), chosen at the reference site.
- =PointInstancer= for N identical pieces (chess pawns).

| ours | textbook | verdict |
| component row | =Toaster.usd= interface + payload + geom | ✔ MODELED = the geom file; =assetInfo= = LABELED + SOURCED; Blender's =userProperties:blenderName:object= = SOURCED.blend |
| =COMPOSED.nodes[].part= + TRS | =def "X" (references = …) { xformOp… }= | ✔ exactly; the node carries no kind |
| group | =def Xform "…_grp" (kind = "group")= — a nesting Xform, no geometry | ✔ a node with children, not a row |
| family (=class= prim) | =class Scope "Prototypes"= | ✔ symbol side; Kitchen_set doesn't even use it — plain file references suffice |
| variant | =modelingVariant= on the component, picked by the reference | not needed for pt10; bolt lengths are separate components |
| joints, torque, steps | nothing. No textbook has them | ours to mint — no USD schema for assembly semantics (UsdPhysics joints are the nearest, wrong purpose) |
| subcomponent | zero uses across Kitchen_set, chess, hardware | DROPPED from the kind list until a case demands it |
