* the law

1. A buffer is a working area: =mime= · =data= (live state in SQL, mirrored) · =files= (m:n, the Files it loads or was parsed from). It is owned by a mode, hangs on a thread, and on the turns that surfaced it (m:n). A File is a file the system holds: =mode · path · mount · mime · hash · integrity · bytes=, one row per =(mode, path)= (ruling 36).
2. A View is code: =slug · mime · presents · entry=, owned by a mode, one row per =(mode, slug, mime)=; its bytes are its File rows (=file.view=, m:1 nullable), =entry= the one the client imports; a compile is a File mutation inside the View (=upstream · downstream= DEAD, Q38 10-21). It says what it is and which buffer mime it presents.
3. View and Buffer hold no relation. =view.presents === buffer.mime= is the join. A mode's buffer mime is minted from its REFERENCE (m96 ruling 3, 10-21: =/daemon/chess/mode/board/play= → =application/vnd.vivalence.daemon.chess.mode.board.play+json=); =presents= defaults to it.
4. A mode declares ONE buffer schema (=export const buffer=) and its views (=export const views=); =mode.buffer(desc)= validates against the one schema.
5. The client decides by a =[[predicate, Part]]= table walked in order: a view that presents the buffer's mime (compiled on the runtime, fetched by row — the client renders nothing of a mode's and bundles nothing, m96 10-21 /"There is no rendering on the client"/) → a chrome part for the buffer's own mime → the =+json= part → a line. =accept= is derived from the table; the runtime never knows what a client can show.
6. A code view mounts by =default(target, { terminal, buffer, surface })=; =surface.place ∈ cell · frame=; one component serves both places.
7. Several runnable views for one buffer: the toggle; =RENDERED: { cell, frame }= pins by slug; default compiled-then-latest.
8. FILESINK writes: =receive= → a File · =compile= → a view. FILESET reads the declared directory into File rows. RENDERER compiles the declared views and mints the mode's buffer. Paladin moves bytes; repositories record and import no paladin.
9. The system serves by row: =/attached/view/:id= · =/attached/file/:id=, both with =x-viva-integrity=. =Bundle · App · Freight · Cargo · /attached/bundle · /attached/cargo= die.
10. Presence is a patrol: a lifecycle beat over views and Files stats each =mount= and sets =MISSING=.
11. A client mode carries no views.
12. Notes hang on buffers and turns. Not on threads.

export const RENDERER = async (mode, context) => {
  if (!mode.module.buffer) return;
  mode.mime = mime.vivalence(context.reference.branch(`/mode/${mode.type}/${mode.slug}`));
  for (const declared of mode.module.views)
    await mode.files.compile({ slug: declared.slug, mime: declared.mime, presents: declared.presents ?? mode.mime, entry: join(mode.module.source.dirname, declared.mount) });
  mode.buffer = (desc = {}) =>
    context.entities.buffer.create({ mode: mode.entity.id, mime: mode.mime, ...desc, data: mode.module.buffer.fill(desc).data });
};

// systems/runtime/mode/traits/filesink.js — write (ruling 24: the route moves bytes, the repository records). Ruling 38 (10-21): a compile is a FILE MUTATION INSIDE THE VIEW —
// the View row is upserted by (mode, slug, mime); its bytes are File rows with file.view = view; `entry` names the one File the client imports. No upstream, no downstream.
export const FILESINK = (mode, context) => {
  const bundler = paladin.bundler(mode.mountpoint.absolute);
  mode.files.receive = async ({ path, bytes, mime }) => {
    const file = await paladin.state.store(join(mode.mountpoint.absolute, path), bytes);
    return context.entities.file.upsert({ mode: mode.entity.id, path, mime, mount: file.absolute, ...digest(file) });
  };
  mode.files.compile = async ({ slug, mime, presents, source, entry }) => {
    const view = await context.entities.view.upsert({ mode: mode.entity.id, slug, mime, presents });
    const built = await bundler.bundle(source === undefined ? { mime, entry } : { mime, source });
    for (const out of built.files)
      await context.entities.file.upsert({ mode: mode.entity.id, view: view.id, path: out.path, mime: out.mime, mount: out.absolute, ...digest(out) });
    return context.entities.view.updateOne({ id: view.id }, { entry: built.entry });
  };
  mode.aperture.post("/files/receive", (input, ctx) => mode.files.receive(input)).post("/files/compile", (input, ctx) => mode.files.compile(input));
};
