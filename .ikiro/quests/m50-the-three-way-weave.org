** what a process gets — beef's question answered

/"what does a process get? a wafer? a mask? does a process need something like that? it has the control vector."/

A process gets a *command* (its declaration) and a *die* (the record of its cast). It does not get a
mask — a mask turns a MODULE into an instance and a process is not made from a module; giving it one
would be the overlap beef warns about. It does not get a wafer — the wafer was a class that fused the
declaration carrier, the live product, the status and five verbs into one inheritable thing; the die
carries the same four fields as DATA and the verbs are the dossier's =use[]=. What makes a process a
process is not a carrier but the two contracts: it answers the control vector, and it obeys the process
contract. An entity answers neither — it has a repository.

** the dossier — the pattern (kajuit precedent, =entities/thread/dossier.js=)

holds; abort unwinds through =stop=.

#+BEGIN_SRC js
import { Pipe, Queue, Status, shape, Vector } from "@vivalence/typology";

export const Child = (identity, command, attachment = "inherit") => ({
  identity,
  command,
  attachment,
  good: null,
  status: new Status("<uninitialized>"),
  abort: new AbortController(),
  in: new Queue(),
  out: new Pipe(),
});

export const ChildDossier = {
  name: "child",
  kind: () => Child,
  use: [
    async (die, next) => {
      die.good = new Deno.Command(die.command.bin, { args: die.command.args, cwd: die.command.cwd, env: die.command.env, clearEnv: true, stdin: STDIO[die.attachment] === "piped" ? "piped" : "null", stdout: STDIO[die.attachment], stderr: STDIO[die.attachment] }).spawn();
      die.status.set({ code: "SPAWNED", pid: die.good.pid });
      try {
        await next();
      } finally {
        await stop(die);
      }
    },
    async (die, next) => {
      await Promise.race([alive(die), exited(die), late(die)]);
      die.status.set("alive");
      await next();
    },
  ],
  effect: (die) => Promise.race([die.good.status, aborted(die.abort.signal)]),
};

export const run = (die) => shape.selbstbestimmt(vector(ChildDossier))(die);
#+END_SRC

** the OS signal table — one meaning each, total

| OS signal | sender → recipient                          | meaning                                                                                  | recipient's duty                                                  |
|-----------+---------------------------------------------+------------------------------------------------------------------------------------------+-------------------------------------------------------------------|
| SIGTERM   | supervisor → child · =stop= → supervisor    | =/down=: go away gracefully                                                              | disintegrate, exit 0; never ignore                                |
| SIGINT    | tty → foreground group                      | the operator's =/down=                                                                   | same as SIGTERM; exit 0 (was 130)                                 |
| SIGQUIT   | operator → any                              | =/down= + dump =status.reflection= to stderr                                              | same, plus the dump                                               |
| SIGHUP    | terminal close → session                    | never reaches a supervised child (own process group); to a supervisor = SIGTERM          | treat as SIGTERM (F4)                                             |
| SIGKILL   | supervisor → child, ONLY after =grace=      | the escalation; the recipient cannot react                                               | —                                                                 |
| SIGURG    | any reader → a claimed pid                  | the liveness probe (=Lock.read=); never a request                                        | ignore (default)                                                  |

** the SIGKILL standard

1. SIGKILL is never the first signal. The order is SIGTERM → wait =command.grace= → SIGKILL → await exit.
2. Only the die that owns the claim (the token holder) may signal its children; =stop= signals the SUPERVISOR, never a child.
3. Children are spawned in their own process group (=detached: true=) so the operator's SIGINT reaches only the supervisor and each child is signalled ONCE (m49 F4); group escalation = =Deno.kill(-pgid, "SIGKILL")=.
4. A child that exits on its own is EXITED, not stopped; its exit folds into the supervisor's exit code (=run= exits 1 iff any child !success); a signalled set is STOPPED and exits 0.
5. Readiness = the child's own =Status:ALIVE= line (=integrate.js:47=, =vite.config.mjs:100=), parsed by =Status.parse= (F7) within =command.deadline=; =inherit= children are alive at spawn.
6. The claim is written BOOTING at spawn and ALIVE at readiness; =Lock.read()= prunes a dead pid; a die releases only its own token; a live claim refuses a second cast.
