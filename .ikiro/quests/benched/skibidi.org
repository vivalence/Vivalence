* the decision trail

*** 1 — peer-to-peer or server · RULED by /"1:m for sure."/
P2P mesh is n² upstream encodes; fine at 1:1, dead at 1:m. An SFU forwards one upstream per client. The 1:1 design (a =Call= row with offer · answer · candidates over the datamap broadcaster, needing a cross-user scope on the row) died with the ruling.

*** 2 — which SFU · recommended LiveKit, not contested
LiveKit (Go, one docker binary, pure-JS server SDK that runs under Deno — proven) over mediasoup (Node worker Deno cannot host), Janus (plugin config), ion-sfu (dormant). Egress · recording · transcription hooks are LiveKit's, a later language-learning seam.

*** 3 — shared buffer or own buffer · settled by the SFU
Roster and media live in LiveKit. Each user's mode renders its own buffer with a token from =daemon.call skibidi.join=. No Buffer scope change, no runtime change.

*** 4 — "something in system only?" · RULED no, by terrain
=systems/= is runtime · ghost · anima, the machine. Skibidi is a citizen package. First citizen carrying BOTH halves — DOCKER (media outside) and ATTACHED (webhooks inside) — with no new trait invented.

*** 5 — who authorizes · the grant
Policy is a LiveKit grant minted by the daemon: =canPublish: shape !== "LECTURE"=. The daemon decides, LiveKit enforces, the mode carries nothing.

#+BEGIN_SRC js
// commons/services/skibidi/provider/index.js
import { AccessToken, RoomServiceClient } from "livekit-server-sdk";

export default function provider(service) {
  const { remote, rtc } = service.statics;
  const { key, secret } = service.secrets;
  const rooms = new RoomServiceClient(remote, key, secret);
  return {
    rooms,
    token: async ({ identity, room, shape }) => {
      const token = new AccessToken(key, secret, { identity });
      token.addGrant({ room, roomJoin: true, canSubscribe: true, canPublish: shape !== "LECTURE" });
      return { url: rtc, token: await token.toJwt() };
    },
  };
}
