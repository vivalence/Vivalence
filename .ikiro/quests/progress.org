#+SUBTITLE: sweep result → spec → designer brief

* intent

The learner exercises a literal; the domain evolves a =Retention= and writes a =Trace=; the
learner is never told. Today the only place a person can see their standing is the aprende
homepage, and it is a *cold* surface — you go there deliberately, between sessions. Inside a
game, where the learning actually happens, retention is invisible: every mode fires
=/review/literal= and throws the answer away.

This quest closes that. Three moves, smallest first:

1. *the receipt* — =/review/literal= already returns the updated retention. Render it at the rep.
2. *the ledger* — a trace-history surface (recent · mistakes), which exists nowhere live.
3. *the board's three lies* — UNTOUCHED reads 0, strength collapses to 0, due is a bare count.

Move 1 is the whole point. Moves 2–3 are the debt the sweep turned up on the way.

* the three lies the real data exposes

** lie 1 · UNTOUCHED always reads 0

=statistics.js:37= counts =retention.count({status})= per rung. No row is ever written with
=UNTOUCHED= (=Literal.ts:190= creates then immediately evolves), so the bucket is structurally
empty — measured above: =untouched-rows = 0= against 6512 untouched literals.
=Retention.svelte:44= renders =← untouched · {counts.UNTOUCHED || 0}= — permanently "0".

The dead dewey knew this. =registry/education/modes/bak/dewey.bak/gather.js:49=:
#+BEGIN_SRC js
  histogram.UNTOUCHED = Math.max(0, totalLiterals - memories.length);
#+END_SRC

** lie 2 · strength is 0 for everything you actually need to study

=Retention.ts:131-136= → =bayesian.js: sql.strength=:
=exp(-(now - lastAt) * 24 / state[2])=. With a 0.79 h halflife and 3.5 days elapsed the exponent
is ≈ −106, so =strength = 0.0= — all six rows above, identically.

=Ranks.svelte:19= then does
#+BEGIN_SRC js
  const litPct = (d) => Math.round((100 * (Math.log10(Math.max(d.strength, 1e-3)) + 3)) / 3);
#+END_SRC
=log10(1e-3) = -3= → *every weak item draws a 0 % bar*. The "weakest" list is real; its bars are
a flat row of nothing, and its ordering among the zeros is arbitrary.

Strength answers "would you recall it *right now*" — it is a within-the-hour quantity. For "how
am I doing" the honest axes are *status* and *overdue-ness* (=nextDays=, which reads −3.56,
−3.58, −3.68 above — legible, ordered, true).

(=bak/dewey.bak/gather.js:19-21=):

* THE DESIGNER BRIEF

Read this section alone if you are drawing. Everything is grounded in the data above.

** what we are designing

Three surfaces, in priority order.

*** A · THE RECEIPT — inline, at the rep (the one that matters)

The learner just answered. Within ~200 ms the daemon answers with the new retention. Show it
*without breaking the rep loop*.

Payload available at that instant (real shape, from =/review/literal=):

#+BEGIN_SRC json
{ "status": "LEARNING",
  "nextIn": 15.705913763892246,
  "nextAt": "2026-08-20T07:21:51.338Z",
  "lastSignal": "SUCCESS",
  "state": [4.2742256827588, 4.274225682897581, 15.706205682056474] }
#+END_SRC

Plus what the client already knows locally: the previous status (from the knowable —
=dojo/buffer/fold.js:29= carries =status=), and the signal it just sent.

So the receipt can state a *transition*:

#+BEGIN_EXAMPLE
  andiamo        UNKNOWN → LEARNING        next in 16 h
  del            UNKNOWN                   next in 48 min
  Buongiorno…    LEARNING → KNOWN          next in 8 d
#+END_EXAMPLE

**** hard constraints (violate these and it ships broken)

- *FOCUS LAW.* Dojo keeps exactly one persistent =<input>= alive, never disabled, never
  readonly; =TypeInput= stays mounted for every gameplay ([[project_rep_o_mat]],
  [[project_dojo_mode]]). The receipt *must not* take focus, mount over the input, or reflow the
  input's position. On phone the keyboard is up and must stay up.
- *Phone first.* beef drives this on a phone. Narrow tier already docks the verdict *above* the
  input (=TokenFeedback dense=). The receipt rides that same dock — one line, not a card.
- *Never block the advance.* The rep may be over before the response lands (dojo advances
  optimistically). A receipt that arrives after the next prompt is drawn must either attach to
  the outgoing item's fading feedback or be dropped. It must never delay the next question.
- *Fire-and-forget stays the fallback.* If the call fails, play continues silently — current
  behaviour (=.catch(console.warn)=). No error UI in the rep loop.

**** what to draw

1. the transition (previous → current), or just the current rung when unchanged
2. the interval in human units — =48 min= / =16 h= / =8 d= (=nextIn= is hours; see the copy table)
3. the rung's colour, from the existing palette (below)

*** B · THE LEDGER — trace history (exists nowhere live)

Two lists. Both were in dewey (=bak/dewey.bak/gather.js:88-89, :94-95=), both are gone.

**** recent

#+BEGIN_EXAMPLE
  SUCCESS   essere.future.indicative     15:36
  FAILURE   essere.future.indicative     15:36
  SUCCESS   il.determiner                14:31
#+END_EXAMPLE

*The collapsing problem is the design work here.* The real data shows 4 traces in the same
second for one sentence rep (see the two-trace sample above: =...4416= / =...4423=). A raw list
is unreadable. Options for the designer to pick between:

- collapse by =(literal, second)= → one row, worst signal wins
- collapse by rep → needs a rep id on the trace; there is none today (fork F4)
- show sentence-level only, tokens on expand

**** mistakes

Last N where =signal ∈ {MISTAKE, FAILURE}=. Real counts in this corpus: =FAILURE 51 · MISTAKE 21=
against =SUCCESS 198 · NEUTRAL 1=. So the mistakes list is ~27 % of activity — dense enough to
be a real surface, not an empty state.

**** the day histogram (free win)

The trace-day fold above is already computed for =streak=. Eight bars, values =4 … 92=. A
GitHub-style ribbon under the streak number costs one extra field.

*** C · THE BOARD — fix the three lies

- UNTOUCHED := =literals − retentions= (6512, not 0)
- replace the strength bar with *overdue-ness*; keep strength only where it is honest (a
  freshly-reviewed item), or drop it from the ranks entirely
- due gains a magnitude: =17 due · oldest 3.7 d=

** density tiers (match dojo's existing breakpoints)

Dojo's drawer already tiers on the *shell* width: narrow < 700 · medium < 1040 · wide.
=parts/Desk.svelte= / =TokenFeedback= take a =dense= prop. The receipt should be:

- narrow — one line in the docked verdict strip, above the input
- medium/wide — a line beside the verdict, right-aligned
- never — a modal, a toast that moves layout, or anything focus-taking

- *F5 · is strength shown to the learner at all?* Measured, it is 0 for everything overdue. Either
  it becomes an *hours-since-review* readout, or it stays an internal sort key and never renders.
