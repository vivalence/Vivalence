* Intent
A throwaway =playground= daemon that tests buffer emission reactivity and
buffer navigation, ahead of the activation loop. One mode emits buffers that
belong to *another* mode; we verify (a) server→client subscription delivers
those buffers live, and (b) the moat navigates them. Three milestones, each
adding a way to *trigger* emission: manual click → LLM tool-call → continuous.

This is the de-risking probe for =activation-loop.quest.org= TODO 1 + 3.

* Architecture (grounded in code, not invented)
** Emit path (server)
- A mode with the =EMITTER= trait exposes =/emit/*= routes
  (=systems/runtime/daemon/traits/emitter.js:53=). Each handler returns
  =ctx.mode.buffer({data, literals})=; the trait pools the outputs, attaches
  them to =ctx.thread=, stamps =buffer.index = thread.counter++=, and
  =em.flush()='s (emitter.js:30-49).
- =mode.buffer()= (=systems/runtime/daemon/traits/viewable.js:35=) stamps
  =mode: mode.entity.id= — so to emit a buffer *for another mode*, call that
  other mode's =.buffer()=. Sibling modes are reachable at
  =ctx.daemon.modes[type][slug]= (=daemon/lifecycle/population.js:143=).
- =ctx.pool= (Pool) collects buffers, including delegated ones — the cross-mode
  delegation seam.
** Subscription path (server→client) — ALREADY WIRED
- MikroORM =afterCreate= → =twitch= → =broadcaster= → SSE =/subscribe=
  (=gestalten/shard/datamap.js:151-171=).
- Client calls =daemon.entities.buffer.subscribe()= at boot
  (=entities/daemon/dossier.js:84-85=) → =RemoteRepository.merge= →
  =entityManager.refreshStore= → =buffer.$entities= atom fires.
- *Conclusion:* a server-emitted buffer reaches the client with NO manual
  re-fetch, provided it persists via =em.flush()=.
** Moat render (client) — ALREADY WIRED
- Panel A is the moat (=app/panels/a/a.svelte:60=) → =drapes/panels/Frame.svelte=
  → dynamic =import(buffer.mode.view.url)= → mounts the buffer's mode view with

* Subscribe reactivity — root cause + fix decision
** Symptom
Emitter creates buffers (DB rows written, =is.yieldish= true on the client), but
the F-panel buffer list never updates. Only the boot-loaded buffer shows.
** Root cause (confirmed read-only)
=broadcaster.push(event, entity)= (=prototypes/broadcaster.js:68=) matches the
*live MikroORM entity* against the subscription filter via =object.match=
(=belt/object.js:54=, strict ===). The buffer subscribe scope is
={ thread: { user } }= (=daemon/aperture/userspace.js:15-18=). A buffer has no
=user= — only =thread.user=, two hops deep — and the live entity's =thread.user=
is an unloaded Reference. Nested strict-=== match fails → every buffer event is
dropped → client =buffer.$entities= never updates → =thread.$buffers=
(EM auto-computed, =entity-manager.js:179=) never recomputes → panel frozen.
General fragility: =object.match= on a live ORM relation can't equal a scalar id.
** Reactive contract (how it SHOULD work)
server flush → =shape.subscriber= (MikroORM EventSubscriber) → twitch
=/buffer/create/after= → =broadcaster.push= → SSE on
=/userspace/entities/buffer/subscribe= → client =repo.subscribe= → =em.integrate=
→ =stores.buffer= ($entities) → refreshStore → =thread.$buffers= computed → chain
→ f.svelte. Grounded in =tests/gestalten/shard/datamap.test.js= +
=runtime/tests/sse.integration.test.js=.
** SHIPPED: owner-stamp from ambient + match the wire shape
Two coordinated edits, no schema change, no DB query, no populate.
- =reactive(repo, twitch, { scope })= (=shard/datamap.js=): (1) match against the
  *serialized (toJSON)* entity, not the live ORM entity — live relations are
  unloaded References that never === a scalar id (this alone repairs thread-sub);
  (2) when =scope= is set (user-scoped entity), stamp =serialized.user= from the
  writer's request context (=ambient.current()?.user?.id=, bound at the root
  aperture =resolution.js:6-7=) so a flat ={ user }= filter matches with no
  relation hop; (3) =/subscribe= filter uses the =scope= arg when present, else
  =ctx.scope= — keeps the repo find/create scope decoupled (buffer find still
  uses ={ thread: { user } }=, which would throw on a flat ={ user }=).
- =userspace.js=: buffer + turn reactive pass ={ scope: (ctx) => ({ user: ctx.user.id }) }=.
  Thread unchanged (its existing ={ user }= scope works once the match is serialized).
Ownership ACL: no =scope= (literal/symbol) → events carry no =user=, subscriber
filter ={}= → broadcast to all (global, correct). =scope= set + missing owner →
=console.warn= + dropped — NOT broadcast-all, which would leak one user's data.
- Unit: =tests/gestalten/shard/datamap.test.js= 41/41 green (no scoped-broadcast
  coverage yet). LIVE verification PENDING: emit → F-panel buffer list updates.
- OPEN: writes outside an authed request (no ambient user) → user-scoped event
  dropped + warned. Fine for user-scoped data; revisit only if owned entities are
  ever broadcast from a non-request context.
** Plan B — FALLBACK (not taken): denormalize =user= onto Buffer
Add a =user= column to Buffer; scope ={ user }= uniform. Heavier (schema migration
+ stamp on every write path; emitter creates via =em.create= directly, bypassing
the scoped-create helper). Superseded by the ambient stamp — keep only if the
ambient/owner route proves unreliable.
