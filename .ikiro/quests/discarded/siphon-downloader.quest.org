#+TITLE: Siphon — yt-dlp Downloader Daemon
#+AUTHOR: Vivalence
#+DATE: 2026-06-04
#+STATUS: DESIGN

* Intent

Stand up a brand-new, otherwise-empty daemon whose single mode is a yt-dlp
frontend. Open the mode, get a UI: link drop + advanced settings. Hit run, the
mode downloads the link into the daemon mountpoint, optionally post-processes
with ffmpeg, and surfaces the resulting asset(s) back to the UI with live
download progress.

No kernel, no corpus, no learning loop. An empty daemon shell carrying one
=downloader= mode. This is the first mode of a new mode TYPE (=downloader=),
which is a free manifest string requiring no central registration.

** Desired End State

- New daemon =conduit= (working name) declared in =testament/variant/circuitry.js=,
  modes: =["@vivalence/downloader/siphon"]=, nothing else.
- Mode =@vivalence/downloader/siphon= with traits
  =["BUFFERED", "SELFEVIDENT", "EXPOSED", "FRAUGHT"]=.
- Aperture (NOT emitter) exposing =/probe= and =/pull=. Buffer is SELFEVIDENT —
  no prepopulation; the Svelte UI owns initial state and drives everything via
  =terminal.daemon.call=.
- =/probe= verifies binary deps present (spawn =--version=) and dumps media
  metadata (=yt-dlp --dump-json=) to populate the advanced-settings format list.
- =/pull= builds yt-dlp argv from advanced settings, spawns piped, streams
  =[download] N%= progress as Signal packets to the UI, writes asset(s) into the
  mode mountpoint, returns an asset manifest.
- Asset surfaced via mountpoint path in the UI. FRAUGHT/cargo write is
  scaffolded but a commented dud (cargo route is not reactive yet).

** Key Design Decisions

- *Aperture, not emitter.* Mode exports =aperture= (Aperture class, =aperture/index.js=),
  mirroring =registry/modes/@vivalence/bak/teacher/dewey=. EXPOSED trait makes it
  callable; BUFFERED serves the buffer schema/url.
- *SELFEVIDENT.* No emitter pushes an initial buffer. =buffer= schema is still
  declared via =BufferView= (can be empty data), but the UI initializes itself.
- *Streaming via async-generator → SSE.* A =/pull= handler that returns an async
  generator of Signal packets is auto-detected by =gestalten/shape/http.js=
  (=Symbol.asyncIterator=) and framed as SSE by =response.publish()=. No
  =ctx.pool=/emitter machinery needed. Packets are Signal-shaped:
  =/pull/tick= (progress) … =/pull/done= (terminal, carries manifest).
- *Pure argv builder.* =settings → argv= is a pure function (no spawn), so the
  flag mapping is unit-testable in isolation and "start lean, architect heavy"
  is a matter of extending one pure function.
- *Cargo is a dud.* New cargo isn't reactive. Write the asset into freight so the
  wiring exists, but comment it dead with the reason. Surface the mountpoint path
  instead.

Spawn + stream shape (pull.js):

#+begin_src javascript
import paladin from "@vivalence/paladin";

export default async function* pull(ctx) {           // async generator → SSE
  const dir = ctx.mode.cake.mount.absolute;          // mountpoint dir
  const cmd = ["yt-dlp", ...argv(ctx.input), "-o", `${dir}/%(title)s.%(ext)s`];
  const proc = await paladin.system.spawn({
    type: "downloader", slug: "siphon", cwd: dir,
    attachment: "piped", cmd,
  });
  for await (const line of proc.out) {               // Pipe async-iterable
    const pct = parseProgress(line);                 // /\[download\]\s+([\d.]+)%/
    if (pct != null) yield { event: "/pull/tick", pct, line };
  }
  const status = await proc.status;
  const paths = await scanMount(dir);                // Deno.readDir diff
  // FRAUGHT cargo write — DUD: cargo route not reactive yet, surface mountpoint.
  // await Deno.writeFile(ctx.mode.cake.freight.path.branch("/"+name).absolute, ...)
  yield { event: "/pull/done", ok: status.success, dir, paths };
}
#+end_src

Pure argv builder (argv.js), the "lean now, heavy later" seam:

#+begin_src javascript
export function argv(settings = {}) {
  const out = [settings.url];
  if (settings.format)        out.push("-f", settings.format);
  if (settings.audioOnly)     out.push("-x", "--audio-format", settings.audioFormat ?? "mp3");
  if (settings.subfolder)     out.push("-P", settings.subfolder);
  if (settings.subtitles)     out.push("--write-subs");
  if (settings.metadata)      out.push("--write-info-json", "--embed-thumbnail");
  if (settings.ffmpegArgs)    out.push("--postprocessor-args", settings.ffmpegArgs);
  return out;
}
#+end_src

=datamap=/=lighthouse=/=kernel= boot, given =population.modes= runs inside

- [ ] Create =aperture/index.js= with =/manifest=-style noop + a =/ping= returning =true=

* Gaps

- *Empty-daemon boot (Phase 1 risk).* =population.modes= runs inside
  =daemonDie.datamap.shard.context=. Unknown whether a daemon with no datamap
  boots. If not, define the minimal null-datamap shape and record it here.
- *Buffer→mode-aperture address.* Existing buffers call daemon-level paths
  (=terminal.daemon.call("/pick/literal/feed")=). Confirm the exact string/form
  to reach THIS mode's aperture (=/probe=, =/pull=) — mode-scoped vs mount-prefixed.
  Resolved in Phase 1 via =/ping=.
- *SSE subscription primitive.* Confirm whether the buffer consumes =/pull= via
  =connection.socket= + =inbound.open=, an EventSource, or a streaming
  =terminal.daemon.call=. Resolved in Phase 4.
- *Names.* =conduit= (daemon) / =siphon= (mode) are working placeholders. Finn
  owns the final ontology before merge.
- *yt-dlp output surface.* =--dump-json= shape and =[download] N%= line format
  are external contracts; pin a version or guard parsing.
