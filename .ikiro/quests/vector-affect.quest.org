* Intent
A reusable pattern (maybe a primitive) for *reactive, middleware-composed Vector
consumers*: build a =Signal= from live state, =invoke= it through a =Vector= whose
=.use()= carries pre/post processing and whose =.open()= / =.affect()= hold the cases.
The generalization the stall ALMOST became — explored deeply, then deliberately NOT
adopted there (incidental for four flat phases). This quest gives the idea its own home
so it can land where it actually fits: a richer reactive surface with real routing depth
and genuine pre/post composition.

This is M6 of the stall arc. It is the *road-not-taken from M1–M3, promoted to its own
road.* DESIGN / SEED — scope is open; Finn narrows it before any build.

* How we got here (D4 · the fingerprint)
Mid-stall-design, Finn proposed lifting the phase machine onto a Vector, verbatim:
  "How about we take a vector, make this combinator vector? with maybe just three
   effects for now. Manual, inertia, and whatever. Continuous… create a signal based on
   whatever. run it through a vector and have things like middlewares and pre and post
   processing handled and composable."
The connoisseur reading: this IS the system's deepest pattern (a =Vector= consumed by a
strategy family) applied to a reactive driver. It is structurally the *twitch* and the
*emitter*. But for the stall's four flat phases reacting to two atoms, the Vector's
routing depth is unused — the win would have been only middleware-compose + cast, not
worth the machinery. Finn then gated the actual build to prod primitives:
  "solve this function using no speculative interfaces! only whats apready tested and
   used in prod!"
So the stall stayed a closure-object. The Vector-combinator idea is sound — it just
needs a consumer whose shape EARNS it. That consumer is what this quest hunts.

** The pieces

- =steer.invoke(vector, signal)(input)= — route a Signal to ONE effect, run the composed

- Context channels (proven): =input= (call-time, =guarded= casts it) · =.use(
  shard.context.bind(k,v))= (build-time closure) — NO seat.
** The existing reactive-Vector precedent — the TWITCH
=gestalten/shard/datamap.js:152-185= already does this: a =twitch= Vector, leaves opened
=twitch.open("/<entity>/<op>/after", effect)=, FIRED reactively by
=shape.subscriber(twitch)= (=shape/subscriber.js=) — which builds =new Signal(
`${name}/${event}`)=, =steer.shotgun='s the vector, and calls each handler with the event
as =ctx.input=. *This is the template.* "vector affect" = recognizing this shape, naming
it, and making it reusable where today each reactive surface hand-rolls it.

* SETTLEMENT — the shape rotation + the steer regroup (DECIDED · build-gated)
This SUPERSEDES the M6 seed's central open question ("what does =affect= mean?").
ANSWER: =affect(fn)= = set THIS node's SINGULAR terminal effect. The Vector rotates
its internal shape — the effects-Map collapses into one =effect= per node; routing
depth lives entirely in =trajectories=; a leaf is a trajectory node with =.effect= set.
The seed's reactive-Vector framing (twitch/subscriber) stays valid as a CONSUMER; this
settlement is the CORE shape it consumes. Analysis: 23-agent fan-out (functional steer
audit + full rotation blast diff), verified against the live code.

** Vector shape rotation (the core)
: CURRENT  class Vector { effects: Map<Pattern,Effect>; trajectories: Map<Pattern,Vector>; carry:[] }
: NEW      class Vector { effect;                        trajectories: Map<Pattern,Vector>; carry:[] }
- leaf = a trajectory node with =.effect= set + no children; a node MAY be BOTH leaf and branch.
- =affect(fn)= ⇒ =this.effect = fn= (terminate-here; NOT the old null-key catch-all).
- =open(sig,fn)= ⇒ =this.branch(sig).affect(fn)= — call-signature UNCHANGED, so every
  registry/system call-site is untouched; the rotation is INTERNAL to typology.
- leaf metadata (=input/output/valence/schema=) migrates from the fin effect-key pattern
  onto the tip TRAJECTORY key — =branch()= must STAMP even when it FINDS an existing key.
- the leaf/branch DUALITY dissolves: =feed='s heir-vs-effect pick and =object='s
  =Object.assign(fn,namespace)= reunification become intrinsic per-node.
- NEW capability (the ask): middleware on singular-effect vectors — a leaf IS a full
  Vector with its own =carry=.
- wire: =shape.strip= keeps the =\{leaves,branches\}= shape byte-identical (leaves keyed by
  segment nature); strip + connection.wire + messenger deploy ATOMICALLY.
  (SUPERSEDED later this-arc: the contract rotated node-centric to =\{effect?,branches\}= — the
  faithful cata of the Vector; =leaves= dissolved, root effect now strips + wires. See 47.03.)
