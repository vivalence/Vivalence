* stage II — the pinhole, fire-once

beef: the thunks are innocent; the pinhole is blind. Three things it must learn — where it is, what
the thunk read, and which branches must not hand back a value — and *one* branch expresses the last:

#+BEGIN_SRC js
return deferred ? node : value;
#+END_SRC

Fire every thunk exactly once. Record what it read. For a deferred branch, hand back the *thunk*
instead of the value, so no secret lands on the instance. No sentinel, no second walker, no
=usable: null= special case — all three were mine and all three delete.

*Known limit*: a recording view sees only the keys a thunk reads on that run, so a branching thunk
reveals one path. Every thunk in the tree is a one-liner today; the record under-reports rather
than lies. Deferred thunks are pure reads by contract; a side-effecting one would run twice.

** II.1 required-ness is derived, and it may tell you something you did not want to hear

=usable= is strict: a Url needs an =origin=; anything else must not be =undefined=, =null= or ="".
Then the verdict is mechanical — and *the check reports what the code demands, not what the author
intended.*

*The first thing it catches is one of beef's own assumptions*, and he confirmed it:
/"yes you caught it."/ =VIVA_SERVICE_NLP_REMOTE= will read *REQUIRED*, because
=education.js:73= is =remote: () => new Url(paladin.env.get("VIVA_SERVICE_NLP_REMOTE"))= — no
fallback, no guard. beef has called nlp optional throughout (/"nlp might be null but registry
required"/); the declaration has never said so. *Optionality was never expressed anywhere in this
codebase* — that is the finding, and it is exactly the class of thing the check exists for.

Nothing breaks on landing (no caller gates on =rows.fails= yet), so this surfaces as a doctor row
and a decision, not a red suite. Two honest resolutions, and it is a *declaration* decision, not an
env one:

#+BEGIN_EXAMPLE
accept    the daemon really does need nlp → seed the key. one line in <instance>/.env.

            remote: () => { const held = paladin.env.get("VIVA_SERVICE_NLP_REMOTE");

          runtime question nobody has answered, and the reason this is beef's call and not mine.

* stage III — the schema

** III.1 ${VAR}, and only ${VAR}

POSIX / docker-compose form, lazy at =Env.get= so it resolves across strata regardless of load order,
with a cycle guard. Bare =$VAR= is deliberately NOT expanded — too easy to write inside a password.
Expansion resolves within one bag, so =env= can never reach into =secret=. =Env.vars= stays raw so
doctor shows source text.

*Not marginal*: on hello-world it collapses 9 address/service keys into 3 answers, and because
=get= expands lazily the written =.env= STAYS in that form — change a port once, nine values move.

** III.2 the schema is a sibling export, and there is no .env.example

Generation loses something in both directions: =declaration → template= cannot write prose,
=template → declaration= drifts from what is read. So the schema is *authored*, in code, beside
=manifest= — the codebase's own idiom, and where the whole ecosystem puts it (terrain 6).

*The pinhole does not generate it — it CHECKS it*, in exactly one direction:

#+BEGIN_EXAMPLE
UNDOCUMENTED   a thunk read a key nothing describes      ← always a bug, never false
UNREAD         described, nothing observed reading it    ← DELETED: 20% false positive (terrain 12)
#+END_EXAMPLE

*=.env.example= is deleted, not generated.* Its only unique job was bootstrap-without-tooling, and
the tooling ships inside the instance. Every job it looked like it had goes somewhere better:

#+BEGIN_EXAMPLE
tell me what to fill        → the wizard
cp bootstrap                → init writes .env directly
read it without cloning     → docs, rendered from `environment`
CI / docker needs the names → viva instance/doctor --json
#+END_EXAMPLE

*Accepted cost, stated plainly*: an instance cloned by someone who never runs =viva= then has no
committed hint of what it needs. The hint becomes the declaration itself — readable JS sitting right
there, and better than a file that lies.

** III.3 the wizard

*Paging is a sheets concern, not a caller's.* A page index living in =Init.jsx= would make the next
multi-page form re-implement it; =state/form.js= is where the codebase already puts exactly this
kind of pure interaction fold. So =form.js= grows pages and a single-page form becomes
=pages.length === 1= — one concept, not two — and =Form= takes =pages= rather than =fields=. One call
site, so nothing else moves. Fields come from =environment= ⋈ the record:
prose and defaults from the schema, /needed by/ and required-ness from the pinhole. Writes through
=state.env=, so the resulting =.env= keeps every comment the schema carried.

* expectation vs reality — the blast log

Appended as the blast runs. Each row is a place this quest was wrong, incomplete, or right in a way
worth pinning. *This is the record; keep it current.*

** ① Env.ambient had to become a LIST, not one entry

QUEST said =Map<source, {tag, keys}>=. REALITY: one file can be observed at more than one stratum,
and a single entry evicts only the last — the earlier claim survives and keeps outranking the owner.
=Map<source, [{tag, keys}]>=, and =claim= walks all of them. *Found by a test, not by reading*
(=env.expansion.test.js= "a second observe of the same file re-points the ambient record").

** ② usable was deleted by accident, not by design

A blast hazard, not a design change. The earlier probe insert had put =probe()= BETWEEN =watch= and
=usable=, so slicing "probe-start → PINHOLE" took =usable= with it. Restored strict. *Only caught
because the suite ran immediately after.* Lesson for the remaining steps: slice by exact anchors,
never by a start/end pair spanning code that moved.

*RECURRED, 40 minutes later, and that is the real finding.* Generating the three =@education=
instance declarations used =.replace("D", "${")=, which ate every uppercase D: =SECRET_VIVA_DEEPGRAM_API_KEY=
→ =SECRET_VIVA_${EEPGRAM_API_KEY= (crashed beef's runtime at =vip.supply=), and — the one that
matters — =traits: ["ATTACHED"]= → =traits: ["ATTACHE${"]=, which PARSES, type-checks, and would
have booted kajuit without the trait, silently. A lesson written into a quest does not fire; it is
now =methods/generated.md= plus a line in =world/codemap/invariants.md=, the path-gated channel,
exactly where [[thin]] had to go for the same reason.

** ③ the schema grew 15 → 17 keys, and the two new ones VALIDATE the check

QUEST said "three free variables answer nine keys" but did not notice that two of the three —
=VIVA_RUNTIME_ORIGIN=, =VIVA_CLIENT_KAJUIT_ORIGIN= — *do not exist anywhere today*. No thunk reads
them; they exist only to be referenced by =${...}=.

Under the OLD check they would have been =UNREAD= false positives — two more on top of the three
that killed that verdict, taking it to *5 of 17*. Under the new one they are =documented=, which is
exactly right. The deletion of =UNREAD= paid for itself before the step that removed it finished.

** ④ paladin grew three named ingresses, not one

QUEST specified =observe=/=claim= on =Env= only. In practice =paladin.assign= had to split into
=split()= plus =assign= / =observe= / =claim=, because the key-split and the claim-strength are
