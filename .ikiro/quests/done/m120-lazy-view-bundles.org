* the law

1. A bundle is a cache of its view's sources; the consumer asks for the VIEW, never for the cache's state.
2. Computed and checked at the fetch. Boot seats views and builds nothing.
3. Unbuilt = no File at =view.entry=. No trait, no flag.
4. One name per view: =bundle/<slug>.<mime stem>.mjs=. A build overwrites; the File keeps its id.
5. =mount= is the declared string, verbatim and relative; =entry= only ever names the built file; =sources= is every file the build read, =path · bytes · mtime=, never sent to a client.
6. The File entity is the announcement of a build; a client holding the view reloads on its new fingerprint.
7. The fingerprint travels as =ETag= (RFC 9110) and as =x-viva-integrity=.

// subsystems/typology/entities/View.ts — bundle, called by the /attached/view/:id route
  async bundle(view, { bundler, source }) {
    const held = this.em.getRepository(FileEntity);
    const file = await held.findOne({ view: view.id, path: view.entry });
    if (file && (await bundler.fresh(view.sources))) return file;
    const built = await bundler.bundle({ mime: view.mime, entry: source, name: view.entry });
    const [compiled] = built.entries;
    view.sources = built.sources;
    const written = await held.ensure({
      mode: view.mode.id,
      view: view.id,
      path: view.entry,
      mime: mime.javascript,
      mount: `${bundler.directory}/${view.entry}`,
      hash: compiled.integrity,
      integrity: `sha256-${compiled.integrity}`,
      bytes: compiled.bytes,
    });
    await this.em.flush();
    return written;
  }
