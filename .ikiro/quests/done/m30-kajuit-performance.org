** the ruling — two entities, no separate spine

beef: *"the entities ARE the spine"*. Two observability entities, each with exactly one
view. **telemetry = the umbrella** — the FAMILY name grouping ={inspector, logger}=, not a
third thing and never a panel. If remote viewing ever lands, it is expressed as the same
two verbs pointed at a remote subject — remote logging, remote inspecting — new members of
the telemetry family, not a new concept.

| entity    | is     | flow | written by                     | view                        |
|-----------+--------+------+--------------------------------+-----------------------------|
| inspector | the IS | pull | NOBODY — writers write stores  | H                           |
| logger    | the WAS| push | everyone — ambient pen         | G, and Boot.svelte at boot  |

Laws:
- a record never mutates; a node never persists. Anything with a timestamp → logger;
  anything readable from a store → inspector.
- *during boot, state changes LOG; nobody snapshots.* Boot screen gaps are producer gaps.
- H's trace tree (a WAS surface) emigrates to G. One panel, one entity.

** natures — the construction, side by side

*Records are the data; the span is the pen; the pipe is the wire; the journal is the
memory; views are folds.* The inspector: *a projection — a pure function stores→nodes,
materialized only under observation; it has no write API and no memory by nature.*

|              | logger                             | inspector                          |
|--------------+------------------------------------+------------------------------------|
| atom of data | record ={span,trace,path,verb,at,data}= | node ={nature,valence,children,invoke}= |
| root primitive | ONE root =Span("client")= — every span a branch of it | lazy =computed= over the deck stores |
| prototypes   | =Span= (pen) · =Pipe= (wire) · journal ring (memory, cap 1000) | plain object literals — NO prototype |
| grammar      | =open·close= (lifecycle) + =note·warn·fault= (one-shot ≙ log/warn/error) | compose fns: =row= · =table=, ROW_CAP 30 |
| folds        | =trace.chronicle= → =$story=; taps = destinations (UI · dev console mirror · =dump()=) | none — the computed IS the read |
| lifecycle    | always on — append is cheap        | cold unless a view subscribes (mount boundary) |
| retention    | root journal ring, trim 200 roots  | none — discarded cold              |

Key structural point: today =telemetry.js= mints a NEW root per =span(nature)= call; the
design commits to ONE root — =span(nature) = root.branch(nature)= — so one journal, one
channel, all provenance rooted at =client=. Branch journals already delegate to the root
(span spine), so the machinery natively supports it.

** EM epoch — typology, HOLY, gated

Mechanism: merges land in the identity map IMMEDIATELY; nothing rolls back. Only store
notifications defer — the refcounted window coalesces them to ONE =set= per touched store
at outermost close. Nested finds (cast → resolve → repository.merge) nest epochs; the
refcount holds them in one window. Subscribe echo (single row) stays immediate.

=subsystems/typology/prototypes/entity-manager.js= — constructor gains:

#+begin_src js
this.epochDepth = 0;
this.epochTouched = new Set();
#+end_src

new method:

#+begin_src js
async epoch(work) {
  this.epochDepth++;
  try {
    return await work();
  } finally {
    if (--this.epochDepth === 0) {
      const touched = [...this.epochTouched];
      this.epochTouched.clear();
      for (const name of touched) this.refreshStore(name);
    }
  }
}
#+end_src

=refreshStore= gains the gate:

#+begin_src js
refreshStore(name) {
  if (this.epochDepth > 0) {
    this.epochTouched.add(name);
    return;
  }
  if (this.stores[name]) {
    this.stores[name].set([...this.stores[name].get()]);
  }
}
#+end_src

* the disease (one sentence)

A write fans out to a full recomputation with no gate — identity, then the debug tree,
then persistence. Each milestone here removes one gate-less fan-out; none of them is a
throttle, a debounce, or a guard around the symptom.

Refined after the critical pass: the fan-outs are three ARCHITECTURE defects multiplied
by one data fact. (1) The client hydrates the whole world at boot (=dossier.js= populate
volley) — every downstream cost scales with prod's row count. (2) Reactivity has no
granularity or batch seam — per-ROW store refreshes, whole-world subscriber recomputes,
fresh-object writes that always notify. (3) Identity is heavyweight (=deep= sort +
=JSON.stringify= + fnv1a) and =Vector.branch= forces it inside an O(K²) sibling scan, so
CONSTRUCTING a Vector costs quadratic identity work — fine for 20-node trait declarations,
catastrophic for a 5000-row debug tree per pointermove. The multiplier: prod italian's
dataspace. Localhost never sees any of it.
