** what the pass does

Four modes, one law between them: **a mode's rows come from a source, and the source is the mode's
business.** The vdex's source is the mountpoint paladin dressed onto it — disk, watched. Mail's and
the calendar's source is a PROVIDER MODE, and there is one per office mode: =dummy/mail= and
=dummy/calendar=. Each is a demo dataset plus the endpoints that record what the office does — a
mail sent, an event created, renamed, moved, dropped. Nothing leaves the machine.

The dummy is not a fixture bolted on the side; it stands exactly where the real thing will stand.
=office/email= names its provider in one static (=provider: "dummy/mail"=) and speaks to it through
that mode's aperture. When the scouted endpoints land — Gmail =users.messages= · Graph =message= ·
IMAP/SMTP · Google Calendar =Event= · Graph =event= · CalDAV =VEVENT= — the static becomes
=gmail/mail= and NOTHING else moves: same routes, same rows, same aperture, same App.

** decisions (mine — every one overturnable)

- **=event= is a fourth literal ontology**, beside =vdex= · =message= · =transaction=. A calendar
  entry is not a message: it has a span, a recurrence and a response state, and every read tool
  would fork if it shared =message='s traits. The TOPOGRAPHICAL symbol is =event=; the trait is
  =EVENT=; a deadline is the same row with no =end= and =allDay: true=.
- **recurrence is stored as the master with its RFC 5545 =rrule= string, never as expanded rows.**
  Google and CalDAV both hand RRULE text; Graph hands a structured =patternedRecurrence= its own
  service translates. The mode expands a series for the range the App asked for, in memory, in
  =occurrences()=. A 2026 week never touches a thousand rows.
- **an event's provenance rides =EVENT.external=**, the same shape the message rows get:
  ={account, id, thread, etag}=. The design's inspector footer reads it: an event whose
  =external.account= is set is a VENDOR row (/"edits go back through gmail"/); one without is
  MINTED (/"minted row · lives with its source"/) and its =uses= edge names what minted it.
- **the held send is the design's, and it lands now.** The main quest said outbound was an ungated
  tool call and the gate was the officer stage's; the V3 mail screen draws the gate in the mail App
  — an =email_send= from an officer arrives as an OUT row with =MESSAGE.hold= set and the symbol
  =message.status.held=, and the operator's =key= releases it. That is better than the earlier note
  and supersedes it: the officer can compose, only the human can send. The tool =send= HOLDS; the
  aperture's =/key= is the only route that clears the hold, and it is not armed as a tool.
- **the calendar mints from what it can see.** A message whose row carries a date the office cares
  about is not automatically an event; minting is a call (=mint=), and the minted row =uses= the
  message literal. The inspector's =uses= list is that edge, read back.
- **coordinates cross ontologies.** A message and an event both take =vdex.area.* · vdex.category.* ·
  vdex.id.*= symbols when they belong to a coordinate — the main quest's open T2 fork, ruled in by
  the two designs: the mail row shows =→ 22.04=, the agenda row shows its coord chip, and both jump
  into the vdex. One coordinate groups documents, mail and the calendar.
- **the Apps never fetch twice.** Both subscribe precisely (=ontology: "message"= · =ontology:
  "event"=) and apply each event to the row it names — the V3 vdex twitch discipline, unchanged.
- **rows are =$state.raw=**; cursor and chrome are =$state=. Keys live on the App root
  (=role="presentation"= · =tabindex="-1"=), never on the window.
- **one dummy per office mode** (his /"one per"/): type =dummy=, slugs =mail= and =calendar=; a
  =dummy/chat= joins when chat lands. Type =dummy= is the register the vendor families will share
  the shape of — =gmail/mail= · =outlook/calendar= · =caldav/calendar= — so the type names the
  VENDOR and the slug names what it serves. The dummy is the vendor called "none".
- **the dummy owns both directions.** In: a demo dataset of =message= / =event= literals, installed
  by the ordinary DATASET pass. Out: an aperture that RECORDS — =/send= writes the OUT row, =/create=
  =/rename= =/move= =/delete= write the event row and answer the way a vendor would (an id, an etag).
  That is the whole provider seam, and it is the only place the office touches the outside world.
- **the office mode names its provider in a static**, never by import: =statics.provider =
  "dummy/mail"=, resolved at call time through =ctx.daemon.modes=. One line in =daemon.js= swaps the
  dummy for =gmail/mail=. No trait, no flag, no branch — the office never asks who is behind it.
- the dummy is **one kernel line**, never a trait, never a flag: it is in the instance =daemon.js= or it
  is not. If it is not, the office mode's provider call refuses and the App shows the refusal in the
  status bar — the same way every other refusal reaches the screen.

** the law — a fourth ontology

House mechanism, unchanged: the ontology IS the one TOPOGRAPHICAL symbol; traits carry payload shape;
symbols classify. The office now holds four:

#+begin_example
literal
├── vdex         a file on the mount        DOCUMENT     {asset:{path}, title, format, readable, bytes, mtime, hash}
├── message      a message on a channel     MESSAGE      {channel, direction, from, to[], at, body, external, hold?}
│                                           MAIL         {subject, cc[], messageId, inReplyTo, references[], attachments[]}
│                                           CHAT         {platform, chat, sender:{id,name}, replyTo}
├── event        a span on a calendar       EVENT        {kind, title, start, end, allDay, tz, rrule, who, where, external}
└── transaction  (T3, empty)                TRANSACTION  {at, memo, entries:[{account, amount, currency}]}
#+end_example

  from: "notariat@example.de",

  at: "2026-09-08T08:14:03.000Z",

  (mail) or =context.id= / =reply_to_message= / =thread_ts= (chat).
- attachments ride the mode's freight (=attachments/<slug>/<name>=) — every provider hands an id you

#+begin_src javascript
// ~/.viva/registry/vcompany/modes/dummy/calendar/occurrences.js
// RFC 5545 in the small: FREQ + INTERVAL + COUNT/UNTIL, the four frequencies the office uses.
// A vendor service replaces this file's INPUT (its own rrule text) and keeps its OUTPUT.
const STEP = {
  DAILY: (date, n) => date.setDate(date.getDate() + n),
  WEEKLY: (date, n) => date.setDate(date.getDate() + 7 * n),
  MONTHLY: (date, n) => date.setMonth(date.getMonth() + n),
  YEARLY: (date, n) => date.setFullYear(date.getFullYear() + n),
};

const parse = (rrule) =>
  Object.fromEntries(rrule.replace(/^RRULE:/, "").split(";").map((pair) => pair.split("=")));

const shift = (iso, from, to) => new Date(new Date(iso).getTime() + (to - from)).toISOString();

export const occurrences = (held, from, to) => {
  const start = new Date(from);
  const end = new Date(to);
  const out = [];
  for (const literal of held) {
    const { rrule, start: at, end: until } = literal.trait.EVENT;
    if (!rrule) {
      if (new Date(at) >= start && new Date(at) <= end) out.push(literal);
      continue;
    }
    const { FREQ, INTERVAL = "1", COUNT, UNTIL } = parse(rrule);
    const step = STEP[FREQ];
    if (!step) continue;
    const cap = COUNT ? Number(COUNT) : 500;
    const last = UNTIL ? new Date(UNTIL) : end;
    const cursor = new Date(at);
    for (let n = 0; n < cap && cursor <= last && cursor <= end; n++) {
      if (cursor >= start) {
        const on = cursor.toISOString();
        out.push({
          ...literal,
          slug: `${literal.slug}@${on.slice(0, 10)}`,
          trait: { ...literal.trait, EVENT: { ...literal.trait.EVENT, start: on, end: until ? shift(until, new Date(at), cursor) : null } },
        });
      }
      step(cursor, Number(INTERVAL));
    }
  }
  return out.sort((a, b) => (a.trait.EVENT.start < b.trait.EVENT.start ? -1 : 1));
};

import { provider } from "../provider.js";

const one = (ctx, slug) =>
  ctx.daemon.entities.literal.findOne({ ontology: "message", slug }, { populate: ["symbols", "uses", "in"] });

const statusOf = (literal) =>
  literal.symbols.getItems().find((symbol) => symbol.slug.startsWith("message.status."))?.slug.split(".").pop() ?? "read";

const at = (literal) => literal.trait.MESSAGE.at;

// the thread: walk to the root through `uses`, then collect everything that `in`s back down
const thread = async (ctx, literal) => {
  let root = literal;
  for (let hop = 0; hop < 32; hop++) {
    const parent = root.uses.getItems()[0];
    if (!parent) break;
    root = await one(ctx, parent.slug);
  }
  const seen = new Map([[root.slug, root]]);
  const queue = [root];
  while (queue.length) {
    const held = queue.shift();
    for (const child of held.in.getItems()) {
      if (seen.has(child.slug)) continue;
      const full = await one(ctx, child.slug);
      seen.set(full.slug, full);
      queue.push(full);
    }
  }
  return [...seen.values()].sort((a, b) => (at(a) < at(b) ? -1 : 1));
};

    }

export const DOW = ["mon", "tue", "wed", "thu", "fri", "sat", "sun"];
export const MONTHS = ["january", "february", "march", "april", "may", "june", "july", "august", "september", "october", "november", "december"];
export const MON3 = MONTHS.map((name) => name.slice(0, 3));
export const H0 = 8;
export const H1 = 19;
export const PX = 48;

export const ymd = (date) =>
  `${date.getFullYear()}-${String(date.getMonth() + 1).padStart(2, "0")}-${String(date.getDate()).padStart(2, "0")}`;

export const add = (date, n, unit) => {
  const held = new Date(date);
  if (unit === "d") held.setDate(held.getDate() + n);
  else if (unit === "w") held.setDate(held.getDate() + 7 * n);
  else if (unit === "m") held.setMonth(held.getMonth() + n);
  else held.setFullYear(held.getFullYear() + n);
  return held;
};

export const monday = (date) => {
  const held = new Date(date);
  held.setDate(held.getDate() - ((held.getDay() + 6) % 7));
  held.setHours(0, 0, 0, 0);
  return held;
};

export const rangeOf = (view, anchor) => {
  if (view === "day") return [anchor, anchor];
  if (view === "week") return [monday(anchor), add(monday(anchor), 6, "d")];
  if (view === "year") return [new Date(anchor.getFullYear(), 0, 1), new Date(anchor.getFullYear(), 11, 31)];
  return [new Date(anchor.getFullYear(), anchor.getMonth(), 1), new Date(anchor.getFullYear(), anchor.getMonth() + 1, 0)];
};

export const labelOf = (view, anchor, [from, to]) =>
  view === "day" ? `${DOW[(anchor.getDay() + 6) % 7]} ${anchor.getDate()} ${MON3[anchor.getMonth()]} ${anchor.getFullYear()}`
  : view === "week" ? `${MON3[from.getMonth()]} ${from.getDate()} – ${from.getMonth() !== to.getMonth() ? `${MON3[to.getMonth()]} ` : ""}${to.getDate()}`
  : view === "year" ? `${anchor.getFullYear()}`
  : `${MONTHS[anchor.getMonth()]} ${anchor.getFullYear()}`;

export const dayOf = (card) => card.start.slice(0, 10);
export const minutesOf = (iso) => Number(iso.slice(11, 13)) * 60 + Number(iso.slice(14, 16));
export const clock = (iso) => iso.slice(11, 16);

export const on = (rows, key) => rows.filter((card) => dayOf(card) === key);
export const within = (rows, [from, to]) => {
  const a = ymd(from);
  const b = ymd(to);
  return rows.filter((card) => dayOf(card) >= a && dayOf(card) <= b);
};

export const sorted = (rows) =>
  [...rows].sort((a, b) => (dayOf(a) === dayOf(b) ? (a.allDay ? -1 : b.allDay ? 1 : a.start < b.start ? -1 : 1) : dayOf(a) < dayOf(b) ? -1 : 1));

export const grouped = (rows) => {
  const bag = new Map();
  for (const card of sorted(rows)) {
    const key = dayOf(card);
    if (!bag.has(key)) bag.set(key, []);
    bag.get(key).push(card);
  }
  return [...bag.entries()].map(([key, items]) => ({ key, date: new Date(`${key}T00:00:00`), items }));
};

export const weeksOf = (anchor) => {
  const first = new Date(anchor.getFullYear(), anchor.getMonth(), 1);
  const days = new Date(anchor.getFullYear(), anchor.getMonth() + 1, 0).getDate();
  return Math.ceil((((first.getDay() + 6) % 7) + days) / 7);
};

    height: Math.max(20, ((end - start) / 60) * PX - 2),
    meta: ((end - start) / 60) * PX >= 40,
  };
};
