#+TITLE: Intent-as-Template Refactor
#+AUTHOR: Vivalence
#+DATE: 2026-04-11
#+STATUS: DONE

* Intent

Reframe IntentEntity from "a thing that generates buffers" to "a template
that seeds a Thread". Intent loses its =type= column entirely. Intent and
Thread now share a mirrored trait enum. Thread becomes the runtime
authority — when a thread is created with an intent ref, the intent's
traits and trait JSON are copied into the thread at construction time,
and no runtime code reads through the intent ref again.

After: =intent.type === "APPLICATIVE"= branches disappear. =FEEDING=
renames to =QUEUEING=. Thread carries its own trait set, populated
from its intent template at create time or set directly by callers
when no intent is provided. The intent ref stays on Thread for
provenance, never for config lookup.

* Desired End State

- Intent has no =type= field.
- IntentTraitsEnum and ThreadTraitsEnum mirror: { QUEUEING, FURNISHED, SELFEVIDENT }.
- Thread is the runtime authority. Intent is template-only.
- All =intent.type === "APPLICATIVE"= branches replaced with =thread.traits.includes("QUEUEING")=.
- All =FEEDING= references renamed to =QUEUEING= everywhere EXCEPT the archive entry on IntentTraitsEnum (kept, exempt from cleanup).
- Default thread.traits when no intent: =[]= (not [SELFEVIDENT]).
- Trait copy happens in ThreadSchema =beforeCreate= hook. Always fires when intent is present. Thread =trait= JSON is deep-merged with thread values winning per nested key.

* Design Decisions

| Decision                | Choice                                           | Rationale                                                               |
|-------------------------+--------------------------------------------------+-------------------------------------------------------------------------|
| Trait copy mechanism    | ThreadSchema =beforeCreate= hook (Skin C)        | Automatic for all create paths; no caller discipline needed             |
| Hook condition          | Fires whenever intent present                    | No =traits.length === 0= guard — create-time is the only place it runs  |
| traits array semantics  | Intent.traits replaces thread.traits wholesale   | Intent fully owns the capability set at seed time                       |
| trait JSON semantics    | Deep merge with thread winning per nested key    | Allows partial overrides — e.g. override =trait.QUEUEING.limit= only    |
| Merge implementation    | =merge= from belt/object.js                      | Existing deep-merge primitive, matches JSON Merge Patch convention      |
| Import path             | Relative: =../../gestalten/belt/object.js=       | Explicit, no package-export self-reference                              |
| Intent ref on Thread    | Kept                                             | Provenance for replay/debugging; never read for config at runtime       |
| IntentEntity.type       | Dropped                                          | Collapses into trait presence on Thread                                 |
| FEEDING archive entry   | Kept on IntentTraitsEnum under =// archive=      | Back-compat marker; exempt from cleanup per Finn                        |
| ThreadRepository custom | Not added in phase 1                             | Hook covers the happy path; repo factory can grow later if needed       |
| Default intentless trait | =[]= (empty)                                    | Callers who want SELFEVIDENT set it explicitly                          |

    Two-line change in =subsystems/typology/gestalten/shape/object.js=:
    =execute = steer.direct= → =execute = steer.request= on both =object()= and =proxy()= defaults.
    No other shape.object callers pass =steer.direct= explicitly (only archived =.bak.js= files), so
    the change is fully localized.

* Known Issues

** Reference-not-loaded latent bug in client-side thread creation
   =systems/html/src/routes/pincer/panels/navigation.js= (live as of 2026-04-11) calls:
   =daemon.entities.thread.create({ mode: mode.id, intent: intent.id })=

   This sends scalar IDs to the server. At server-side em.create time, MikroORM resolves
   =intent: intent.id= into a *Reference*, not a loaded entity. The =beforeCreate= hook in
   ThreadSchema guards with =if (!intent || !intent.traits) return;= — on an unloaded Reference,
   =intent.traits= is undefined, so the hook no-ops. The thread will NOT inherit the intent's
   trait/trait-config in production via the navigation flow.

   The typology =thread.test.js= tests pass a freshly-created, still-in-identity-map IntentEntity
   to =em.create=, which resolves to the loaded entity (synchronously) and the hook fires
   correctly. That's why unit tests don't catch this.

   Fix options (pick one when this blocks navigation):
   1. Server-side: in the thread create handler, populate =intent= before =em.create= (e.g.
      =const intent = await intentRepo.findOne({ id: data.intent })=). Explicit, obvious at
      the call site.
   2. Hook-side: make =beforeCreate= async-load the intent if it's a Reference. Centralized
      but introduces async I/O inside a MikroORM hook — check the =mikro_hook_flush= rule and
      the async-hook constraints before doing this.

   Recommended direction: option 1, in the server thread create handler. Option 2 risks
   cascading flushes or recursion inside the unit-of-work.

   Add a test case that passes =intent: intentId= (scalar) to =em.create(ThreadEntity, ...)=
   and asserts the trait copy still happened — this will currently fail, which is the point.
