* the law

1. A buffer is a working area: =mime= · =data= (live state in SQL, mirrored) · =files= (m:n, the Files it loads or was parsed from). It is owned by a mode, hangs on a thread, and on the turns that surfaced it (m:n). A File is a file the system holds: =mode · path · mount · mime · hash · integrity · bytes=, one row per =(mode, path)= (ruling 36).
2. A View is code: =slug · mime · entry= (=presents= GONE, m96 ruling 13: the join is =view.mode=; a cross-mode use is a =buffer.views= pin), owned by a mode, one row per =(mode, slug, mime)=; its bytes are its File rows (=file.view=, m:1 nullable), =entry= the one the client imports; a compile is a File mutation inside the View (=upstream · downstream= DEAD, Q38 10-21). It says what it is; its mode says what it shows.
3. =buffer.views= (m:n) is the SELECTION — a pick or a generation; empty, the mode's views stand (RULED 10-21 Q10′ /"a"/, superseding 30 · 35 and m96 ruling 12's mode join). =mime= stays as KIND: the fallback renderers and =mode.buffer(desc)= key on it. OLD (dead): =view.presents === buffer.mime= was the join. A mode's buffer mime is minted from its REFERENCE (m96 ruling 3, 10-21: =/daemon/chess/mode/board/play= → =application/vnd.vivalence.daemon.chess.mode.board.play+json=); =presents= defaults to it.
4. A mode declares ONE buffer schema (=export const buffer=) and its views (=export const views=); =mode.buffer(desc)= validates against the one schema.
5. The client decides by a =[[predicate, Part]]= table walked in order: a view of the buffer's own mode, or one pinned in =buffer.views= (bundled on the runtime, fetched by row — the client renders nothing of a mode's and bundles nothing, m96 10-21 /"There is no rendering on the client"/) → a chrome part for the buffer's own mime → the =+json= part → a line. =accept= is derived from the table; the runtime never knows what a client can show.
6. A code view mounts by =default(target, { terminal, buffer, surface })=; =surface.place ∈ cell · frame=; one component serves both places.
7. Several runnable views for one buffer: =buffer.views= pins (RENDERED DIED 10-21, Q10′); the client picks among the candidates by =view.mime=.
8. FILESINK writes: =receive= → a File (receive ONLY, m96 ruling 14). A view is made by =ViewRepository.bundle(data, { bundler })= — datamap =/view/bundle=; VIEWABLE (was RENDERER, m96 ruling 12) bundles the declared views; =mode.buffer= mints the buffer with =mode.buffer.mime= (ruling 13). FILESET reads the declared directory into File rows. Paladin moves bytes; repositories record and import no paladin.

10. Presence is a patrol: a lifecycle beat over views and Files stats each =mount= and sets =MISSING=.
11. A client mode carries no views.
12. Notes hang on buffers and turns. Not on threads.

const fetched = async (url, integrity, name) => {
  const response = await fetch(url);
  if (!response.ok) throw new Error(`[attached] ${name} ${response.status}`);
  const text = await response.text();
  if ((await digest(text)) !== integrity) throw new Error(`[attached] ${name}: integrity sha256 mismatch`);
  return text;
};

  (read.get(file.integrity) ?? read.set(file.integrity, fetched(attach.branch("/file").branch(`/${file.id}`).absolute, file.integrity, file.id)).get(file.integrity));
const verified = new Map();
export async function load(view, attach) {
  if (verified.has(view.integrity)) return verified.get(view.integrity);
  const text = await fetched(attach.branch("/view").branch(`/${view.id}`).absolute, view.integrity, view.slug);
  const url = URL.createObjectURL(new Blob([text], { type: "text/javascript" }));

    const module = await import(/* @vite-ignore */ url);
    verified.set(view.integrity, module);
    return module;
  } finally {
    URL.revokeObjectURL(url);
  }
}
