* the law

Three tiers, one direction, one rule per tier:

#+begin_example
tier        declares                                   falls through to
ledger      <ledger>/ledger.viva.js   manifest.type "ledger"    every instance on this ledger
instance    <instance>/*.viva.js      manifest.type "instance"  every daemon / service in it (already: resolve.defaults)
daemon      recipe daemons[n]                                    its modes (already: resolve.ground for the seat)
#+end_example

- *A SLOT is the unit for a mask; a KEY is the unit for the environment.* =runtime · lighthouse · datamap · hallucinators · clients · services= fall through WHOLE: an instance that declares =hallucinators: []= has said "none", not "merge mine in". This is the same rule =resolve.defaults= already applies daemon-ward (=inherit(daemon, "hallucinators")=), so the two tiers speak one verb. The environment schema folds key-wise because the strata already fold VALUES key-wise — a KEY decides (m41), and the doctor must know that the ledger's =SECRET_VIVA_ANTHROPIC_API_KEY= is documented when the hallucinator that reads it came from the ledger.
- *Fold BEFORE hydrate.* If the ledger's thunks fired and the instance overrode the slot, the requirements record would carry reads nobody uses — false REQUIRED rows in the doctor. So the raw modules fold first (thunks unfired), then =at(label)= walks the folded declaration once. Every downstream organ — =hydrate= · =resolve.mountpoints= · =resolve.ground= · =settle= · =check= · =Instance.cast= — sees exactly what it sees today.
- *=daemons= never fall through.* A daemon IS what an instance is; a ledger has none. =manifest= is each tier's own.
- *The ledger's slots are the =Ledger= schematic's keys.* Paladin derives the slot list from =Object.keys(Ledger.properties)= — no second list to drift.
- *The file's place IS the declaration — derive by default, lock to override.* ANY =.viva.js= at the ledger root (depth 0: =instances/= and =registry/= below are not its word) is the ledger. =manifest.type= derives (=ledger=), =manifest.slug= derives from the stem (=viva.viva.js= → =viva=, the scaffold's =ledger.viva.js= → =ledger=); an exported =manifest= only LOCKS a field. beef: /"i dont like manifest export on ledger. slug on ledger especilly. can we default them on the viva.js file at ledger root?"/ · /"not ledger.viva.js specifically. ANY .viva.js file at ledger root."/ The instance keeps its manifest (many per ledger, the slug is its record key); the ledger is one per home, its name is its place.
- *Absent is silent; two is a throw; a foreign type is a throw.* No file → nothing inherited, =instance.inherited = []=. Two files → =ledger: one declaration per ledger — <home> holds a.viva.js, b.viva.js=. A =manifest.type= other than =ledger= → =declares manifest.type "x" — a file at the ledger root is the ledger; drop the type or say "ledger"=. (The earlier =mute= verdict is gone with the manifest requirement — beef's first draft, =manifest: { manifest: { type } }=, now derives and is simply LOCKED to nothing useful: the nested key is ignored.)
- *Provenance is a list, not a relabel.* =instance.inherited= names the slots the ledger supplied; =instance/doctor= prints it. Requirement rows keep the slot label (=runtime.statics.serve=) whoever declared it — the doctor's question is "what does this instance read", not "who wrote the line".
- *The runtime is untouched.* It reads =paladin.instance.runtime · lighthouse · daemons · services= after =lifecycle.mount= — the folded, cast instance. The runtime pass is a blast: its suite, then a live boot on a slimmed recipe.
