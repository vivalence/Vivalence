* Meta
** Intent

=DATASET= is anabolic: registry files → daemon entities, once, at install.
This quest builds the katabolic path: daemon entities → registry files,
ongoing.

Enrichment that happens INSIDE the daemon — harvested candidates, agentic
annotation, minted lemma symbols, rank corrections — currently dies in the
sqlite file. Draining it back makes the registry the durable, versioned,
travelling home of the data, and the daemon merely working memory.

Not sync. Two one-way operations at different times:

| operation | truth    | shape                          |
|-----------+----------+--------------------------------|
| install   | registry | idempotent upsert              |
| drain     | daemon   | wholesale scoped projection    |

No reconciliation, ever.

** The shape in one screen

#+begin_example
  registry files ──DATASET(install)──▶ daemon entities
        ▲       paladin.find/read            │
        │                                    │ writes (harvest, agentic, mint)
        │                                    ▼
        │                          twitch /after/{type}/{op}
        │                                    │ debounce 1500ms
        │                                    ▼
        └──────DATASINK(drain)───── row → match → shape → strata → scribe
                                                              paladin.state
#+end_example

Three layers, and the boundary between them is the whole design: typology
CARRIES (pure declarations + pure row algebra), paladin does the OS (walk,
codec, atomic write), the trait WIRES. Nothing under =prototypes/= touches
=Deno.*=; nothing under =paladin/= knows what a sink is.

|------------------------------+---------------------------------------------------------------------+-----------------------|
| =selector.js=                | =belt.object.match= (=gestalten/belt/object.js:55=)                 | the operators         |

=paladin.read.file= (=subsystems/paladin/belt/read.js:37=) already dispatches
a codec by extension, and =paladin.find= (=belt/find.js:11=) already skips
=bak=/=archive=/=slp= — which =reader.dir= did not. The first draft's walker
was a worse copy of a live primitive.

**The seam, stated once**: a carrier holds DECLARATIONS, never loaders.
Nothing under =prototypes/= touches =Deno.*=. This is the =Bundle= shape —
=prototypes/bundle.js= is pure (hash, entries, fetch-by-integrity),
=paladin/belt/bundler.js= does the filesystem, =traits/application.js= wires
them, and a module imports =Bundle= without ever seeing paladin.

So the vocabulary is:

- =Dataset= — carrier ={ schema, intent, ...sources-per-type }= where a source
  is a mount-relative STRING, a directory STRING, or an inline row array.
  Legacy ={ schema, entities }= lifts free (every existing module UNCHANGED).
- =Datasink= — carrier of per-type tuple lists, normalized to
  ={ type, where, match, shape, target }=. Owns =canonical(rows) => string=
  and =strata(rows, target) => Map<path, rows>= — both pure. Neither writes.
- =reader= / =writer= — the nouns SURVIVE, the directory does not. @beef:
  /"i actually like the name reader and writer. they are nicely explicit and
  obvious."/ They are now pure DESCRIPTOR factories, exported beside the
  carrier each one feeds: =reader= from =prototypes/dataset.js=, =writer=
  from =prototypes/datasink.js=. =reader.dir(t)= => ={ walk: t }=,
  =reader.json(t)= => ={ read: t, codec: "json" }=, =writer.json(t)= =>
  ={ write: t, codec: "json" }=, =writer.split(pattern, target)= =>
  ={ write, split }=. A bare string lifts to the extension's descriptor, so
  declarations stay terse. Nothing here opens a file — the trait hands the
  descriptor to =paladin.find= / =paladin.state=. The explicitness @beef
  wanted is at the declaration face, which is the only place it was ever
  doing work.
- =%= is the ONE wildcard, in the selector and in the target alike:
  ={slug: {$like: "word.lemma.%"}}= selects, =writer.split("word.part-of-
  speech.%", "…/%.json")= partitions. No second glob register.
- =project= — the row algebra, exported from =prototypes/datasink.js=:
  =row/refs/lean/detail/slug/drop=, plus =pick/omit/pipe= as thin CURRIED
  adapters over =belt.object= (=omit = (...keys) => (row) =>
  object.omit(row, keys)=). Curry at the declaration face, no second
  implementation.
- =belt.query.where(query)= — compiles a MikroORM query object to a row
  predicate; =null= on an operator it cannot compile → conservative
  dirty-all, DB stays authoritative. =object.match(obj, query)= becomes
  =where(query)?.(obj)= — ONE compiler, and the five live =object.match=
  call sites gain operators.
- =belt.object.ordered(value)= — recursive key sort. General, sibling to
  =clone=/=descend=.
- =paladin.state.scribe(path, text)= — atomic tmp+rename, write-if-changed,
  returns whether it wrote.
- =paladin.find.data(dir)= — the codec walk, =index.js= skipped.

Nothing is added to =gestalten/index.js=, =index.client.js=, or =fromm=. On
that last one @beef was right and it is structural: /"SMELL!!! big smell. not
good."/ — every =fromm= member is =fromm.X(thing) => { get view() }=, a lazy
coercion view; =selector(where) => fn= has a different shape, and the
re-export crossed a directory barrel. It is belt.

** Forks

ONE fork open, and it is empirical rather than a design choice — it gets

1. **=carry= vs a re-scoped fork for the detached lane — CLOSED, by the
   instrument.** The prediction was right: the pump DOES interleave with the
   flush tail. Measured on a real ORM, =seen= is already populated the moment
   =await em.flush()= returns, because the flush's own awaits drain the
   microtask queue. The question the fork actually asked, though, was whether
   that breaks the reentrant read — and it does not: the deferred handler's
   =repo.count({})= resolves against the carried context and returns a live
   count. So =carry= holds, and =shard.params()= is NOT added to the provider
   contract. The fallback was correctly not pre-built.

   it" is false and was never what =detached= guarantees. The guarantee is that
   the subscriber's =await= returns without waiting on the handler — the flush
   is never BLOCKED. The gate now asserts that (=order[0] === "flush-called"=)
   instead of asserting an emptiness that a microtask can invalidate.

const like = (pattern) => {
  const source = String(pattern)
    .split("%")
    .map((part) => part.replace(/[.*+?^${}()|[\]\\]/g, "\\$&"))
    .join(".*");
  const expression = new RegExp(`^${source}$`);
  return (value) => is.string(value) && expression.test(value);
};

const refs = (value) =>
  [value ?? []].flat().map((item) => (is.string(item) ? { slug: item } : item));

const SCALAR = {
  $eq: (argument) => (value) => value === argument,
  $ne: (argument) => (value) => value !== argument,
  $in: (argument) => (value) => argument.includes(value),
  $nin: (argument) => (value) => !argument.includes(value),
  $gt: (argument) => (value) => value > argument,
  $gte: (argument) => (value) => value >= argument,
  $lt: (argument) => (value) => value < argument,
  $lte: (argument) => (value) => value <= argument,
  $like: like,
  $re: (argument) => (value) => new RegExp(argument).test(value),
  $exists: (argument) => (value) => (value != null) === argument,
};

const COLLECTION = {
  $some: (inner) => (items) => items.some(inner),
  $every: (inner) => (items) => items.every(inner),
  $none: (inner) => (items) => !items.some(inner),
};

const predicate = (expected) => {
  if (is.array(expected))
    return (value) => is.array(value) && expected.every((item) => value.includes(item));
  if (!is.object(expected)) return (value) => value === expected;

  const tests = [];
  for (const [operator, argument] of Object.entries(expected)) {
    if (COLLECTION[operator]) {
      const inner = where(argument);
      if (inner == null) return null;
      tests.push((value) => COLLECTION[operator](inner)(refs(value)));
    } else if (operator === "$not") {
      const inner = predicate(argument);
      if (inner == null) return null;
      tests.push((value) => !inner(value));
    } else if (SCALAR[operator]) {
      tests.push(SCALAR[operator](argument));
    } else if (operator.startsWith("$")) {
      return null;
    } else {
      const nested = predicate(argument);
      if (nested == null) return null;
      tests.push((value) => is.object(value) && nested(value[operator]));
    }
  }
  return (value) => tests.every((test) => test(value));
};

export const lift = (selector) => {
  if (selector == null || selector === true) return {};
  if (is.fn(selector)) return null;
  if (is.string(selector)) return { symbols: { $some: { slug: selector } } };
  if (is.array(selector)) return { $and: selector.map((slug) => ({ symbols: { $some: { slug } } })) };
  if (!is.object(selector)) return null;
  return selector;
};

export const where = (selector) => {
  if (is.fn(selector)) return selector;
  const query = lift(selector);
  if (query == null) return null;

  const tests = [];
  for (const [key, expected] of Object.entries(query)) {
    if (key === "$and" || key === "$or") {
      const parts = expected.map(where);
      if (parts.some((part) => part == null)) return null;
      const fold = key === "$and" ? "every" : "some";
      tests.push((row) => parts[fold]((part) => part(row)));
      continue;
    }
    const test = predicate(expected);
    if (test == null) return null;
    tests.push((row) => test(row?.[key]));
  }
  return (row) => tests.every((test) => test(row));
};

      for (const [selector, second, third] of tuples) {
        const [shape, target] = third === undefined ? [null, second] : [second, third];
        this.sinks.push({
          type,
          where: query.lift(selector),
          match: query.where(selector),
          shape,
          target: writer.lift(target),
        });
      }

    const claimed = new Set();
    for (const target of this.targets) {
      if (claimed.has(target)) throw new Error(`[Datasink] two sinks write "${target}"`);
      claimed.add(target);
    }
  }

  get types() {
    return [...new Set(this.sinks.map((sink) => sink.type))];
  }

  get targets() {
    return this.sinks
      .map((sink) => sink.target)
      .filter((target) => !target.split)
      .map((target) => target.write);
  }

  of(type) {
    return this.sinks.filter((sink) => sink.type === type);
  }

  concerns(type, row, ctx) {
    return this.of(type).filter((sink) => sink.match?.(row, ctx) ?? true);
  }

  static canonical(rows) {
    return JSON.stringify([...rows].sort(bySlug).map(object.ordered), null, 2) + "\n";
  }

  static captures(row, pattern) {
    const bound = new Set();
    for (const value of Object.values(row ?? {})) {
      if (!is.array(value)) continue;
      for (const item of value) {
        const slug = is.string(item) ? item : item?.slug;
        const hit = is.string(slug) ? slug.match(pattern) : null;
        if (hit) bound.add(hit[1]);
      }
    }
    return [...bound].sort();
  }

  static strata(rows, target) {
    if (!target.split) return new Map([[target.write, rows]]);
    const pattern = glob(target.split);
    const strata = new Map();
    for (const row of rows)
      for (const capture of Datasink.captures(row, pattern)) {
        const path = target.write.replace("%", capture);
        (strata.get(path) ?? strata.set(path, []).get(path)).push(row);
      }
    return strata;
  }
}

** M22.4 — the DATASINK trait

NEW =systems/runtime/daemon/traits/datasink.js=. Reads:

1. lift the carrier onto =mode.datasink=;
2. the same =DATASPACE= allow-list plus user-relation invariant M22.3 uses —
   one policy, stated once, imported here;
3. one type-level =dirty= set, wholesale rewrite per type;
4. twitch opens =/after/{type}/{op}= per declared type, gated on =armed= —
   which the FINALIZER sets, so the install storm's own twitches never mark
   dirty;
5. =fn.debounce(1500)= settle, single-flight =mode.drain= (shared in-flight,
   cleared on settle).

The drain is one pipeline per sink, and the trait is where every descriptor
finally meets the filesystem:

#+begin_example
  repo.find(sink.where)            DB-side, authoritative — sink.where IS the lift
    → find(populate: relations)
    → project.row(relations, keep)  normalize refs, keep the schema's columns
    → match(row, {daemon, mode})    memory-side classify
    → shape ?? lean                 the declared projection, or the default
    → drop nulls
    → Datasink.strata(rows, target) Map<path, rows> — split binds here
    → claimed.add(slug)             ← from the STRATA, never from match
    → paladin.state.scribe(path, Datasink.canonical(rows))
#+end_example

#+BEGIN_SRC javascript :tangle ../../systems/runtime/daemon/traits/datasink.js :mkdirp yes
import { fn, shard, project, Datasink } from "@vivalence/typology";
import paladin from "@vivalence/paladin";

const DATASPACE = new Set(["symbol", "literal"]);
const DEBOUNCE = 1500;

export const DATASINK = (mode, daemon) => {
  const datasink = new Datasink(mode.module.datasink ?? {});
  mode.datasink = datasink;

  const meta = shard.datamap.strip(daemon.datamap.introspect());
  for (const type of datasink.types) {
    const scoped = Object.values(meta[type]?.properties ?? {}).some((relation) => relation.target === "user");
    if (!DATASPACE.has(type) || scoped)
      throw new Error(`[DATASINK] ${mode.type}/${mode.slug} declares non-dataspace entity "${type}"`);
    if (!daemon.entities[type])
      console.warn(`[DATASINK] ${mode.type}/${mode.slug} declares unknown entity "${type}"`);
  }

  const dirty = new Set();
  let armed = false;
  let flight = null;

  const drain = async (input = {}) => {
    const types = input.all || !dirty.size ? datasink.types : [...dirty];
    const report = { drained: [], written: 0, orphans: {} };

    for (const type of types) {
      dirty.delete(type);
      const repo = daemon.entities[type];
      if (!repo) continue;

      const relations = Object.keys(meta[type]?.properties ?? {});
      const claimed = new Set();

      for (const sink of datasink.of(type)) {
        const columns = sink.target.keep.filter((name) => meta[type]?.columns?.[name]);
        const found = await repo.find(sink.where ?? {}, { populate: relations });
        const rows = found
          .map(project.row(relations, [...columns, ...relations]))
          .filter((row) => sink.match?.(row, { daemon, mode }) ?? true)
          .map(sink.shape ?? project.lean(relations))
          .filter((row) => row != null);

        for (const [target, slice] of Datasink.strata(rows, sink.target)) {
          for (const row of slice) claimed.add(row.slug);
          const path = `${mode.module.mount.dirname}/${target}`;
          if (await paladin.state.scribe(path, Datasink.canonical(slice, sink.target.codec))) report.written++;
        }
      }

      const total = await repo.count({});
      report.orphans[type] = Math.max(0, total - claimed.size);
      report.drained.push(type);
    }

    return report;
  };

  const once = (input) => (flight ??= drain(input).finally(() => (flight = null)));
  const settle = fn.debounce(() => once({}), DEBOUNCE);

  mode.drain = once;

  for (const type of datasink.types)
    for (const op of ["create", "update", "delete"])
      daemon.twitch.open(`/after/${type}/${op}`, () => {
        if (!armed) return;
        dirty.add(type);
        settle();
      });

  return {
    finalize: () => {
      armed = true;
    },
    terminate: () => {
      armed = false;
      settle.cancel();
    },
  };
};
#+END_SRC

=claimed= is fed from the STRATA and not from =match=, and that ordering is
load-bearing rather than stylistic: a row that satisfies a sink's selector but
binds no =split= capture lands in no stratum and is never written. Claiming it
at match time would mark it covered while dropping it — silent loss, invisible
to the very census built to catch it. Fed from the strata, it becomes an
orphan and says so.

=project.row(relations, keep)= takes the columns off the same stripped
metadata that supplies the relations, which is what retired the first draft's
=SYSTEM= constant (@beef: /"feels like thats system level interfering on
module level"/). =id=, =createdAt=, =updatedAt= and =installed= are not in a
list any more; they are simply not in =meta[type].columns=, because they never
were the module's data.

The orphan census (=count({})= minus claimed slugs, per type) is the sink
coverage measure: rows in the DB that no declared sink claims will be LOST on
the next install cycle. It rides in the drain report rather than warning,
because on a partial topography a nonzero orphan count is expected.

*** THE DRAIN HAS NO PROVENANCE — trait selectors cross package boundaries

Found by @beef reaching for a full =.js= → =.json= migration and stopping
himself: /"ah. shit. not possible. since the data is assembled from many
modules."/ The instinct was right and the mechanism is sharper than the phrase.

=repo.find(sink.where)= queries the daemon's WHOLE dataspace. **No row records
which module installed it** — there is no owner column, no package stamp,
nothing. A sink partitions by CONTENT, and content is a shared vocabulary.

So the declaration this quest shipped is self-contradicting:

| the quest's sink                | what it actually matches                   |
|---------------------------------+--------------------------------------------|
| ={traits: ["ONTOLOGICAL"]}=     | italian's 3 =word.suffix.*= **+ the 156 topology-owned symbols** |
| stated =orphans.symbol=         | 156 — which assumes those rows go UNCLAIMED |

Both cannot be true. Under the trait selector those 156 are not orphans, they
are CAPTURED: =dataset/symbols/ontological.json= would be written with 159 rows,
and the next install would make italian the declaring owner of symbols belonging
to =topologies/{word,sentence,conjugation}=. One drain and one reinstall is all
it takes for a topography to absorb another package's vocabulary — silently,
because every count still looks plausible.

**Slug namespaces are the only selector that respects package boundaries**, because
a slug prefix is owned by its declaring module and a trait is not:

#+begin_src javascript
  [{ slug: { $like: "word.suffix.%" } }, project.omit("literals"), "…/ontological.json"]
#+end_src

={traits: ["STRUCTURAL"]}= survives TODAY only because no other mounted package
declares a STRUCTURAL symbol. It is the same latent bug with no current
trigger — a fact about the deployment, not about the selector.

Second half of the same finding: =report.orphans[type]= is computed from
=await repo.count({})=, also UNSCOPED. So "orphans" means *rows in this daemon
that this module's sinks did not claim* — which on a shared daemon includes
every other module's rows. It is a meaningful number only when the draining
module is the daemon's only =DATASET=. Italian happens to satisfy that (it owns
2436 of 2592), which is why the figure looked sane and hid the capture.

Two ways out, neither built:
1. **discipline** — every selector slug-namespaced, and the census read as
   "unclaimed on this daemon" rather than "unclaimed of mine". Free, fragile.
2. **provenance** — the installing module stamped on the row, and both
   =find= and =count= scoped by it. A schema change to the dataspace, and the
   honest fix. It also makes =orphans= mean what everyone reads it as meaning.
