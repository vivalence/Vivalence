Brief Description: A wireless distributed system for early detection and direction-finding of mechanical vibrations and impacts. Built on ESP32 microcontrollers using the ESP-NOW protocol for real-time communication without requiring a traditional Wi-Fi router.
Key System Components:
1. Sensor Nodes:
  - ESP32-C3 microcontrollers equipped with ADXL345 accelerometers.
  - Autonomously monitor surfaces or objects for vibrations exceeding a predefined threshold (Vibration Threshold).
  - Upon detecting an impact, instantly calculate force (g) and directional angle, then generate a data packet with a unique ID and timestamp.
2. Relay Nodes:
  - Intermediate ESP32 nodes that extend network range using a mesh topology principle.
  - Receive packets from remote sensors, increment the hop counter (hop_count), and forward them instantly.
3. Central Hub (Endpoint):
  - The final data-collection point connected to a computer or control device.
  - Aggregates all telemetry from the network, synchronizes time via periodic sync packets, and outputs structured JSON data streams through the Serial port for further processing or visualization.

* literal schema — the annotation p(line) mints

Per data line, one *reception literal*, slug-namespaced (dataspace has no provenance — the
namespace IS the provenance):

#+BEGIN_EXAMPLE
{
  slug: "stucatch.reception.<origin>.<seq>.<via>.<ingestMs>",
  traits: ["EMITTED", "STAMPED", "RECEIVED", "INGESTED", <kind trait>],
  trait: {
    EMITTED:  { node, seq, kind },                # utterance identity, sender's claim
    STAMPED:  { at, epoch },                      # sender clock value + frame — raw, uncorrected
    RECEIVED: { via, hops, rssi },                # the PATH — rssi omitted on self-lines
    INGESTED: { at, raw },                        # wall clock spine + the verbatim line
    SYNCED:   { authority },                                    # kind 0
    RANGED:   { peer, rssi },                                   # kind 2 — the node↔node edge
    SENSED:   { magnitude, bearing },                           # kind 3 — bearing = sensor frame
    REPORTED: { fw, role, boots, uptimeS, syncAgeS, tx, rx, drop },  # kind 4
  },                                              # kind 1 PING = header traits only
  symbols: [{ slug: "node.<origin>" }],           # + node.<via> when relayed (fork 3)
}
#+END_EXAMPLE

- =node.<id>= symbols minted lazily on first sight: =traits [STRUCTURAL, LABELED]=.
- Duplicates are DATA: a relayed copy or blackout resend = distinct reception of the same
  utterance — (origin, seq) equal, path/ingest differ. Never dropped at ingress.
- Log lines: skipped in m43 (fork 4). Junk lines: counted, never thrown.

=boot(daemon, mode)=:
1. resolve source path (fork 2): a *file-shaped stream* — serial device or FIFO. Device:
   =stty -f <dev> 115200 raw= subprocess once, then =Deno.open= → readable → TextDecoderStream
   → line split. FIFO: same code path, zero branches.
2. per line: =p(line)= — strict parse (v==4, kind known, origin hex, seq u16; junk tolerated)
   → mint reception literal + lazy node symbol → flush discipline per the mikro memos.
3. return teardown: abort the reader, close the handle. Daemon disintegrate calls it.

Dev rig (the answer to the big fat no — the mode NEVER spawns its source):

VIVA_STUCATCH_SOURCE=/tmp/stucatch.fifo …             # boot just opens a path
#+END_EXAMPLE
Same open/read/annotate code for sim and hardware; the path is the only difference.
