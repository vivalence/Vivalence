* the decision trail

- *one package, one owner* — =@commons=. The =@viva= vs =@vivalence= owner question dissolves
  (=// rename to vivalence= in =package.viva.js= dies with the file's rewrite). =@vivalence/*= stays the
  JS workspace namespace (=@vivalence/paladin=, =@vivalence/typology=…); =@commons/*= is the module
  lookup grammar. Two resolvers, two prefixes, no overlap.
- *type names stay* — =playground= (beef: "@development/playground/xyz", this session) and
  =chaosmonkey= and =fixture= are the module TYPES; they become the second segment of the lookup, which
  is exactly beef's =@commons/playground= · =@commons/fixtures= reading. Dirs mirror the type:
  =commons/playground/<slug>/=, =commons/playground/chaosmonkey/<slug>/=, =commons/fixtures/=.
- *registry keeps its word* — store, record, verbs, scope, env: untouched (F1 to confirm). The
  README sentence becomes "the first =viva= you ran seeded the record from the checkout's =commons/=".
- *no lock on disk* — derive-by-default (methods/quest.md): =corpus.viva.js= drops =owner: "@testing"=;
  the override path stays exercised by the in-memory fixture in =tests/vip.test.js=.
- *the record heals itself* — M2: =reconcile(checkout, seedRoot)=: dead location under the checkout
  → rediscover =<repository>/commons=; dead elsewhere → keep + skip + report. Prod, every dev box, and
  the README walker all carry =/…/registry/{commons,testing,development}= absolute — none need a hand.
- *ONE blast, not rungs* (m11 lesson, beef: "not as atomic step by step microprocess, but as a blast
  change"). M1 is the whole move in one pass between two green suites; M2–M4 are the organs around it.
