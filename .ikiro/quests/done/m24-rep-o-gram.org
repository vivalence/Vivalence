* Intent

Aggregate =write=, =shadow=, =listen=, =flashcard=, =pick=,
=conjugation= and the dead =bak/translations= LLM machinery into ONE
well-designed mode: =rep-o-gram=. All things reps.

Six live modes were six copies of the same "prompt → answer → judge →
review → advance" machine, with drift already present: three grading
semantics, two speed tables, batch-vs-limit intent keys, five copies
of the correction machinery, three of the token-chip UI, eight of the
self-feed fallback.

Every old mode is one point in an axis space. Rep-o-mat exposes the
raw axes and NEVER prohibits a combination. Presets are emitter-side
conveniences, not machine branches.

* Decisions (settled with beef)

- **Presets never constrain.** The machine reads only raw axes from
  =buffer.data=. Preset routes are =object.merge(PRESET_AXES,
  ctx.input)= at the emitter edge — every field overridable. No branch
  anywhere on a preset name.
- **Judge is automatic, never a caller prop.** FLIP → self-grade,
  PICK → identity, TYPE → forgiving MATCH unless the knowable carries
  =judge: "LLM"= (stamped by =/generate=, never by callers).
- **Streak reviews EVERY rep.** Each attempt sends its signal to
  =/review/literal=; the memory driver owns time-weighting. Streak
  accounting is session-local.
- **=streak= optional, NO default.** Absent = single pass, no requeue.
  =streak: 1= = repeat the set until each is correct at least once.
  Failure resets that knowable's consecutive count and requeues.
- **=preview= applies to a knowable's FIRST rep only** under streak;
  requeued reps go straight to recall.
- **prompt TEXT also shows an audio button** whenever VOCALIZED
  resolves. AUDIO = audio-only; every knowable must resolve an asset.
- **=input= renamed =gameplay=.**
- **=limit=** optional ={reps, seconds}= hard cutoff, releases even
  mid-streak.
- **Knowables are word, sentence, or conjugation FORM.** An
  =ontology: "conjugation"= literal is a paradigm ROW (CONJUGATED:
  =infinitive= + =paradigm{slot: slug}=, NO TRANSLATED) — never
  playable raw. Emitters resolve rows → member form word-literals and
  stamp grammatical context, labels from symbol =trait.LABELED=
  daemon-side. Conjugation folds IN; the =paradigm= keyed-slot grid
  stays a separate mode. =match=, =judge=, =cloze=, =exhibit=,
  =nyan=, =riddler= stay out.
- **The buffer owns continuous.** =data.continuous= makes the machine
  refetch a fresh set on completion instead of releasing. Thread
  AIMED+QUEUEING re-pull is an ALTERNATIVE outer loop, not the
  mechanism. Many ways to do things.
- **LLM seam is cortex-direct** (riddler pattern,
  =registry/education/modes/games/riddler/hal/evaluation.js=):
  =ctx.daemon.cortex.hallucination({tune}).output.object(schema)=. No
  HARNESSED trait — no chat dock on a rep game. The GRADES rubric
  carries the NEUTRAL axis (acceptable alternative) that
  =subsystems/typology/gestalten/belt/string.js= =matches()= cannot
  express.
- **Schema descriptions ARE the app documentation** — LLM provisioning
  reads them. Cross-prop interactions live in the top-level
  =v.buffer({}).desc()=; props keep one-liners.

* The knowable

The rep unit. Two carriers, one interface, **UNION — no precedence**
(corrected by beef: *"conjugations are absolutely playable"*):

1. =buffer.literals= (corpus rel) — word/sentence literals, folded
   client-side by =fold.fromLiteral=; reviews land per literal.
2. =buffer.data.knowables= (direct) — caller-authored sets,
   =/generate= output, resolved conjugation forms. Review fan-out only
   where a =literal= id exists; inline-only knowables rep without
   touching memory.

The view's set is =[...literals.map(fold), ...data.knowables]= filtered
by =playable=. Precedence DISSOLVED because a mixed draw needs both at
once: a =conjugation= literal is a paradigm ROW (no TRANSLATED) that
must be resolved daemon-side into its member forms, so the row rides
=literals= as provenance (and is filtered out by =playable=) while its
forms ride =knowables=. Union + playability guard = mixed sets work
with zero branching, and the earlier "literals wins" rule — which
would have silently dropped every conjugation in a mixed feed — is
gone.

=buffer.symbols= (rel) carries the symbol scope the set was drawn from
(=/symbols= route) — display + continuous re-query.

* The machine — =registry/education/modes/games/rep-o-mat/buffer/=

Per-knowable phase chain: =preview? → prompt+input → feedback +
correction → advance=. The loop policy owns advance:

- no streak: queue walk, =buffer.release()= at end.
- streak N: per-knowable consecutive-success counter; success requeues
  until counter = N; failure resets to 0 and requeues; release when
  every knowable is done.
- continuous: on set completion the buffer refetches (requery
  =buffer.symbols= scope when present, else repeat its feed policy)
  and keeps going; releases only on =limit= or the player leaving.
- =limit {reps, seconds}= releases early from any of the above.

*** The intent, read properly

**The console is the axis space made drivable.** The whole thesis of
m24 is that six modes were points in ONE axis space; the console is
the live proof — walk the presets, flip any single axis mid-session
and watch the machine restart, scope the draw against the daemon's
REAL symbol inventory, author ad-hoc knowables inline (rep without
touching memory), see the emitted buffer JSON — the contract made
visible. It is the driver's cockpit for a surface beef sits in hours a
day, and the tuning bench: any dead mode is reproducible as preset
chip + one perturbation. Without it the machine's one real claim —
"never prohibits a combination" — is invisible and untestable from
the seat.

**The inspector is the machine made transparent.** The streak fold
state (streak/attempts/pending), the pending queue with per-knowable
runs·reps — the requeue law OBSERVABLE (failure resets and requeues at
the tail, you can watch it), every =/review/literal= dispatch as it
fires — the "streak reviews EVERY rep" law auditable, and the
narrated feed — the machine explaining each transition. It is the
trust surface and the debug surface.

** =buffer/streak.js= — pure loop accounting (invariant-tested)

#+BEGIN_SRC js
export const begin = (knowables, streak) => ({
  streak: streak ?? 0,
  attempts: 0,
  pending: knowables.map((knowable, index) => ({ index, runs: 0, reps: 0 })),
});

export const current = (state) => state.pending[0];
export const complete = (state) => state.pending.length === 0;
export const first = (state) => current(state).reps === 0;

export const record = (state, success) => {
  const [head, ...rest] = state.pending;
  const entry = { ...head, reps: head.reps + 1, runs: success ? head.runs + 1 : 0 };
  return {
    ...state,
    attempts: state.attempts + 1,
    pending: entry.runs >= state.streak ? rest : [...rest, entry],
  };
};
#+END_SRC

around =Rep.svelte= was the bug: remounting destroys the focused

- **never =disabled=, never =readonly=** on the live field — both
  dismiss the iOS keyboard. Lock by reverting =oninput= while
  =submitted=.
- **=onpointerdown={e => e.preventDefault()}=** on tray buttons.
  =onmousedown= does not cover touch.
- refocus only behind =document.activeElement !== field= — an
  unconditional =.focus()= is itself a flap.
