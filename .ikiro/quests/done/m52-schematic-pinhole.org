* the decision trail

1. *Nothing new at the pinhole.* beef's "unless we define every key to be a possible thunk" — that is the
   standing law: =hydrate= walks functions, arrays, plain objects; a fired value is walked again. The
   ternary was never about thunks; it was optionality with nowhere else to live.
2. *The gap is the schematic.* =statics: v.record(v.string(), v.unknown())= makes the pinhole schema-blind:
   it cannot fill, cannot mint, cannot judge. beef: /"solid schematics for what the config is expected to
   be."/ Type what typology KNOWS — =serve= on runtime/client/service, =remote= on the lighthouse.
   Module-specific statics (nlp =remote·language·processors=, openrouter =models=, datamap =db.file=) stay
   =unknown= in =Mask=: that contract belongs to the MODULE, not to typology (deferred, trigger named).
3. *The Url codec wraps the scalar.* =v.prototypes.Url()= exists as =Type.Codec(Type.String({pattern:
   "^.+$"})).Decode(wire => new Url(wire))= — measured: it decodes ="NaN"= to a Url. =v.url()= is the RFC
   3986 grammar (m48). The codec becomes =Type.Codec(url(options))=: the wire side IS the scalar, decode
   mints the prototype, encode folds it back. One grammar, two faces — the pair =signatures.js= already
   names (ana/cata).
4. *Faults are data. The doctor runs the pipeline.* beef: /"should instance/doctor actually do the
   processing? maybe"/. Yes — it collapses the fork this quest first carried (a lenient =mount= for the
   doctor, a strict =settle= for boot). One pipeline; =instance.faults= is a list; =check.environment=
   already works this way for env rows (doctor reads rows, =run=/=init= read =check.wrong=). The throw
   moves to the two boot edges and points at the doctor.
5. *Decode once; a faulted slot stays as hydrated.* Measured: =Value.Decode= is Check-then-transform;
   =Check= on an already-decoded value is =false=; decode twice throws. So =held()= decodes only when
   =errors()= is empty. A faulted slot keeps the hydrated value (a string, or =null=) — the runtime never
   sees it because =bootable= is false.
6. *Lighthouse inheritance moves AFTER settle.* Today =materialize= assigns =held.lighthouse ??
   instance.lighthouse= by reference before validation. Under decode the shared object would be visited
   twice (measured: the second visit survives — =Url= coerces a =Url= — but plain objects are
   shallow-cloned, so identity breaks and =lighthouse.test.js= "inherits, module and all" =toBe= would
   fail). Settle each daemon with its OWN lighthouse (=Lighthouse.optional()= passes when absent), then
   =daemon.lighthouse ??= instance.lighthouse= — the instance's already-decoded object, identity kept.
   "No lighthouse anywhere" becomes a fault line, no longer a schema accident on an inherited ={}=.
7. *Dormancy = hallucinators only, and why.* Measured: =new OpenAI({apiKey: null})= and =new
   Anthropic({apiKey: null})= both CONSTRUCT. The education recipes
   (=~/.viva/registry/education/instances/*/daemon.js=) already declare the flat array with three
   =.optional()= keys — and boot DEAD openrouter/elevenlabs/deepgram faculties into the cortex, which then
   advertises =has("speech")= and dies at first request. m48 decision 3 kept the ternary precisely to dodge
   this; two recipes, two idioms, one missing law. The law lands where a ROSTER mechanism consumes it: the
   cortex. =consume= is a fixed contract (=daemon.services.nlp= is called by name; a dropped entry is a
   worse failure than a rejected key) and no recipe declares an optional consume key — trigger 10, default
   only what a producer emits. =services= are processes, not masks. Hallucinators only.
8. *=hallucinators= defaults to =[]=.* So =daemon.hallucinators.filter(alive)= is total and the recipe
   may omit the key entirely.
9. *=Client.statics.serve= is optional.* Six recipes declare a =ghost= client with empty statics
   (measured: every instance + education recipe). =Runtime= and =Service= =serve= are required — a runtime or
   service without an address is a fault, not a warning.
10. *=launch= untouched.* Its =if (!url) warn-and-return= now covers only "no runtime declared at all"
    (still legal: =Instance.runtime= is optional). A declared runtime without =serve= is a fault and never
    reaches it. Minimal delta.
11. *Doctor keeps row-shaped =problems=; =faults= and =dormant= land beside it.* Init.jsx and the ghost
    Effect renderer read rows; a fault is a sentence. Two keys, no reshaping of the env table.
12. *A blank address shows twice at the doctor* — key row =REQUIRED= (env schema) and fault
    =runtime/statics/serve: must match pattern …= (instance schematic). Two schemas, two true sentences.
    Dedupe by matching the fault path to a recorded =at= is a 3-line join (array index formats differ:
    =/hallucinators/0/= vs =[0]=) — fork F1, not now.
13. *No =${KEY}= references in recipes.* The thunk =() => paladin.env.get("X")= only names a key once the
    schematic types the leaf; the env schema already names keys as ="${VIVA_RUNTIME_ORIGIN}/"=. Unifying
    the two registers would turn a recipe into pure data (recording proxy → regex). beef did not ask;
    flag-day over every recipe + hydrate; deferred with its trigger.

    scope: { instance: HOME, mountpoint: new Path("/mountpoint") },
    state: { dir: async () => {} },

  };
