* the laws the research settled (carry into every tool built here)

- tools are a CONTRACT with a non-deterministic caller, not an API wrapper. Fewer,
  higher-leverage; ≤8 params; enums + defaults in the SCHEMA, not the prose.
- response shaping is the biggest lever: agent-facing projection (our card: 104 B vs
  610 B full = 5.9×), row caps + offset paging, ~10 kB byte budget with a steering
  truncation message.
- error strings are prompts: name the fix in the message ("unknown entity 'litreal' —
  this daemon has: …"). Errors STAY in context (yield-lexicon dispatch already does this).
- progressive disclosure: operator/column prose lives behind an introspection tool
  (entity_schema), never in always-loaded valences.
- definitions cost before anything runs: 3 MCP servers ≈ 143k/200k window; deferred
  definitions save 20–40%; masking beats removal (cache).
- keep the prefix stable (10× cache price); recitation beats memory for long loops.
