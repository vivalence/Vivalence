#+TITLE: Viva Install — product distribution channels
#+AUTHOR: Vivalence
#+DATE: 2026-05-25
#+STATUS: DESIGN

* Intent

Ship =viva= (the ghost CLI) as an installable product, not just a
repo-linked dev tool. Two end-user channels:

1. *JSR* — ~deno install -g jsr:@vivalence/ghost~
2. *curl bootstrapper* — ~curl https://viva.sh/install | sh~

Both converge on the same machine anchor: =${XDG_CONFIG_HOME:-~/.config}/viva/env=.
The launcher delivery swaps per channel; the env-file anchor is the
durable through-line.

* Why

| Problem                                              | Channel answer                                  |
|------------------------------------------------------+-------------------------------------------------|
| dev install is repo-symlink — end users have no repo | JSR-managed launcher / fetched binary           |
| no canonical "get viva" one-liner                    | ~deno install -g jsr:~ or ~curl … \| sh~         |
| machine config scattered                             | single ~$XDG_CONFIG_HOME/viva/env~ both channels write |
| no uninstall                                         | ~viva uninstall~ / bootstrapper ~--uninstall~    |

* The through-line — env-file anchor (already built)

Shipped for the dev channel today (=systems/ghost/install.sh= +
=ghost.sh= sources =$XDG_CONFIG_HOME/viva/env=). The product channels
reuse it verbatim:

- =~/.config/viva/env= holds ~export VIVA_REPOSITORY_MOUNT~ (+ later
  ~VIVA_SYSTEM_MOUNT~, role, mode, licence). Upserted, one source of truth.
- launcher sources it, then runs ghost.
- *only the launcher origin differs per channel.* repo-symlink (dev) →
  jsr-managed (JSR) → fetched script (curl). Anchor unchanged.

* Channels

** Dev (DONE — baseline, not a product channel)
- ~deno task viva/install~ → =install.sh= writes env + symlinks
  =ghost.sh= into =~/.deno/bin/viva=.
- repo = source of truth; launcher generic; edits live.

** M1 — JSR: =deno install -g jsr:@vivalence/ghost=
- Requires the publish track green (per-member publish, workspace intact).
- BLOCKERS (from publish dry-run):
  - =typology/entities/**= 72 TS errors (DataEntity stale vs mikro v6).
  - spawn pipeline ~deno task --config <repo>~ → must become ~jsr:~
    specifiers (ghost spawns runtime/kajuit as modules, not repo paths).
  - =import.meta.url= repo offset dies post-publish → ~VIVA_REPOSITORY_MOUNT~
    must be explicit (env-file already supplies it).
- Post-publish: ~$REPOSITORY_MOUNT~ becomes the package cache, not a checkout;
  code = jsr graph. variants stay user-side, registry stays marketplace.

** M2 — curl bootstrapper: =curl https://viva.sh/install | sh=
- Hosted shell script that:
  1. resolves deno (install deno if absent, or require it),
  2. ~deno install -g jsr:@vivalence/ghost~ (delegates to M1) OR fetches a
     compiled binary,
  3. writes =$XDG_CONFIG_HOME/viva/env= (no repo mount — code is the package),
  4. ensures deno bin dir on PATH (warn/append).
- Mirrors rustup / deno's own installer.
- Depends on M1 (jsr published) unless shipping a compiled binary.

** M3 — robustness + lifecycle
- ~viva uninstall~ (rm launcher + env) and bootstrapper ~--uninstall~.
- resolve deno bin dir (~$DENO_INSTALL_ROOT/bin~) instead of hardcoded
  =~/.deno/bin=.
- PATH check + guidance on install.
- ~viva install~ subcommand (self-update, calls install.sh) — sugar.

* Contract

- *One anchor, many launchers.* Every channel writes the same
  =$XDG_CONFIG_HOME/viva/env=. Never the shell rc.
- *No secrets in env-file.* Bootstrap config only (mounts, role, mode,
  licence). Secrets → variant ~environment/secrets.jsonc~ or keychain.
- *Variant-free install.* No default variant baked (orb 2026-05-25:121).
- *Absence is information.* Default ~/.viva~ → no ~VIVA_SYSTEM_MOUNT~
  written. Only non-defaults persist.

* Dependencies

- publish track (Q1 self-contained graph DONE; entities-TS + spawn→specifier OPEN).
- =viva-cli= quest (system/init, instance/*) — the commands the installed
  viva runs; orthogonal to *how* it installs.

* Open

- M1 vs M2 ordering: JSR first (M2 delegates to it), or ship a compiled
  binary so curl works pre-publish?
- compiled binary feasible only once spawn pipeline is repo-independent
  (ghost spawns runtime/kajuit) — otherwise binary still needs source.
- domain viva.sh — register + host the bootstrapper.
