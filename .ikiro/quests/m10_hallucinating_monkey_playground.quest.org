* Intent

The hallucinating monkey is the playground's *harness exercise rig* — a mode (or
small family) that demonstrates EVERY way the cortex/harness can be driven, in
isolation from the brazilian domain. The playground (=registry/playground/=,
type =playground=) already proves emit→render→reactivity (=spawner=/=spawned=);
monkey extends it to prove the AI surface: sessions, ephemeral chat, stall
phases, harnessed emitters, tool-driven emission, plain tools.

Born from the Riddler (=registry/modes/@vivalence/game/riddler/=) — same
HARNESSED mechanics, renamed =monkey=, lifted into the rig so the standing
live-cortex test runs controlled. This is a BIG task: six demonstrable axes, not
one port.

* Naming caveat

The cluster slug is =monkey= (=chaosmonkey= is reserved for something else — do
NOT use it here). =monkey= is a MODE slug, NOT a trait: the deprecated
=CHAOSMONKEY= trait (=Mode.ts:25 // deprecated=) is unrelated; live harness
wiring is =HARNESSED= (=systems/runtime/daemon/traits/harnessed.js=). The mode
carries =HARNESSED= et al.; it revives no trait.

* The six axes (the requirements — each a demonstrable slice)

** AXIS 1 · Conversations (sessions) — PERSISTENT turns
The harnessed =/dialogue= branch (=harnessed.js=): loads thread history, creates
a user =turn=, scribes assistant turns back (stream-aware =soma.pour= →
=/turn/close= → =turn.create=). Multi-turn, survives reload.
- Demonstrate: a monkey buffer/app that holds a real session over
  =/harness/dialogue=, turns persisted to =daemon.entities.turn=, history
  replayed on reopen. CONVERSATIONAL trait for the ws session if live-streamed.

** AXIS 2 · Ephemeral in-buffer / in-app conversations — NO turns
The Riddler pattern: the whole exchange lives on =buffer.data.history=, never in
=turn= entities. Turn-free =/assistant/message=.
- Demonstrate: a buffer whose chat is purely =data.history= (append on each
  judge), dies with the buffer. Contrast AXIS 1 side-by-side — same harness,
  persistence on vs off.

** AXIS 3 · Stall phases (inert / manual)
The Stall (=prototypes/stall.js=, terminal cursor) reacts per phase:
- =inert= — does nothing; deliberate null =active= respected; app self-manages.
- =manual= — auto-focus + advance-on-release; the app drives pulls.
- Demonstrate: monkey buffers that run under INERT (app owns its own
  render, no cursor advance) AND under MANUAL (resolve → advance to next
  buffer). The app/buffer shows it cooperating with each phase. (Drivers set
  =thread.phase=; the buffer calls =buffer.release()=.)

** AXIS 4 · Emitter uses the harness
Riddler =/riddle/cast=: the emitter calls =ctx.mode.harness.object.render(...)=
to GENERATE buffer content (riddle + flow + chosen literals), then
=ctx.pool.add(ctx.mode.buffer({...}))=.
- Demonstrate: an emitter nature that hallucinates its payload before casting
  the buffer — harness inside the emit path, AIMED-pulled.

** AXIS 5 · Buffer emission via TOOL use
A tool whose effect spawns a buffer — the agentic loop calls a tool, the tool
adds to =ctx.pool= / casts via =ctx.mode.buffer=. Emission triggered by the
model's tool call, not a direct emitter pull.
- Demonstrate: during a dialogue/object run, the model invokes a tool
  (e.g. =/spawn/challenge=) that emits a fresh buffer into the thread.

** AXIS 6 · General tool use
Plain TOOLED tools the harness loops over (=shape.agentic(cortex.tools)= +
=hallucination.absorb=) — return data, no emission. Riddler's
=/literal/review= · =/literal/search= are the template.
- Demonstrate: a tool round-trip (model calls tool → result → final answer)
  with no side effects, proving the agentic protocol end-to-end.

* Structure (open — one mode vs a family)

Two shapes to pick between:
- *One monkey mode*, six axes via distinct natures/buffer variants (denser,
  one manifest, shared harness).
- *A small playground family* (=monkey/session=, =.../ephemeral=,
  =.../tooler= …), each isolating one axis (clearer demos, more files).
Lean: one mode, axes as aperture/emitter/tool natures + buffer flags — mirrors
how =spawner= is one hub. Confirm.

* Open questions (decide before go)

- *structure*: single mode vs family (above).
- *literal coupling*: Riddler grounds in the brazilian corpus
  (=literal.feed/find= + memory strength + trace). Does the playground daemon
  mount a literal repo, ship a tiny self-contained set, or drop grounding to
  pure-prompt? Forks AXIS 4/5/6's tool surface.
- *cortex on playground daemon*: HARNESSED throws without =daemon.cortex=.
  Confirm the playground variant resolves a hallucinator service.
- *AXIS 1 session transport*: SSE stream via CONVERSATIONAL, or render-only
  turns? (Affects whether the ws session machinery is in scope.)
- *stall driver*: who flips =thread.phase= inert↔manual in the rig — a panel
  control, or the monkey app itself?
