* the deep changes — v6 → v7, for the reader arriving cold

1. SQL generation moved inside mikro. v6 handed table changes to knex; knex's sqlite compiler held both our bugs (the glued pragma, the FK on =column[0]= of a string). v7 writes every statement itself as an array item and uses kysely only as the runner — /"Kysely is now used as the query runner, while the actual query building is done entirely by MikroORM itself"/ (release blog). The glue cannot recur.
2. The driver is yours to choose, and =sqlite3= is gone. =@mikro-orm/sqlite= = better-sqlite3 (loud on a multi-statement string); =@mikro-orm/sql= + =NodeSqliteDialect= = =node:sqlite= (silent, the same failure class as today's bug); libsql · sql.js beside them. =driverOptions= takes a Kysely dialect straight.
3. Entities are identified by their class, not by name strings. =getAll()= is a =Map<class, meta>=; =entity: "Name"= throws at discovery; a repository's =entityName= is the class; =prop.pivotEntity= and =meta.extends= are objects. Our =Datamap= and the strip iterate =getAll()= as a plain object and would come back EMPTY, silently. A class-name STRING still resolves through =get= · =find= (=core/metadata/MetadataStorage.js:87-98=, smoke 10-05); only =has("Name")= turned false.
4. Rules are declared, never inferred. No FK =on update=/=on delete= or nullability from =cascade=; =validate= and =strict= always on; auto-flush before a query checks only =persist=ed entities. Every v6-built db carries the implied =on update cascade=; v7's first comparison rebuilds those tables unless the rule is declared.
5. Defaults flipped: =processOnCreateHooksEarly= true (ids and timestamps at =em.create=, not flush — =BufferRepository.create= orders queries before the mint, =Buffer.ts:23=); =forceUtcTimezone= true — inert here: our dates are INTEGER epoch ms on disk (10-05); =loadStrategy= =balanced= (ours already).
6. The migrator is built in (umzug gone), the words changed (=orm.migrator= · =checkSchema= · =create= · =getPending= · =up=; =orm.schema= · =create= · =refresh=), the snapshot normalized; =checkSchema()= diffs the snapshot FILE, not the live db; a v6 history table and snapshot read fine. =transactional: false= stays a law on sqlite.
7. ESM-only, Node 22.17+, on JSR too (untested here). =emit: "js"= migrations are still CJS and fail under Deno — ours are =.ts= (ESM) already.

* the law

#+BEGIN_EXAMPLE
mikro owns the schema; we own the rows. Never a hand-written migration, never a hand-edited snapshot.
migrations.transactional stays false on sqlite: pragma foreign_keys is a no-op inside a transaction, a rebuild inside one violates its own FKs.
a populated sqlite db meets a schema delta ONLY through a migrator that splits statements — until mikro-7 lands, no populated instance boots on 6.6.7 after an entity edit; the delta waits or goes road A (capture first).
a pivot's name and columns are DECLARED on the owner, never derived from a naming strategy's current mood; a raw SQL string may name a pivot only because the owner declares that name.
every m:1 declares nullable · updateRule · deleteRule; a rule that is not written is not a rule.
a driver that runs one statement of two and says nothing is refused; the driver throws or runs all.
metadata is walked as a Map of classes; a repository knows its class, never its class's name.
the first v7 boot of a populated db is preceded by its dry diff on a copy, and the diff is the expected set or the boot does not happen.
#+END_EXAMPLE
