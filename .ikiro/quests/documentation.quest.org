* per-file specs (brief)

** /docs/README.md
Front door. Reader-type decision tree (newcomer → 01; structural reader → 03; doer → how-to; orienter → tour; planner → roadmap).

** /docs/01-context.md
C4 L1. What vivalence IS (paraphrase from =/readme.org= vision excerpts). What's OUTSIDE: Deno, browser/iOS Safari, Anthropic, Deepgram, ElevenLabs, jj, the learner. Names primitives once canonically (daemon, mode, literal, symbol, trait).

** /docs/02-containers.md
C4 L2. Narrative + diagram listing 7 containers with one-line role + link to each =03-containers/<name>.md=. Same shape as root =.ikiro/CLAUDE.md `system map`= but framed for first-time reader.

** /docs/03-containers/<name>.md
C4 L3. Each opens with the container's canonical aphorism (lifted from its ikiro). Paraphrases ikiro's architecture section for outsiders. Ends with =deeper:= link to the ikiro itself.

Container-specific cross-links:
- =typology.md= → =explanation/channel-grammar.md=
- =paladin.md= → =explanation/manifest-contract.md=
- =runtime.md= → =explanation/lifecycle.md= + =explanation/trait-arc.md=
- =kajuit.md= → ship metaphor in =explanation/language-map.md=
- =ghost.md= → states "design-only, see =systems/ghost/README.org="

** /docs/03-containers/registry/*.md
Five files because registry has 4 internal kinds (kernels/modes/services/wafers) + a README index. Each kind has its own grammar; flat single file would conflate.
