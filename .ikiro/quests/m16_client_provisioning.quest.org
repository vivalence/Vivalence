** Doctrine (CANONICAL)

One grammar, two trees. The server composes capabilities down a vector
via ctx; the DOM composes contexts down the tree via setContext.
=+layout.svelte= is the daemon.js of the DOM — the composition root.

Three kinds, one law each:

- *structures* (=src/typology=) — pure reactive state + verbs: atoms,
  entities, stores, reactors (Stall). NEVER import the world: no fetch,
  no localStorage, no console, no AudioContext.
- *effects* — observe structures, touch the world, ALWAYS return
  teardown. The ONLY home of IO. Mount at the DOM scope that provides
  their subject's context; live exactly as long as that scope.
- *surfaces* — render structures, call verbs. Consume contexts, may
  provide narrower ones below.

Laws:
1. purity boundary is greppable:
   =rg "localStorage|fetch\(|console\.|AudioContext" src/typology= → zero.
2. one provider per context; effects mount at the provider. Collection
   effects at the collection's scope, member effects at the member's.
3. entities receive capabilities (connections, pipes, storage handles),
   never construct them — seed/ctx above, Svelte context below.
4. derive near the structure (Stall is the exemplar), sync at the effect
   (=stall.on.release → removeOne= is an effect, not entity code).
5. one loop: surface verb → atoms → effects → world → SSE/response →
   repo merge → atoms → surface. Never sideways.
6. one observability egress: the telemetry pipe. Console, panel G,
   anything else = drains on it.

The provisioning tree narrows, mirroring entity flow
(Mode → Thread → Buffer → Turn):

** The three bleeds (found, this session)

1. =stores/terminals.js= — =rehydrate(terminals, lighthouse)= +
   =arm()=: storage+network effect inside a structure, cross-deck reach,
   chain-subscribes terminal internals. THE bug: a thrown =findOne=
   killed the whole rehydrate (session loss); an inert daemon made
   =restore= return null → =arm= → =write= serialized =thread:null= →
   localStorage overwritten (permanent loss). Fault and absence
   conflated.
2. =typology/logger.js= =narrate= — console effect, correctly app-layer,
   but unowned (beef: =//@beef this is shit:= on the mount).
3. =entities/daemon/dossier.js= — daemon BOOT (connect, manifest,
   dataspace, SSE subscribe, status stamping) inside entity CAST
   middleware. Consequences: half-built daemons (entities assigned, finds
   failed, status lies), no mid-session probe/re-boot, status stamped in
   try/catch instead of derived, daemon constructs its own connection.

#+begin_src svelte
<script>
  const pipe = telemetry();
  const connection = new Connection(
    new Url(env.PUBLIC_VIVA_LIGHTHOUSE_REMOTE),
    shard.transmitter.retry(shard.transmitter.fetcher, { maxRetries: 2 }),
  ).use(shard.track.span((call) => call.request.url.pathname, pipe));

  const lighthouse = new stores.lighthouse.Lighthouse(connection, { telemetry: pipe });
  const terminals = new stores.terminals.Terminals();
  const bridge = new stores.bridge.Bridge();

  setContext(LIGHTHOUSE, lighthouse);
  setContext(TERMINALS, terminals);
  setContext(BRIDGE, bridge);

  onMount(() =>
    effects.mount({ lighthouse, terminals, bridge, pipe }, [
      effects.lighthouse.hydrate,
      effects.lighthouse.persist,
      effects.daemons.lifecycle,
      effects.terminals.hydrate,
      effects.terminals.persist,
      effects.terminals.settle,
      effects.narrate,
    ]),
  );
</script>

{@render children()}
#+end_src

Carrier: effect-closure (beef's *"bypass this variable entirely"* — the

NEW =src/effects/terminals.js= (placement fork open, see Forks):

- =hydrate({ terminals })= — storage → plain =Terminal({ id })= shells,
  published immediately; unresolved wire ids →
  =serialized: Map<terminal.id, { thread, buffer }>= in module closure.
- =persist({ terminals })= — chain-subscribe set + each terminal's
  =$thread=/=$buffer= (re-arm on set change); write =
  ={ ...terminal.toJSON(), ...serialized.get(terminal.id) }= — total,
  outage-safe, no freeze. Returns teardown (old =arm()= leaked).
- =settle({ terminals, lighthouse })= — reactive over =$daemons= + each
  =daemon.status.$transient=. Tri-state per ref: entity → assign atom +
  delete key · ABSENT (a reachable daemon answered null everywhere) →
  delete key (true deletion) · UNREACHABLE (any fault) → keep, retry on
  next status flip. Occupied-atom rule: navigation during outage beats a
  late resolve. Buffer resolves only after thread settled (thread setter
  clears =$buffer=). Inflight promise memo + queued re-pass flag.

*** Subscription ownership (A + B, beef: "i want both a and b" — lands here)

Root constraint (fork 6, RESOLVED): browser HTTP/1.1 pools cap at 6
connections per host:port, shared across ALL tabs of the profile.
Boot's 3 daemons × 2 SSE subscribes = exactly 6 → every later fetch to
:2501 queues forever. This was the whole terminals-loss/unclickable-
modes day: never the server.

- *A — multiplexed stream per daemon*: one =/userspace/subscribe= SSE
  carrying thread + buffer (later turn) events tagged by entity.
  Server: userspace.js route + a multi-repo =shard.datamap.reactive=
  variant folding several repos' twitch filters into one stream.
  Client: dataspace-level subscribe dispatching tagged events to the
  owning repository's merge. 3 daemons → 3 streams, 3 slots free.
- *B — lazy subscribe*: a daemon's stream opens only when something
  binds to it (first terminal mounting one of its threads), closes when
  the last consumer leaves. Doctrine-native: the subscription is an
  effect mounted at consumption. Needs an idempotence/refcount guard on
  the subscribe path. With A in place, B decides WHEN a daemon's one
  stream exists → idle daemons cost zero connections.
- Budget invariant to enforce afterward: total live streams per client
  ≤ 4, leaving ≥ 2 slots for request traffic. Multiple kajuit tabs
  still share one pool — the invariant is per PROFILE, not per tab.
- C-interim REVERTED same session — beef: *"actually i want that
  subscription. lets instead simplify the daemons. we have chaosmonkey
  in playground. its fine."* Interim is now daemon simplification:
  chaosmonkey daemon retired from =testament/variant/test.viva.js=
  (its bystander/oracle modes already ride the playground kernel) →
  2 daemons × 2 SSE = 4 streams, invariant met before A even lands.
  Both subscriptions live. Leftover: chaosmonkey row in
  =lighthouse.viva.db= needs a =removeOne= prune after the runtime
  restarts on the new variant (else the client boots an inert dossier
  against a dead URL every session).
