* the law

- a client is a HOST like the runtime and a daemon: =reference= =/client/<slug>=, =mountpoint= =<scope>/client_<slug>=, =modes= seated by =ground= as =/mode/<type>/<slug>= under it, loaded through the one =registry.wire(mask)=. Paladin writes all of it; the recipe says only =modes=.
- paladin never enters the client typology: the DOOR wires (ghost: =lifecycle/shell.js= =ground()=; anima: =vite.config.mjs= at build), the lifecycle receives =die.register= — the runtime's own word (=die.runtime.register=).
- =HOME.reference= is ABSOLUTE (his ruling 10-14: /"HOME.reference - absolute."/): a hosted mode =/client/ghost/mode/home/home= or a host mode =/runtime/runtime/mode/home/home= — one grammar, the reference says which host owns it. A hosted =Mode= on the client carries the absolute reference the way a remote one does (=ModeDossier=: =host.reference ⊕ /mode/<type>/<slug>=).
- HOME enters EVERY new terminal, not the first only (/"home sets mode on new terminals. incl thread."/): a hosted home sets =terminal.$mode=; a host home creates its thread and seats it — the thread then carries the mode. Both in the terminal lifecycle, on =client.$home=.
- =terminal.$mode= is an atom the terminal lifecycle sets: the thread's mode when seated, the client's HOME otherwise. =terminal.mode= reads it; nothing else derives it.
- NOTHING is rebuilt (his 10-14: /"we dont rebuild the modes on repl change. terminal.repl is a function of terminal.mode/daemon,client.repl."/): =terminal.repl(base)= RETURNS the verb vectors in precedence — =[mode.repl, base]= when the seated mode carries one, =[base]= otherwise. A line resolves by =steer.dispatch.traverse= over that list, first hit wins (=gestalten/steer/dispatch.js:16=, a miss returns =[null, …]=); the client's =*= (a bare line → =turn/send=) sits last, so it never shadows a mode's verb. No =$repl= atom, no graft, no copy — the mode's Vector stays the mode's.
- the repl's EXECUTION is a PIPE, not a trie of verbs: =lifecycle/repl.js= keeps only the =(ctx, next)= middlewares (capturing · helping · streaming · killing · painting) and its ROOT EFFECT resolves =ctx.signal= over =ctx.repl= (the list) — the root effect as the answer to an empty signal, the connoisseur's law. The verbs it grafts today (=runtime · entity · dock · key · quit · help · doctor · reports · records · yap=) move onto =client.repl= where they belong. His three m86 questions: rebuild — no, a function · the verb source — the mode's =repl= (was =repling=, m96 ruling 7) export · flat — yes, by precedence not by merge.
- =REPLING= travels with =repl= (was =repling=, m96 ruling 7) (a Vector). The trait mints the live Vector and grafts the declaration — never =.use()= on =mode.module.repl= (=connoisseur.md=, the harnessed canon).
- a trait catalog is picked at the SEAT, the runtime's way (=systems/runtime/lifecycle/runtime/population.js:131=): a hosted mode staggers over ={ REPLING }=, a remote mode over the five wire traits. One trait file, one stagger, two seats.

** the law

1. The runtime PULLS; the client never pushes its repl. Every harness call from a terminal pulls =/terminal/<id>/metadata/repl= over the socket the call arrived on. No socket state, no hash, no change ping.
2. The strip is the declaration, the Signal is the call. A looped tool's input schema is =Call = { body, flags }=; its name is the route under =/repl= (=repl_mode_console_hello=); its valence is the verb's.
3. A capability is a trait on the MODE, on both catalogs. Runtime =LOOPING= mints =mode.looping(ctx)=, ONE slot the tools beat reads beside =ctx.mode.tools=. Ghost =LOOPING= grafts the two routes onto =client.aperture= once.
4. The client has ONE aperture, handed to its multiplex. What the runtime may call on the client is a route on it, as what the client may call on the runtime is a route on =die.aperture=.
5. The harness request is a schematic: =v.primitives.harness.Request= — =thread · terminal · turn · parts · tune · config · system · output · tools=. A terminal ALWAYS sends =terminal=.
6. The tool result is the verb's =output=.
