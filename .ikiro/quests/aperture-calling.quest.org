* Intent — desired end state in plain language

=.call= today is two unrelated things wearing one name. The daemon's EXPOSED trait
compiles =mode.call = shape.object(mode.aperture)= — a dot-navigable object, and the
runtime tests already speak it (=mode.call.assistant.wakeup.statistics=). The client
binds =entity.call = entity.connection.call.bind(entity.connection)= — a string-path
function, self-annotated =@beef legacy. to be repurposed for full aperture stripwire.=
Same spelling, different calling convention across the wire: worse than two names.

End state: =.call= IS the compiled aperture on both sides — same spelling, same calling
convention, different backing, exactly the EMITTER⟷emit stripwire law. Raw string-path
transport is only ever spelled =entity.connection.call(path, body)= — dot-notation
provenance, no aliases, no squatters. The aperture joins emitter and harness as the
third (and largest) stripwire surface; streaming leaves and route params ride the same
compile instead of being carve-outs.

* The model — pinned laws

- **=.call= = the compiled aperture, both sides.** Daemon: fold of the live Vector.
  Client: wire over the =/metadata/aperture= strip — which is ALREADY SERVED at both
  levels (=systems/runtime/daemon/aperture/metadata.js:9= daemon root,
  =:26= per mode). No new metadata plumbing; the strip source exists.

- **Raw transport is explicit.** Every string-path call is
  =entity.connection.call(path, body)=. The three bind-aliases die
  (kajuit =mode.js:47=, kajuit =daemon/dossier.js:60=, runtime
  =lifecycle/population.js:93=). Nothing else may alias =connection.call= onto an
  entity — the name belongs to the compiler now.

- **Dot-notation is the MODE surface, never kajuit's — guaranteed at the buffer
  boundary.** Beef: "nowhere in kajuit do we use this dot notation pattern! we only
  use connection directly. the dot notation pattern is purely for the modes! we
  guarantee it at the buffer boundry!!! except of course testing!!" — kajuit COMPILES
  =daemon.call= / =mode.call= (that compilation is the buffer-boundary guarantee it
  hands to mounted buffer views) but kajuit's own code (dossiers, decks, panels,
  stores) consumes =connection= directly, always. Consumers of dot-nav = registry
  buffer views + tests. Sibling of the buffer-bundle law (views import only
  @vivalence/typology): the boundary provisions, the shell abstains.

- **Shape compilers are folds over the trie via steer primitives — no Pattern
  internals.** The callout: =matchChild= in
  =subsystems/typology/gestalten/shape/object.js= re-implements segment matching by
  discriminating =pattern.type === "literal"/"parameter"/"wildcard"/"remainder"= and
  scraping params with =pattern.nature.slice(1)= — shape reaching into Pattern's guts,
  duplicating what =pattern.apply(signal)= / =steer.match.scope= / =fromm.match(steps)=
  already own canonically. The rebuilt proxy asks the pattern to match
  (=pattern.apply=) and asks =fromm.match= for parameters; it never inspects pattern
  type or slices natures. =matchChild= / =wrap= / =proxyRemainder= die as written; the
  existing proxy-shape suite in
  =subsystems/typology/tests/gestalten/shape/object.test.js= is the spec and stays
  green.

- **Streaming is an edge fact, and the whole architecture is one edge fact projected
  four ways.** The edge (pattern) already carries =input=, =output=, =valence=, =keyed=.
  A leaf that yields packets over time declares =yields= (schema of one packet) instead
  of =output= (schema of the one value). Projections:
  - =shape.http= — keeps its runtime auto-framing (async-iterator body → SSE,
    =gestalten/shape/http.js:39-44=). The edge fact is the compile-time dual of that
    runtime detection; server behavior unchanged.
  - local fold (=shape.object= / =shape.proxy=) — nothing to do: the effect returns an
    async iterator and it passes through untouched.
  - remote wire — a =yields=-leaf compiles to a =connection.stream= adapter instead of
    =connection.aim=. Same caller spelling both sides:
    =for await (const packet of mode.call.assistant.stream({...}))=.
  - =shape.agentic= / =shape.mcp= — may document yields like they document valence.
  One fact, four projections: that is how the right solution falls out naturally
  instead of streaming being a special case bolted onto the wire.

- **Methods are the Aperture's own leaf fold.** =Aperture._route= stores handlers on
  the effect dispatcher (=fn.methods=, =prototypes/aperture.js:32-41=). Today
  =steer.strategy.request= builds ctx with no =request.method=, so a =.post()=-only
  leaf 405s even under the local object compile — latent breakage. Law: method
  discrimination only discriminates when ambiguous.
  - =strip= plucks =methods: Object.keys(effect.methods)= onto the leaf (pluck gains
    access to the effect in the fold — today it sees only the edge pattern).
  - single handler (one method, or ="*"=) → transparent callable. Local: =methods()=
    falls back to the sole handler when =ctx.request.method= is undefined. Remote:
    wire sends that one method.
  - multi-method leaf → see OPEN fork 1.
