* the answer in English

The =Deno.*= calls are the cheap part. 153 live in the repo's production code and 67 in the registry's, almost all fs · env · process, and each has a =node:*= twin that Deno 2 and Bun both implement. Rewriting them is mechanical.

The real cost is three things Deno does that Node does not. First, a process-global import map: registry code at =~/.viva/registry= has no node_modules of its own and still resolves the repo's names, because Deno applies =import_map.json= to every module in the process. Second, loading =.ts= and =.jsx= on the fly: typology's front door is =mod.ts=. Third, the =npm:= · =jsr:= · =https:= specifiers. The first one is solved by one =package.json= and one link under the ledger, which held on Node and Deno today. The second means turning 51 =.ts= and 27 =.jsx= files into =.js=. The third means moving 130 import-map entries and 17 esm.sh lines into package.json.

After that, two seams per host remain: serve with websocket upgrade, and spawning itself. Then the toolchain: tasks, specimen, Dockerfiles, CI, and 73 lines of canon that name Deno.

A move to Node alone pays nearly every one of these costs and ends coupled to Node. Making vivalence host-agnostic adds per-host branches in the two seams plus a CI matrix, and it ends the question. "Entirely independent" means a =viva= binary that runs on a machine with no JS runtime installed. That is a compile step over host-agnostic source, not a different road.

* in depth

** what Deno does that Node does not — the real cost

1. *The process-global import map.* Deno applies =import_map.json= to every module the process loads. That is how 339 registry files import =@vivalence/*= (plus =svelte= 36 · =@mikro-orm/core= 18 · =three= 7) with zero =node_modules= under =~/.viva/registry=. Node and Bun resolve differently: they walk up from the importing file's own directory. The probe below gives every host the same answer, using no loader hooks:

#+begin_example
probe-walk/
  repo/
    package.json                      { "type": "module" }
    typology/package.json             { "name": "@vivalence/typology", "exports": { ".": "./mod.js", "./specimen": "./specimen.js" } }
    typology/mod.js                   imports "@vivalence/typology/specimen" (self-reference)
    node_modules/@vivalence/typology → ../../typology
    node_modules/typebox             → <repo>/node_modules/typebox
    runtime/run.js                    imports "@vivalence/typology", then import(<registry mode>)
  ledger/
    package.json                      { "type": "module" }
    node_modules                     → ../repo/node_modules
    registry/chess/mode.js            imports "@vivalence/typology" + "typebox"
#+end_example

#+begin_example
node:  self-reference ok | …/repo/typology/mod.js | object      one instance: true
deno:  self-reference ok | …/repo/typology/mod.js | object      one instance: true
no ledger package.json →  node: "To load an ES module, set "type": "module""   deno: Import "typebox" not a dependency
#+end_example

Resolution follows the realpath, so the registry and the runtime share one typology. Both the ledger's =package.json= and its =node_modules= are load-bearing.

2. *=.ts= and =.jsx= at load time.* =subsystems/typology/mod.ts= is 12 lines with zero type syntax. Its line 12 is =export * from "./types.d.ts"=, a declaration file imported at runtime. Node 20 refuses the extension. Node's newer type stripping is said to reject =enum=, which is unmeasured here because Node 24 is not installed. There are 9 live =enum= declarations in 8 repo files, plus 6 registry files. No Node version runs JSX. Deno transpiles it because root =deno.jsonc= sets =compilerOptions.jsx: "react"=.

3. *Specifier schemes.* =jsr:= covers 36 map entries (=@std/*= · =@cliffy/*= · =@oak/*= · =@cross/*=). =npm:= covers 94 entries plus 7 inline lines. =https:= is chess only. Two canon laws exist only because of these schemes. The first is =world/map.md:18=: Deno cannot prefix-map into =npm:=. The second is the package law in the same bullet: /"A registry package adds nothing to the repo's import_map.json and imports by URL"/ (=~/.viva/registry/chess/topographies/puzzles/harvest.js:12=):

** F0 — the word

"runtime" is already taken: =systems/runtime=, the =Runtime= prototype (=systems/runtime/run.js:12=), =die.runtime=. In beef's sentence, "runtime independent" means the JS engine underneath.

1. *host* — Deno · Node · Bun are hosts. It joins the spirit family: a ghost, a daemon, an anima inhabit a host.
2. *engine* — the plain technical word.
3. keep "runtime" and carry the double meaning.

Lean: 1. This quest says "host" provisionally.

** F1 — which independence

1. *Node* — swap one vendor for another.
2. *host-agnostic* — one source runs on Deno · Node · Bun, and a CI matrix proves it.
3. *entirely independent* — option 2, plus =viva= ships as a single executable, so a machine with no JS runtime runs it.

Lean: 2 now, 3 as the last milestone. Option 1 pays the same resolution, transpile, specifier, seam and toolchain costs as 2, and still ends coupled to one vendor. Option 2 adds per-host branches in two seams and a matrix. Option 3 compiles source that option 2 has already made neutral, and any host's compiler can do that.

** F2 — the registry's import law

Today a package /"imports by URL"/ (=world/map.md:18=). Node and Bun load no =https:= module.

1. A package declares its own deps in a =package.json=, and =paladin.ledger.registry.tap= (=subsystems/paladin/prototypes/ledger/registry.js:145=) installs them into =<package>/node_modules=. Shared names (=@vivalence/*= · =svelte= · =@mikro-orm/core=) resolve upward to =<ledger>/node_modules=. This gives one resolution law on every host.
2. Tap vendors each URL module into the package, pinned by hash. No network at boot.
3. URL imports stay, and each host gets a loader hook that fetches them (Node =module.register=, Bun =Bun.plugin=).

Lean: 1. The probe already proved its upper half on two hosts. Option 3 re-implements Deno's loader twice. Option 2 invents a vendoring format.

Hazard: a shared name declared as a regular dependency installs a second copy, and the result is two svelte instances. Shared names must be peers, installed without peers. That is unmeasured and is an M0 row.

* decisions — mine

1. *Staging.* Deno stays green at every milestone. Each milestone adds a host to what passes and never swaps one out. REJECTED: a flag day — /"unreliable at large scales"/ (=self.md=).
2. *The dialect.* Commodity calls use =node:*= builtins and web standards. REJECTED: a vivalence wrapper over fs — Deno 2 and Bun already implement =node:fs=, so a wrapper would be a second API for the same call.
3. *No new module for the seams.* serve + upgrade lives where the upgrade already lives (=subsystems/typology/gestalten/shard/serve.js=). spawn-self lives in ghost, the only self-spawner (paladin's =skills/shell.js= spawns the user's shell and =belt/clone.js= spawns git; neither spawns itself). watch is a script line. REJECTED: a =host= subsystem — it would carry two functions.
4. *Resolution* is package.json + node_modules: a root =package.json= (workspaces + deps) and one per member (=name= · =exports= · =type=). Deno 2 reads both. =import_map.json= and =deport_map.jsonc= are deleted at M1's end, and the duplicate =@cliffy= keys die with them.
5. *=.ts= → =.js=.* An =enum= becomes an =Object.freeze= table. =mod.ts= becomes =mod.js=, and =types.d.ts= leaves the runtime graph.
6. *specimen stays the one test door.* It is backed by =node:test=, which held on Node and Deno. The 28 =Deno.test= files and 17 direct =@std/testing/bdd= files route through it. specimen sits in typology's PROD barrel (=subsystems/typology/mod.ts:10= =export * as specimen=), so every runtime import already loads the test harness. That makes its backing a production concern, not just a test one.
7. *Order against live quests.* =m78-mikro-7= rewrites the mikro layer that the =.ts= entities sit on, so it lands before M2 touches them. =runtime-testing-recast='s census (=HOME= set to an empty dir) is M5's baseline.

* the law

Proposed end state, to be ratified when this leaves roadmap/:

1. A vivalence source file runs unchanged on every supported host. No file outside the two seams names a host (=Deno.= · =Bun.=).
2. There is one resolution: package.json + node_modules — the repo's workspaces, plus the ledger's =package.json= and =node_modules=. No import map, and no =npm:= · =jsr:= · =https:= specifier.
3. Nothing transpiles at load. Server-side source is =.js=; =.svelte= stays bundler-owned.
4. A suite is green when it is green on every host in the matrix. Counts are stated per host: =node --test= counts leaves, =deno test= counts tests + steps (probe: =tests 2= vs =1 passed (3 steps)=).
5. A child process runs on the host that runs its parent.
