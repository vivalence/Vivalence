* terrain — what is broken or missing
1. *verbatim is mis-plumbed through the dialogue machinery.* =Hallucination.streaming("verbatim")= lowers the request into a hallucination record (=turns=, =tools=, =cache=) and runs it through =shard.hallucinate.respond= — the tool loop, which =soma.pour=s every packet into a turn. verbatim events (={nature: "partial"}=) are not turn packets; pour will choke, the tool loop is meaningless for ASR, and the declared =yields: Packet.Response= is a lie. same lie in =HARNESSED=, which passes =ctx.hallucination= (the assembled record) where the faculty wants =(audioSource, config)=.
2. *no =Verbatim= schema family.* the event grammar lives only in the deepgram provider and the spec test, unvalidated.
3. *no harmonizer.* deepgram interim results flicker — each partial replaces the whole utterance text. nothing produces the commit/tail split.
4. *no upstream body decoding.* the daemon handler receives SSE-framed text chunks (=data: {json}\n\n=); nobody parses them back into an audio source.
5. *no encoder.* Microphone emits Float32Array frames; the faculty wants base64 linear16.
6. *no dictation surface in the dock.* no mic affordance, no ghost text, no draft insertion.
7. *=conversation.listen()= drains verbatim events through =drain()=,* which pours them as dialogue turns — wrong consumer for dictation.
8. *=publish= never asks for a stream back.* the multiplex transmitter only hands over the streaming =follow()= body when =accept: text/event-stream= is set (=transmitter.js:80=), and =publish= doesn't set it — a caller today gets exactly one event and a closed frame. =publish= should default the accept header; =listen()= inherits the fix.

* design decisions (settled — argue in review, not mid-build)
*event grammar.* a =Verbatim= schema family beside =Packet= in the primitives, one object per nature + =Verbatim.Any= union — mirroring how =Packet.TurnOpen … Packet.Any= is laid out:

#+begin_example
{ nature: "turn.start" }
{ nature: "commit",  text }
{ nature: "partial", transcript }
{ nature: "final",   transcript, words? }
{ nature: "polish",  transcript }
{ nature: "turn.end", meta? }
#+end_example

=commit= carries only newly-stabilized words (append-only downstream). =partial= carries the full volatile tail (replace downstream). =final= carries the settled full utterance — client reconciles committed+tail against it and takes final as truth. =polish= swap-replaces final's text once the cleanup pass lands. providers need only emit partial/final/turn.*; commit and polish are minted server-side. (=nature= is the established discriminator for faculty event streams — spec test and deepgram provider both use it; =event= stays the discriminator for turn packets. two families, two fields, no mixing.)

*harmonizer runs daemon-side.* it sits between faculty and wire so every client gets the anthropic experience for free and provider quirks stay server-side. pure function, lives in typology so tests need no daemon.

*algorithm: LocalAgreement-2 with similarity tolerance.* the published technique behind the observed behavior — WhisperKit/ufal whisper_streaming: commit the longest common word-prefix of two consecutive hypotheses; everything after is the tail. add per-word Levenshtein tolerance (≥0.8 normalized) so ="vivalance"→"vivalence"= doesn't stall the commit frontier (the SAPrefix refinement). tail capped at 8 words in the partial event; defaults: agreement window 2, tolerance 0.8. that yields the observed 4-5-words-in-flux feel on natural speech.

*verbatim does not pass through the respond loop.* the Hallucination vector gets a dedicated =transcribing(type)= leaf: resolve faculty, call =faculty.via.stream(source, config)= directly, pipe through the harmonizer. no turns, no tools, no pour. same shape later for =speech=.

*wire audio format.* each upstream SSE data line is ={ audio: <base64 linear16 @16k>, pts }= — matches what the deepgram faculty already decodes and what the spec test stubs. chunk cadence ~64ms (1024 samples) from the encoder.

*dictation is a composer feature, not a conversation feature.* dictated text lands in =draft= at the cursor; the user still presses send. no auto-submit in this quest.

*configuration rides the thread, INTELLIGENT-style.* new claim-gated trait =thread.trait.VOCAL=:

#+begin_example
{ language?, tune?, harmonize?: { window?, tolerance?, tail? } }
#+end_example

validated at the harness boundary, projected field-by-field, absent fields mean "the mode decides". harmonizer constants therefore live in one place — the harmonize defaults object — overridable per thread for live tuning without redeploys.

*multilingual by default, code-switching native.* the deepgram faculty defaults to =model=nova-3&language=multi= — real-time code-switching across languages within a single utterance, word-level language tags, =endpointing=100= recommended for switch pauses. =VOCAL.language= pins a monolingual model when set (measurably better on short single-language utterances). the polish pass must be language-preserving: fix punctuation and formatting in whatever languages were spoken, never translate.

*post-final polish pass is in scope (phase 2 folded in).* on =final=, the daemon pipes the settled transcript through a =fast=-tier dialogue faculty for punctuation, capitalization, and inverse text normalization, then emits ={nature: "polish", transcript}= after =final=. client splices =final= immediately (no added latency to the felt experience) and swap-replaces with =polish= when it lands ~300ms later — the same revise-into-coherence gesture the tail already performs. =VOCAL= can disable it (=polish: false=) once that field earns its place.

* forward contracts — speech out, dialogue mode, language learning
decisions that cost pennies now and fortunes to retrofit. binding on this quest.

1. *verbatim streams are multi-turn.* one open frame carries N utterances (=turn.start … turn.end= repeating); the daemon branch and harmonizer key state per turn and never close the stream on =turn.end= — only on upstream close or abort. dictation happens to stop after the first settle; dialogue mode keeps the mic open across the whole session on the same protocol. deepgram's UtteranceEnd already fires mid-stream, so this is also just correct.

2. *the =Speech= family is defined now, unimplemented.* =Speech.Packet= ={nature: "packet", audio, rate, codec, pts, align?}= + =Speech.Close=, matching the spec-test stub. =rate= is mandatory — TTS engines emit 22.05/24/44.1k and the mic context is pinned at 16k; nothing downstream may assume a sample rate. =align= reserves word/char-level timestamps (elevenlabs emits them) — karaoke highlighting and pronunciation feedback for the language tooling hang off this field.

3. *=final= carries words.* =words?: [{word, start, end, confidence, language}]= — deepgram already produces all five per word on =language=multi=; pass them through instead of stripping. costs one spread now; retrofitting timing + per-word language onto stored transcripts later is a migration.

4. *the dictation fold is a pure export.* =verbatim.fold= — the commit/partial/final/polish → ={committed, tail}= reduction — is a standalone belt function consumed by the dictation prototype, not buried in its closure. voice mode reuses the identical fold for live captions; the language tooling reuses it for read-along.

5. *playback path stays rate-parametric.* =AudioDriver.decode(audio, rate)= and the speaker device resample or run a second context; the 16k pin is a mic-capture fact, not an audio-system fact. speaker keeps =flush()= — barge-in interruption in dialogue mode depends on it.

polish stays an /additional/ event after final precisely so dialogue mode can trigger the dialogue faculty off =final= without waiting on it.

** the research, distilled into code
the 2026 meta: multi-signal turn detection (VAD → transcript endpointing → semantic completeness), with deepgram flux collapsing the stack into the ASR itself — a conversational state machine emitting StartOfTurn / Update / EagerEndOfTurn / TurnResumed / EndOfTurn, ~260ms EOT, StartOfTurn guaranteed to carry transcript (the reliable barge trigger). barge-in consensus: transcript-confirmed interruption only, backchannel lexicons, min-word thresholds, interruptibility as per-utterance policy, <60ms flush, word-level truncation of context to what was actually heard.

all of it landed as two pure belt modules:

- *=belt/verbatim.js=* — =harmonize= (LocalAgreement-2 over a hypothesis ring, per-word Levenshtein tolerance so =vivalance→vivalence= doesn't stall the frontier, tail cap, multi-turn reset) and =fold= (the client ={committed, tail}= reduction — dictation, live captions, and read-along all share it).
- *=belt/turn.js=* — =decide= (the arbiter: listen / arm / yield / hold / draft / scrap / respond / confirm, full flux vocabulary, backchannel lexicon en+de, min-word arming, interruptible policy flag), =cursor= (spoken position by align offset or text length), =truncate= (word-boundary cut, =meta.state: "interrupted"=). the voice quest wires these; they ship tested now. /(pass: PARKED under =m33-dictation/deferred/= — out of this quest's stated scope, zero consumers.)/
