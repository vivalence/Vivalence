* the four escape hatches

The request-outliving consumers any solution must answer. ALS law first
(Deno/V8): a store set by =run()= propagates through awaits, promise chains,
and timers/microtasks SCHEDULED inside the scope (init-time capture). It does
NOT follow (a) generator bodies pulled by a foreign frame, (b) callbacks run by
a shared scheduler created elsewhere, (c) coalesced timers reset across
requests (last-scheduler's context wins).

1. *streaming persist* — =traits/harnessed.js:86-131= (ex :60-105; generator :95-118,
   flush :113): the async generator keeps
   creating+flushing turn entities while the client pulls, AFTER the handler
   returned (=shape/http.js:47= publishes the iterator; Deno's writer pumps it).
   ORM fork survives ONLY because inject re-wraps each pull with =carry()=.
   Proven empirically: probe =inside=USER-123 · outside=null · carried=USER-123=
   ([[project_reactive_owner_orm_context]]). Any SECOND ambient store needs its
   own carry pass — or must BE the same store.
2. *debounced datasink drain* — =traits/datasink.js:60-71=: =fn.debounce(…, 1500)=
   (=belt/fn.js:13-21=, raw setTimeout, reset per write). Fires 1500ms after the
   mutating request resolved; the timer's ALS context = whoever called =settle()=
   last, which runs inside the shared detached pump — and N users' writes
   coalesce into ONE timer. No per-request store can answer "whose drain" even
   in principle. Defused today only because datasink REFUSES user-scoped types
   (=datasink.js:12-15=, dataspace-only throw).
3. *pool drain* — =traits/emitter.js:41-51=: delegate promises are created inside
   the request frame (=ctx.pool.add= before flush, [[feedback_emitter_delegation_via_pool]])
   and =drain()= is awaited in-middleware → ORM fork AND any ALS survive.
   The weakest hatch — everything passes it.
4. *reactive broadcast* — =shard/datamap.js:176-195=: =/after= handlers run in the
   detached pump but inside =carry()= captured at flush time →
   =getFilterParams("user")= resolves in EVERY write context, including lazy
   streams; null throws loud (:185-189). The landed decision: owner rides
   ORM-carried filter params, NOT ambient — =shard.ambient.store= was in
   resolution.js and was REMOVED for exactly this hatch ([[project_reactive_owner_orm_context]]:
   "Do NOT reintroduce ambient for owner routing").
