* the law

#+BEGIN_EXAMPLE
A part the kit ships is a literal with qty, whether or not a mesh exists for it; the guide's bill is derived, never authored.
A fastener is a PARAMETRIC part placed once per bolt, its placement carrying JOINED.joins on what it holds and one joint.* symbol; a step names the fastener placements it threads, and "loose" or "tight" is the step's note, not the placement's.
No coordinate is typed from a picture: every fastener translation is a function of a measured anchor (a standoff centre, the grommet pattern, a motor centre) written in the harvest, so a re-import moves them all.
The rows live on disk, in VCS, as the topography's DATASET; the daemon is working memory. DATASET installs them, DATASINK drains every change back; the harvest writes the dataset files ONCE in the drain's own canonical form, so a drain over an untouched install is a no-op diff.
A step's pictures are the manual's pages on the freight (manual/<id>.webp); a step cites the page it came from in its description.
#+END_EXAMPLE

* the loop — fork 7, ruled 10-06

Both halves exist in the runtime; nothing new is invented, the topography declares them. =DATASET= (=systems/runtime/lifecycle/mode/traits/dataset.js=) installs a mode's files into the daemon when the files' stamp differs from =mode.installed=; =DATASINK= (=traits/datasink.js=) opens =twitch /after/literal/{create,update,delete}=, marks the sink dirty, and 1500 ms after the last write drains every claimed row to the file in canonical form (sorted by slug, sparse, ordered keys) and restamps =installed=. The round trip is pinned: =systems/runtime/tests/datasink.roundtrip.test.js= — js → json → js → json, byte-identical dataspaces. The live precedent: =~/.viva/registry/education/topographies/english-to-italian/italian.viva.js= (traits =DATASET FRAUGHT DATASINK=, sinks on =literal= only).

Two topographies, ruled 10-06 (/"call it models. and add another topography for guides."/): =model= renames to =models= and keeps the drone; =guides= is new and holds the guide.
