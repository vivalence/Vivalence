* Meta
** Intent

The reframe, verbatim:

#+begin_quote
"lets rethink this from the perspective of building a conversational experience
that crosses text, speech and further faculties. we have the conversational
trait which proxies through the harness into hallucination. thats good. very
composable. we have this conversation prototype. i dont know what its purpose is
supposed to be, now that harness and hallucination are the way they are. we can
subscribe to sets of entities on repository. we send requests via connection and
can stream adn render anything. what do we need conversation for anymore on the
client??"
#+end_quote

Answer: nothing.

** The arc that got us here (rejected branches — keep them, don't relitigate)

The bug lived in a dedicated 2nd WebSocket: client =connection.socket("/conversation")=
opened a raw WS carrying the token as a *query* param; server =authorize= only ever
worked via the *header* path (which the multiplex uses). Proven live: a raw
=new WebSocket(deep-path + real token)= upgrades 101 AND the server answers
=/handshake/open=. So server-good, client-locus.

Attempts to keep =Conversation= and just move it onto the multiplex, each rejected by beef:
- *dedicated session primitive* (child-socket-as-session): "i dont like the idea of
  a dedicated session primitive. not at all."
- *reuse pooled socket + slurp inbound + prefix scoping*: "fold those correctly such
  that there is only minimal code change." + "i dont like the idea of having the mode
  level feature know about the underlying implementation specifics."
- *socket recursion* (child Socket over a =\{session, packet\}= link envelope): beef —
  "socket on multiplex. socket recursion. similar to hallucionation/provider proxy
  recursion aka /cortex binding." Built it (Packet =session= variants, =#accept=/=#tunnel=,
  =#sessionLink=). Rejected: "no. still not."
- the pin that broke it: *"is the socket prototype used during multiplexing?"* — yes
  (=transmitter.js:30= =new Socket(open(address), vector)=; server =serve.multiplex= =new
  Socket(ws, aperture)=). One Socket already stands up per side. Nesting a second is redundant.

Then the reframe above dissolved the question entirely: don't fold =Conversation= onto
the socket — *delete it*.

** The insight — what Conversation provided vs who already provides it

| Conversation gave                         | already provided by                                  |
|-------------------------------------------+------------------------------------------------------|
| persistent bidirectional socket           | a turn = request→stream; only continuous mic needs   |
|   (handshake → LIVE → messenger)           |   true duplex, and that's ONE multiplex stream-frame |
|                                           |   (=feed= up / =flow= down)                            |
| shape handshake (each side learns the      | pointless — channels are static (dialogue/speech/    |
|   other's receive-routes)                  |   verbatim), not negotiated; harness+hallucination   |
|                                           |   own the turn protocol                              |
| =messenger(shape).send.dialogue.packet=     | =connection.observe / publish= + =soma.pour=           |
| turn accumulation                         | =soma.pour= (stays, in the trait)                      |
| history                                   | repository entity subscription (=turn.subscribe=)      |
| render anything                           | harness → hallucination                              |

Every leg is covered without the prototype. A dialogue turn is just a *streaming
request over the (multiplex) connection* — same shape as cortex and entities.

* Design (minimal diff — pending go)

** Client — the conversational trait collapses to observe + pour

#+begin_src js
// systems/kajuit/src/typology/entities/thread/traits/conversational.js
send(parts):
  for await (const packet of connection.observe("/conversation/dialogue",
                     { method: "POST", body: { thread, parts, tune } })) {
    assistantTurn = soma.pour(assistantTurn, packet);
    thread.$streaming.set(assistantTurn);
  }                                      // /turn/close → turnRepo.merge(assistantTurn)
history:  turnRepo.subscribe({ thread })  // reactive entities, already there
abort:    the observe()'s AbortController
#+end_src

Gone: =Conversation=, =thread.socket=, the =/handshake/open= dance, =messenger=, the
=inbound= Vector, =connection.socket()= call site.

** Server — the mount collapses to a streaming route

#+begin_src js
// systems/runtime/daemon/traits/conversational.js
mode.aperture.branch("/conversation").open("dialogue",
  async function* (ctx) { yield* mode.harness.dialogue.stream({ parts, thread, tune }); });
#+end_src

Gone: =serve.websocket= mount, the per-WS =new Socket= + =new Conversation=. The multiplex
=#answer= already frames an async-generator back as a stream; =connection.observe=
already consumes it. Auth rides the multiplex bearer (header path). *The original bug
cannot recur* — no dedicated WS, no query token.

** What is NOT touched
- =mode.harness.dialogue= → hallucination (the composable spine beef praised). Untouched.
- =soma.pour=, the turn ontology, =TurnRepository= + subscriptions. Untouched.
- =Socket=, =Packet= schema, =serve.multiplex=, the multiplex transport. Untouched
  (the =\{session\}= schema/socket-recursion work is REVERTED, not extended).
