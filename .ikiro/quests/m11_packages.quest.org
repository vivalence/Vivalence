* Meta
** Intent

Turn registry loading into a functional fold over a declared list of *packages*,
and settle the repo's package distribution + the four run scenarios BEFORE any
loader change. The unifying idea: *=registry= is not a thing, =package= is.*

The supply is FOUR in-tree packages (beef, verbatim: *"core call vivalence -
services and such. education is education. playground check. add another for
testing called simulation."*):

| package     | holds                                                          |
|-------------+----------------------------------------------------------------|
| @viva       | platform services: datamap, hallucinator, lighthouse, nlp (fork 5, beef: "go on @viva instead of @vivalence") |
| @education  | the domain: corpus/ontology/domain kernels + game/tactic/teacher/homepage/dashboard modes |
| @development | dev/demo modes, type =playground= (spawner, card, dealer, automaton, switchboard, spawned) |
| @simulation | the testing world: the test variant (daemons/services inlined, no circuitry indirection) + future fixtures |

And the identity axis is RENAMED (beef, verbatim: *"the package name is now the
owner name … we need to rename this variable owner. I think package is the more
accurate term."*): =owner= → =package= throughout — manifest field, pensieve top
axis, =cast.lookup=, =is.lookup=. Free disambiguation win: =owner= stays
available for the datamap's user-scoped ENTITY owner (different concept, same
word today).

Reference ripple (beef: *"the things now don't need to only reference @vivalence
but also all of the other package names"*): every module lookup string re-homes
to its package — =@vivalence/game/write= → =@education/game/write= (the
=@vivalence= source here is what beef's quote above and the disk both say
TODAY — that identity itself is now =@viva=, see the locked-design section).

Testament dissolves as a package and survives as the machine's RUN SURFACE
(beef: *"the testament is the thing that we run live … the running files"* +
*"We might want to move the circuitry for that package, like the package as a
whole, into the registry"* — judged YES for the authored half): the authored
variant (test.viva.js + environment jsonc) moves into
=registry/simulation/variant/=; the derived half (system locks/logs, mountpoint
dbs, .env, secrets) stays gitignored under =testament/=. **The gitignore line
becomes the authored/derived line** — same axis as variant-declares /
ledger-pins.

*NO circuitry indirection* (beef, addendum: *"let's lose the circuitry
terminology entirely. Our variant modules don't export any circuitry.
Paladin doesn't handle circuitry. They just export runtime services daemons,
such stuff."*): a variant module exports =daemons=/=services=/=runtime=/=clients=
DIRECTLY — no separate =circuitry.js= file, no =export * as circuitry from
"./circuitry.js"= re-export, no =cake.circuitry?.X= merge in =variant.js=.

=testament/variant/circuitry.js= (daemons: brazilian + playground) into
=test.viva.js=; =registry/wafers/@vivalence/variant/multiplayer/circuitry.js=
(daemons: brazilian) into =multiplayer.viva.js=. =localhost.viva.js= never
had this indirection — its daemon was always inline. Content-drift NOTE

carries =tactic/five-fold-session=+=tactic/clinic=+=dashboard/dataspace=

This quest resolves the *in-tree* case. Out-of-tree apparatus (ledger,

** The locked design (the decision trail)

*** owner = the manifest KEY; package = the module TYPE (fork 7 reshaped this)
beef (fork 7, reversing the key-rename before it ever landed): *"i dont like
the package name here: package: pkg. maybe this is one of those cases where
we not name the think after its mode/module type. maybe owner was the better
name. module type is package. but the key on manifest i think makes sense as
'owner'."*

So: =pensieve= keys =owner→type→slug→version= — UNCHANGED from live. What
changes is where the VALUE comes from and what it means: =owner= names a
package (=@viva=, =@education=, … — fork 5), derived from the mount path by
default, lockable by self-declaration. The THING on disk is a *package*
(=type: "package"=, the four self-manifests; the ledger's =registry.json=,
the supply record) — the manifest FIELD that points at one stays =owner=.
Don't name the field after the module type it references.

Two packages shipping =game/flashcard= land under different owner keys → no
collision. =@viva= is the core PLATFORM package, not "the org".

**** DERIVED by default, LOCKED on demand (beef, addendum)
The owner is computed *within =vip.mount='s own scope* — a package needn't
author =owner: "@viva"= at all; the name derives from the mount path
(=registry/viva= → =@viva=). No mode/kernel/service needs to export
=manifest.owner= either — a module inherits whatever its mount stamped, by
default.

A =package.viva.js= (or any module) MAY still self-declare =manifest.owner=
to *lock* an explicit identity — the self-declaration wins over the
mount-derived default when present. Opt-in, not required (the real fixture is
postponed, fork 4; the mechanism is proven in-memory in =vip.test.js=).

The reserved-word wrinkle (=package= is a strict-mode reserved word; a whole
convention existed to dodge it: keys =package=, bindings =pkg=) DISSOLVES
under fork 7 — =owner= binds freely, every =pkg= binding dies unborn, the
=cast.lookup= destructure stays exactly as it is live. The earlier
"revert to owner?" analysis concluded "no revert needed" on narrow syntax
grounds; fork 7 reverts on SEMANTIC grounds — the syntax analysis stays true,
just moot.

*** supply / demand — now TRUE in code (fork 8 fixed the violation)
system = supply (fills the pensieve, pre-variant). variant = demand (composes
module identities). The earlier =variant.packages= put the supply declaration
ON the demand object — fork 8 removed it. Runtime and variant both stay
package-blind; =vip.supply()= (the ledger's =registry.json=, seeded by
discovery) is the one supply mechanism.

*** system supplies, variant demands (fork 8 — was: "variant declares, ledger pins")
The flake.nix analogy RETIRES (wrong layer — flakes pin inputs to BUILD a
system; the variant composes RUNTIME demand). The true analogy is
pip/site-packages · Homebrew cellar: the registry directory = the cellar,
PRESENCE = installed, =viva install= (ghost) = pip, and a demanded-but-absent
package = ImportError (=vip.accio= throws "not supplied", distinct from
"Module 404"). In-tree, the ledger IS the filesystem (a file restating
=ls registry/= is a tautology); a real ledger FILE
(=testament/ledger/packages.json=, name→mount pins, resolved via the parked
=paladin.source=) arrives with the first OUT-OF-TREE package — that's the
trigger, fork 9 named the home for it.

export default function source(paladin) {
  paladin.source = (reference) => {
    if (typeof reference === "object" && reference.file)
      return new Path(resolve(dirname(fromFileUrl(reference.file)), reference.source)); // relative to the declaring file
    const target = typeof reference === "string" ? reference : reference.source;
    if (isAbsolute(target)) return new Path(target); // absolute — as-is

      return new Path(resolve(cwd, target));
    }
    return paladin.scope.repository.branch(target); // bare segment — repo-root-relative
  };
}
