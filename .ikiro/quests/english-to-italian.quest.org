* Italian adaptations vs the criteria doc

- *6-cell paradigm*: firstSingular (io), secondSingular (tu), thirdSingular (lui/lei/Lei),
  firstPlural (noi), secondPlural (voi), thirdPlural (loro). Same slot names as Castilian.
- *Passato prossimo is COMPOUND* (avere/essere + participio). Divergence from the Spanish
  simple-preterite mirror. Design: deep paradigms carry =pastParticiple= as a nonfinite
  (like gerund) + tense tables for presente, imperfetto, futuro, condizionale, congiuntivo
  presente, imperativo (tu). Passato prossimo taught at SENTENCE level (participle +
  auxiliary visible in examples), not as a 6-cell pivot table — no syncretic fake rows.
- *-isc- subclass*: third conjugation splits (dormire vs finire/capire). Regularity symbol
  distinguishes; paradigm exemplars include one of each.
- *Deep verb set (16)*: essere, avere, andare, fare, stare, dare, dire, potere, volere,
  dovere, sapere, venire + regulars parlare (-are), credere (-ere), dormire (-ire),
  finire (-isc-). Pattern-recognition before irregulars, per BR paradigm design.
- *No variant symbol*: no brazilianism/castilianism analogue — standard Italian, no
  dialect fork. Regional vocab (if any) deferred.
- *Diacritic suffix convention*: à→a-gv, è→e-gv, é→e-ac, ì→i-gv, ò→o-gv, ù→u-gv
  (existing -gv/-ac codes cover all Italian diacritics).
- *auxiliary symbol* (new, small): essere-vs-avere aux choice on verb lemmas — drives
  future passato-prossimo teaching; authored per lemma, validated in QA.

* Vocalization strategy

*Words (2000 FIRM, harvest-only) — INDEX-FIRST fan-out, not per-word search.* The Spanish
per-word =srsearch= grind doesn't scale to 5000 targets and under-reports. Instead:
1. Dump full Commons category listings ONCE via =categorymembers= pagination (~30 calls
   total): =Lingua Libre pronunciation-ita= (12,235 files) + =Italian pronunciation=
   (1,209) → =.harvest/audio-index.json= mapping normalized form → [file titles].
2. Fan out further schemes into the same index: =It-<word>.oga= variants, capitalization
   variants, any =(ita)-= pattern outside the LL category (one =srsearch= sweep for
   stragglers), other Commons Italian-pronunciation categories discovered from sample
   files' category lists.
3. Match the frozen 5000-form target list against the index LOCALLY (diacritic-exact
   first, then documented normalization fallbacks). Exact coverage number lands in the
   Ledger within the first hours.
4. If matches < 2000: the open-class expansion bands (B1 buffer nouns/adjectives/adverbs)
   PREFER index-covered words at equal frequency tier — closing the gap by word choice,
   never by TTS. Closed-class + high-frequency core stays frequency-driven regardless.
5. Download ALL matched candidates → ffmpeg normalize → =.harvest/candidates/<form>/<speaker>.mp3=
   (throttled, backoff, state.json resume). NO promotion, NO VOCALIZED — beef picks
   (fork 3), then a =compile-picks= step promotes =word-audio-picks.json= →
   =freight/audio/words/<slug>.mp3= + surgical VOCALIZED insertion.
Unreachable forms → =word-gaps.json= (flag, don't block).

*Sentences (500 of 1000)*: the 500 vocalized sentences ARE NM1 audio sentences — literal
text aligned to audio verbatim (never out-of-step audio-literal). Selection from the 1591
pool: 100% ANNOTATED-token coverage against the frozen word list, round-robin over grammar
pivots (didactic spread), length spread 2–8 words. Download via
=tatoeba.org/audio/download/<audio_id>=, ffmpeg 2-pass loudnorm, 2s spacing.
The other 500 sentences: authored/curated didactic sentences (Tatoeba ita text pool as
reference), same token-coverage law, no VOCALIZED.

* Laws inherited from the Spanish build (compact: "the spanish corpus learns to speak")

- *Inversion doctrine*: vocalized sentence literals realign =learning= text to the audio
  verbatim — audio↔learning coherence is the HARD gate; =known= retranslate + ANNOTATED
  re-annotation are deferrable debt, displayed text must match the recording.
- *Surgical VOCALIZED insertion*: word files carry =RANKED= floats (=309.0=) that a
  parse→stringify round-trip flattens — NEVER reserialize a whole authored data file to
  add one trait; brace-match and insert the VOCALIZED object only. (Authoring fresh files

- *PII law*: NO email/name/any ambient-context PII in any file, script, or User-Agent —
  bare product string =vivalence-harvester/0.1= only.
- *Attribution sibling export*: =attribution= const beside the manifest (never a manifest
  field) — Tatoeba NM1 CC-BY-4.0 + Lingua Libre/Commons CC, "not owned, sourced
  agentically". NOTE: beef commented the attribution export out in =spanish.viva.js= —
  his edit is canonical; mirror the CURRENT spanish.viva.js shape (commented block).
- *Candidates live in =.harvest/=, not =freight/=* — freight holds final assets only
  (FRAUGHT serves the whole cargo dir).
- *Assess before pull*: stratified-sample coverage measurement BEFORE any bulk download.
- *Fresh installs recompute everything*: the entity-variant per-facet fold

* Loop protocol (per 15-min cycle)

1. Read this quest's =* Ledger= → resume cursor.
2. Execute the next unit (one batch / one phase step). Background harvest jobs keep
   running across cycles; check-don't-block.
3. QA within the cycle: staged → mechanical audit → integrate. Never unreviewed writes
   into =dataset/=.
4. Update =* Ledger= (cycle #, done, next, blockers). Idempotent — any cycle can die
   mid-flight and the next one recovers from staged files + state.json.
5. Converge-stop: targets hit + QA clean + 2 consecutive no-progress cycles → write
   final report, stop re-arming.
