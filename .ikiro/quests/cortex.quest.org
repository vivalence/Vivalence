* Intent

Daemon-level orchestrator for all generative AI/ML interactions. Hallucinator
services expose faculties; cortex resolves providers by tune, spawns
hallucinations. Modes never touch hallucinators directly — they invoke
=mode.harness.dialogue.{render,stream}= compiled by the CHAOSMONKEY trait.
CONVERSATIONAL is the WS session owner.

* Settled Architecture

** Turn (entity)

#+begin_src javascript
Turn { id, parent → Turn?, children → Turn[], role, parts JSON, meta JSON?, createdAt }
#+end_src

DAG via parent pointers. Thread = head turn + ancestry. Open role strings.
Domain-agnostic content graph — knows nothing of LLMs.

** Packet stream protocol

/turn/open → /part/open → /part/delta* → /part/close → ... → /turn/close.
=/part/delta= string fields append, non-string replace. =tool_use.input=
streams as raw string, parse JSON on close. SSE-framed for HTTP.

** Faculty contract

#+begin_src javascript
{ type, channels:{in,out}, tune:[c,q,s], context, via:{ render?, stream? } }
#+end_src

Hallucinator service translates between turn/part and provider's native API.
All normalization internal to the service.

** Cortex composition

=cortex.extend(faculties)= populates table indexed by type. =resolve(type, {tune, via})=
filters by =!!faculty.via[v]=, picks nearest in 3-space (euclidean, =belt/array.js=).
=spawn(input)= returns =new Hallucination(cortex, input)=. =shard.harness= is
middleware that binds =ctx.hallucination=. =shard.effects(vector)= bolts
stream/render leaves per faculty type.

** Hallucination class

Pool-shaped conditioned environment (=typology/prototypes/hallucination.js=).
=add= smart intake (string/turn/array). =tool/tune/configure=. Protocol loop
extracted into =streamLeaf / renderLeaf / executeTools= inside =cortex.js=
(Free monad pattern — protocol yields tagged effects, interpreters dispatch).
Stream IS the visibility mechanism — each =/turn/close= is a persistence point.

** Trait wiring

CHAOSMONKEY (fully implemented):
- fail-fast guard
- shard.harness middleware
- /dialogue branch assembly (history load, user turn, ctx.turn)
- root scribe (persists turns on /turn/close, stream + render paths)
- shard.effects bolt-on
- =mode.harness = shape.object(conversation)=
- /harness aperture mount

CONVERSATIONAL: thin WS session owner. Invokes =mode.harness.dialogue.stream=,
pushes packets, voyage signal. Per-WS-message =RequestContext= via
=daemon.datamap.shard.context(...)= + =shard.bind("user", ...)=.

** Conversation flow

Client sends ={parent, turn}=. Server creates user turn, walks parent chain
for history, calls faculty, persists assistant turn, returns new head.
Branch/retry by sending different parent.

* Load-Bearing Design Decisions

1. All AI interaction reduces to turns + typed parts.
2. Faculty type + via.{render,stream} = branch + effect on the harness Vector.
3. Hallucinator services translate turn/part ↔ provider native; cortex never
   sees model names.
4. Tune resolution: filter by =!!faculty.via[v]=, nearest in 3-space.
5. One cortex call = one provider. Multimodal modes compose results.
6. Turn is sole persistence primitive. Thread is a pointer, not an entity.
7. System prompt is middleware concern — prepended at call time, outside the
   graph unless explicitly persisted.
8. Stream is fundamental delivery; render derivable via =soma.bridge=.
9. Vector.slurp deep-merges trajectories by nature. shape.http auto-publishes
   async generators as SSE.
10. CLIENT_SHAPE must use branches (=branches.dialogue.leaves=[{nature:"packet"}, {nature:"voyage"}]=),
    never flat leaves with slashes (causes =//dialogue/packet= double slash).
