# codemap: cross-container invariants

- **trait grammar everywhere**: declarative metadata in artifact + functional dispatch in resolver → emergent wiring. Ask "what trait expresses this?" before "what code implements this?".
- trait check: `entity.traits.includes("X")` (array), never `entity.trait?.X` (values may be null = present-with-no-data).
- **transport**: never raw fetch in Connection — the transport chain carries auth.
- **MikroORM**: hooks can't flush; `lazy:true` drops fields from serialization (Memory.strength; the createdAt footgun). **To-many populates are SELECT-IN, never JOINED** — `loadStrategy: "balanced"` lives ONCE in `registry/viva/datamap/libsql/libsql.viva.js` `config()`, which every `MikroORM.init` (provider + 5 test/fixture sites) rides; JOINED to-many populate + limit + a where on another to-many left unconstrained joins on the paginate outer query when a formula (`Retention.lastSignal`) was selected → `symbols^k` rows per literal, the dojo 16 GB. Invariant: `systems/runtime/tests/repository.populate.test.js`.
- **an OBJECT SPREAD of namespace imports pins the whole barrel** — `export const components = {...decor, ...stage}` is a real object built at module scope, so every member module must be evaluated and esbuild's `treeShaking:true` (`subsystems/typology/gestalten/bundle/svelte.js:40`) can drop nothing. **Re-exports are NOT the problem**: isolated measurement (4000-export fixture) — `export * from` **32 B**, `export * as ns from` **32 B**, `export const map = {...ns}` **214880 B**; identical with and without module side effects, so it is the spread, not `export * as` and not `css:"injected"`. Real case: `drapes/mod.js`'s `components` map (zero consumers, one readme line) dragged echarts 551 + zrender 174 + carbon 35 KB into every buffer view. Deleting it: **1.33 MB → 0.54 MB** prod, flashcard 0.89 → 0.10, while `import { Canvas, stage }` still pulls echarts for the 5 views that ask. An aggregate map belongs in its OWN module so only its importers pay. Separate pin, TRACED: typebox 292 KB enters every client bundle through `mod.client.js` → `schematics/index.js`, which **assembles the `v` facade at module scope** — `import * as scalars/primitives/entities/prototypes` then `v.scalars = scalars; v.rel = …; v.literal = entityFactory(…)`. Top-level mutation of an imported binding is a side effect esbuild may not drop, so the module and its whole reach are retained no matter what the view imported. Proof: a probe importing `gestalten/index.client.js` directly instead of the barrel → `typebox present: false`. (An earlier note here blamed `prototypes/{cortex,hallucination}.js`; those merely also import `v` — they are not the reachability path.) Unfixed: typology is holy and the split needs beef.
- **emitted buffers** bind thread ONLY if `ctx.input.thread` forwarded (cross-mode emit delegation forwards before inner flush; feed results into `ctx.pool`).
- lifecycle everywhere: `construct → populate → resolve → integrate → disintegrate`, parent cascades to children ([[totems]] wafer).
- **STRIPWIRE**: a trait's ONE Vector is callable on both sides — daemon `shape.object(vector)` (local) ⟷ client `shape.connection.wire(conn, strip(vector))` (remote, off `/metadata/*`). Same spelling (`mode.emit.x`, `mode.harness.object.render`), different backing. `wire`+`messenger` are the transport-dual of `object` (callable-AND-namespace both sides); the contract is node-centric `{effect?, branches}` (the cata of the Vector's `{effect, trajectories}`; `leaves` dissolved), and the ROOT effect strips+wires (`side()` local≡remote — "no path is a path", `branch("/")≡affect`). **Built+symmetric: EMITTER · HARNESSED · EXPOSED (daemon uses `shape.proxy` — apertures carry `:id` routes) · cortex (`/cortex/{render,stream}` mounted, client re-inflates a real `Cortex`).** Still unwired: APPLICATION (hand-rolled both sides); TOOLED (`mode.tools` is a live Vector but `/metadata/tools` stays commented — in-process only). See `documentation/content/40-49_repository/47_integration/47.03_stripwire.mdx` + `42_typology/42.05_shape.mdx`.
