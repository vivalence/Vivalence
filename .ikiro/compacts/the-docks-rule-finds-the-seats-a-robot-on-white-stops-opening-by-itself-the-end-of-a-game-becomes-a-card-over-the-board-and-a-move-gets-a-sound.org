** S12b — the dock's rule (41)

- *Measured before changed.* Seat row 34 px with its border INSIDE (rule at y 74–75); tab strip 32 px plus a border OUTSIDE (rule at 73–74).
  One pixel. The crop showed roughly twelve, which is the height of a note row — the only thing that could sit above the tabs.
- *The fix is two lines and one move.* =.tabs= takes =height: 34px= with =box-sizing: border-box=, and the ={#if note}= block moves BELOW the
  =.tabs= div. Re-measured on the served bundle in paper: play and practice both read seat =41–75= · tabs =41–75=, practice's note =75–109=.
- *The deviation is deliberate and recorded.* The design stacks the note ON TOP of the tabs. Kept the design's content, took its own order:
  with the note above, the strip's alignment depended on whether a note happened to be showing.
- Two =P-render= assertions carried the old note-before-tabs order and were re-ordered, not relaxed.

** S12c — the start gate and the end card (44)

- *The bug was three paths, not one.* =fresh()=, =seat()= and =onMount= each drove a bot as soon as it owned the move; only the two-bot case
  ever waited for ▶ start. Now: =waiting = pending && seats[turn].kind !== "user"=; =fresh()= and =seat()= never play a move; =onMount= resumes
  only a =playing= match. The user's own first move stays the start when the user has white — the design's /"drag a piece to open the clock"/.
- *Start says itself three ways* — the card over the board, the rail's ▶, the dock's note — because the complaint was that it said itself
  nowhere.
- *=Shell= gains =overlay== ={ label · title · text · actions }=, a card centred over the =.square=, under the board's own promotion picker
  (z-index 3 against the picker's 6) and over its tints. It is the Shell's only new prop; the other four views pass nothing and are unchanged.
- *The end card names the outcome as the reader's own* where exactly one seat is the user's (=you won= · =you lost= · =a draw=), and by colour
  otherwise (=white wins= · =black wins=). Four choices: *rematch* (same seats swapped, clock kept) · *set up* (new match, setup tab open) ·
  *analyse* (the sealed game into a FRESH study buffer, the library's =open= + =analysis.load= recipe) · *review* (card away, moves tab open;
  a =hidden= state remembers which game was dismissed, so it does not return on the next render).
- *Practice does not wear the card* — not asked for, and its own note already carries a result line.
- =open= from =kit/open.js= collides with the dock's own =open= state inside a view; imported as =openMode=.

** S12d — the sound (47)

- *The hunt ruled out the obvious source first.* lichess's =standard= sounds are listed as a non-free exception in lila's =COPYING.md= — only
  =piano= · =nes= · =futuristic= · =sfx= are AGPL, =lisp= is CC BY-NC-SA. Not usable, and knowing that is the reusable half of the search.
- *Taken:* freesound =546119=, /"Piece Placement"/ by el_boss, CC0, described by its author as a light snap recorded on a wood board, 0.111 s.
  freesound serves the =-hq.mp3= preview without a login, and for a clip this short the preview IS the whole recording.
- *Conditioned:* peak −12.2 dB → +11.2 dB gain → mono 22.05 kHz 48 kbps mp3, peak −1.5 dB, *1 323 bytes*.
- *Carried inline* as a base64 data URL in =kit/sound.js=. Not a sibling file: the bundler keeps only the entry's output, so a =.mp3= beside the
  module is dropped on the floor — the same law that made =Theme= a component at S11.
- *The module is three exports.* =wanted()= / =remember(on)= over =localStorage["chess.sound"]= (absent = on, so it is on by default and the
  preference is a browser's, not a buffer's); =play()= decodes once into an =AudioContext= and starts a buffer source, quiet on any failure.
- *=Board= sounds a move that LANDS* — an =$effect= keyed on =`${lastMove}@${fen}`=, so it covers the user's move, the other seat's, and a step
  through a study alike. Silent on the first render (a loaded game arrives carrying its last move) and on a reset (no last move at all).
- *=Shell= carries the switch* — a =♪= on the rail after =☰=, lit when on, and =s= toggles it. Turning it ON plays once, inside the gesture, so
  the context may resume.
- =play= collided with =Board='s own =play(from, to)=; imported as =sound=.

* laws

- *A rule that lines up only in one state is not lined up.* The tab strip matched the seat row until a note appeared above it. Alignment has to
  be measured in the state that shows the most chrome, or the fix is conditional and will be re-reported.
- *When a control fires from three call sites, the gate belongs in the state, not the call sites.* The auto-start bug was three paths each
  doing something individually reasonable. Naming the state (=waiting=) and letting every path read it is what made the fix one line instead of
  three, and it is what makes the ▶ appear in all three places without repeating a condition.
- *A bundler that ships only JS decides your asset format.* A 1.3 KB CC0 clip becomes a base64 data URL; anything larger would force the
  question of where a chess package's binaries actually live, which is unasked and unruled.
- *Under browser automation a sound can be traced but never heard.* The extension's clicks grant no user activation
  (=navigator.userActivation.hasBeenActive= stays false), so =AudioContext.resume()= never settles. Verification reaches =decodeAudioData= with
  the right byte count and then stops; the audible half needs a human. Say which half was measured.
- *The licence is part of the search, not a step after it.* Ruling lichess out took one fetch of =COPYING.md= and saved wiring an asset that
  could not ship. A found file with an unread licence is not a found file.
- *An identical message outside the dedupe window is its own turn.* 45 and 47 are the same sentence 17 minutes apart; the method keeps both on
  purpose, and here the second is the one that carried the answer.
