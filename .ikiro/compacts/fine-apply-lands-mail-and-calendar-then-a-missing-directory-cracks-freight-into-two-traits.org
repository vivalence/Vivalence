He asked whether a mode always has a mountpoint. It does not, and the trace said so:

Paladin points **daemons and services**, never kernel entries; =dress()= only converts a declared
string. Landing a mint broke two settle tests, and they were right to break: =null= means a slot was
declared and is unfilled — a REQUIRED fault the doctor names — while =undefined= means no slot exists.
**Two absences, two meanings**, and =if (!declared)= erases the distinction. That attempt was reverted
on /"not yet a go really. more of a trace this."/

The pin, now ledger invariant 8: =mountpoint= is FS, =mount= is an internal reference. Measured:
=Mask.mount // mountpath= is fs, =Daemon.mount // internal root= is a route, =mode.mount= is
=/mode/<type>/<slug>= and =mode.url= hangs off its nature — and the outlier is =module.mount=, which
paladin sets to the mode's own =.viva.js= FILE, so =module.mount.dirname= is the mode's root on disk.
One word, four objects, three meanings.

Then /"freight lives in the mode"/, and the blast:

=module.mount.dirname + freight.nature= always would root vdex's catalog at the mode directory while
every key is a jdex-tree path — every document 404s, the pdf viewer a sibling landed this session
included. The rule is right and vdex is what it exposes: **vdex's cargo was never freight.** Freight is
what a mode carries and owns; vdex indexes a tree it does not own, and =Freight("/")= was only ever a
way to say "serve the mountpoint". The =??= let one trait mean both.

#+begin_src javascript
// systems/runtime/daemon/traits/index.js
const carry = async (mode, daemon, root) => { … };

// freight is what a mode CARRIES: its own files, under its own directory, at the path it declares.
export const FRAUGHT = (mode, daemon) =>
  carry(mode, daemon, join(mode.module.mount.dirname, mode.module.freight.path.nature));

// a mode that SERVES the tree it reads: the operator's mountpoint is the root, and the mode owns none of it.
export const MOUNTED = (mode, daemon) => {
  if (!mode.mountpoint)
    throw new Error(`[MOUNTED] ${mode.type}/${mode.slug} serves its mountpoint, but its kernel entry names none`);
  return carry(mode, daemon, mode.mountpoint.absolute);
};
#+end_src

=Mode.ts= gained the enum member; the three sites that asked /does this serve cargo?/ now ask both
(=resolution.js:23= Cargo · =resolve.js:47= client serve · =metadata.js:42=); education's harvest tool
stays FRAUGHT-only because it wants a datasink topography, not cargo; vdex dropped =FRAUGHT= and its
=Freight("/")= export. =Thread.ts:49= already carried =// also trait MOUNTED= in a comment, so the name
was waiting for it. **No behaviour moves today** — what changes is that giving =office/email= a
mountpoint no longer teleports its attachments out of the mode.
