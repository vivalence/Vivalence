** what running the code found that reading it would not

- **No segment-type precedence.** =42.01= claimed =literal → parameter → wildcard → remainder=. False. =scope= collects in trajectory-insertion order, =feed= takes the first WITH an effect — so =/u/:id= declared before =/u/list= makes =list= permanently unreachable. Proven both directions in the example.
- **The arity trap.** =fire= dispatches on DECLARED parameter count, so a handler spelled =(input) => …= is arity 1 and receives the CONTEXT. Capture caught me making this exact mistake while authoring the example; it became a demonstrated line rather than prose.
- **=yields= is a complete edge-declared streaming contract** spanning three files: =harnessed.js= declares ={nature:"stream", yields:Packet.Session}= → =strip.js:7= plucks it → =shape/connection.js:35= returns a =connection.stream()= caller. New example proves the round trip.
- **A =Connection= is a memoized tree, not a URL builder** — =child()= caches, and its transport is =(ctx)=>parent.dispatch(ctx)=, so one root shard sees every descendant call.

** the eight natures

Endowments (grant a power, mount machinery) · Provisions (deliver content once) · Flags (no payload, read by others) · Dials (the trait IS its payload) · Coordinates (position in a space) · Facets (what data the bearer carries) · **Relations** (=REQUIRES {concepts}= — points AWAY from the bearer; the primer's curriculum DAG) · Roles (deployment identity).

Magnitude asymmetry: endowments in the tens, read once at boot by the runtime; facets in the hundreds, read on every render by a view. Same word, two consumers.

Naming-register observation: the vocabulary is **participial** — TRANSLAT/ED/, VOCALIZ/ED/, HARNESS/ED/, MASK/ED/, FRAUGHT (archaic participle of freight). The exceptions are nouns — =APPLICATION=, =EMITTER=, =DATASET= — and they are the ones whose names have historically been unstable (=BUFFERED= was really =APPLICATION=).

** the complexes and the laws

Exceptionless across all 53 modules:
: STANDALONE ⇒ APPLICATION
: HARNESSED ⇒ APPLICATION, STANDALONE
: CONVERSATIONAL ⇒ APPLICATION, STANDALONE, HARNESSED, EMITTER
: TOOLED ⇒ APPLICATION, STANDALONE, EMITTER
: INTENTED ⇒ EMITTER
: FRAUGHT ⇒ DATASET

Read by nature: **flags and dials presuppose the endowments they modify.** The apparent exclusions (=APPLICATION ⊥ DATASET= etc.) are module-type separation, not orthogonality — dropped from the writeup because they read as laws and aren't.

Six recurring bundles name kinds of mode better than =manifest.type= does. Sharpest line: **games are the only face-bearing modes that are NOT =STANDALONE=** — a game cannot exist unless something deals it.

The unifying mechanism, found while writing: **an entity is a stable skeleton + an open trait-space, narrowed at the point of use.** =narrowable= (=schematics/v.js:72=) is the bridge — a call site hands in a plain object for a narrowable key, =v= wraps and intersects it. One mechanism behind two things that look unrelated: a mode's buffer mask (=v.buffer({data:{…}})= narrows =data=) and a domain's trait contract (=v.literal({trait:{TRANSLATED:…}})= narrows =trait=). The kernel ships the open space; the domain narrows it — proven by =enum LiteralTraitsEnum { _ = "_" }= in typology against six members in the domain.

New example asserts the invariant that matters: **a trait can be CLAIMED without carrying a payload** (=claims → ["TRANSLATED","VOCALIZED"]= vs =carries → ["TRANSLATED"]=). Hence =traits.includes("X")=, never =trait?.X=.

Roster: 5 of 11 entities carry traits. =Buffer=, =Turn=, =User= deliberately do not — their variability lives in =data=/=parts=; they are payload carriers, not typed citizens.
