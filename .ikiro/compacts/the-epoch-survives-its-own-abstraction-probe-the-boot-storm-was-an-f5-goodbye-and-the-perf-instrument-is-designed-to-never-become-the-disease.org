* the two probes, and why they held

**Abstraction**: epoch = the shape every reactive system converged on (Solid =batch=,
MobX =transaction=, React =batchedUpdates=). The load-bearing reason it must be explicit:
find's cast chain awaits PER ROW, so one find spans hundreds of microtask ticks — a
=queueMicrotask= auto-flush would fire mid-find. Only a refcounted window survives
=await=; nanostores has no scheduler to defer into. Known weakness stated: opt-in — a
future bulk path that forgets to wrap regresses silently; surface is small (find /
findAndCount / update are the only bulk entries). Honest limit: epoch cuts fire COUNT,
not fire COST — the diet handles cost (thread-size rows). Rung above if needed: granular
per-entity stores (kills the disease category, rewrites every subscriber). Not now.

**Caching**: re-click = ZERO wait for the session (hydration ledger + scoped subs stay
live, background threads stay fresh). Reload repulls per thread — buffer/turn repos are
not =persist()=ed, and enabling that waits on coalescing =store()= (the M5 landmine),
which could ride epoch close for free. Separate item, beef says when.
