* the two bugs (one toggle, two wrong places)

** 1 — the authority split (why the button "can't toggle")
=panels/f/f.svelte:107= gates the "start chatting"/"hide chat" button on =harnessed= (=mode.implements("HARNESSED")=). Click → =setDockCollapsed= flips =collapsed= → the button LABEL flips (F subscribes). But the dock PANE lives in =panels/a/a.svelte:73= and gated rendering on =engaged= = =thread.$traits ⊇ CONVERSATIONAL && mode.implements("CONVERSATIONAL")=. CONVERSATIONAL lands on a thread ONLY via panel-E engage — and the auto-engage widgets are =.bak=/dead — so in the normal path never. F flipped a flag A ignored: the button toggled its own text, the chat never opened. Two gates for one toggle — the "two channels for one fact" bug ([[the-continuation-problem-ambient-state-dies-at-every-async-boundary-and-the-cure-is-never-carry-harder-but-put-the-fact-on-the-one-thing-that-already-crosses]]: "two contexts for one fact is one context and one bug").

** 2 — the singleton dock (why "separate docks" was impossible)
=stores/bridge/bridge.js= held ONE =this.$dock= atom, constructed once in =+layout.svelte:33= (=new Bridge()=), shared by every panel via =setContext(BRIDGE)=. =terminals.create()= spawns N terminals; all read/write the ONE dock. One global side/share/collapsed. Multiple terminals = one dock between them.

* the design (beef pinned each fork)
Three layers, one authority:
#+begin_src text
dockable   DERIVED   active thread.mode.implements("HARNESSED")   ONE gate; F, A, shoulder, B all read it
geometry   STORED    terminal.$dock {side, share, collapsed}      per terminal, dies with it
content    BOUND     <Dock thread={$thread}/>                     follows the thread
#+end_src
Home = the Terminal entity (=typology/entities/terminal.js=), beside =$buffer=. Reasoning that changed on "think again":
- =$buffer= is ALREADY the terminal's view-state (a render pointer), not an entity the terminal IS. Dock geometry is the same category — sits beside it.
- Dock is PLAIN DATA, not an entity ref → rides =terminal.toJSON()= raw, hydrates direct, and NEVER enters the settle tri-state (=ABSENT/UNREACHABLE= in =app/terminals.js= is for async-resolved refs only).
- Living on the terminal means it DIES WITH the terminal → the orphaned-dock / split-brain category can't exist. The rejected alternative — a =bridge.$docks= map keyed by terminal id — reintroduces GC + a cross-blob id join, the exact bug class =app/terminals.js='s total-fold persist was built to forbid.
Bridge keeps only genuinely-global layout (pincer/viewport/composer). Pure geometry (=resolve=/=shareAfterDrag=/=clampShare=/=normalizeSide=) stays in =stores/bridge/dock.js=; mutators become free fns over a =$dock= atom (=state is data, lifecycle is functions over data= — free fns, not methods; [[feedback_functional_lifecycle]]).

* the connoisseur reading
The toggle "couldn't toggle" because the flag and its reader lived under different laws — the fix was not "make the flag work" but "make one authority." Same shape as the singleton: state that should be many-per-terminal lived one-per-app. Both bugs are "the fact is in the wrong place / split across two." Put the geometry on the terminal (the thing that already crosses thread-switches and persistence), gate on the one capability that means "can chat" (HARNESSED), and the two-channel drift can't recur.
