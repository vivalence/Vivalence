#+STATUS: APPLIED (stop tree-kill pending)

* Arc

Resurrected process spawning out of ghost's inline =Deno.Command= into a paladin
capability. =System= gained =spawn=/=kill=; new =Process= prototype is a pure
executor. Ghost trajectories (=run=/=start=/=stop=) went thin. Locks/logs flat
under =~/.viva= as =<type>_<slug>=. Child output surfaces as typology =Pipe=
(out/err) + =Queue= (in); ghost wires them to log files + =ctx.span=. Fixed the
kajuit client crash via a =publish= belt tool + an =is.url= null-guard.

* Decision: process management is paladin's job

@beef: *"maybe process spawning should be a capability provided by paladin. that
way it would survive restarts and multiple invocations of ghost. might be
interesting for runtime and kajuit too. process management is paladin job.
paladin is our registry and provider."*

Killed the earlier B-handle/=ghost/belt/process.js= approach. @beef: *"your design
is incoherent! ... you still attach the process to the ghost."* → ALL process
logic in paladin; ghost trajectories =import paladin= directly; nothing on
=ctx.process= (removed the mount middleware + deleted =ghost/belt/=).

@beef on the catalog smell: *"the presence of this file tells me that our
schematics arent aligned yet. we are still in the design phase here. if the shape
of the files at system_mount need to evolve, they may. same for apis."* — the WHAT
(which processes) should ultimately derive from the variant, not a hardcoded
=CHILDREN=. Stopgap stands for now.

* Process prototype (pure executor)

=subsystems/paladin/prototypes/system.js= (inlined). Holds spec + lock; no config,
no log/file knowledge.

- =spawn()= — =new Deno.Command(bin, {args, cwd, env: spec.env, clearEnv})=.
  @beef: *"i would argue that we dont want the full env cloned."* → dropped
  =...Deno.env.toObject()= (redundant: =clearEnv:false= already inherits). =env=
  carries only curated anchors from the caller. NO =VIVA_PROCESS_SLUG= injection
  (see [[project_no_process_slug_composition]]).
- attached: stdin/out/err =piped=; detached: all =null= + =unref()=.
- =get pid=, =get status=, =kill(signal)= (SIGTERM→SIGKILL ladder).
- =alive()= on Lock: =Deno.kill(pid,"SIGCONT")= probes a stale lock (lock says
  running, process may be a corpse).

* Streams: Pipe out, Queue in

@beef: *"this obviously doesnt belong into process. process might provide with the
propper prototypes (QUEUE??? PIPE?? check typology) and then the consumer(ghost)
does the wiring."*

Split settled: output = =Pipe= (child fans out → many taps), input = =Queue=
(consumer feeds → one sink = child stdin). @beef: *"yes on the pipes. what about
stdin? ... make the right choice while were at it."*

Process exposes =this.out=/=this.err= (=Pipe=) + =this.in= (=Queue=); module
helpers =relay(readable, pipe)= (decode + line-split + =pipe.send=) and
=feed(queue, writable)= (=queue.drain()= → child stdin). =in.close()= on child
exit.

* Ghost trajectories (thin) — enum target

@beef: *"we make the parameter an optional enum[kajuit,runtime,all]! if its present,
we boot that, else we boot fallback all. same semantics for start/stop."*

=target.js= → =specs(param, {detached})=: param ∈ =[runtime,kajuit,all]= (default
all). Mount from =paladin.scope.variant= (NOT a path arg — that was the
=found 0 cakes= bug: =kajuit= got resolved as a path). slug = variant dir
basename. cmd = =deno task --config <repo>/deno.jsonc -q <task>=.

- =run= (attached): spawn → tap =process.out/err= lines → per-process
  =out.log=/=err.log= (raw); branch =ctx.span= per process (subject=pid, fault on
  nonzero exit, seal on status). @beef: *"there is already a span on ctx!"* — use
  it, don't mint a new Span (branches can't =drain= to file; only roots emit).
  =ctx.span.drain()= in mod.js carries the tree → =client_ghost/spans.jsonl=.
- =start= (detached): unref, lock persists, ghost exits, child survives.
- =stop=: read lock → =Deno.kill(pid)=.

* publish belt (PUBLIC_* → Deno.env)

kajuit client crashed: =new Url(env.PUBLIC_VIVA_LIGHTHOUSE_REMOTE)= → undefined.
Root: =paladin.env= is in-memory, separate from =Deno.env=; SvelteKit
=$env/dynamic/public= reads =Deno.env=. Variant =environment/*.jsonc= loads into
=paladin.env= only. See [[project_paladin_env_publish]].

@beef: *"this used to be functionality of the paladin. check paladin lifecycle
publish. maybe we need to turn the lifecycle into a belt tool and run it in
variant&system mount."* — =integrate.publish= existed but ran once at boot, before
=variant.mount= loaded the vars. Moved to =belt/publish.js= → =paladin.publish()=,
called at end of =variant.mount()= + =system.mount()=. Plus =is.url= null-guard
(=if (thing && thing.origin ...)=) so a missing var fails soft.

* Findings (empirical)

- =deno task --config <path>= roots cwd at the config dir (proven), so a task's
  relative =--cwd ./systems/runtime= resolves against repo root regardless of
  spawn cwd.
- =deno task= traps + forwards SIGTERM through 2 nesting layers (proven). So stop's
  orphans are NOT signal-drop — they are =kajuit/watch='s vite helper procs
  (esbuild) + =--watch=, which are descendants of the deno leaf.
- macOS has no =setsid= → process-group kill route closed. Fix = recursive
  tree-kill (=pgrep -P= walk).

@beef confirmed the orphan prediction (*"correct prediction!"*) and approved the
spawn/Pipe/publish architecture (*"works."*).
