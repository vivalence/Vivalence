* the dead retry was a state machine hole (turns 1-5)

/"the retry button in kajuit doesnt work. rework this into just one signin page propper
state display."/ (with =pasted-24.png=: error / unauthorized / retry)

Trace, not click handler: =refresh()= failure runs =logout()= (authority → null) then
sets =SESSION_EXPIRED=/=ERROR=; the gate computed in
=systems/kajuit/src/app/+layout.svelte= ranked those codes ABOVE =!authorized=; retry →
=boot()= → =verify()= → no token → returns =NO_TOKEN= **with no =$status= write** —
nothing observable changes, ever, and the signin form is unreachable. Wrong password
hits the same trap: =login()= sets =ERROR= → error page eats the form.

Category kill, not hotfix: =!authorized → "signin"= checked FIRST; authorized +
=OFFLINE=/=ERROR= also → signin. Gate values now ready | verifying/populating/boot
(→ Boot.svelte, untouched) | signin. The old auth/error/offline branches, =onReconnect=,
and their styles deleted.

=app/widgets/Login.svelte= = the one signin page, rendering =lighthouse.$status=
DIRECTLY — its private status/error state machine deleted (one writer, one display).
Standing line = code lowercased + server message; =retry= only when
=$authorized && failed=; busy disables the button only (inputs never =disabled= — iOS
keyboard law). Nanostore idiom = the =d.svelte:15= pluck-then-=$= precedent; lighthouse
prop is boot-stable so the plucked-store freeze trap does not apply.

* signup no worky (turns 7-9)

Focus-TUI paste: =✕ auth/signup Client error: 400 @
/attached/process/lighthouse/multiplayer/auth/signup= + /"signup no worky"/

Two layers:
1. The 400 is =USERNAME_EXISTS= working as designed — the multiplayer identity table
   already held =beef= (plus beefd, beefdd, lre, lorem, testuser, readmedemo,
   beefreseed). The wizard (=Init.jsx= → =init.js=) ran SIGNUP as its auth step on
   every init, so re-initing an enrolled instance could never pass.
2. The reason was invisible — =ConnectionError.fromStatus= read =body.message= but the
   lighthouse speaks =={status:"ERROR", error:{code, message}}== — nested. A PARALLEL
   session landed that fix (=held = body?.error ?? body=) while this one was
   root-causing; found on disk, built upon, not duplicated.

tries =/auth/signup=, on =error.context.response.body.error.code === "USERNAME_EXISTS"=
calls =/auth/login= with the same creds, anything else rethrows; =poll= and the wizard
closure both ride it; poll's retry loop deliberately untouched (a transient 404 while
the lighthouse attaches must stay retryable). The comment-litter hook rejected the
first draft's authored comment — the kernel law enforcing itself; stripped, landed.
