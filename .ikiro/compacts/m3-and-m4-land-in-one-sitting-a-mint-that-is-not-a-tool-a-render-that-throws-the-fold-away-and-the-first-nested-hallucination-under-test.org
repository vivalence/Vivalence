* Arc

** M3: two doors onto one mint, and the mint binds no thread

The scout (107) read the section back and the landing (108) followed it — with two corrections
the tangle could not have known, both from reading the mount site rather than the plan.
=drapes/panels/Frame.svelte:59-67= mounts a view with ={terminal, daemon, mode, thread, buffer}=,
so the shell destructures =buffer= and the payload is =buffer.data=, not =terminal.buffer.data=.
And =/view/render= has to CATCH: nothing upstream does, so an unguarded =refuse()= throw would end
the round instead of telling the model what to change.

The shape is the point. =emitter= (nature =/article=) is the ONE place a buffer is born and is
absent from =tools= on purpose — =harnessed.js:71= arms =mode.tools= only, and EMITTER mounts it
at aperture =/emit= + =mode.emit=. =generator= is the model's door, slurped by =generative.js:62=,
and its EXISTENCE is what suppresses the trait's own fallback mint at =:69= — the one with no URL
guard and no house style. =generator= branches under =/view= BY HAND, because a declared generator
mounts at the ROOT while the fallback mounts under =/view=: the same capability would otherwise
arm under two different names.

The double-bind is closed by omission. The mint passes NO thread to =gen.buffer=. Two live lines
bind and both advance the counter — =generative.js:39-40= when handed a thread, =emitter.js:80-81=
for every buffer drained — and this is the first mode to declare both. =emitter.test.js= runs the
REAL EMITTER trait against a stub =gen= that reproduces =generative.js= faithfully *including the
bind*, because a stub that ignored =thread= could not fail the marker. Proven able to fail:
passing =thread= into the mint fires the live =[m3:emit] DOUBLE BIND= probe and reds 2 of 5.

Traits go AFTER =TOOLED= in the manifest: =stagger= applies them in declared order and GENERATIVE
slurps into the same =mode.tools=, so the armed order is the declared order and S1 pins it.

** dapper had no door onto its own design system

=P-tokens= needs the generated CSS. =generateCSS(ds)= takes a design system, and building one
needed =colors= / =tokens= / =paper= — default-only exports that =export *= cannot re-export,
which is why dapper's own tests reach around the barrel with relative imports. Not a door a
consumer can use, and a cross-package relative import is forbidden. Added =lib/system.js=
=design()=, exported it, collapsed =lifecycle/index.js= onto it so the pipeline has one source.
Trap on the way: =generateCSS= returns ONLY ={output:{css}}= and drops the ds it was handed —

26 taught tokens exist in BOTH themes — the test checks per theme, because a token only nordic
defines would unstyle a drawn page the moment the operator switches.

** M4: the scout found the load-bearing mechanism and a catch that would lie

beef: /"ok. are you ready for m4?"/ — not a go. The terrain check (109) found what M4 rests on:
=soma.transcript='s =/tool/yield= case accumulates every non-=message=/=object= key of every inner
tool result as an array on the inner fold. So a nested =dialogue.render= that calls =view_render=
genuinely surfaces =output.buffer=. The projection to ={message, buffer}= is what M4 needs — but it
discards more than the quest said: =url[] title[] chars[] truncated[] selector[] matched[] count[]=
too, since =web_read= returns eight keys and none are arrays.

And the defect: =shard.hallucinate.render= THROWS on any close but =complete=. The tangle's catch
would swallow every failure — rounds, =max_tokens=, a refusal, a provider fault — and report all of
them as /"research needs a hallucinator… set SECRET_VIVA_ANTHROPIC_API_KEY"/. A researcher that
worked for twelve rounds and got cut off would tell the operator to set a key they already have.

** "there is some simplification… and we want more than 12 rounds"

beef (110). The two questions had one answer. =render()= throws =folded= away — including a buffer
already minted, thread-bound and FLUSHED at =emitter.js:88= inside the inner tool call. On
exhaustion the page is on the operator's screen and the outer agent gets an exception. More rounds
buys more of that outcome. =dialogue.stream= is the same =respond()= without the throw; fold it
with =soma.transcript= and every close hands back what was drawn, with =condition= set from
=meta.state= so the dead =folded.condition= line comes alive.

Rounds: =POLICY.rounds= has no maximum, =INTELLIGENT.rounds= caps at 50. beef: /"30."/ — and then
/"any changes to code outside the commons?"/ (111). No, verified item by item; the one that could
have bitten is =Vector.use=, which only pushes to the root's =carry= and never descends, so sharing
=web='s nodes with =mode.tools= by reference is safe as long as nothing calls =branch()=.

** the second pass corrected the sketch twice

beef: /"do another pass. all gucci?"/ (112). Went after what I had reasoned about but not read.
The 8s the M1 walk hit is =dossier.js:59= =shard.connection.timeout(8000)= and it exempts streams
by design — =shard/connection.js:14= /"a stream's lifetime is not a request timeout — SSE connects
exempt"/ — and =Connection.stream()= sets that header. A minute of silence inside an outer round
survives the client.

Two corrections to my own sketch. Flat 30, NOT =iq.rounds= — the thread's =rounds= is the OUTER
conversation's per-turn tool cap; a thread dialed to 3 would starve the researcher. And the flat
bag has to carry =condition=: =fromm.wrap= reads =thing.condition ?? "NOMINAL"= and strips it out
of =output=, so ={message, buffer}= alone reports a =length= close as success.

And =P-yield= could be a real test: =Cortex.register= demands only ={type, tune, via}=;
=respond()= reads =state(turn)= off the parts; =soma.drain(turn)= turns a whole turn into packets.
A scripted faculty yielding =drain(turn)= per round lets the REAL loop dispatch the REAL
=view_render= through the REAL EMITTER. The buffer surfacing in the outer yield is then produced
by the machinery, not asserted into it.

** M4 landed: 8 + 4 green on the first run

=research/index.js= streams and folds, checks =cortex.findOne({type:"dialogue", via:"stream"})=
BEFORE the call so that is the ONE path that says "set the key", projects to a flat bag with
=condition=, and on an early close says what happened — state, rounds, the provider's fault
message, whether a page was drawn first, and the model's last words. =tests/rig.js= is the rig:
a real =Cortex=, a scripted faculty, the real EMITTER, a stub bundler. =deliver= retries only
=fault.retryable=, so a fixture throwing a plain =Error= fails fast — the provider-fault path is
testable without sleeping. 30 rounds run in 5 ms.

=P-early= ×3 pin the reason for streaming: exhaustion after a draw, a fault after a draw, a fault
before any. Mutating the door back to =render()= reds =P-yield= and all three. S4 pins the inner
request as =lowering= built it — =brief= 1033 · =render= 5197 · four tools · =policy= stripped
from the wire — and S4 ⊂ S1 is compared as two files, so the recursion guard is visible rather than
hard-coded.
