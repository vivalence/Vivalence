#+title: corpus becomes topography and ontology becomes topology as module types — terrain versus structure — while the entity ontology layer stays put
#+filetags: :registry:typology:naming:module-type:ontology:rename:

A module-type rename in the kernel taxonomy. Two of the three kernel `type` values get terrain names; the third holds; the entity-layer =ontology= that shares the word is deliberately left alone. Small surface, one real trap. Pins [[project_module_type_taxonomy]].

* the proposal — and the one ambiguity in it

beef, mid-thought (session already renamed to "topology topography"):
#+begin_quote
i am thinking of renaming corpus and ontology to topology and topography on module types.
the domain stays domain.
the trait for topological data remains ontology.
#+end_quote

His sentence *ordered* it =corpus→topology, ontology→topography=. But his last line — "the trait for topological data remains ontology" — points the other way: topological = structural = the ex-ontology module. The stated order and his own trait-clue disagreed. I surfaced that as a blocker ("Both can't hold"), then still recommended the semantically-correct crossed pairing. **Reflection: when the user's loose word-order contradicts their own clue AND the semantics resolve it cleanly, LEAD with the resolved answer — don't stage the contradiction as a standoff.** beef's reply made the cost of that framing clear.

* the correction — the semantic pairing, pinned

#+begin_quote
stupid.
copus -> topography. ontology -> topology. obviously?!?!???
fuckface
#+end_quote

So the pairing, decided:
- *topography* = the surveyed terrain, the empirical body of language (ex-*corpus* — english-to-brazilian: harvested sentences, words, audio).
- *topology* = the invariant relational structure (ex-*ontology* — word/sentence/conjugation paradigms).
- *domain* unchanged.
The word map: =corpus→topography=, =ontology→topology=.

* the map — what a type rename actually touches

=map= → I walked the surface before editing. Key findings:
- =Manifest.type= is =v.string()=, NOT a closed enum — nothing HOLY to edit, the type is free-form.
- The load-bearing coupling: =identifier = ${owner}/${type}/${slug}= (=subsystems/paladin/prototypes/manifest.js=). Rename =type= and every DERIVED specifier string must track — the variant kernel lists (=registry/viva/variant/{localhost/education.js,multiplayer/…}=) reference =@education/ontology/*= / =@education/corpus/*= and would throw =Module 404= at =accio= if left stale. Dirs were already renamed (=topologies/=, =topographies/=) — cosmetic, since the resolver reads =manifest.type=, not the dirname.
- The *layer split*: two different "ontology"/"corpus" senses were tangled in the grep. Module =type= (renames) vs the ENTITY layer — =literal.ontology= field, =ONTOLOGY[]= glyph maps, Symbol traits =ONTOLOGICAL=/=TOPOGRAPHICAL= (stay, per "trait remains ontology"). Also nyan's local =kind==="corpus"= and the =tests/corpus/= snapshot regime — data-body senses, not the type.
- No runtime code branches on the type string (only =type==="domain"= checks exist) — so the rename is purely nominal, zero behavior change.
