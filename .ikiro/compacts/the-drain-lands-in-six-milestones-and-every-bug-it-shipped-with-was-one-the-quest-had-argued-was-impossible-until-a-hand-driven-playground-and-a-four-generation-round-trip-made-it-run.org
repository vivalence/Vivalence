* the bug class this session kept finding

Every defect below was something the quest had ASSERTED was fine. None were
found by reading. All were found by running.

** =$lt= was =$gt=

#+begin_src javascript
$lt: (arg) => (value) => value <= arg === false,   // (value <= arg) === false  ≡  value > arg
#+end_src

The gate covered =$lte= only, so it could never have caught it. A rank cutoff
would have drained the complement of what it asked for, silently. This sat
inside the very patch that argued operators must be one-to-one with MikroORM
"or not at all".

** =where= as DATA was handing MikroORM the sugar

The carrier stored the RAW selector on =sink.where=, so a =["word", …]= tuple
issued =repo.find("word")= — which MikroORM reads as a primary key. Measured on
the first drain: every literal sink matched NOTHING, no split file was written,
=orphans.literal= reported 6 of 6. The in-memory predicate lifted the string and
the DB query did not.

That is the two-sites-disagree failure the design names as its own reason to
exist, reproduced inside it. Fixed by making the lift first-class —
=query.lift(selector)= normalizes string/array/null/true/object into one query
object, =query.where= compiles THAT, and the carrier stores the lift. One
normalization, both sites, by construction.

** dual capture broke reinstall

The quest, in two places: /"reinstall upserts by slug, so =file = fn(DB)=
survives the duplication"/. False. =upsert= does =findOne= then =create=, and
both copies of =del.contraction= (one from =adposition.json=, one from
=determiner.json=) land in the same unflushed chunk, so neither sees the other:
=UNIQUE constraint failed: Literal.slug=. On italian that is 30 rows detonating
on the first reinstall after M22.6.

Found by the round-trip scenario on its FIRST run — the test beef asked for
existed for eleven minutes before it paid for itself.

** =find.data= would have crashed on the corpus it exists to read

=read.data= is =import()=, and Deno refuses a =.json= specifier without
=with { type: "json" }=. The authored walk mapped one reader over a regex that
matched =json=. It detonates at M22.6 step 4 — the moment the sources are
repointed at the emitted =.json=, which is the fixpoint gate, which is the whole
claim of the quest.

** =writer.js= wrote JSON bytes into a =.js= file

=target.codec= had ZERO readers; =canonical= was unconditionally
=JSON.stringify=. beef's question is what surfaced it —

#+begin_quote

and datasink writes to json?
or both written by sink?
#+end_quote

— and his answer to the fix was to widen it rather than delete it:

#+begin_quote
2. Honour the codec — canonical takes it and wraps in export default …; for js.
we watn a LOT of codecs eventually
#+end_quote

So it became a TABLE, not a boolean: =writer.codec = {json, js, jsonl}=, open
for a package to extend, =canonical(rows, named)= dispatching, extension
inferred with an explicit name winning, and a THROW on an extension no codec
claims. The read side moved with it. **The contract: a write codec without a
matching =find.data= read path is a one-way door**, and =paladin/tests/corpus.test.js=
round-trips every registered codec to prove there isn't one.

* the fork closed on measurement

The quest left exactly one fork open, explicitly to be /"decided by a test, not
by argument"/: whether =carry= survives the =queueMicrotask= pump interleaving
with the flush tail.

It does interleave — =seen= is already populated when =await em.flush()=
returns, because the flush's own awaits drain the microtask queue. But the
reentrant read still resolves against the carried context and returns a live
count. So =carry= holds and =shard.params()= is NOT added to the provider
contract.

What was wrong was the CLAIM. "Does not run inside the flush that triggered it"
is not what =detached= guarantees; the guarantee is that the subscriber's
=await= returns without waiting — the flush is never BLOCKED. The gate now
asserts =order[0] === "flush-called"= instead of an emptiness a microtask can
invalidate.

* the round trip

#+begin_quote
expand testing for this.
test js->json->js->json with full cata/ana equality
#+end_quote

#+begin_quote
scenario testing
#+end_quote

Four generations, each installing a FRESH daemon from its predecessor's emitted
corpus via a directory walk: authored =.js= → =gen1/*.json= → =gen2/*.js= →
=gen3/*.json= → =gen4/*.js=. It asserts ANA equality (all four dataspaces
byte-identical under =Datasink.canonical=), CATA equality (gen1 ≡ gen3, gen2 ≡
gen4, byte-for-byte, same file set every generation), that the vantages differ
by the codec ENVELOPE alone (=js === `export default ${json};`=), and that a
fifth drain reports =written: 0=.

That last assertion is M22.6 step 5 — the fixpoint, =file = fn(DB)= — proven
without a live boot. What M22.6 still owns is SCALE and the real corpus, not the
mechanism.

* traits can now declare teardown

Driving the playground surfaced it: after arming, the 1500ms =fn.debounce=
settle fires into a closed datamap → =DriverException=, unhandled; and before
that, the pending timer keeps the process alive. The trait held a resource it
had no way to release.

#+begin_quote
go a
#+end_quote

**My first reading was wrong and is worth keeping.** I reported that modes have
no teardown hook, on the strength of =grep disintegrate systems/runtime/daemon/lifecycle=
coming back empty. The cascade exists one level up — =systems/runtime/die.js:43=
walks children, =daemon/die.js:60= closes the datamap. Only the MODE rung was
missing. The estimate collapsed from an hour to twenty minutes the moment the
right file was read. **A grep scoped to the wrong directory reads exactly like
absence.** =family: assume-dont-verify=

=stagger= KEEPS its array-of-finalizers contract — measured, four consumers, all
spreading the return. A trait may now return ={finalize, terminate}=;
=terminate= lands on =mode.terminators=, and the daemon runs them BEFORE
=datamap.disintegrate()=, while the connection is still alive. Zero call sites
changed. The trait's own return-shape change then caught its two direct callers
on the first run — which is the argument for having left =stagger= alone.
