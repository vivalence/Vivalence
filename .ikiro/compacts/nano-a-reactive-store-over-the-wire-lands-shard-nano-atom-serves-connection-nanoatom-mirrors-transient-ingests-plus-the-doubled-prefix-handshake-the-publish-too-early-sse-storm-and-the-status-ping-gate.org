* The nano design space (the survey, methodical)
All six are the SAME dynamic — a remote store mirrored locally — varying on home / source-arg / output / lifecycle:
1. =mirror(connection, endpoint)= — standalone; primes via =call(endpoint)= + subscribes; new atom; =onMount= lazy. → name+signature wrong.
2. =connection.reactive(endpoint)= — Connection method; new atom; lazy. → "don't want it on the connection" (the NAME; location returns later as =nanoatom=).
3. =belt.atom.live(open)= — open-fn thunk; new atom; lazy. → thunk + trailing =.subscribe= ugly.
4. =shard.nano.transient(connection, endpoint)= — explicit endpoint; new atom; lazy.
5. =shard.nano.transient(connection)= — connection pre-branched; new atom; lazy; still needs a manual =.subscribe= to fold.
6. =shard.nano.transient(connection, store)= — connection pre-branched; INGESTS a sink; EAGER; returns unsubscribe. ← the "ingest all, no manual subscribe, transient passed at branch" rework.

* Lessons
- *Branch a scoped connection by RELATIVE segments only.* =daemon.connection='s base already carries =/daemon/:slug=; =Url.branch= = =join= = pure concat (no dedup), so branching by an ABSOLUTE path that re-includes the scope DOUBLES it. mode.js was the lone offender; everything else was already relative.
- *=publish()= pre-wraps too early.* A response body should stay SEMANTIC (the async-iterable) through the transport-agnostic layer; each transport renders it (socket = raw object frames, HTTP = SSE via =http.js:41=). Wrapping into a ReadableStream at the handler binds it to one transport and breaks the other.
- *=.open= vs =.get=; =connection.call= defaults to POST.* A snapshot/read route that must answer the default =call= has to be method-agnostic (=.open=) or the caller passes =method:"GET"=. A =.get("/")= silently returns =null= to a POST — the null "snapshot" that briefly fooled me.
- *The consumer is just the nanostores lazy-store pattern.* =atom= + =onMount= IS the shim — no Proxy, no wrapper object; =onMount= gives ref-counted wire lifecycle for free. Don't Proxy a nanostore (=computed=/batching expect real stores).
- *nano = the transport-dual of a nanostore.* Same relationship =connection.wire= has to =object=. Pin the dual, then the API falls out: serve one side, mirror/ingest the other. The six "variants" were all one dynamic — resist proliferating; land the two simplest archetypes.
- *Split storms before fixing.* The "expensive ticking" was TWO independent problems (live-daemon publish storm + stale-daemon boot barrage); one fix each. Naming them apart stopped a hotfix cascade.
