** the mission-level finding

#+begin_quote
Isolation rests ENTIRELY on the MikroORM =user= filter (=default:true=). =authorize()= only
sets =ctx.user= from the token — there is NO server-side thread-ownership check ANYWHERE.
Ownership IS the ORM filter, and two entities that need it don't have it (Turn, User).
#+end_quote

So the "diligence collar" the quest's lean called ergonomics is actually the SECURITY
BOUNDARY, and it is absent on the harness path.

* what it settles for the design

- the store debate (A/B/C/D) was NEVER the whole problem. Two must-fixes are now
  non-optional and UPSTREAM of the store choice: (1) Turn gets the =user= filter (closes the
  crown IDOR + the skill leak), (2) the harness GATES on the thread row it already loads at
  =harnessed.js:27= (bounce foreign/deleted threads) and binds the ENTITY not the string.
  A/B/C/D only decide how user/thread TRAVEL, which the ORM filter + a harness gate already
  largely settle.
- fork #3 (entity-at-bind vs id-string) is no longer cosmetic — it's root cause 5, live,
  one assignment from fixed.
- fork #2 (scope-of-law) has TEETH now: rank 1 proves the userspace-WRITE law is a security
  boundary, not a nicety. =review.js='s soft ERROR collar is the RIGHT SHAPE at the WRONG
  LAYER — it guards one tool, not the harness seam every write rides.
- recorded: full map in the quest's "where it breaks"; the five live security-critical
  breaks (crown IDOR, bricked thread, boot crash, account-switch leak, tool DoS) also logged
  in =known-issues.org= so they don't sink into a design memo.
