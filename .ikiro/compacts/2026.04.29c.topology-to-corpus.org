* Decisions

- Atomicity follows pensieve indexing model: manifest.type + circuitry kernel-array imports + class field MUST move together (single commit). Directory mv is independent and cosmetic. Test surface (paladin.vip.accio) reflects this — proved by 6/6 baseline test including negative case.
- "Literal topology" prose (graph-sense metaphor) renamed to "Literal corpus map" because the kernel-type rename creates reader-collision risk for any future reader who only knows the new vocabulary. Graph topology metaphor was fine standalone; not after.
- =bak/= manifests get the type rename even though archived. Otherwise type-vs-path invariant breaks (under =corpus/bak/= dir but =type: "topology"= in manifest). Cheap edit, big consistency.
- Workpackage filename gets renamed when concept renames. Compact filenames don't, unless topology was in the topic-tag (verified neither of mine had it).
- Sub-agent inventories are STARTING points, not COMPLETE inventories. Always do a second-pass grep before claiming "all files identified". This session: Explore agent missed 4 active workpackages, 2 claude.md surfaces, 1 typology comment. Second-pass `rg` caught all 7.
- Pre-existing bench seedDataset bug (Literal.ontology NOT NULL on UPDATE) blocks full topology kernel load via bench. Verification doesn't need full DATASET seeding — paladin.vip.accio + manifest.type assertion is sufficient to verify rename correctness. Pivoted test scope when bench bug surfaced rather than chasing the bug.
- When Finn asks "tell me the choice" — show CONCRETE CODE with side-by-side options (=// option A= vs =// option B= comments showing actual produced lines). Abstract recommendations get rejected with "what". Diff-style choice presentation gets locked in one message.
- For workpackages whose target file moved post-DONE: update path with explanatory note (`(was active at workpackage write; flattened into english-to-brazilian + archived to bak/ post-DONE)`). Don't silently rewrite history; don't leave broken refs either.
