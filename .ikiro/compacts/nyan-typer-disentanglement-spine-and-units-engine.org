* The three-memory spine (the load-bearing design thesis)

One typed attempt's keystroke timestamps decompose by SHAPE into three lanes — no domain, no KNOWN-state gate needed standalone (onset captures recall by construction, steady-state captures motor):

- recall  — the pre-first-keystroke onset gap (=onset_ms=); long onset then a fast clean burst = retrieval bottleneck (vocabulary).
- spelling — mid-word: long gaps before specific chars, backspaces, accent-confusion (=accentMiss=), especially diacritics; forgiving grades ç→c correct for the SIGNAL but the raw accent miss is still logged.
- motor    — steady intra-word inter-key intervals with no error; the only lane a typing trainer should "fix".

A session keeps three ephemeral accumulators (plain JS, NOT domain Memory entities): per-item onset, per-grapheme accent histogram, per-digraph latency table. Review renders the three. Persistence later = serialize the keystroke atom array; the analysis is unchanged. Optional sharper disentangler = the retype pass (type each word twice; pass-2 onset removed → pure motor), shipped via =prevSame=.
