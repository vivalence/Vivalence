* AIMED vs AIMABLE — beef asked, reasoning given, no rename

Beef: /"maybe we should rename the trait AIMED into AIMABLE. what do you
think?"/ Checked the register: every trait in the system names a STATE
(=MASKED=, =LABELED=, =QUEUEING=, =CONVERSATIONAL=, =HARNESSED=, =EXPOSED=,
=STANDALONE= — past-participle/gerund), never a capability-suffix.
=traits.includes("AIMED")= means "this thread HAS BEEN aimed" (toggled on,
=trait.AIMED.mount= stamped) — a state, correctly named. The thing that
actually reads as a capability check
(=e.svelte:37=, =\($mode?.emitter?.leaves?.length ?? 0\) > 0= — "can this mode
even offer AIMED") is a DIFFERENT, already-separate concept from the trait
name itself — same shape as the STANDALONE split above (mode-capability vs
thread-state). Recommended against the rename — =AIMABLE= would be the one
loner "-able" name in an otherwise consistent register, for no semantic
gain. If beef wants to name the capability concept, that's a NEW trait, not
a rename of this one. No code changed.

* the harness-call live-debug — false lead, real bug was trivial

=Oracle.svelte='s =askHarness()= (interaction 2, the client-compiled harness

for "render" (only =.branch()= does), so =resolve()= falls back to the
parent — but the request URL is computed independently
(=this.url.branch(endpoint)=) and dispatch still bubbles through the same
carry chain via the parent's transport closure, so this is harmless, not a
bug. Floated an alternative, EXPLICITLY UNCERTAIN hypothesis (TypeBox schema
built client-side and JSON-serialized over the wire vs built server-side,
losing Symbol-keyed type markers) — flagged as an untested guess, not a
claim.

Actual root cause, beef found and fixed it himself: a SHARED =pending=
boolean gated both async handlers; the form's =onsubmit= calls
=askAperture(); askHarness();= sequentially — =askAperture= set the shared
flag before =askHarness='s own guard (=if (pending) return;=) ran, so
=askHarness= silently no-op'd every time. Split into =pendingAperture=/
=pendingHarness=. Nothing to do with the harness/schema mechanism at all —
beef: /"fixed. issue was a shared pending state gate. ignore."/ Both
interactions confirmed live, working, side by side.
