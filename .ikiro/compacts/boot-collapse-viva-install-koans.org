* Variant ontology (corrected)

@beef: *"you have not understood what a variant is yet. a variant shows up
unter $SYSTEM as an instance. its a running instance of the system according
ot config in our variant."*

- =$SYSTEM= (~/.viva) = the machine ledger of running instances (instances.json,
  locks/, logs/).
- variant = a *running instance of the whole system*, configured by its variant
  config. The .viva.js marker is its declaration, not the variant itself.
- it registers under $SYSTEM: instances.json[slug] → mount.
- ~/vivatemp = the "localhost" instance (marker + environment/ + materialized
  mountpoint/{daemon_*,service_*}); ~/viva = dead pre-current-architecture home.

* viva install

@beef: "THIS SHOULD LIVE IN GHOST" · "ghost.sh but used per default as viva"

Findings:
- =deno install -g= IGNORES =workspace= + =importMap= → "@vivalence/typology not
  a dependency". Global install = self-contained tool only. Works only post-publish.
- Repo-install needs a WRAPPER (=deno run --config <root>= honors workspace).
  deno install is the *jsr-future* UX, unreachable from a workspace.

Built — env-file anchor + generic symlinked launcher:
- =systems/ghost/ghost.sh= (generic): sources =$XDG_CONFIG_HOME/viva/env=, sets
  =VIVA_ENV_FILE=, execs =deno run --config $VIVA_REPOSITORY_MOUNT/deno.jsonc=
  ghost/mod.js. No baked path → committable verbatim → symlinkable (live edits).
- =systems/ghost/install.sh= (pure sh, no viva/deno needed = valid bootstrap):
  upserts =VIVA_REPOSITORY_MOUNT= into =~/.config/viva/env=, symlinks ghost.sh →
  =~/.deno/bin/viva=.
- root =viva/install= task → =sh systems/ghost/install.sh "$(pwd)"= (escape-hell gone).

Through-line: =~/.config/viva/env= is the durable machine anchor across channels
(dev symlink / jsr / curl). 3-tier config: ~/.config/viva (bootstrap, pre-mount)
· ~/.viva (state) · variant/environment (per-instance + secrets).
