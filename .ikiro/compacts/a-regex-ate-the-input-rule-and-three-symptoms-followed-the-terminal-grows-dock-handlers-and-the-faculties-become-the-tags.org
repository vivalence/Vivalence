* one deletion, three symptoms

#+begin_example
  .agent input,
  .composer input {          ← the regex matched HERE and cut to the closing brace
    flex: 1; background: transparent; border: none; outline: none;
    color: var(--ink); font-size: var(--font-size-xs);
  }
  .agent.blocked input { cursor: not-allowed; }

                              ↓ after the cut

  .agent input,
  .agent.blocked input {
    cursor: not-allowed;     ← the input's ONLY remaining style
  }
#+end_example

Lost `flex: 1` → the button had nothing pushing it, so it sat wherever the box collapsed to.
Lost `background: transparent` → the browser's default white field inside a cream bar.
Lost `font-size` → the default 16 px against a 12 px design.
Gained `not-allowed` unconditionally → the cursor beef named.

Four defects, one line of regex. The check I ran afterwards was the Svelte compiler's
`css_unused_selector` list, which is exactly blind to this: a deleted rule raises no warning, and the
orphaned selector went on matching. The audit that WOULD have caught it is one grep —
`^\s*\.[a-z].*,$` for comma-grouped selectors, which found the orphan in one line once I went looking.

* three callouts

- *a regex is not a parser, and a compiler warning is not an audit.* Cutting CSS rule blocks by
  `\.selector \{[^}]*?\}` is correct only for rules that are not comma-grouped, and nothing in the sweep
  tested that. Corrective rule: when deleting declarations, delete by SELECTOR LIST — check for a
  trailing comma on the line above and the line below first — and verify with a grep for orphans
  (`^\s*\.[a-z].*,$`), never with the compiler's unused-selector output, which cannot see an absence.
  Same family as the codemap's `generated` invariant: parsing is not verification.
- *a screenshot that names three things can be one thing.* beef reported the button position, the
  background and the cursor as three complaints. Treating them as three would have produced three
  patches over a corrupted rule. Corrective rule: before fixing any of them, read the rule that governs
  all three — a cluster of symptoms in one component usually shares one declaration block.
- *prove a trait from the route, not the manifest.* /"is it harnessed?"/ is answerable from
  `mode.viva.js` in one grep, and that answer is a claim about a file. `/metadata/harness` returning 200
  is the trait itself, because `metadata.js:47` only mounts that route when `implements("HARNESSED")`
  holds on the live mode. Reach for the surface a trait CAUSES, not the declaration that requests it.
