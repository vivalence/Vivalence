* the latent bug — validate and flag

beef pushed back on my bug claim: /"i am not sure this is a bug
actually. i suspect the connection middlewares are handled different
from koa middlewares. i think there is a fetch at the top of the
dispatch queue that can handle multiple next loops. validate. and
flag!"/

Validation, static: =Connection.dispatch= is
=compose(this.carry)(ctx, this.transport)= — the transport is NOT above
the queue; =middleware.js= splices it in as the final dispatch position
(=if (i === middleware.length) fn = next=) under the same monotonic
=index= closure. Nothing resets it. Child connections nest fresh
closures per level, but retry loops within one level.

Validation, empirical (scratchpad repro, real compose + real retry,
transport failing once retryable):

: RESULT: rejected — next() called multiple times { attempts: 1 }

Transport never re-invoked. retry NEVER retried since birth; every
retryable failure crashed the whole chain instead. Flagged ⚠ BROKEN at
the site. Live confirmation arrived in beef's next console paste: CORS
failures (=:2501/attached/process/lighthouse/multiplayer/*=) → retryable
→ crash. beef: /"you seem to be correct. ok. show me the diff for
fixing this"/

Also triaged en route, unrelated: every-refresh
=ConnectionError: Network request failed @ …/thread/find= — daemon
connection has NO retry middleware; that one is teardown/HMR abort of an
in-flight batched fetch, surfacing uncaught because =d.svelte= calls
=find()= bare and =batch= fans one abort into N rejections.

* the connoisseur assessment (beef: "bingo! thats the right level")

First diff moved the loop into =Connection.request= (re-issue per
attempt, stamp middleware carries policy). beef: /"let the conoisseur
have an assessment here. i dont want to overload teh connection."/

Verdict: retry-as-middleware vs retry-in-request is the FALSE BINARY —
both misplace it. Third object: retry is policy on the network EFFECT,
and the effect already has a boundary — the transmitter. Rubric hits:

- effect over model — retry doesn't belong to the transport dual
  (branch/resolve, cata/ana pair 4); it belongs AT the effect.
  =shard/transmitter.js= already holds the transport family (=fetcher=,
  =inline(serve)=) — a combinator joins that register.
- transducer shape (external canon) — "the reducing function wrapped":
  =retry(transport, options) => transport'=. Same signature in, same out.
- the request-loop diff winced twice: prototype's core verb absorbing
  backoff math (trigger-3 twin), and a stamp middleware whose name lies
  (=.use(retry)= reads "retry sits here in the onion" while behavior
  lives elsewhere — metaphor must be TRUE).
- guard stays holy — wrapper owns the inner call; compose never sees a
  second next(). Zero diff to middleware.js and connection.js prototype.
- tree-wide for free — =child()= transports funnel into the root's
  transport, so every branched daemon path inherits the policy from one
  construction site. beef: /"and the nesterd shards is fucking elegant
  as fuck holy shit."/

* landed (on "go") and verified

- =gestalten/shard/transmitter.js= — =retry(transport, options)=
  combinator (maxRetries/baseDelay/maxDelay/shouldRetry, exponential
  backoff + jitter, =ctx.response= reset + =_controller= null per
  attempt).
- =gestalten/shard/connection.js= — retry middleware DELETED, =Response=
  import dropped.
- =kajuit +layout.svelte= — =new Connection(url,
  shard.transmitter.retry(shard.transmitter.fetcher, { maxRetries: 2 }))=.
- =stores/lighthouse.js= — =.use(shard.connection.retry(...))= dropped.

Proof: repro completed ={ attempts: 3, middlewareRuns: 1, body: "OK" }=
(onion runs once, transport retried) + exhaustion path returns the error
