Symptom: spawner emitter creates buffers (DB rows written, client console =is.yieldish(body)= true with 3 buffers), but the F-panel buffer list stays frozen at the one boot-loaded buffer. * Root cause (confirmed read-only)
=broadcaster.push(event, entity)= (=prototypes/broadcaster.js:68=) matches the subscription filter against the *live MikroORM entity* via =object.match= (=belt/object.js:54=, strict ===). Buffer subscribe scope = ={ thread: { user } }= (=daemon/aperture/userspace.js=). A buffer has no =user= — only =thread.user=, two hops — and the live entity's =thread= is an unloaded Reference. =object.match(buffer, { thread: { user } })= → nested key absent / Reference !== id → FALSE → every buffer event dropped → client =buffer.$entities= never updates → =thread.$buffers= never recomputes → panel frozen. DB write is a separate path, so rows land while the broadcast silently drops. General fragility: =object.match= on a live ORM relation can never === a scalar id; this also silently breaks thread/turn subs.
Finn distilled it: "whats the issue?! issue is that the entity that twitches receive doesnt contain the information we need to match across relations. correct?" — yes.

* Subscription IS user-scoped (server-stamped)
=userspace.js= line 6 =branch.use(shard.secure.authorize())= sets =ctx.user= on every request incl the SSE =/subscribe= GET; =scope= middleware sets =ctx.scope={thread:{user}}=; reactive =/subscribe= builds =filter={...where, ...ctx.scope}=. Client sends nothing about the user — the server stamps the scope from authed =ctx.user=. Scope correct; the MATCH is starved of data.

* SHIPPED — owner-stamp from ambient + match the wire shape
The true root cause is matching the LIVE entity instead of the serialized payload =reactive()= already builds (=toJSON= collapses every Reference to a scalar id). The writer's user is already in the request context: root aperture (=lifecycle/resolution.js:4-7=) runs =authorize= + =ambient.store(ctx=>({user: ctx.user}))= + =bind("user")= for every authed request including =/emit=, so =ambient.current()?.user?.id= is the owner at buffer-create time.
=subsystems/typology/gestalten/shard/datamap.js= — =reactive(repo, twitch, { scope })=:
#+begin_src js
twitch.open(`/${name}/${op}/after`, (ctx) => {
  const serialized = ctx.input.entity?.toJSON?.() ?? ctx.input.entity;
  if (scope && serialized && typeof serialized === "object") {
    const owner = ambient.current()?.user?.id;
    if (owner != null) serialized.user = owner;
    else console.warn(`[reactive] ${name}/${op} written without an owner — dropped from user-scoped broadcast`);
  }
  broadcaster.push({ op, entity: serialized }, serialized);   // match the wire shape, not the live entity
});
// /subscribe filter: scope ? scope(ctx) : ctx.scope || {}   — decoupled from repo find/create scope
#+end_src
=systems/runtime/daemon/aperture/userspace.js= — buffer + turn reactive pass ={ scope: (ctx) => ({ user: ctx.user.id }) }=. Thread unchanged (its existing ={ user }= scope works once the match is serialized).
Why decoupled scope: the branch's =shard.datamap.scope= still feeds the repository find/create as ={thread:{user}}= (a flat ={user}= would throw — Buffer has no =user= column). Only the broadcaster filter flips to ={user}= to match the stamped field.

* The ACL question (Finn's instinct, half-right)
Finn: "in cases where we dont have a user, we want to subscribe to EVERY entity. that SOUNDS correct.!??!" Resolution:
- no =scope= (literal/symbol, global): events carry no =user=, subscriber filter ={}= → =broadcaster.push= empty-filter branch pushes ALL → everyone. Correct, already true.
- =scope= set (owned) + missing owner: =console.warn= + DROP — NOT broadcast-all. Treating a user-scoped entity that lost its owner as "public" would leak one user's data to every subscriber. The =scope= flag is exactly what separates global-public from owned.
