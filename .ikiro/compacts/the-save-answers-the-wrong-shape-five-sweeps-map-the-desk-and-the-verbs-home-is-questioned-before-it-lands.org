- *Buffer carries no trait.* ORM, schematic, table — none. Only =data= and =view= are atom-backed

  idiom. Kernel =LiteralTraitsEnum { _ }= sits under =// @beef: FILE trait on literal=.

  SSE → =em.merge= → =Buffer.set data= → =$data.set=. Zero Apps read =buffer.$data= except
  Card/Spawned. No harness section carries any buffer; the model's whole view of a document is
  =fs_read=; no =ctx.buffer= in tools.
- *Two writers never meet in the vdex.* Agent =fs_write= → disk; user =save()= → =/write= →
  disk; the App's text is local =$state=. =DOCUMENT.hash= exists on the row; nothing reads it.
- *Domain traits replace, not extend.* voffice re-declares the =traits= property with its own enum
  (=collate= takes the last tier); a system noun on the literal needs the domain enum to spread the
  kernel's. Mikro validates enum arrays at flush — the m23 boot crash — so this is not decorative.
