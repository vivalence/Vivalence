#+TITLE: chaosmonkey/oracle — high level

Companion to the detailed compact
(=chaosmonkey-oracle-harness-lexicon-and-exposed-aperture.org=). This one's
the zoomed-out version.

* what shipped

- =registry/development= → =registry/playground= (package rename).
- =chaosmonkey= — two modes: =bystander= (bare control, no interaction) and
  =oracle= (the real demo). Both =STANDALONE=.
- Oracle proves M12's core mechanism LIVE, two ways side by side: an
  exposed aperture calling =harness.object.render= server-side, and the
  same call made directly from the client via a strip-wired harness.
  Both verified against the real anthropic API, not mocked.
- Ontology fixed: harness = a FIXED lexicon (dialogue/object × render/
  stream, same shape everywhere, cortex-derived) — never mode-semantic.
  A mode's own custom nature (like =/ask=) belongs on an EXPOSED aperture
  instead — a pre-existing, generic, trait-driven mechanism (any mode can
  export an =aperture=, no new machinery needed).
- =cortex.js='s object faculty now returns =.object= directly (no more
  =parts.find(p=>p.type==="object")?.data= per caller) — pushed into the
  source once, propagated to every existing call site (dealer, riddler×2,
  oracle).
- Client-side harness wiring (strip-wire, mirrors emitter's) shipped and
  proven live for the first time this session.
- Two real bugs found via live use, both fixed: =STANDALONE= missing from
  both manifests (blocked buffer creation entirely), and the browser's
  6-per-host SSE connection cap (3 daemons wedged all fetches) — fixed by
  retiring the standalone =chaosmonkey= daemon into =playground='s kernel.

* why it matters

M12's design (aperture → harness.object.render, strip-wired client call)
isn't just designed anymore — it's built and demonstrably works end to end,
in a real browser, against a real model. Along the way, two already-existing
but under-used mechanisms (=STANDALONE= for emitter-less buffer creation,
=EXPOSED= for mode-authored raw apertures) turned out to be exactly the
right tools for problems that first looked like they needed new
infrastructure — nothing new had to be invented in typology. The harness-
is-lexicon-not-vocabulary distinction is a real, reusable design rule for
whatever gets built on HARNESSED next.

* what's still open

- The ORIGINAL M12 demo (toolcalling inside aprende's helpdesk) — not
  started. Chaosmonkey/oracle proves the mechanism works, not the aprende
  integration itself.
- M10's =monkey= (six-axis harness testbed, reserved slug) — untouched,
  still distinct from chaosmonkey.
- Browser connection-budget real fix (multiplexed =/subscribe=, quest m16)
  — deferred; the retired standalone daemon was the interim patch.
