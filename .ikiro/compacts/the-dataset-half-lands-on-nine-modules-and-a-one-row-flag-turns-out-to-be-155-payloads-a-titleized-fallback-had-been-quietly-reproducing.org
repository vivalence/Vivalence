Correct, and it was worth proving rather than agreeing. =DATASINK= has zero
production consumers: the trait itself, one warn at
=lifecycle/resolution.js:45= for exporting =datasink= WITHOUT the trait, and

and the grep is what turned that from a hope into a fact.

* the one-row flag was 155 rows

Filed at the end of a proposal as a courtesy note: =topologies/conjugation=
uses =data:= where every other row uses =trait:=. Flagged, not fixed.

#+begin_quote
fix.
check which and fix.
#+end_quote

The check inverted the flag. =data:= is not a one-off typo — it is the
MAJORITY spelling in the topology files: =word/ontological.js= 111 rows,
=sentence/ontological.js= 44, plus the conjugation one. And
=entities/kernel/Symbol.ts:54= declares =trait: { type: types.json }= with no
=data= property at all, so all 156 installed with **empty trait payloads**.

Why nobody ever noticed, and this is the keeper:

#+begin_src javascript
// systems/kajuit/src/app/panels/e/widgets/form/picker.js:57
return symbol?.trait?.LABELED?.name ?? titleize(symbol?.slug?.split(".").at(-1) ?? "");
#+end_src

A titleized =word.part-of-speech.adjective= is "Adjective" — character for
character the authored name. **A fallback that reproduces the value it replaces
hides its own failure indefinitely.** The data had been broken since it was
authored and the UI looked correct the entire time. It only surfaced because
the cutover made me read the symbol files, and it only got fixed because beef
asked which key was right instead of accepting the flag as written.

Family: `graceful-degradation-conceals-the-defect`. The same shape as a skip
that counts as a pass, later the same session.

* inline entities did not work, and running it is what said so

beef, reading the conjugation cutover:

#+begin_quote
ah gooood. its already possible to keep entities INLINE!
#+end_quote

#+begin_quote
this works right?
#+end_quote

No. =[sources].flat()= cannot tell a list of SOURCES from a list of ROWS: it
flattened the row array, and =reader.lift(row)= took the =is.object= branch and
returned THE ROW as a source descriptor. Eight of the nine modules passed;
conjugation — the only one declaring inline — died with
=paladin.read[source.codec] is not a function=. The quest's own vocabulary
section had promised "a source is a mount-relative STRING, a directory STRING,
or an inline row array" for four sessions, and the carrier had never been able
to do the third.

#+begin_quote
i for sure want inline entities
#+end_quote

Fixed with a structural discriminator, not a domain sniff:

#+begin_src javascript
const descriptor = (item) =>
  is.string(item) || is.array(item) ||
  (is.object(item) && ("rows" in item || "read" in item || "walk" in item));
#+end_src

The first draft of that predicate omitted =is.array= and would have broken the
live mixed case at =tests/datasink.test.js:23= —
=["dataset/literals/words", [{slug:"synthetic"}]]=. Caught by reading the
existing gate before running it, which is the cheap half of blast-bracket doing
its job. New gate case landed beside it.

* "update teh system" was a real second implementation

=systems/runtime/tests/scenarios/bench.js:201= read
=mode.module.dataset.entities= — which the carrier stops exposing — so after

* the red that was a skip wearing green

The runtime suite went 16/95/0 → 15/93/1 immediately after the rename, which
reads exactly like a regression from the thing that just landed. It wasn't.
=tests/aperture.snapshot.test.js= hardcodes =const DAEMON = "brazilian"= and
guards with =alive()=, which only asks whether =:2501= answers — not whether
the daemon it wants is mounted. Three states, two of which are indistinguishable
from outside:

| runtime | brazilian mounted | result        |
|---------+-------------------+---------------|
| down    | —                 | SKIPS → green |
| up      | yes               | runs → green  |
| up      | no                | 404 → RED     |

beef's boot flipped it from state one to state three. The live variant mounts
italian + playground. Written up in =known-issues.org= — same class as the
=BASELINE = 39= pin: a test asserting a literal about a deployment it does not
control. **A skip that counts as a pass makes "green" mean "verified OR not
run", and nothing in the output separates them.**

* the sink has no provenance, and beef felt it before he could name it

Asked for the italian sink and a full migration:

#+begin_quote

#+end_quote

#+begin_quote

#+end_quote

Right, and the mechanism is sharper than the phrase. =repo.find(sink.where)=
queries the daemon's WHOLE dataspace and **no row records which module installed
it**. So the italian declaration this quest had carried for four sessions is
self-contradicting: ={traits: ["ONTOLOGICAL"]}= matches italian's 3
=word.suffix.*= AND the 156 topology-owned symbols, while the same section
states =orphans.symbol: 156= — a number that assumes those rows go unclaimed.
Both cannot be true. One drain plus one reinstall and italian becomes the
declaring owner of =topologies/word='s vocabulary, silently, with every count
still looking plausible.

Slug namespaces are the only selector that respects a package boundary, because
a slug prefix is owned by its declaring module and a trait is a shared
vocabulary. ={traits: ["STRUCTURAL"]}= survives only because nothing else
mounted declares one — a fact about the deployment, not the selector.

Second half of the same finding: =report.orphans= is computed from
=repo.count({})=, also unscoped. "Orphans" means *rows on this daemon nobody
claimed*, not *rows of mine*. Italian owns 2436 of 2592, which is exactly why
the figure looked sane and hid the capture underneath it.

That is what makes the demo NOT italian — =daemon_playground= has Symbol 0 /
Literal 0, so it is the only daemon where the census means anything.
