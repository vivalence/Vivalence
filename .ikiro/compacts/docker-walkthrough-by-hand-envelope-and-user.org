* Decision: Dockerfile install path — reuse install.sh, not bespoke shim

@beef: =RUN deno install --entrypoint ./systems/ghost/mod.js ./systems/runtime/run.js
... is this the right way to install ghost mod? what are our alternatives=

Surfaced four options:
- A: reuse =systems/ghost/install.sh= (host parity, symlinks =~/.deno/bin/viva=
  → =ghost.sh=, writes =~/.config/viva/env=)
- B: =deno install -g ... -n viva ./systems/ghost/mod.js= (deno-native, but
  loses cwd-magic + env-file sourcing)
- C: pre-cache + corrected manual shim (duplicates install.sh logic)
- D: drop the line entirely (less is more)

@beef: =a.= → applied. Also asked: scaffold B as commented alternative for
quick swap. Result:

#+begin_src dockerfile

# alt: deno-native global binary (no env-file sourcing, no INIT_CWD)
# RUN deno install -g --config ./deno.jsonc -f -A -n viva ./systems/ghost/mod.js
#+end_src

Also killed the broken =/viva/repository/./systems/shell/mod.js= hand-rolled
shim (stale path — shell renamed to ghost). install.sh is now the single
source of truth for "how viva gets on PATH" across both host and container.

* Decision: runtime Dockerfile loses the re-COPY

@beef on a 3-line dissection (=COPY systems/=, =COPY subsystems/=, =COPY registry/=):
*"do we need this? less is more?!"*

No. Base Dockerfile already COPYs all three. =deno task build= chains
base→runtime→kajuit, so base is always fresh when runtime builds. The
re-COPY is a duplicate layer with zero benefit. Cut. Runtime Dockerfile is now:

#+begin_src dockerfile
FROM vivalence/vivalence:alpine
WORKDIR /viva/repository
ENV VIVA_SYSTEM_MODE="RUNTIME"
CMD ["deno", "run", "-A", "systems/runtime/run.js"]
#+end_src

Two effective lines over base (mode pin + cmd). Image = engine. Envelope = fuel.

* Bind-mount convention: =testament/docker/=

@beef ran the full envelope with =-v ./mountpoint/:/viva/mountpoint= from a
new =testament/docker/= dir. Docs absorbed this as a convention: drop into
=testament/docker/=, bind-mount =./mountpoint/= (and optionally =./system/=)
to keep dev state out of git but visible on host.

Per-daemon and per-service subdirs (=daemon_<slug>= / =service_<slug>=) each

container teardown.

* What's *not* in the envelope yet — answered the @beef inline marker

@beef left an =@beef whats missing?= marker in the §4.4 example after the
12-flag invocation. Documented what the bare invocation does *not* unlock:

- =VIVA_SYSTEM_ROLE=RUNTIME= — defensive, image bakes MODE not ROLE
- hallucinator secrets (=SECRET_VIVA_ANTHROPIC_API_KEY= / =ELEVENLABS= /
  =DEEPGRAM=) — three providers declared in the daemon manifest, inert at
  boot, throw on use without secrets
- =VIVA_SYSTEM_MOUNT= — defaults to =/root/.viva= in container (vanishes on
  exit); bind-mount if you want =instances.json= + locks to survive

"Twelve flags get you booted. Sixteen get you a production-shaped deploy."
