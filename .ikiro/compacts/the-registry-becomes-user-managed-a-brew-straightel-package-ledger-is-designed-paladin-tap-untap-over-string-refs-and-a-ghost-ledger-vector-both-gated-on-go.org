* Proposal ① — the paladin layer (=tooling, interface, tests=)
The SHIFT: =registry.json= stops being DISCOVERED (=seed(scope.registry)= lists one tree) and becomes MANAGED — a manifest of user-tapped references. Two distinct "registry" things pinned:

- **registry MANIFEST** = =ledger.registry= / =registry.json= — a list of references.

**Reference = a STRING discriminated by prefix** (the keystone — NO schema change to =registry.json=, backward-compatible with today's absolute-path array):
#+begin_src text
"/abs/path"             → verbatim external dir  (dev monorepo checkout)
"./rel" | "rel"         → relative to registry root  (tapped/installed)
"@owner/type/slug[@v]"  → logical identifier → store path under registry root
#+end_src
Resolution is registry-owned (base = registry root), NOT a =paladin.source= overload (whose base is cwd/repo) — the two resolution contexts must not bleed.
