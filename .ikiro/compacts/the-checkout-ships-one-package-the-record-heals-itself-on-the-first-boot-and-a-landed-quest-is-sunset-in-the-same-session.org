* the two code laws that landed

=Vip.supply()= = =registry.reconcile(checkout, <checkout>/commons)= ?? =seed(<checkout>/commons)=. A dead
record location ANYWHERE under the checkout heals by rediscovering =commons/=; a dead external one is
kept, skipped, =vip.stale=. =Registry.discover= over a missing root returns =[]= so =accio= says
=not supplied= instead of a stack trace. The real ledger proved it unasked: the runtime suite's first
=supply()= after the move rewrote =~/.viva/registry.json= from three dead =registry/*= rows to
=[education, stucatch, <repo>/commons]= — critical pass §10 said this would happen during the test
run, and it did.

=Pensieve.register= throws when a second FILE claims a held owner/type/slug/version — and ONLY a
different file. The pre-check that shaped it: ghost's =lens.js=, =registry/index.js= and
=instance/create.js= and runtime's =populate.js registry()= all call =supply()= on the same paladin
singleton, so a =use italian run= chain re-registers every module from the same path. Identity ↔ one
source file; the same file twice is idempotent, a second path is a shadow. =find.js= skips =*.bak=
beside =bak|archive|slp=; the F9 census found zero duplicate identities across education · stucatch ·
commons once =*.bak= was out, and education's old =tmp/= shadow tree is gone.

* the scratch-ledger lesson

=export VIVA_LEDGER_MOUNT=<scratch> VIVA_REGISTRY_MOUNT=<scratch>/registry; viva registry/doctor= did
NOT run on a scratch ledger. The strata are =flag > cwd > instance > .env > os > session > ledger=:
the repo-root =.env= (cwd stratum) outranks the exported var, and =ghost.sh= re-sources
=~/.config/viva/env= on top. The doctor ran against the REAL record with a scratch STORE and printed
two taps as =gone= — =reconcile= kept them (dead-external = kept + reported), and =cat
~/.viva/registry.json= afterwards showed the three rows intact. The working shape: =cd <scratch>= (no
=.env= in cwd) and =deno run --config <repo>/deno.jsonc -A <repo>/systems/ghost/mod.js …= with the
vars exported — no =ghost.sh=, no cwd stratum, no session file in a ledger that has none. Non-TTY
render of =registry/list= is the key/value list, not the table; the docs keep the table with the
captured row data, home-normalised as they already were.
