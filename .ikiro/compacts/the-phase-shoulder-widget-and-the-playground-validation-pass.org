* TWO ARCHITECTURE FINDINGS (load-bearing — the reason for the detours)
** buffer-views are typology-only — confirmed the hard way ([[project_buffer_bundle_typology_only]])
A legend rendered in the spawner (a BUFFER VIEW) imported the drapes =<Icon>= → the buffer bundle
served but CRASHED at mount: =Cannot read properties of null (reading 'f') at CaretLeft=. The
runtime bundles each buffer view standalone (its own Svelte); carbon-icons-svelte's *legacy* (Svelte-4)
components crash in that isolated runtime. Finn's hypothesis — "in typology/ bundler we define our
importmap for svelte buffers. fix!?" — checked out FALSE: =runtime/daemon/traits/application.js=
ALREADY maps =@vivalence/drapes=; resolution isn't the problem, the Svelte dual-runtime is. *The
rule holds: buffer views import ONLY typology.* The fix = inline the Carbon SVG paths (extracted
from the lib) — buffer-safe, keeps isolation. The app-layer Phase widget uses the real =<Icon>=.
(The legend was later removed — Finn: "remove the ephemeral stuff from spawner" — once icons were chosen.)
** Svelte style-scoping doesn't cross component roots (the "nothing is clickable" bug)
Finn: "the label is still not clickable! none of them are clickable." Root cause: =shoulder.svelte=
has =.population { pointer-events: none }= + =.population > * { pointer-events: auto }= — but that
scoped => *= rule gets the shoulder's style-hash, which the child =<Phase>='s root never has (scoping
stops at component boundaries). So Phase inherited =pointer-events: none= → the whole widget was
inert the entire time (every prior live-click silently missed). Fix: =pointer-events: auto= ON the
widget root itself. JS-confirmed after: =key.click()= → menu cells render.
** runtime/run caches bundles
=deno task runtime/run= (not watch) bundles each mode once and caches; a buffer-view source change
needs a runtime RESTART to re-bundle (HMR only covers the app layer). Several restarts this pass.
