** fix both, with the right pointer (row 24)

beef quoted the =sudo= row and the =curl … | sh= row: /"fix both. second one with right pointer. then give me the
remaining issues again"/. The pointer was measured, not guessed — deno's =install.sh= runs its shell setup
only when =[ -z "$CI" ] && [ -t 1 ]= or =should_run_shell_setup= (=-y=); headless it writes nothing. Proven in a
fresh =$HOME= inside the container: =sh -s -- -y= → =Deno was added to the PATH=, =~/.deno/env= written and
sourced from =.profile=, a new login shell finds deno. So:

#+begin_src sh
# README.md §0 — after
# sudo apt-get update && sudo apt-get install -y curl ca-certificates unzip git   # debian/ubuntu — drop sudo as root

curl -fsSL https://deno.land/install.sh | sh -s -- -y     # -y persists PATH in your rc even headless (docker, CI, piped)

export PATH="$HOME/.deno/bin:$PATH"                       # this shell only — new terminals read the rc
#+end_src

The third line had been COMMENTED (=# tty install=) — a same-shell reader hit =deno: command not found= at
=deno task install=. Live now. Side effect: =-y= writes the very file ghost's =install.sh:9= tests, so the
false warning left the README path before its own fix landed.
