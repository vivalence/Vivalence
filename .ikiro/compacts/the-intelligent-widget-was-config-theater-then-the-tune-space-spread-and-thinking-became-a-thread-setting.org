* arc

** the widget that lied twice

The phone screenshot said "BUGGY and ugly"; the code said worse. The presentation lied
(iOS keeps =:hover= after tap, and hover was near-identical to on — three chips read
selected in a provably single-select field), and the SEMANTICS lied deeper: every chip
tap wrote =trait.INTELLIGENT= without ever claiming the trait, so the daemon's
=claimed()= gate — =traits.includes= first, the codemap's own invariant — discarded the
config wholesale. The header saying AVAILABLE while the widget accepted input was the
tell. Config theater: UI state accumulating client-side with zero projection. The fix
made configuring CLAIM (first write carries =traits=), and the presentation went
unambiguous — filled chip, hover only where hover exists.

** beef asks, and a memory law dissolves

The intelligent-trait memory carried a standing law: model/provider names NOT shown,
extending the strip = ask first. Row 89 was beef asking from the other side. The strip
gained =provider= + =config= (spread-guarded — fixtures carry neither), registration
stamps the manifest slug, two providers put =config.model= on their faculties, and the
widget's resolved line now names its machine. Then row 96 turned the new visibility on
the data itself: the tune vectors were byte-identical across providers — nearest() was
resolving three exact ties by boot order. The spread that followed was MEASURED into
place: a scratch matrix over the real =nearest= showing every tier's winner and margin,
before and after. The E-panel cell grids now differ per chip because the underlying
space actually does.

** screenshots as work orders

The window's rhythm: beef fires a phone/desktop screenshot with one sentence of scorn,
the diagnosis comes back with the mechanism named, the fix lands, the next screenshot
arrives. Four rounds: widget bugs → axes redo → dock meta chrome → thinking setting.
The one correction that stung usefully: "do a BIIIIT more brain on design" — the axes
had been laid out structurally (grid, 1fr, fixed name column) instead of designed
(what does a 0-1 scalar WANT to look like at any width). Discrete cells was the answer
the second time; it should have been the first.
