* The oracle trace crash → three durable LAWS

1. **Span records must be serializable snapshots, never live object graphs.** Noting =terminal=/=buffer= (cyclic reactive entities) poisoned the whole downstream (render recursion, persist cycles). Category-kill PROPOSED (typology, deferred): =Span.mark= snapshots =data= at record time so a live ref can't enter the stream.
2. **A trace story → =$state.raw=, never deep =$state=.** It's replaced wholesale each fold (reference-reactivity is the fit), and deep-proxy DEFEATS a WeakSet cycle guard (Svelte re-wraps proxies per access).
3. **Instrumentation ≠ domain state.** Client debug trace = client storage (localStorage keyed by id), not =buffer.data=→daemon. The reactive-=$data=-sync (server↔client via a nano shard) is a real project but "massive scope creep" — correctly out of scope.
