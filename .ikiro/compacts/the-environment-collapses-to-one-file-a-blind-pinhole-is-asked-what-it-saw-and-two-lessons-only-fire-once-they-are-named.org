* the schema is authored, and the pinhole CHECKS it (turns 16, 18, 22)

=.env.template= was rejected as /"the right instinct and the wrong artifact"/ — it needs syntax dotenv
does not have, and beef's own accepted law routes it: *anything with structure stays JSON; anything
that is an env bag is a =.env=*. The field agrees — envalid, znv, t3-env, zod, dotenvx all put schema
in CODE and none parse the env file.

So: =export const environment = {…}= beside =manifest=. beef: /"amen."/

Generation was abandoned in BOTH directions — /declaration → template/ cannot write prose,
/template → declaration/ drifts from what is read. The pinhole does not generate the schema, it
*checks* it, and only in the direction that is never wrong: a thunk reading a key is proof of a
requirement, so =UNDOCUMENTED= survives and =UNREAD= dies.

=.env.example= was killed outright, not generated: /"its only unique job is bootstrap without tooling
— but the tooling ships inside the instance."/
