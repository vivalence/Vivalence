* Decisions

- Canonical identity: =crackedbeefcake <beef@vivalence.org>= (Finn flipped from workpackage's locked =beef=). All three sources (git global, jj user, =.mailmap= line 1) aligned to this single name+email tuple BEFORE filter-repo ran.
- =.mailmap= line 8 dropped entirely. The originally-proposed inverse mapping ( =crackedbeefcake <...> beef <...>=) was unnecessary — workpackage scope confirmed no =beef <beef@...>= bytes existed in history (88+94 commits with that email all authored as =crackedbeefcake= via name-only-difference).
- Backup strategy: single zip of full repo (excluding =node_modules=, =.svelte-kit=, =dist=, =tmp=) → cloud manual upload. NOT 3-tier (sibling + archive + cloud + remote-branch). Robbery context shifts priority to "off-laptop survives", not "rollback fidelity".
- Skip =presentation= remote ( =ssh://git@git.vivalence.org:2222/vivalence/vivalence.git= ). Remains on pre-rewrite history. Future cleanup or abandonment is a separate decision.
- Push =trunk= only on origin, not =--all=. Dead =feature/*= and =push-*= refs are not worth landing through GitLab branch protection. Github already ate them all (no protection there); origin gets the live ref only.
- =.mailmap= deleted post-rewrite. Bytes are canonical now; the file is a runtime-alias artifact whose only purpose was the rewrite-input. No stub kept.
- jj recovery from filter-repo: =rm -rf .jj && jj git init --colocate= is the recipe. Selective op-log repair is not viable when working-copy SHA disappears. Op-log loss is acceptable because (a) zip backup preserves pre-rewrite =.jj=, (b) rewritten git is the new source of truth.
- Filter-repo's origin strip is safety-by-design ("Why is my origin removed?"). Manual =git remote add= post-rewrite. Don't fight it; just restore the three remotes (or two — Finn dropped =presentation= follow-through).
- Github's blanket force-push acceptance vs GitLab's protected-branch rejection: known asymmetry. GitLab requires UI unprotect (or "Allowed to force push" toggle) per protected branch before destructive history rewrites land. =trunk= was the only protected ref relevant.
- Single-line bookmark push beats =--all= when push is destructive + remote is selective. Even when no protection exists, =--all= ships dead history (every old =push-*=, every abandoned =feature/*=) to the rewrite. Curate before push.
- zsh =$VAR= without quotes does NOT word-split (bash does). For multi-line variable expansions, use =xargs -n1=, =${=VAR}= (zsh-native split), or explicit array. Will show up again any time =for-each-ref= output drives a loop in zsh.
