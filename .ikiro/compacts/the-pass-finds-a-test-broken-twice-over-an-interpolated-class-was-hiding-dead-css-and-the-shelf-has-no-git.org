* what happened, in one breath

Four words reopened the quest — /"do another pass over drapes editor. are we ready?"/ — and the honest
answer was no. The pass probed instead of reading, and the gated wrapper's own test turned out to be broken
twice over: it reached for =.parser= on a =LanguageSupport=, which has =.language=, and then asserted seven
generic lezer node names against a =StreamLanguage= whose node names are its own =tokenTable= keys. Both
halves were stale from the =simple-mode= sketch the real org mode had replaced, and neither had been re-run
since. A second blocker followed from the same discipline: the swap left =caret= write-only, because its
one reader was the paint layer the swap deletes. Three smaller defects and two judgment calls went with

".pdf"= after, and the cause was not a regression but Svelte's pruner — an interpolated class attribute
makes every class selector possibly-matching, so =.pdf= had been dead the whole time and merely hidden.
=cleanup= then turned up the sharpest fact of the session, and it was almost lost by being tidied away:
=~/.viva/registry/vcompany= has no =.git= anywhere above it. The shelf is not version controlled, so a
=.bak= in a scratch directory about to be wiped was the only copy of eighty-one deleted lines. Folded

* the pass: probe, do not read (row 10)

The trigger was a question, not a go, so nothing was edited. What made the pass worth anything is that
every claim went through a probe. Three of them overturned what reading alone would have concluded.

** the gated test was broken twice over

=languages.js= hands back whatever =grammars[format]()= returns, and for org that is =org()= — a
=LanguageSupport=. The test called =language("org").parser.parse(text)=. Probed:

#+begin_src text
ctor: LanguageSupport
has .parser?: undefined          ← TypeError on .parse()
language.parser?: true
NODE NAMES: Document · org-block · org-block-mark · org-bullet ·
            org-directive · org-headline-1 · org-link · org-verbatim
  expects meta/heading/list/link/monospace/keyword/string -> false ×7
#+end_src

So two defects in one =specimen.it=, not one. The reach is =language(format).language.parser=; and the
names a =StreamLanguage= emits are the keys of its own =tokenTable=, never lezer's generic vocabulary.
The assertion list was a fossil of the =simple-mode= sketch that =editor/org.js= had superseded, and it
had never been re-run against the mode that replaced it. The quest had recorded this file as
/"7/7 gate green in scratch"/ — true when written, false by the time the org mode landed. **A green
recorded in a quest is a green at the moment of writing, not a standing property.**

** =caret= became write-only

Its single reader was the painted =<span>= at =Reader.svelte:108=, which the swap deletes. The =.caret=
at 188 and 281 is the ▸/▾ disclosure glyph — a different noun wearing the same name, exactly the
same-name-different-verb trap the blast-bracket names. Dropped =caret=, =at()= and the =oncaret= wiring;
kept =oncaret= on the drapes component, because that is the library's API and the App simply does not ask
for it yet.

** three smaller ones, and two calls

The =jdex.js= hunk dropped the function but not the comment above it, which would have orphaned a line
that had become false. The test titled /"every format the vdex declares has a grammar"/ lied — the vdex
declares =["md", "org", "json", "txt", "pdf"]= (=vdex.viva.js:26=) and =txt=/=pdf= correctly have none;
it was asserting the drapes list. And =export const focus= was dead surface with nothing binding =this=,
so it was cut rather than wired. On judgment: the Editor went into ={#key open.literal.slug}=, closing a
hole where ⌘Z after switching documents undid into the previous file's text — a hole the old textarea had
too, so not a regression, but one line to close.

** what the pass got WRONG, and caught before writing code

Grepping =subsystems/dapper/= for =--zone-accent-base= returns nothing, and the first reading of that was
that four of the theme's colour roles did not exist and most of the syntax highlighting would be invisible.
Wrong. =flatten.js:5= holds =INTERACTIVE_ROLES = ["primary","secondary","accent","info","success",
"warning","danger"]= and emits them as =--zone-${role}-${state}=, so the names exist only as
interpolations in source and in full in the generated stylesheet — where all of them are, along with every
=--colors-skeleton-0-*-base= and =--font-family-code=. **Grepping source for a token name proves nothing
when the emitter interpolates.** Checked the emitter, not the corpus, and =theme.js= landed unchanged.

* the build (row 11)

Five wrapper files, the compile gate, and the three vdex hunks. =Reader.svelte= 698 → 616. Both blockers
fixed first. Two more findings came out of the landing itself, neither visible from reading:

** =.pdf= was dead CSS all along, and the swap only exposed it

The suite went red on =css_unused_selector: ".pdf"= immediately after the swap. Rather than assume a
regression, both versions were compiled on the same compiler: BEFORE =[]=, AFTER one warning. The cause is
Svelte's pruner. The old markup carried =<span class="line {line.kind}">= — an *interpolated* class — which
makes every remaining class selector count as possibly-matching, so nothing in that stylesheet was ever
reported unused. Delete the span and the mask goes with it. =.pdf= was genuinely dead: ={:else if pdf}=
renders =<Paper>= with no wrapper element. **When a swap removes a dynamic class attribute, expect a burst
of =css_unused_selector= and treat each as a real find, not as damage.**

** =.reader= never flexed

It sits in =.stage= (=display: flex; flex-direction: column; overflow: hidden=) already carrying
=min-height: 0; overflow: hidden= — both meaningless on a flex child that never flexes. Without =flex: 1=
the =.raw= box has no height and CodeMirror mounts at zero. Pre-existing layout debt the editor exposed;
one line, and it cannot shrink =read=/=edit=, which are content-sized inside a now-taller box. Reported as
an adjustment beyond the diff shown, per the standing rule.

* the failures, kept

- **a quest's recorded green is not a standing green.** =tests/editor.test.js= was written and passed in
  scratch against the =simple-mode= sketch; the org mode replaced the sketch; the test was never re-run and
  the quest still said 7/7. Two defects sat in it for the whole gap. A gated file that outlives the thing it
  tests has to be re-probed before it is called ready, not re-read.
- **grep-as-proof, twice nearly wrong.** =--zone-accent-base= is absent from dapper source because the
  emitter interpolates it. Caught. The same habit is what made =.pdf= look like a regression rather than an
  exposure — caught only by compiling both versions.
- **the walk order was wrong in the build.** The blast-bracket wants the consumers' suites green BEFORE the
  change; the vdex suite was first run after the edits, which turned a baseline question into forensics.
  The answer came out clean, but it was recovered by structural argument, not by a recorded baseline.
