* arc

** the flag stratum is where a chained verb points (rows 1, 2)

=init= has no target parameter; it reads =paladin.instance.home= after =remount()=, and the mount comes from the seven strata. =--use= writes the session record and sets the =session= stratum, but from the repo root the gitignored =.env= outranks session — m41's own law, written when beef pinned hello-world there — and the live drive showed it verbatim: =selected.stratum: ".env"= while the freshly created =second= sat in the session file. So =--init= can ride neither =--use='s pin nor nothing; it pins the =flag= stratum, which is what the entrypoint does for =--instance=<path>= and outranks every file. That makes the two flags independent by construction: =--use= alone pins nothing in-process (a test asserts =provenance === null=), =--init= alone pins flag, both chain use first (session record, register) then init.

** one arbitration, three verbs (rows 7, 8)

The picker fold — =search.seek= over a lens, one match headless, many prompt (in a pipe: name the candidates and throw), none null — was already the grammar for =use= and =create=. =delete= predates the lens and went to paladin's =resolve=, which is record-key-or-path and nothing else; =doctor= did the same and additionally folded a failed resolve into "it was a filter". So beef's =delete hello= was refused by the one verb that had not joined the fold — the earlier compact records =delete.js= being "joined to the resolver", and that resolver is exactly the exact one. The cut is the one the no-hotfix doctrine asks for: not a prefix hack in delete but =locate(ctx, token)= in =target.js= beside =register= and =specs=, the file every instance verb already imports, returning ={mount}= or the effect registers ghost already uses (={aborted: true}=, ={error}=). =use= lost fourteen lines and kept its bare-=use= semantics (report in a pipe, picker in a terminal). =mod.js:143= keeps exact resolve on purpose: the entrypoint has no =ctx=, no picker, and a flag value is a path or a slug someone typed deliberately.

** where the fold stops (row 8)

=lens.instances()= searches =slug= and =mount=. Right for a picker column and harmless for =use hello=, but =doctor <one>= is polysemous — target if it resolves, otherwise a filter over env rows — and =doctor viva= or =doctor finn= would match every mount on the machine. The two-param form =doctor <target> <filter>= is unambiguous and rides =locate=; the one-param form stays exact-record-or-filter, and the dossier row says why, so the next session does not "finish" the hoist.
