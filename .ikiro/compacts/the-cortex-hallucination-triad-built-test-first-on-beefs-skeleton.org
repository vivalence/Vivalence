* The contract (praised — "looks great. go.")

The outer boundary is FIXED and already live (=registry/viva/hallucinator/anthropic/provider/index.js=): a faculty is dumb, stateless, single-shot — no loop, no tool execution, no memory.

: { type, tune, context, channels:{in,out}, via:{ render(turns,config)→Turn, stream(turns,config)→AsyncGen<Packet> } }

- *in* (both verbs): =turns[]= + =config {maxTokens, thinkingBudget, tools, tool_choice}=. Provider consumes tool SPECS only (=translateTools= strips =execute=; it never crosses the wire).
- *out*, two grammars for one content: turn grammar (=render= → sealed =Turn=) and packet grammar (=stream= → =/turn/open · /part/open · /part/delta · /part/close · /turn/close=). The binding law: =Turn ≡ fold(soma.pour, packets)=. Stream IS render, observed incrementally — the whole streaming design rests on that equivalence.

Hallucination internals = one composition: *render = parse ∘ loop ∘ compile*. compile folds closure state → one provider call (context→system turn, tools SPLIT: specs ride =config.tools=, executes stay home, turns ordered ARRAY). loop = the only recursion, an unfold over the transcript until =stop ≠ tool_use=, bounded by =config.rounds=; the ONLY cortex touch. parse = enrich (mirror object part → =turn.object=). stream = same skeleton, loop inside a generator: provider packets pass through UNBUFFERED while =soma.pour= shadow-accumulates the turn the loop needs; tool_result turns re-enter via =soma.drain= as synthetic packets (why the tool case shows 3 =/turn/open=). render/stream kept as TWO twins — turn grammar vs packet grammar — never force-collapsed.

* The tune axis ontology — pinned (praised: "perfect")

beef: "where is defined what which value in the tune means? is there a primitive? is that primitive properly described?" — Answer at the time: primitive existed (=Tune= = 3-4 floats [0,1]) but described only SHAPE, never axis MEANING; the semantics lived implicitly in the =tiers= table + provider vectors. I refused to fabricate axis names, surfaced the inference, asked beef to pin. beef: "pin the eaxis ontology and describe. read the nearest function."

=nearest= (=belt/array.js=) read: equal-weighted squared-Euclidean, loop bounds on =target.length= — every axis weighted the same; a 3-axis desire ignores the 4th; only axes present in BOTH the (padded) faculty and the desire count. That constrains the ontology: axes must share scale and be independent enough for distance to mean anything.

Pinned from the data (=opus [0.9,1.0,0.3]= · =haiku [0.1,0.3,1.0]= · =frugal [0.1,0.3,0.9,1.0]= · =unleashed [0.9,1.0,0.2,0.2]=). Four axes, each [0,1], 1 = maximal that virtue; two CAPABILITY axes trade against two ECONOMY axes (nothing maxes all four):

: 0 intelligence  raw problem-solving capability    (haiku 0.1 → opus 0.9)
: 1 reasoning      deliberation depth / thinking      (sonnet 0.7, opus 1.0)
: 2 speed          inverse latency; 1 = fastest       (opus 0.3, haiku 1.0)
: 3 thrift         cost economy; 1 = cheapest          (unleashed 0.2, frugal 1.0)

Verifies against every sample (=frugal= = dumb-cheap-fast, =unleashed= = max-capability-cost-no-object). Canonical name lives ONCE: =export const axes = ["intelligence","reasoning","speed","thrift"]= in the schematic; =.desc()= threaded onto Tune + Tier; the =tiers= table annotated per row. Kept POSITIONAL (nearest indexes numerically, every provider ships arrays) — named via the export + doc, not an object rewrite. Documented caveats: providers may ship only the first 3 (cortex pads thrift 0.5); axis names are dialogue-centric — for speech/verbatim the vector is an opaque proximity key. The axis-0/1 co-variance is real but justified: sonnet reasoning 0.7 < opus 1.0 at similar intelligence — extended-thinking is a distinct axis from raw capability.
