* the bracket, as walked

Beat 1 distinguished four "playground"s: the package (=registry/playground=, owner =@playground=,
slug =playground=), the mode TYPE (=type: "playground"= on six rig modes — beef kept it), the DAEMON
(=hello-world/playground.js=, slug =playground=, =daemon_playground/= mountpoints, =playground.viva.db=
— renamed), and two same-name strangers left alone (=tests/drain.playground.js= is a topography slug;
typology's =/daemon/playground= is an arbitrary Path literal). The owner of the standard library
STAYED =@viva= because beef pinned =@viva/package/commons= explicitly; fixtures and playground had
owner = slug = dir, so their rename was all three.

Beat 4's red is the lesson worth keeping: =grep 'registry/viva'= finds every absolute reference and
ZERO relative ones. =registry/testing/data/lighthouse.js= imported =../../viva/datamaps/libsql/…= —
no literal =registry/= in it. A rename blast greps =\.\./(old)/= as well as =registry/old=.

The ledger edit and the =mv= were one beat on purpose: =vip.mount()= has no catch on =find.viva=,
so a =registry.json= naming a moved dir killed every =viva= boot — which is exactly what beef then
ordered fixed for prod.

* reconcile — the category kill

Desired end state, plain language: a recorded package location that is gone is a stale record, not
a boot failure. Inside the repository's own registry the record FOLLOWS the repository — rediscovered,
rewritten, new repo packages recorded too. Elsewhere the reference is the operator's — kept, skipped
this boot, surfaced as =vip.stale= and =viva ledger/doctor= =record[].present:false=.

Tests first in =subsystems/paladin/tests/registry.test.js= (a =homed()= scaffold adds a =repository=
scope): dead in-repo heals · dead external stale + kept · healthy record not rewritten (mtime) · no
record → =null= (seed path) · =Vip.supply= over a mixed stale record mounts =@viva= and =@real=. RED
reproduced the production shape verbatim (=ENOENT readdir …/registry/viva=). One consumer red after
landing — =vip.tap.test.js='s scaffold has no =repository= scope — fixed in the SYSTEM (=scope.repository?=,
=inside= false without a checkout), not by growing the test's scaffold.

Live proof on a scratch =VIVA_LEDGER_MOUNT=: =[…/registry/viva, …/registry/testing, /nowhere/checkout]=
→ owners =@testing @viva @development=, =stale: ["/nowhere/checkout"]=, record =[…/testing, /nowhere/checkout, …/commons, …/development]=.
Note the healing discovery also RECORDED =development=, which the scratch record had never held —
the repository half of the record is the repository's, that is the rule.

* the owner pass and its exact undo

=@viva= as a bare word turned out to be pure string: no regex, no default, typology's =cast.lookup=
examples already used =@vivalence=. Forward: =perl -pi -e 's/\@viva(?![A-Za-z])/\@vivalence/g'= over 37
files (the first attempt passed the newline-joined list as ONE filename — "File name too long", nothing
edited; caught by the residue grep, redone via =xargs -0=).

The revert could not be a blind reverse: =@vivalence/<workspace>= (=paladin=, =typology=, =runtime=…) was
pristine everywhere, and 19 more pristine non-workspace =@vivalence= uses lived in files I never touched
(=ghost/localhost/localhost.viva.js= is =@vivalence= at HEAD; typology's cortex tests; kajuit's manifest).
So: a Deno script per candidate file — pristine text from =git show HEAD:<path>= (moved files mapped to
their old paths, the education clone against its own HEAD, shelf instances with no pristine) — and a
line reverts only when its text is not in the pristine set. 38 files touched, 0 kept-by-mistake, ONE
over-revert where a pristine =@vivalence= shared a line with an edited one (=codemap/registry.md:7='s
=…/wafers/@vivalence/<type>/<slug>/= tail) — the diff check named it, hand-fixed, and the same line's
stale dir names restamped while there.

Concurrency, recorded not hidden: beef rewrote =registry/commons/instances/hello-world/= during the
revert (=development.js= gone; =hello.js= type =demo=, =App.svelte=, =multiplayer.js=). His new
=multiplayer.js= carried =@vivalence/lighthouse/…= copied from the momentarily-renamed text; the
revert script set it to =@viva=, which is the working owner after the skip. Zero rename residue in his
files. =subsystems/paladin/prototypes/instance.js= shows modified and is his.
