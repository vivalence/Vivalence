* Stall — the new phase paradigm
The Stall moved kajuit → =subsystems/typology/prototypes/stall.js= (pure nanostores; importable by both the kajuit app and buffer-view bundles) and was rewritten as a PHASE machine, a constructor FUNCTION (not a class). Finn: "new paradigm, neww stlal" and "we can change adjust mold how stall works."
- Phases: =INERT / STATIC / CONTINUOUS / ESCORT / MANUAL= (a frozen =Phase= map). All phase verbs collapse onto one combinator =engage(phase, react)=; only the =react= differs. nanostores fires on subscribe, so =observe= primes itself — no explicit wire()/react() calls.
- =STATIC= = settle (cursor walks the queue). =CONTINUOUS= = =(settle(), pull())=, =fetch= refills to =queue=. =MANUAL= = stall steps aside (no observe, no bridge); the app owns progression. =INERT= = does nothing.
- =ESCORT= (added last): captures the active buffer as =home=, seizes into the queue, walks it, then restores =home= + goes inert when the queue drains. The round-trip phase — "add another phase that returns back to the original mode once the buffers are done." This replaced an app-level re-home hack in the spawner.

** release-as-hook (Finn's "former")
Completion is signalled by =buffer.release()=. The Stall mirrors the Buffer's hook surface: =stall.on.release(cb)= + =stall.hooks.release= + =stall.release(buffer)=. Finn: "do stall.on.release() and use stall.on for all things hooked like in the buffer class." On the question of in-stall eviction, Finn: "either we completely eliminate the remove aspect here and let the buffer hooks take the burden here or we build this out into a full hook system. i'd probably prefer the former. why do we NEED remove?" — pointing at the relay line =buffer.on.release(() => stall.released(buffer))= as "context on the hooks remove topic."
→ Eviction is NOT baked into the Stall. The terminal registers an =stall.on.release= consumer hook that drops + removeOnes the buffer. The Stall never touches persistence. =observe= bridges each source buffer's release into =stall.release=, which is PHASE-GATED (STATIC/CONTINUOUS/ESCORT act; a stale bridge no-ops once the phase is MANUAL/INERT — multimethod on the live =$phase= atom).

** the settle root-fix (a real bug)
=settle()= originally advanced whenever the active buffer was outside the FILTERED items, so =.only(isSpawned)= instantly evicted a hub buffer (not in the filter) and captured the moat. Root fix: advance only when the active buffer has left the =$source= (was deleted) — =only()= scopes what the cursor CYCLES, it never seizes the cursor from a buffer the user is viewing. A null/gone active still seizes (so a real game with a null initial active auto-shows card 0). Locked by a test ("settle leaves a filtered-out active alone").

** the "pretty pass" caught a latent bug
Finn: "do a sanity pass. is this optimal? is this pretty?" The pass found a double-advance: an =$active→null= subscription fought =consume='s own advance, so the cursor could skip a buffer. Fixed by =settle= (advance only when active absent) + advancing once. Also DRY'd the four phase methods into the =engage= combinator and dropped redundant priming. Added a 3-buffer regression test that distinguishes "advance to immediate next" from "skip".

* Trait ↔ phase — the mental model (formulated, then benched)
Finn wanted the unifying abstraction for "the interplay and control and interplay of the types, phase, and traits", saying of derive-vs-manual: "i want both. they are one system. thats the crux." The model I formulated:
- Phase is the **trait-arc at the rendering layer**: declarative metadata (thread traits) → functional dispatch (terminal projects) → emergent runtime (stall phase). The same arc that runs everywhere else in vivalence. Traits = source code; phase = the running process; terminal = the compiler; an app override = a hot-patch (same verb surface, different caller — that's why it's ONE system).
- Two orthogonal planes meeting at one call. SOURCE (where buffers come from): =AIMED {mount}= → =thread.pull= (the fetch), =MASKED= → the pull/create params, =STANDALONE= → self-seed. CURSOR (how the active advances): =QUEUEING {depth}= → CONTINUOUS; else STATIC/MANUAL/INERT. They meet at =stall.continuous({ fetch: thread.pull, queue: depth })=. =APPLICATION= is the gate (no view → no phase).
- The seam = a pure =project(thread, stall)= function (one source of trait→phase truth; the terminal calls it on thread-mount, an app can override). Constraint: CONTINUOUS needs a fetch → needs AIMED; QUEUEING-without-AIMED is degenerate (warn + fall back to STATIC).
Finn then: "lets bench this discussionnn and get back to code with a reduction and simplification. simple wins." → =project= was NOT built; only the model is captured here for when the trait→phase work resumes.
