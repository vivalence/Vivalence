* the callout — a directory with one file is a rename, not a structure

He asked for structure: /"impose propper file directory structure ... break hello world up
into nested /harness /tools or whatever makes most sense. clean. bottom sup. check how
typology and runtime do it."/

I checked, and I read the tree honestly: =nlp/tools/index.js= is ONE file in a directory,
=nlp/provider/index.js= is ONE file, =dealer/buffer/Dealer.svelte= is ONE file. From that I
derived a law — /"a role directory with an index.js, single member or not"/ — and applied it
uniformly, producing =emitter/index.js=, =generator/index.js=, =doctor/index.js=,
=aperture/index.js=. Nine words came back:

: 2 bad. thats just a directory around each file. worse.
: i want you to do a factor analysis and cluster the mode cleanely

**The evidence against it was in my own diagram and I did not read it.** Every directory had
exactly one child. A tree whose every node has one child is not a tree; it is a rename with
extra typing. And the tree held a counter-example I had already listed and not weighed:
=chaosmonkey/oracle= keeps =aperture.js=, =emitter.js= and =harness.js= FLAT.

The deeper failure is the order of operations. I asked /"what does the tree do?"/ and answered
it, when the question was /"what does this content need?"/. Convention is evidence about
content, never a substitute for looking at it. Taking a real observation from three samples
and generalising it into a uniform rule felt like rigour — it cited files, it had a law, it
matched precedent — which is exactly why it was not caught by the checks I usually run.

*The diagnostic, cheap enough to always apply:* after proposing a structure, count children
per node. Any node with exactly one is a rename. If most nodes have one, the structure is
ceremony and the analysis has not been done.

Family: =taxonomy-before-content=, adjacent to [[feedback_no_fabricated_conventions]] but
distinct — nothing here was fabricated. Every citation was true. The error was applying true
citations uniformly instead of deriving the cut from what actually co-varies.

* the factor analysis

Three factors separate this mode's contents, and they do different jobs:

| factor | poles | what it decides |
|--------+-------+-----------------|
| effect | pure ↔ effectful ↔ agentic | what a test needs: nothing, a stub, a key |
| audience | machine ↔ model | prose a model reads is not code and reviews differently |
| subject | this machine ↔ the web ↔ a drawn page ↔ the nested agent | what changes together |

Effect and audience make a unit standalone-testable; subject makes a directory earn itself.
Crossed, every subject takes the same three parts — *capability* (no Vector, no ctx, effects
injected), *language* (prose a model reads, one export, no logic), *doors* (thin Vector nodes).

#+begin_example
hello-world/  aperture.js · harness.js · doctor.js      flat: 15 · 15 · 46 lines
              web/    marginalia.js · choose.js · index.js
              page/   style.js · draw.js · index.js
              research/ brief.js · index.js
reader/       guard.js · hop.js · skeleton.js · extract.js · service.viva.js
#+end_example

Nothing under 40 lines gets a directory. The house style and the tool that consumes it are
one concern and now sit in one directory — under the surface-clustering they were in different
files, and that is the concrete thing the subject cut buys.

They did not. Eleven assertion tests, zero snapshots. Reading the regime first turned up the

: .gitignore:29-30   *.snapshot.json

Both the files and the directory. A fresh clone has none, and a default run is DRY — asserts
and logs, never writes. **A snapshot in this repo is a working-session drift detector, not a
committed golden.** Nothing load-bearing may live only in one. That is not a defect to fix
here; it is a constraint that decides what belongs in which instrument.

Four files, one per step: S1 the catalog =declarations(mode.tools)= sends · S2 one committed
fixture page through =skeleton= and =extract= · S3 the assembled system sections and the buffer
row a draw mints · S4 the inner request and the outer projected yield.

Three expectations in the firing matrix are the actual value, and none of them is "it matches":

- *S1 must NOT move across M2.* Reading changes what comes back, never what the model can ask
  for. A diff there means the contract moved when only behaviour should have.
- *S1 grows by EXACTLY two across M3.* Three means the generator leaked a branch; one means
  =generative.js:32= installed its fallback instead of ours.
- *S4's catalog is a strict SUBSET of S1.* The researcher arms web + generator and must never
  see =research= itself or =viva_doctor=. That is the recursion guard, and comparing two
  snapshots is the only place it becomes visible — an assertion would hard-code the list and
  rot. New marker =P-subset=.

* rulings carried forward

- A directory with one file is a rename. Count children before proposing a structure.
- Convention is evidence about content, never a substitute for reading it.
- =provider= is a NAMED export in a =.viva.js=. A default export is called at load.
- =cortex.hallucinate.object.render= needs =output: { schema }=; only the harness wraps it.
- A service that demands a cortex is not a service. The model belongs to the caller.
- Snapshots here are session-local. Anything that must hold is an assertion.
- A document is sorted for the reader who arrives at one milestone, not for the writer.
- =str.index()= on a heading matches its first MENTION. Ask a file for its heading map.
