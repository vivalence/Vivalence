* the structural law — nested on disk, FLAT basename routes

The trap: the glob loader's default =generateId= strips dots AND, if you keep the nested path as the id, deep routes break every wikilink and the jdex breadcrumb math. The resolution decouples the two axes — **folders organize on disk, routes stay flat by basename**:
#+begin_src javascript
pattern: "**/*.mdx",
generateId: ({ entry }) => entry.replace(/.*\//, "").replace(/\.mdx$/, ""),
#+end_src
So =…/47_integration/47.03_stripwire.mdx= → slug =47.03_stripwire= → route =/47.03_stripwire=. Wikilinks (=[[47.03_stripwire]]= → =/47.03_stripwire=), the jdex-frontmatter sidebar/breadcrumb, prev/next — all untouched by the nesting. One nested-safe fix: =Layout= last-updated reads =entry.filePath= (not =content/docs/${slug}.mdx=, which no longer resolves).
