* the working rhythm (the session's method — worth keeping)
Every knob and behavior was earned by a live run, never designed in the abstract:
propose the shape → run DRY (=console.log= the pojo + resolved path, write nothing) →
read the actual stdout → refine → flip to write → read the file BACK off disk → confirm
it matches. Two demos were explicitly built this way on Finn's instruction (*"iterate them
in two steps. Create them and read their stood out… actually run them and inspect that the
results are as you expect… then execute them, write them… inspect that the read on disc is
actually what was expected."*). This is the methodology the milestone encodes.
