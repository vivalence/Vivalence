*** The slowstart correction is the one worth keeping.*** I reported it /"gone entirely"/ on the strength
of =grep -rl slowstart documentation/= returning nothing. It returned nothing because the word only ever

=generateId: ({entry}) => entry.replace(/.*\//,"").replace(/\.mdx$/,"")= — the whole directory path is
thrown away, so *the JD number IS the URL* and a doc can move anywhere in the tree without breaking a
link. A content grep is not an existence check when the identity lives in the name.

* the eight-second ceiling

The card worked and died at 8.004 seconds. Not a mystery to design around — one line:

: systems/kajuit/src/typology/entities/daemon/dossier.js:59
:   .use(shard.connection.timeout(8000));

Every =mode.call.*= on a daemon rides that one connection. The tool door never hits it because that
call is in-process. Two facts made the diagnosis cheap and both came off the artifacts rather than a
hypothesis: =retry()= short-circuits on =ctx.request.aborted=, so one click was one research run and
not three; and the buffer =0b7556c5087a= landed five minutes AFTER the client gave up, so the work
completed and only the client forgot.

The escape hatch was already written into the shard, with a comment saying why:

: // a stream's lifetime is not a request timeout — SSE connects exempt
: if (ctx.request.headers.get("accept") === "text/event-stream") return next();

And the server side is generic, not harness-specific — =shape/http.js:41= auto-frames ANY async
generator as SSE. So the aperture needed no change; the NODE needed =yields=, because
=shape/connection.js:38= is what wires the client to =connection.stream()=.
