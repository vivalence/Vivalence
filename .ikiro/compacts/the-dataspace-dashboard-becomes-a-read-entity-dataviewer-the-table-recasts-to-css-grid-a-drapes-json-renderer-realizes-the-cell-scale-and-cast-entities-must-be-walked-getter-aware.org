* the alignment law — HTML table dies, CSS grid rules

beef, three times: *"align table headers"* → *"a: the table headers are not inline with te cells"* → *"and the table headers are STILL not in line with their columns."*

The failed ladder: (1) identical box-model on =th=/=td=; (2) =table-layout: fixed= + =<colgroup>= explicit widths. **Both failed** — =table-layout: fixed= with =width: max-content= is non-deterministic in this engine; header and body row-groups sized independently. THE FIX: drop =<table>= entirely. A **CSS grid** where =.grid-head= and every =.grid-row= render =grid-template-columns: {template}= from the SAME derived string — columns physically cannot drift. =.grid-cell { min-width: 0 }= is what re-enables ellipsis in a grid item (the grid analog of the table's overflow trap). LAW: *for a data grid, share one =grid-template-columns= across header and rows; never trust =<table>= column-sync.*

Related: *"b: stop the traits from line breaking. no line breaks within cells. increase width in case"* → per-column widths + =.pills { flex-wrap: nowrap }= + cell ellipsis.

* performance — pagination + virtualization

#+begin_quote
the dataviewer is sooo html expensive that my layout engine is suffereing. what can be done about this?
#+end_quote
2086 literals × 7 cols × pills ≈ 30k nodes, all laid out at once. First pass = pure CSS: =content-visibility: auto= on rows + =contain: layout paint= on the scroll box (sandbox the reflow from the pincer) + =min-width: 0= on the flex chain (a fixed-width grid otherwise stretches the panel). Then beef:
#+begin_quote
how heavy is virtualization to implement?
#+end_quote
#+begin_quote
also implement pages aka limit and offset or whatever its called. give me controls over this. implement both.
#+end_quote
Both landed. **Pagination**: server =findAndCount({}, {orderBy, populate, limit, offset})= → =[rows, total]=; toolbar controls (page-size =100·250·500·1000=, prev/next, =offset+1–end / total=). **Virtualization**: fixed 28px rows, overscan 8, window =shown= by =scrollTop=/=clientHeight=, top+bottom spacer divs hold scroll height → DOM stays ~40 rows. =content-visibility= dropped (redundant once windowed). Two axes: pagination caps the wire payload + node *build*; virtualization caps rendered *DOM* to a constant.

* sort — server orderBy via chevron headers

#+begin_quote
make the tables sort by chevron control within in the header.
#+end_quote
Because pagination is server-side, sort must be too (else you sort 250 of 2086). Each **scalar-DB-field** header (=SORTABLE= set: =slug·rank·ontology·type·installed·status·index·phase·counter·cursor·role=) is clickable with a =▾= chevron; click toggles =asc⇄desc= (flip + highlight), sets =orderBy=, resets to page 1. * the data-quality law — walk cast entities getter-aware, NOT via toJSON

The buffer/thread detail dumped live-object cruft (functions, nanostores, the daemon back-ref graph =cargo{186}=): *"there is a whole bunch of prototype specific data displayed here. no like."* / *"same issue everywhere else."* First fix used the entity's =toJSON()= — beef rejected the coupling:
#+begin_quote
the toJSONS are shit tho. very incomplete. using toJSON forces us to update and extend the toJSONs which will cause issues with caching and storage and linking i think?
#+end_quote
(Correct — =toJSON= drives =RemoteRepository.store()= localStorage + the identity map + relation linking; extending it for display would bloat persistence.) → a **viewer-side =plain()= sanitizer**, zero toJSON dependency. But it came out slim:
#+begin_quote
the data displayed in the json viewer is super poor and slim. console log the outptu and cmopare to diff and improve. thorough! ultra
#+end_quote

A ground-truth agent traced the client cast entity. THE LAW: a cast client entity is =Object.assign(new Kind(), resolvedRaw)= — **no =$raw=, no proxy**. Scalar/blob fields ride =Object.assign= as own-enumerable, BUT store-backed fields are diverted by SETTERS into =$=-atoms and exposed only through **non-enumerable getters**: =Buffer.data= (the whole payload!), =Thread.{mode,phase,traits,trait,label}=, and 1:m accessors like =literal.memories= (a =defineProperty= own accessor, also non-enum). =Object.keys= / =for...in= / =toJSON= (which iterates =Object.entries=) are ALL blind to them. To walk a cast entity completely: =getOwnPropertyDescriptors= on the instance (own enum + non-enum accessors) + every prototype getter up to (excluding) =Object.prototype=, and INVOKE them (skip =$=-keys, functions, nanostores). The client em.schema (the stripped datamap) lists ONLY relations — scalars/embeddeds are excluded, so relation-vs-data detection is by =constructor !== Object && "id" in value= heuristic, not schema.

=plain()= fixes, all three from the diff: (1) =readableKeys= now walks all own descriptors + proto getters (recovers the store-backed fields); (2) depth cap =6→24= (deep blobs like =buffer.data.history= were truncated); (3) the =seen= WeakSet made ancestor-path-scoped (=delete= after recursing) — a global set false-flagged sibling-shared objects as =[circular]= and dropped them. Relations still collapse to ={id, slug}= (deliberate — else the daemon graph explodes). A =console.log("[dataspace] …", {entity, ownKeys, readable, plain})= on select remains for beef's confirmation (removable).
