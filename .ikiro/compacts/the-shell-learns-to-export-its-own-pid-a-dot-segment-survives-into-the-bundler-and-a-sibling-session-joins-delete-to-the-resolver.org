* arc

** the session is a pid, and only ghost carries it (rows 1, 3)

=instances/use= writes =sessions/<VIVA_PROCESS_ID>.json=; =ghost.sh= mints that id from =$PPID= for the one =deno= it execs. A shell running =deno task= itself hands the child no such variable, so =populate.js= skips the stratum in silence and the instance throws with a message listing three cures that all route through ghost. Not a strata bug — the doc sentence "the shell that INVOKED viva owns the session" is exactly true and exactly the gap. beef's remedy was the zero-code one: the shell exports =$$= itself, and =ghost.sh='s =${VIVA_PROCESS_ID:-$PPID}= already yields to a preset. The repo-root =.env= is the second belt; it outranks the session from the repo root, which is by the strata's own design and now written down.

** the dot segment and the string glue (rows 6, 8, 9)

A relative mount is not a =Path=. =Path= has no "relative to" — its absolute form starts at =/= — so =new App("./App.svelte")= minted =/./App.svelte= at construction, before anyone knew which module's directory it meant. The trait then glued =dirname + nature=. Ten development modes had walked the same line for months with =buffer/X.svelte= and never tripped, because no dot. The fix moves the resolution to where the frame is known and uses the resolver paladin already uses for kernel entries. Three files, 5+/4−, bracketed. The proof that the category is dead is the probe run before and after: =./App.svelte=, =buffer/Reader.svelte=, =/abs/App.svelte= all resolve to what they say.
