* the research + the =content=/=yield= split

Beef: /"Could you look into the whole term semantics and check if there's a
neat spot to place [this]... how do other systems working with AI agents
identify artifacts generated inside of tool calls. Is there a semantic that
is already established, or can we start to form our own verbiage?"/

Web research, two independent frameworks converge on the same split:
- *MCP* (modelcontextprotocol.io/specification/2025-06-18/server/tools):
  tool results carry =content= (model-facing) separately from
  =structuredContent= (machine-facing, schema-validated) + a
  =resource_link= type (URI pointer instead of inlining).
- *LangChain* (=@tool(response_format="content_and_artifact")=): a tool
  returns =(content, artifact)=; =artifact= is explicitly "not meant to be
  sent to the model," stays attached for the app layer.

Landed design: =executeTools= (=cortex.js:19=) unpacks a handler's return —
bare value (backward compatible) or =\{content, X\}=; =content= becomes
=tool_result.output= (unchanged wire path, =translate.js:48-53= only ever
read =.output=, ignores unknown sibling keys, zero changes needed there);
=X= rides as a sibling field, never serialized to the model.

* buffer delivery — already solved, not what this field is for

Beef: /"Then how do we handle the following case? Let's say we have a tool,
and that tool returns a buffer or a set of buffers. Give me that flow from
both server and client side calls to the harness step by step."/

Tracing it found: a tool calling =ctx.mode.emit.drill(...)= runs the SAME
=EMITTER= trait chain any direct action-tile emit does — pool/thread-bind/
=em.flush()=, a real persisted row. That triggers
=shard/datamap.js:152-182='s =twitch.open("/buffer/create/after")= →
=Broadcaster.push=, CALLER-AGNOSTIC — the same reactive =/subscribe= SSE
feed =thread.$buffers= already rides for the homepage Action tiles today.
Client delivery is ALREADY solved, independent of the harness response
entirely, usually landing before the LLM even finishes narrating.

Beef, connoisseur pass: /"were sitll in design phase. ask conoisseur. what
should i want?"/ Loaded =.ikiro/self/connoisseur.md=. Verdict: cut, don't
add. The Pool-accumulation machinery planned inside =renderLeaf=/
=synthesizeObject= (a =Pool= collecting drained Yields across rounds,
attached to the final turn) has NO consumer once delivery is understood —
ceremony with nothing reading it, a trigger-9 violation. Cut entirely. The
sibling field's real job narrows to ONE thing: keep =content= (what the
model reads) short instead of dumping a raw entity blob into context — not
transport. Consequence: the earlier-planned client dialogue-stream merge
(MILESTONE 12.2, =is.yieldish(part.output)→buffers.merge=) is now WRONG,
not just redundant — it would race the broadcast for the same data through
a slower path. Cut.

* the field name — =.artifact= → =.yield=

Beef: /"I do not understand why we are keeping the dot content, dot
artifact, but are not using dot buffer."/ Fair — =.artifact= borrowed MCP/
LangChain's label for the axis along with the axis itself. What concretely
rides there is exactly a =Yield= (=Pool.drain()=/=ctx.mode.emit.X()='s
return shape) — =.buffer=/=.buffers= undersells it (not just buffers, the
whole condition-tagged envelope, could be =EXHAUSTED=); =.artifact= is a
loner name, joins no in-repo register. =.yield= joins the existing =Yield=/
=Pool=/=drain= family. Renamed. Confirmed empirically (=node= test) that
=yield= is a strict-mode-reserved bare destructuring binding — ES modules
are always strict, =const \{ yield \} = obj= throws =Unexpected strict mode
reserved word=; fine as an object key or dot-access, a destructure must
rename (=const \{ yield: emission \} = result=).
