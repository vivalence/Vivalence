** the root cause — a two-faced value, amputated
=Connection.socket()= (=prototypes/connection.js:193=):
#+begin_src javascript
socket(endpoint, vector, query = {}) {
  const base = this.url.branch(endpoint).with(query);
  if (this.transport.socket) return new Socket(this.transport.socket(`${base.pathname}${base.search}`), vector);
  const ws = base.scheme(base.secure ? "wss" : "ws");
  return new Socket(new WebSocket(ws.absolute), vector);   // ← DIRECT fallback, unwrapped, unauth'd
}
#+end_src
The daemon connection's transport = =retry(tunnel(url))= (=daemon/dossier.js:54=). =transmitter.tunnel= DOES expose =transport.socket= (opens a Duct channel over the tunnel ws), but =retry= returned a *bare async fn* and dropped it. So =transport.socket= was =undefined= → the direct fallback → a =new WebSocket= to a path the tunnel-only/auth daemon never upgrades → handshake into the void → =awaiting handshake= forever. * Lessons
- *A combinator must preserve the surface of what it wraps.* =retry= wrapped the CALL and amputated =.socket=. Verify the problem against the real mechanism: the bug wasn't in conversation/handshake/auth at all — all proven sound — it was one lost property three layers up in the transport.
- *One span beats a page of console hooks.* =WebSocket.send= patches, =JSON.parse= wraps, raw probe sockets all "worked" but the =dock/handshake= span said =LIVE= in one line. Eat the trace dogfood.
- *Never touch a barrel export at module-eval time.* =belt.trace.chronicle.seed()= at import is TDZ-fragile under HMR; seed with a literal, keep the barrel access lazy.
- *Read the wire, not the transport name.* A "stream" that flattens to buffered =connection.call=; a "tunnel" that's IPv6-only while curl says 101 and the browser says refused. curl ≠ browser (CORS, IPv4/IPv6).
- *The env is not the code.* Half the session was daemon churn (AddrInUse loops, dueling daemons, a stray squatter, IPv6 bind). The fix + tests were green long before the live app could show it.
