* the design that survived the rulings

- ONE schematic =v.primitives.instance.Instance=. The two-contract proposal fell to "why are those two different?" — the answer was that inheritance could simply run BEFORE the cast, at which point a daemon's =lighthouse= and =datamap= are plainly required and "none declared, none to inherit" becomes the schematic's own sentence: =daemon[probe] must have required properties lighthouse=. The hand-written fault died with the second schematic.
- Defaults are COPIES, never shared. m52 measured that =Value.Decode= on an already-decoded value throws; a root lighthouse shared by reference into N daemons would be visited N+1 times. =resolve.defaults= clones with =v.clone= (guarded on =!== undefined= — =??== with an undefined right side leaves an OWN undefined key that TypeBox reads as "must be object"); =resolve.mountpoints= seats each copy (=datamap.mountpoint= + =db.file = <slug>.viva.db=, a declared file wins). A copy repeats its source's faults, so =integrate.settle= filters a daemon sentence whose tail equals a root sentence — reported once, at the root. Measured on the stucatch mirror before and after.
- Identity is a manifest everywhere: =runtime= · =clients[]= (an ARRAY now — a record keyed by the slug it also carries was the parochial shape) · =services[]= carry =manifest: {type, slug}=; daemon =docs= folds into =manifest.{name, description, icon}= and =Manifest= gains =icon=; =runtime.datamap= is gone (zero readers, no =runtime/= dir under any mountpoint); =mask.mount= is =mountpoint= on daemon · service · datamap (beef's fs/reference pin), =module.mount= the one outlier that stays.
- The kernel is =v.union([string, Mode, Module])=; =Mode.mountpoint= is =v.union([Mountpoint, v.null()])= so a thunk that yields null passes the schematic and the REQUIRED env row carries the verdict — measured: a union with a codec branch decodes a string to =Path= and keeps =null=, and an inline module crosses with its thunks and =App= intact. The m53 throw on a RELATIVE kernel mountpoint is kept in =populate.recipe= (=dress=): a union-level fault reads "Expected union value", which would have been a worse sentence than the throw.
- The pinhole is a belt: =paladin.hydrate(node, record?, at?)= in =belt/hydrate.js=. The prototype is 38 lines: fields · =home= · =mount()= = =populate.environment · populate.recipe · resolve.defaults · resolve.mountpoints · integrate.settle · publish=.

* three traps hit while cutting it

1. **A removed line carries the old secret.** The regenerated =paladin-instance.snapshot.json= is redacted, but the DIFF against the old file carries the old key in a =-= line — a patch file would have shipped it. Excluded the hunk; the suite regenerates the file after M2; the org says =rm= the old one first.
2. **Slicing a hunk out by the next =--- a/= swallowed the two =--- /dev/null= new-file hunks that followed it** (33 headers, not 35). Caught by counting; regenerated from the sandbox. A patch file is verified by its header count against the file list, never by eye.
3. **The compact extractor takes the newest transcript, and the newest was the sibling's.** =e2a804e1…= (m57, 231 turns, live within the minute) sat above this session's =6eaf66cc…=. The session id is the scratchpad dir name; pass it explicitly. The sibling touches hello-world too — re-dry-run the repo patch before any =go= (pointer in frontier).
