#+title: the kajuit image never moved because its build stage read nothing from the context — and the stamp arg was never passed
#+filetags: :compact:kajuit:docker:ci:coolify:registry:deploy:

* the arc

/"for some reason the builds of kajuit dont get properly tagged. when i go into

Mid-turn, while I was reading the Dockerfiles, he pasted both Coolify service
panels — runtime's and kajuit's — full startup logs. Trimmed here to the two

#+begin_example
runtime:  Image …/vivalence/runtime:alpine Pulling
          5de55e5ef9c0 Already exists · bb8020821173 Pulling fs layer · … (17 new layers, 148MB)
          Image …/vivalence/runtime:alpine Pulled

kajuit:   Image …/vivalence/kajuit:alpine Pulling
          Image …/vivalence/kajuit:alpine Pulled          ← zero layer lines
#+end_example

Zero layer lines is not a stalled pull; it is docker saying /local digest ==
remote digest/. beef's "not a coolify issue" was right, and the paste is what
made it provable — the asymmetry between two services pulled from the same
registry by the same daemon isolates the variable to the image.

* the grounding — what the two Dockerfiles actually are

=systems/runtime/Dockerfile= is =FROM vivalence/viva:alpine= + =COPY registry/=
+ =RUN deno cache=. It INHERITS the base's layers, and the base does
=COPY systems/ subsystems/ registry/=. So runtime's digest is a function of the
whole repo snapshot: any source change moves it.

=systems/kajuit/Dockerfile= is two stages, and the second one throws the first
away:

#+begin_src dockerfile
FROM vivalence/viva:alpine AS build      # ← mutable local tag, the ONLY input
RUN deno install
RUN deno task kajuit/bundle

FROM nginx:alpine                        # ← the base's layers end here
COPY --from=build /viva/repository/systems/kajuit/build /usr/share/nginx/html
#+end_src

Two facts fall out of that shape:

1. the shipped image is a pure function of the vite output bytes plus three
   tiny static layers (nginx conf, entrypoint heredoc, chmod). Nothing of
   =vivalence/viva:alpine= survives into it.
2. the build stage takes **zero input from the build context** — no =COPY=, no
   =ARG= value. Its BuildKit cache key is the base image ID plus two literal
   RUN strings. A cached base means the bundle stage never runs, the
   =COPY --from= hits cache too, the final image is byte-identical, =docker
   push= uploads nothing, the registry tag does not move, and coolify's
   =docker compose pull= prints Pulling/Pulled with no layers.

* the probe — measure before proposing

Local docker daemon was down (=Cannot connect to the Docker daemon at
unix:///Users/finn/.docker/run/docker.sock=), which turned out to be a gift:
=docker manifest inspect= and =docker buildx imagetools= are registry-only and
worked anyway, and the rest went through the registry HTTP API with the
credential pulled from the keychain (=docker-credential-desktop get=, user
=beef=). Read-only throughout. Raw:

#+begin_example
beef/viva/vivalence/kajuit:alpine   sha256:15f9e892…  created 23:00:58+02:00  arm64
beef/viva/vivalence/runtime:alpine  sha256:5525ac85…  created 23:00:15+02:00  arm64
kajuit history: COPY /viva/repository/systems/kajuit/build …  23:00:58   (fresh layer)
deployed kajuit container started                             19:28:59Z  (older)
edge headers: {'Server': 'nginx'} — no cf-cache-status, no age, no via
#+end_example

Two hypotheses died on that data. A CDN caching the manifest and serving a
stale tag→digest map: dead, plain nginx, and two consecutive GETs returned the
same ETag with no cache headers. "The tag literally never moves": dead too —
kajuit's top layer carried a fresh timestamp, so /that/ pipeline did push a new
image. What survives is the narrow one: the tag moves **only when the bundle
bytes differ**, and the bundle stage is easy to skip.

The clincher is in =systems/kajuit/vite.config.mjs:110=:

#+begin_src js
define: { __VIVA_BUILD__: JSON.stringify(stamp()) }   // stamp() → { …, built: new Date().toISOString() }
#+end_src

A fresh timestamp is baked into every real vite run, so a run that happens
CANNOT produce byte-identical output. Digest unchanged therefore proves vite
never ran — a cache hit, not a determinism story. That inverted the question
from "why is the output the same?" to "why didn't it build?", which is the
question with an answer.

And the arg that was supposed to prevent exactly this had been declared and
never passed. =ARG VIVA_STAMP= sat in the kajuit Dockerfile; neither
=.gitlab-ci.yml= nor =deno.jsonc kajuit/build= passed =--build-arg=. The
frontier had been carrying the debt as /"proof owed on beef's next
=--build-arg= deploy"/ — the fix had been designed a session earlier and only
half-installed, so the one input designed to vary per commit was always empty,
and =.dockerignore= (=.jj=, =.git=) had already killed the fallback path
=stamp()= would otherwise have used inside the container.

* the go

/"go"/ — four files.

- =systems/kajuit/Dockerfile= — =ARG VIVA_STAMP= + =ENV= moved BELOW
  =RUN deno install=. Placement is the whole trick: a build-arg invalidates
  cache from its own line down, so above the install it would re-resolve npm
  every commit; below it, only the bundle re-runs.
- =.gitlab-ci.yml= — =export VIVA_STAMP="$CI_COMMIT_SHORT_SHA
  $CI_COMMIT_SHORT_SHA $CI_COMMIT_TIMESTAMP"=, fed to the kajuit build; the
  four hand-written tag lines and four push lines collapsed into one loop that
  also pushes an immutable =:$CI_COMMIT_SHORT_SHA= tag per image; =stages=
  gained =deploy= and the two commented-out Coolify webhook jobs went live.
- =deno.jsonc= — new =kajuit/stamp= task (jj change id + jj commit id + git
  =%cI=), consumed by =kajuit/build= as
  =--build-arg VIVA_STAMP="$(deno task -q kajuit/stamp)"=; and all eight
  =tag=/=push= tasks repointed from =registry.vivalence.org/vivalence/*= —
  which 401/404s, the local publish flow had been pushing into a repo path
  that does not exist — to =registry.vivalence.org/beef/viva/vivalence/*=.
- =.ikiro/world/frontier.md= — the stamp tail rewritten around the cache-key
  mechanism.

Adjustment flagged, not silent: the two deploy jobs carry
=rules: - if: $COOLIFY_TOKEN && $COOLIFY_BASE=. I cannot see whether those CI
variables exist, and an unguarded =curl --fail= would red the pipeline for a
missing variable. Set them and the jobs fire; unset, they skip.

* what this session is really about

The bug category is /an artifact that carries no identity/. One mutable
=:alpine= tag per image, nothing tagged by commit, no stamp reaching the
bytes — so "did the push happen?" and "what is deployed?" were both
unanswerable, and a silent no-op build was indistinguishable from a working
one. The fix is not a cache-bust; it is making commit identity physically
enter the stage (=ARG=) and making the push leave a receipt (=:$SHA=). A cache
key cannot see what its stage does not consume.

2. =$COOLIFY_TOKEN= / =$COOLIFY_BASE= set in GitLab, or the deploy jobs stay

   =git log -1 --format=%cI=, the last *git* commit — so uncommitted work

   =committer.timestamp().format("%+")= (already the template in
   =vite.config.mjs:50=) is the alternative. Bundle bytes vary either way;
   this only changes what the boot display reads.
