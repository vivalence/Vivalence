** Lessons

1. *Triple-coupled identity*: package name + runtime registry key + docker image often share a single string. Rename one, must rename all three atomically. Codebase grep alone misses this — must trace the resolution path (=vite.config.mjs= → =paladin.variant.clients.X= → wafer manifest). Pensieve-like reasoning: index by content/role, not by filesystem position.

2. *Two-pass scope*: agent first-pass surfaces obvious surfaces (imports, configs); second pass needed for runtime-key reads, comment blocks, nested .ikiro, env-var consumers across wafers. Same pattern as topology→corpus rename (2026-04-29c). Don't claim "complete inventory" after one pass.

3. *jj working-copy semantics*: filesystem =mv= works — jj snapshot detects rename via similarity. =jj mv= explicit not needed. But mid-flight rg sweeps over a moved tree can return stale snapshot output; verify state by reading specific canonical files when in doubt.

4. *Hard cutover policy*: Finn picks short downtime over dual-key complexity. Implication for future renames: accept the brief breakage window; don't engineer compatibility shims unless asked. Cleaner state long-term.

5. *Concrete sweep patterns*: rg patterns to run for any string-rename: bare, with package prefix, with path prefix (=systems/X=, =vivalence/X:=), uppercase, snake-case, env var prefix, image-tag standalone, taskname like (=X/build=). Run them all, glob-exclude bak/, .svelte-kit/, .vite/, build/, node_modules/, .claude/worktrees/, compacts/, zettelkasten.md.

6. *Identity vs MIME / DOM ambiguity*: bare "html" in code can mean (a) our system, (b) MIME text/html, (c) =<html>= DOM tag, (d) file extension =.html=. Context-sensitive distinction — sweep must inspect each hit. Lesson holds for any common-word identity (will surface again if other systems get common-word names).
