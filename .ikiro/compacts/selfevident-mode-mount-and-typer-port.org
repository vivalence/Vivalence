** Root cause — the SELFEVIDENT launch path was never implemented

nyan is launched from the nav (=panels/d/navigation.js= → =openFromMode=) which does =daemon.entities.thread.create({ mode: mode.id })= — **no intent**. Then the daemon =Thread.ts beforeCreate= hook:

#+begin_src js
if (!thread.intent) return;            // ← bails: thread.traits stays []
…thread.traits = [...intent.traits];   // traits only ever clone from the INTENT
#+end_src

So an intent-less, mode-only thread gets =traits = []= → client dossier adds LABELED → =["LABELED"]= only. No QUEUEING (no Stall, no buffer pull), and the SELFEVIDENT bodies are empty markers on BOTH sides (=traits/thread/selfevident.js= → =(thread)=>{}=; runtime =daemon/traits/index.js= → =()=>{}=). Nothing ever calls =thread.$buffer.set(...)=. → yield-dot.

Contrast: modes that render (pick/exhibit = BUFFERED+EMITTER) launch via an **intent** carrying AIMED+QUEUEING → Stall pulls buffers from the emitter → =$buffer= set → Frame loads the bundle. nyan has no emitter, no intent, no queue → no buffer source anywhere.

** Where other thread keys come from (asked, mapped)

- class fields (=thread.js=): =$buffer $conversation $phase $traits $trait $label $liveTranscript=.
- traits install the rest: QUEUEING → =thread.queue= (feeds =$buffer=); LABELED → =label=; CONVERSATIONAL → =conversation=.
- =$buffers/$turns= = auto-wrapped from Collection fields by EM =integrate=, not hand-set.
- Precedent for the fix: QUEUEING is the trait that wires =$buffer=. SELFEVIDENT is the same slot minus the queue — build one buffer, set =$buffer=.

** The design clarification (Finn) + chosen model

Finn rejected the "copy SELFEVIDENT onto the thread" framing: =something is off. idea is that selfevident modes can be opened without an intent. intent just clones into session. so selfevident modes start sessions by them selves possibly.= and =we also have mode traits. [traits dir] why not there?=

Resolved tension: a **mode** trait is mode-scoped (a shared singleton, no thread in scope) — it can OWN buffer construction (it already has =mode.buffer()= + =mode.buffered=) but cannot SET it (the buffer lives in per-session =thread.$buffer=). The setter must be thread-scoped. Final model gates on the MODE's trait at thread-resolve instead of propagating the trait onto the thread → no =Thread.ts= change, no thread-trait copy.

Chosen placement (Finn picked =a= from three: [a] thread-dossier use, [b] main-deck resolve, [c] openFromMode launch-only). [a] wins: dossier is where per-thread setup lives, fires on every resolve (reload-safe), idempotent.

** The fix

=systems/kajuit/src/typology/entities/thread/dossier.js= — new =use= step (after wireConversational), + =import { Buffer } from "../buffer.js"=:

#+begin_src js
async (ctx, next) => {
  await next();
  const thread = ctx.entity;
  const modeId = thread.mode?.id ?? thread.mode;
  const mode = thread.daemon?.entities?.mode?.$entities.get().find((m) => m.id === modeId);
  if (!mode?.implements?.("selfevident") || !mode.buffer || thread.$buffer.get()) return;

  const buffer = Buffer.from(mode.buffer(), mode.buffered);
  buffer.context = { buffer, terminal: thread };
  buffer.status = "ACTIVE";
  thread.$buffer.set(buffer);
},
#+end_src

** The second bug — =buffer.mount is not a function=

First attempt used =await thread.daemon.entities.buffer.merge(mode.buffer())=. It rendered (setup panel showed) but Frame threw on =buffer.mount()=. Root: =entity-manager.js integrate()= bails =if (!raw?.id) return raw= — =mode.buffer()= is an id-less ephemeral pojo, so =merge= returned the **raw pojo** (a plain object, no =Buffer= prototype, no =.mount=). Fix = =Buffer.from(pojo, view)= (=entities/buffer.js:32=): =Object.assign(new Buffer(), pojo)= + sets =view= → a real =Buffer= instance (prototype =mount/destroy/on= intact), skips the repo entirely. Correct for an ephemeral, no-id, no-roundtrip buffer.
