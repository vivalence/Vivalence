* Arc

** the scout found four defects before a line was written

beef asked for recon, not code, and the recon paid. Eight claims from the connoisseur pass were
re-measured live; all eight held, but two of the quest's own facts had drifted and four bugs sat
in the tangle waiting to be typed in.

The drift: =population.js:127= is at =systems/runtime/daemon/lifecycle/=, not
=subsystems/paladin/lifecycle/=. Line number exact, subsystem wrong. And the "pre-existing red,
multiplayer, unrelated" turned out to be diagnosable — the registry census prints no
=@commons/instance/multiplayer= at all, because it lives under =commons/instances/bak/=. The test
asserts a wafer that was moved. Stale assertion, not a registry fault.

The four tangle defects:

| defect | why it mattered |
|--------+-----------------|
| =drink()='s =while (size < LIMITS.bytes)= read a whole chunk THEN added | one oversized chunk blows the 2 MB cap; the bound was advice |
| =response.body.getReader()= on a null body | =hop()= guarantees ok + a text content-type, never a body |
| =extract.js= / =skeleton.js= labelled PURE while importing =LIMITS= from =hop.js= | the "pure" module dragged the network module into its graph |
| =new Blob(chunks).text()= on a byte-truncated stream | a cut multi-byte character becomes U+FFFD at the tail of every capped page |

All four were repaired in the landing rather than the tangle. =LIMITS= got its own module so the
pure halves stay pure; =drink()= slices the overshoot and decodes with =TextDecoder({stream:true})=,
which holds an incomplete sequence back across the boundary so a cut never lands mid-character
and the trailing partial is dropped rather than mangled.

** a test I wrote caught a bug my own fix had

=extract= absolutises links so a relative href quoted back is not a dead reference. The obvious
implementation resolves every href against the base — and =new URL("javascript:void(0)", base)=
*succeeds*, because =javascript:= is a perfectly valid scheme. The array filter =/^https?:/= hid
it: links came back clean while the markdown body kept the =javascript:= target.

Resolving is not vetting. The scheme is now checked on the RESULT, and anything that is not
http(s) loses its href entirely. The quest's own table had claimed this defect "repaired in the
tangle" — the tangle repaired the array only.

** B — the sqlite turns are not duplicated, they are abandoned

beef: /"look at the sqlite hello world turns again."/ 34 user rows against 28 assistant rows.

Not a write-path duplication. **6 user turns have no assistant reply**, exactly the gap:

| thread | text | sends | span | unanswered |
|--------+------+-------+------+------------|
| =01a080aa= | "where we at…" | 5 | 175s | 4 |
| =01a081a2= | "search for dog…" | 3 | 232s | 2 |

Chain integrity is intact — every turn properly parented, no orphans, no cycles. What happens is
that **re-sending while a round is in flight persists a new user turn and abandons the previous
one**. The row stays. Only the last send in each chain is answered.

It matters past tidiness: those rows are still in the thread, so the model reads the same question
five times in its own history. Same shape as the =Request aborted= from M1's walk — a re-send kills
the in-flight round but not its row.

** the m3 trace: five findings, one structural

beef: /"the generator / emitter / tool wiring rn seems to be mildly off. prep this with solid
thorough logging."/ then /"ok trace and log m3. no deploy yet"/.

*** the double-bind is a real path, not a worry

Two places bind a buffer to a thread and both advance the counter — =generative.js= =gen.buffer=
(=buffer.index = found.counter++=) and the =emitter.js= drain loop (=buffer.index =
ctx.thread.counter++=). =gen.buffer= binds whenever handed a thread; the emitter binds every buffer
it drains. **M3 declares EMITTER + GENERATIVE together**, which is precisely the path where one
drawn page advances the counter twice. Nothing in 334 steps exercises it, which is why it has
stayed invisible. =P-nodoublebind= is not a hypothetical; it is two lines of live code. The fix
when wanted: mint thread-free inside an emitter and let the emitter bind.

*** the same capability arms under two names

=generative.js:46= slurps a declared generator at the ROOT and mounts the fallback under =/view=.
So =<mode>_render= if you declare one, =<mode>_view_render= if you do not. Nothing makes a declared
generator branch itself under =/view= — convention held by hand. beef's own =@beef this is weirdly
wired= comment sits on that line and is right.

*** the emitter is never armed as a tool

Confirmed on flashcard · judge · exhibit · dojo · aprende. M3's draw path needs a declared
generator or a tool that delegates; an emitter node alone gives the model nothing to call.

*** CONVERSATIONAL is implemented nowhere

The production map holds 15 traits — AGENTIC APPLICATION BOOTED DATASET DATASINK EMITTER EXPOSED
FRAUGHT GENERATIVE HARNESSED INTENTED MOUNTED SELFEVIDENT STANDALONE TOOLED. =CONVERSATIONAL= is
not among them, and =stagger= calls =traits[trait]?.()=, so it fails silently. hello-world, dealer
and oracle all declare it. The only definition in the tree is a local stub in
=conversation.test.js:40=.

*** two asymmetries to know before writing M3

=ctx.thread= is a STRING id on the tool path (=harnessed.js:69= binds the id) and a loaded ENTITY
on the emitter path (=emitter.js= =findOne=). =gen.buffer= absorbs it by calling =findOne= on
either; a generator author reading =ctx.thread= does not. And =buffer.id= is =undefined= when the
emitter binds, because the flush comes after — correct behaviour, and a trap for anything keyed on
the id at that moment.

* Failures

**Claimed a defect that was not one.** Mid-trace I said the client reads an =entities.buffer= key
no server path writes. Wrong: =settled()= at =turns.js:35= DERIVES =entities= from the m26 bag, so
={message, buffer:[…]}= arrives as =entities.buffer= correctly. I had grepped for who WRITES the
key and concluded from its absence, without reading the fold that builds it. Absence of a writer
is not absence of a path when the path is derived.

**Called the title fix verified when no tool had run.** The model answered with the right title —
from the H1 of a tool_result already in the thread, on a turn showing "thought" and no tool count.
Caught it, said so, and re-ran on a page not in context. The lesson is the one M1 already taught in
another costume: a plausible output is not evidence about the mechanism that was supposed to
produce it.

**Three patch scripts failed on stale text.** =deno fmt= had rewrapped the exact lines the python
was matching, twice on the same file, and once the assertion silently left an edit unapplied while
its siblings landed — the test then failed on a change I believed I had made. Read the formatted
text, patch against that, and never batch asserts that can partially apply.

**Used beef's own browser tab instead of creating one.** No harm, and the task was walking his app,
but the guidance says create your own.
