* three causes, one disease

Identity recomputed forever; transients never released.

** 1. hash recomputed on every comparison

~subsystems/typology/prototypes/vector.js:29~ scans for an existing trajectory:

#+begin_src js
const existing = Array.from(this.trajectories.entries()).find(
  ([i]) => i.nature === pattern.nature || i.hash === pattern.hash,
);
#+end_src

~Array.from(map.entries())~ materialises the whole Map per call, then linear
scans. Inside that scan ~pattern.hash~ was recomputed *per entry*, because
~signature.js:71~ was a bare getter over ~hasher()~, and ~pattern.js:48~
recurses the full trace chain — each link running ~hash.array~ =
~fnv1a(JSON.stringify(deep(arr)))~. Deep-sort + stringify, per link, per
entry, per branch. The same scan is duplicated at ~vector.js:72~ and ~:95~.

** 2. every branch grew its parent forever

~signature.js:37~:

#+begin_src js
from(trace, anon = false) {
  this.trace = trace;
  if (!anon) this.trace?.gauges.push(this);
#+end_src

~shard/track.js:16~ calls ~parent.branch(nature)~ per HTTP request;
~socket.js~ ~#answer~ calls ~this.span.branch(packet.signal)~ per WS frame.
Any span held as a long-lived field accumulates gauges without bound. The
~anon~ escape hatch already existed and nothing used it.

** 3. the root journal was unbounded

~span.js:48~ pushes every record into ~root.journal~. ~telemetry.js:11~ trims
the derived *story* to 200 roots; the journal it folds from kept everything.

Reframing that mattered: this is not a general Span defect. Request-scoped
roots die with their request. Exactly one held root exists — ~Socket.span~ —
and grepping every ~.records~/~.journal~ consumer proved *nothing ever reads
it*. Pure accumulation, written and never read.

* the fixes

beef took B immediately and made me show my work on A:

#+begin_quote

For a, show me three different approaches for implementing this. It's right in
spirit, but I don't yet like the implementation. and propose already divs for
the low hanging fruits.
#+end_quote

I offered A1 (lazy memo + invalidate in ~from~), A2 (hash pinned as data,
shadowing the prototype getter), A3 (abolish deep-hash — identity as a
composed key string). I recommended A3. He went the other way, and caught a
bug in my A2 sketch while doing it:

#+begin_quote
a2 is more like it. but does this work?
~return (this.hash = this.hasher());~
not sure i can overwrite a getter?
ok lets just use the original #hash solution. its fine. go.
#+end_quote

He was right and I was wrong: classes run strict, a prototype getter with no
setter throws on assignment. A2 needed ~Object.defineProperty~ — I had
sketched something that cannot run. **He debugged my proposal before it was
code.**

Landed:

#+begin_src js
// subsystems/typology/prototypes/signature.js
#hash = null;

from(trace, anon = false) {
  this.#hash = null;
  this.trace = trace;

get hash() {
  return (this.#hash ??= this.hasher());
}
#+end_src

#+begin_src js
// subsystems/typology/prototypes/span.js
const CONFIG = { journal: 1000 };

from(trace) {
  return super.from(trace, true);
}

const journal = this.records;
journal.push(record);
if (journal.length > CONFIG.journal) journal.splice(0, journal.length - CONFIG.journal);
#+end_src

~splice~ over ~shift~ so a burst that overshoots trims in one pass. The cap
number is his: *"limit them. 1000 tops."*

Memo safety was grepped, not assumed: ~.nature~ is written only inside
constructors and coercions (~signature.js:15,17~, ~signal.js:63~), so ~from()~
is the sole invalidation point. Span-side, no consumer outside ~signature.js~
reads ~gauges~/~heir~/~descendants~ on a Span.
