* the two false alarms — and why they were caught

The agent's report opened with a BLOCKS entry claiming the lighthouse JWT secret is the literal string =() => paladin.secret.get("SECRET_VIVA_JWT")=, identical in every recipe, published on GitHub, and therefore that anyone can mint a valid token for any identity on the live prod URL today. It cited =jwt.js:81= (=secret = new TextEncoder().encode(service.secrets.jwt)=) and =integrate.js:75= (=is.empty= over secrets, which never fires a function), and backed both with m51 M0's measured diffs.

Every cited line is real. The conclusion is not.

=subsystems/paladin/belt/hydrate.js:16-40= recurses through arrays and plain objects and calls any function it meets, re-firing on the result. =lifecycle/populate.js:176= passes each service declaration through it. So =secrets: { jwt: () => … }= resolves at mount, same as statics. Pinned since m59 by =settle.test.js:194=.

Two lessons, and they are the same lesson twice.

- **A quest's =#+status= is a claim with a timestamp, not a fact.** m51 says /"four defects PROVEN by probe — one of them kills every LLM call at HEAD."/ It was true when measured. m59 made it false without touching m51. An agent reading quests as current state will confidently relay stale measurements, and the more specific the citation the more convincing the error.
- **Question A would have caught it in one step.** What is =service.secrets.jwt= GUARANTEED to be at the end of processing? That is a schematic-and-settle question with one checkable answer. The agent asked Question B instead — it traced the machinery, found a place where a thunk is NOT fired (=integrate.js:75=), and mistook one road for the only road.

The near-miss is the point: the draft relay said prod was forgeable. Checking =hydrate.js= before sending cost two tool calls.
