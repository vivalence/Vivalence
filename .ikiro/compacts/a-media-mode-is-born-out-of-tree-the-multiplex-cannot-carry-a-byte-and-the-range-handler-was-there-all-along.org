* one breath

beef asked how to build a viva mode for editing audio and video, self-rolled or borrowed. The
answer split the work: borrow the engines (ffmpeg on the daemon, the browser's own media
elements), build the ontology. Asked for the full design, it became three literal ontologies
on the mount — =media= · =composition= · =annotation= — with the composition shaped after
OpenTimelineIO (tracks of clips and gaps, positions implied by order), render as a streamed
process that lands a media row, and a Resolve-shaped App: bin · monitor · timeline · inspector.
On /"yes go build"/ it landed as the =@media= registry package, =@media/editor/media=, with
five suites green against a real ffmpeg. Two things the build learned that the design did not
know: the kajuit multiplex decodes every upstream chunk as text, so a file upload needs its own
http door; and the Range handler the design called a missing prerequisite already existed in
the cargo route — the real defect is that it reads the whole file before slicing it.

* laws

- =Socket.feed= (=subsystems/typology/prototypes/socket.js:271=) decodes upstream with
  =TextDecoder= and sends JSON text frames: binary never crosses the kajuit multiplex. A file
  upload needs a plain http =Connection=.
- A literal's =symbol= is a fold of slugs by depth: a slug that shares a root with a deeper
  sibling must match its depth, or the deeper one replaces it.
- A rename-on-settle bin must consume its per-path marks only after a successful upsert: the
  watcher probes a half-written file first and throws.
- =path.extname(".mp4")= is =""= — a helper that takes a filename must be handed one.
