#+TITLE: m17 — the client ctx grammar: terminal is ctx, context is the source, props are the bundle-boundary handoff

Companion to [[m16-provisioning-doctrine-effect-carriers-and-one-grammar-two-trees]].

law "contexts narrow down the tree." M17 answers the question M16 left open —

* the answer (three findings that close the seam)

1. THE TERMINAL IS THE CLIENT CTX. Server =ctx= = an ephemeral per-request
   envelope {daemon, mode, thread, input, pool, turn}, built by the middleware
   onion and torn down each call. The terminal (=entities/terminal.js=) = the
   SAME spine {daemon, thread, buffer, stall} held STANDING and reactive. The
   server UNFOLDS ctx per request; the client HOLDS the folded ctx as a live
   cursor. Confirmed at the leaf: mode apps receive EXACTLY =({terminal, buffer})=
   (=Aprende.svelte:16=, =Oracle.svelte:11=, =Riddler.svelte:2=).

2. "THE CLIENT HAS NO MIDDLEWARE" IS FALSE. It runs the server's own ctx-onion —
   at the DATASPACE, not the DOM: =prototypes/dataspace.js:22= composes
   =shard.context.attach(dossier|repository|dataspace)=; =daemon/dossier.js:23=
   binds =("daemon", daemon)=. Middleware lives where entities RESOLVE — the dual
   of the server composing ctx where requests HANDLE. The DOM/render layer is
   middleware-free and stays so.

3. THE TWO LAWS, unnamed until now: =attach= ⟷ =setContext= (set-once, the
   standing world → the DECKS) and =bind= ⟷ =chain()= (re-resolved per use — the
   server per call, the client per cursor-move → the CURSOR). The client already
   runs both; it never named them as the server duals they are.

are the escape hatch for leaves that left the tree.

  context; it rides a prop only because the app is a separate compilation.

* the grammar (three layers, not a narrowing tree)

- DECKS (attach-dual, host bundle) — the world, at =+layout=:
  LIGHTHOUSE·BRIDGE·TERMINALS·BOX.
- TERMINAL (attach-dual, host bundle) — the active cursor, provided at =+page=
  (the common ancestor of A/D/E/F/shoulder — NOT panel A: they are SIBLINGS in
  the flat pincer, a panel-A provider can't reach them), consumed by every
  host-side surface; sourced from =TERMINALS.$active=.
- THE BUNDLE HANDOFF (props) — Frame → the isolated =.url= app.
Entities narrow by DERIVATION (the data axis), not provision:
=thread.$buffers = computed(daemon.entities.buffer.$entities, by thread.id)=.
ONE new symbol falls out: =TERMINAL=. =BUFFER= was proposed then DROPPED — its
sole consumer is the cross-bundle app (props); host-side it is =terminal.$buffer=.
No THREAD/DAEMON/MODE symbols — attributes read off the entities. A =MODE= symbol
would complect the two modes.

* terminal.mode ≠ terminal.thread.mode — name the pair, made concrete

Two modes on two entities: render-mode =buffer.mode= (what app is on screen) and
session-mode =thread.$mode= (the conversation). They diverge via cross-mode
emission (=EMITTER.js:47=). LIVE PROOF found this session: =stores/inspector.js:48=
reaches for a unified =terminal?.mode?.slug= — but =terminal.js= has NO =.mode=
getter, so the inspector's "active mode" row silently renders "—" forever. The
first consumer that wanted one terminal-mode and discovered there isn't one. The
fix is to show BOTH, never to unify.

* the stolen canon — VERIFIED (22 confirmed / 3 refuted, adversarial 3-vote)

- SOLID Owner node (3-0) — the SPINE. One node {owned, cleanups, owner, context}
  unifies effect-ownership + recursive teardown + context-narrowing on one tree;
  =cleanNode= disposes children-before-self. Svelte's component tree IS this
  Owner tree. → TERMINAL at =+page=, effects at their provider, teardown by the
  destroy cascade.
- RE-FRAME coeffects (3-0) — the KEY steal: the ONLY surveyed architecture with a
  genuine COMPOSE step, the direct dual of the server ctx-vector (docstring:
  coeffects/effects "analogous to request and response"). And the client ALREADY
  spends it — at the dataspace. So the compose isn't missing; it lives exactly
  where re-frame puts it (the resolution boundary), not the DOM.
- XSTATE invoke (3-0, one over-claim refuted) — the CAVEAT: only invoked/OWNED
  effects auto-teardown; manual subscriptions need EXPLICIT teardown. Directly
  validates the =conversational.wire()= teardown that =thread/dossier.js:54=
  DISCARDS — a manual subscription with no owner.
- TCA scope = derivation; Elm Cmd = effects-return-teardown, literal.
