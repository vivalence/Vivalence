#+TOPIC: Companion to =aprende-mode-nyan-domain-emitters-and-v-rel-identity.org= (the WHAT). This captures the HOW: the practices Finn drove and that earned their keep this session, each tied to a verbatim directive and the moment it bit. The throughline: the connoisseur is not only a code JUDGE, he is a problem FRAMER; and root-cause comes from reading code + probing the live system, never from a plausible story.

* The connoisseur frames the problem (not just judges the code)
Twice Finn put the connoisseur BEFORE the work, on the PROBLEM:
- emitter ideation: "ideate twwo emitter that integrate with the learning donain. ... let the conoisseur have a look at the problem first."
- the v.rel bug: "we absolutely want to be able to send literals and other entities through v. figure this out! let the conosseur have a look."
The pattern: before writing, the connoisseur states the *essential structure* and the *seam*. It produced the load-bearing insights — "the seam is the emitter, keep engine.js domain-free"; "the prize is the symmetry pair (ingress dual of egress), build the loop not a feeder"; "two emitters = one shape, two pickers (Vector-consumer law)"; "randomness belongs in the picker, never the engine"; and for v.rel, the one that fixed it: **"a relation is referenced by IDENTITY, not embedded by value — the schema conflated reference with inclusion."** Lesson: reach for the connoisseur at design time, framed at the problem, not only at review time over a diff.

* Probe to ground-truth — never ship a theory
The two bugs were both solved by EVIDENCE, not reasoning:
- *cast/Collection maul.* I theorized "Convert clones → strips the Collection prototype → still breaks." Then I PROBED: a real class-based `Collection` through `cast` → `instanceof` intact, **same reference**. typebox preserves class instances, only shallow-clones plain objects. The theory was wrong; the probe was right; the fix shipped on the probe. (My first guardrail test used a plain-object fake and failed on ref-equality — the fake wasn't representative; corrected to a class instance.)
- *orphaned buffer.* Finn pasted the DB row — "this is from my database." — `"thread": null`. That one fact + reading =daemon/traits/emitter.js= (the buffer is `flush`ed inside nyan's thread-less context BEFORE aprende re-binds) gave the exact chain. Fix = forward `thread` to nyan so it binds before its own flush; verified live (emitted `buffer.thread` now the bound object).
Lesson: when behavior surprises, write the smallest probe (a class through cast; an HTTP emit + inspect the response shape; the DB row) and read the trait. The investigator's ground-truth gate applies to my own hypotheses, hardest.

* Refuse the workaround when the user wants the capability
I first "fixed" the cast maul by passing ids across the boundary — sidestepping entities-through-`v` entirely. Finn rejected it outright: "we absolutely want to be able to send literals and other entities through v. figure this out!" The workaround removed a capability the system should have. Lesson: a patch that AVOIDS the broken thing is not a fix when the broken thing is a capability the user wants — fix the capability (here, in typology core, blast-bracketed: green baseline → minimal `v.rel` change → guardrail test → full-suite bookend).

Finn sent the SAME message twice — "read through the other modes and especially the playground. read about how navigation is handled. we need that for the aprende frontend and action mavigation" — because my first pass jumped to sketching aprende code instead of actually reading the navigation system. The second time I read =app/panels/d/navigation.js=, the =Intent= entity (the AIMED/MASKED/QUEUEING action-navigation primitive, "// TODO activate"), and the spawner's emit→`terminal.buffer` pattern — THEN proposed. Lesson: when told to "read how X is handled," produce the model from the real code first; a sketch that front-runs the read is the thing being corrected. (Finn then scoped it: "direct now ... not via intents. ignore intent now.")
