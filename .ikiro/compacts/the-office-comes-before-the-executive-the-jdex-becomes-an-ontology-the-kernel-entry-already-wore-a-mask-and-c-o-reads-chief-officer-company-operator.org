* the design as it stands (the quest is canonical; this is the fold)

- one literal, three ontologies: =vdex= (DOCUMENT, body served by freight) · =message= (MESSAGE + MAILED | CHATTED, body in row) · =transaction= (POSTED, Σ = 0, empty slot). An ontology IS the one TOPOGRAPHICAL symbol — education's law, unchanged.
- the JD id is a symbol (=vdex.id.22.04=), a file is a literal, the slug is coordinate · stem · extension. Directories never enter the slug; =asset.path= is the truth.
- the per-mode config is the object kernel entry ={module, mountpoint, statics, secrets}=; instance statics OVERRIDE module statics key by key; an unset mountpoint is a doctor =REQUIRED= at its slot, never a silent default.
- office modes OWN their rows (T1.a, the one typology touch: mode↔literal/symbol schematics + =Mode.ts= m:n) and sync them on boot through the factored =install()=, then prune by set difference; scheme symbols ride the modes and are never pruned.
- the c·o family: type =officer=, name "Chief <Domain> Officer", description "company operator — <what it operates>"; =officer/chief= is name "Chief Officer", description "company operator". AGENTIC arms every TOOLED mode under =/<slug>=, so the chief reaches =finance_consult= · =vdex_find= · =email_send= with zero dispatch code.
- services (mail · telegram · slack · ocr) are =@commons/service/*=; the vcompany is its own package, tapped.
