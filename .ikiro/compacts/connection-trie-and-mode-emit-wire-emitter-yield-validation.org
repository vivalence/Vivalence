* The client mode.emit surface — shard.connection.wire

Server builds =mode.emit = shape.object(mode.cake.emitter)= from the Vector directly. Client only has the serialized metadata (=shape.strip(vector)= → ={leaves, branches}=, returned by =/metadata/emitter=). Need the inverse on the client.

Dead-ends Finn rejected, in order:
- a hand-rolled =build()= walker — "directionally correct" but reinvents a primitive.
- =shape.messenger= — "messenger is for socket connections and we are not socketing this. this is not shape.messenger. also it doesnt operate on vector, but connection."
- =aimMerged= per-call wrapper for buffer resolution — "your implementation of aimmerged is wrong. we can instead mode.connection.use() to handle this."

Landed design (Finn: name =wire()=, location =shard/connection.js=):
#+begin_src js
export function wire(connection, stripped) {
  const api = {};
  for (const leaf of stripped?.leaves ?? [])
    api[leaf.nature] = connection.aim(`/${leaf.nature}`);
  for (const [segment, sub] of Object.entries(stripped?.branches ?? {}))
    api[segment] = wire(connection.branch(`/${segment}`), sub);
  return api;
}
#+end_src
=wire= is the connection-flavored sibling of =shape.messenger= (both rebuild =strip= output; differ only in leaf dispatch — =connection.aim= vs =socket.push=). Reachable client-side as =shard.connection.wire= (=gestalten/shard/index.client.js= exports =connection=).

* The big arc — Connection as a url-segment trie

Finn: "when i branch the same branch twice, there is no overlap and no merging. so defining connection.branch(/emit) twice results in two independent instances which means the middlewares i set on one doesnt translate to the other." Wanted overlap "closer to what vector does. although given vector runs on signature whereas connection runs on url. what WOULD that look like?"

Diagnosis: old =branch()= = =new Connection(url.branch(path), this.transport)= — fresh object, snapshot transport. No shared node, no live inheritance.

** v1 spike — explicit parent + pipeline
Trie: =carry= (per-node middleware) + =children= (segment→Connection, memoized) + =parent= field; =get pipeline= walks =this→root= reversing each carry; =request= = =middleware.compose(this.pipeline)(ctx, this.base)=. Ported =connection.test.js= with a "branch overlap" suite (6 cases). Green.

** the path-dispatch bug
Finn showed: =mode.connection.call("/emit/playground/spawn")= did NOT fire the =/emit= middleware, but =mode.emit.playground.spawn()= did. Root cause: middleware fired by DISPATCH NODE, not REQUEST PATH — a root =.call("/emit/...")= treated the endpoint as opaque URL concatenation, never walking the trie. Fix: =resolve(endpoint)= walks EXISTING children (no node creation → no leak on =/entities/<id>=), =fetch= dispatches from the resolved node. Added a regression test (multi-segment call from root hits the branched node's mw). Green.

** v2 — Finn: "can you solve this using a constructor with a signature of two ie without passing parents around?"
Dropped =parent= + =base= + =pipeline=. The parent link became the child's TRANSPORT CLOSURE:
#+begin_src js
constructor(url, transport = shard.transmitter.fetcher) { this.url = ...; this.transport = transport; this.carry = []; this.children = new Map(); }
dispatch(ctx) { return middleware.compose(this.carry)(ctx, this.transport); }
child(segment) {
  let next = this.children.get(segment);
  if (!next) { next = new this.constructor(this.url.branch(`/${segment}`), (ctx) => this.dispatch(ctx)); this.children.set(segment, next); }
  return next;
}
branch(path) { let node = this; for (const segment of segments(path)) node = node.child(segment); return node; }
#+end_src
Child's =transport = (ctx) => parent.dispatch(ctx)= → dynamic, live inheritance, no field. Finn: "ok. better. lets try this."
