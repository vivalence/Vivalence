- =buffer.mode= on a thread buffer is a bare id STRING on the wire — client boot
  (=daemon/dossier.js=) finds buffers with =populate:["literals","symbols"]=, never
  =mode=, and MikroORM serializes an unpopulated m:1 as its scalar id. So a roster row
  must resolve the mode by id against the fully-loaded store =daemon.entities.mode.$entities=
  (keyed reactively), NOT read =buffer.mode.name= directly (=panels/f/widgets/Buffer.svelte='s
  latent bug). =mode.name ?? mode.slug= (name nullable).
- reactive-list idiom for a buffer-view: =atom.chain(terminal,"$thread","$buffers")= +
  =$=-auto-subscription; load = the transparent setter =terminal.buffer = b= (stall
  reacts, no mount/settle/dispatch). Import ONLY =@vivalence/typology= (+ drapes
  components, never =<Icon carbon>= — crashes in a bundle).
- =atom.chain= walks store→plain-prop→store, so
  =atom.chain(terminal,"$thread","daemon","entities","mode","$entities")= reactively
  yields the resolved mode list.
- emitted game buffers all carry =mode.type === "game"= (nyan/write/judge/listen/shadow/
  conjugation/paradigm/riddler); the hub buffer is =type "homepage"=. So the roster
  filter =type === "game"= both selects the games and excludes the hub.

* nyan length slider — logarithmic 1..128

Beef: "look at the nyan mode. i want the slider to go in fluent steps from 1 to 128
logarithmically." =buffer/panels/Home.svelte='s length =<input type=range>= was linear
(=min10 max50 step5=, bound straight to =game.config.count=). Rebound to a normalized log
position: =min0 max1 step0.001=, =value=countToPos(count)=,
=oninput → set("count", posToCount(pos))= where =posToCount(p)=clampCount(round(2^(p·7)))=,
=COUNT_MIN=1 COUNT_MAX=128=. Verified mapping: =0→1, 0.25→3, 0.5→11, 0.75→38, 1→128= —
fine steps low, coarse high, fluent drag. Chips (10/20/30/50) stay as presets.

* the dock close button — one class-name collision, hours of the wrong fix

Beef: "in the dock, add at the top left left of the dot status a close x button icon that
collapses the dock." =panels/a/widgets/Dock.svelte= already had a =<button class="collapse"
onclick={bridge.setDockCollapsed()}>= (mechanism live: =bridge.js:116=, gated by
=a.svelte:73 !dock.collapsed=) — but it never rendered. Moved it left of the pip, swapped
the text × for an SVG X, removed the video-call button per "remove the video call icon
too". Still invisible: "?? no still nothing?!" … "button still invisible" … "I STILL DONT
HAVE A FuKCING CLOSE BUTTON" … "wtf" … "and get me that dock close button to show dammit!"
… "no. i see nothing. i cant hover. no button. nothgin".

The failure was MINE, not the code's: I chased CSS symptoms for round after round — svg
=<path>→<line>=, brighter color, inline width, inline =!important= on button AND svg —
each a guess, each futile. beef's own devtools screenshot showed =button.collapse= at
=0 × 16=; even then I theorized a =!important= width override.

The fix only came once I did the =javascript_tool= DOM assertion the live-validation
ritual already mandates: =getComputedStyle(btn).visibility === "collapse"=. Root cause:
the class name **=collapse= collides with Tailwind's =.collapse { visibility: collapse }=
utility**, loaded globally via =@tailwind utilities= in =client.css=. The button was
=visibility: collapse= — invisible, zero-painted — the entire time; every width/color/
=!important= edit was dead on arrival because the property in play was =visibility=.
=getBoundingClientRect= still reports a box for a collapsed element, which is exactly what
made "0×16 but nothing paints" look like a sizing bug.

Renamed =collapse → dock-close= across the button class + its three CSS selectors;
reverted all the inline =!important= junk to clean class-based CSS. Verified LIVE in a
fresh Chrome tab (=localhost:1794=): =button.dock-close= = =16×16=, =visibility: visible=,
uncovered, =elementFromPoint= at center returns the svg =<line>= (the X paints on top).
beef: "yes. now."

Discipline gap (self-caught, no codeword so not laddered): when an element is in the DOM
but paints nothing, the FIRST probe is =getComputedStyle(el).visibility/display=, not a
width/color edit — and in a project with global =@tailwind utilities=, any component class
name is a potential utility collision (=collapse, hidden, block, flex, grid, container,
visible, fixed, static, table, grow, order=…). Banked to memory as
=project_tailwind_class_collisions=; maps to the existing live-validation family (assert
the DOM, don't guess the CSS).
