* the annotation grammar (row 5)

Beef's m44 inline comment (schema annotation format, =[required] <option> ?optional?=,
env keys, /"semantic level identifiers that are coherent with the @typology/
schematics"/) + /"there is a part in this for you! how do you want the readme.md and
50.01.mdx to format documentation /and tangle demos?"/ Answer held at sketch:

- Principle: the notation is a *render of the schema, never a sibling convention* —
  hand-written =[optional]= beside =.optional()= is two readers and a silent loser,
  m44's disease at the notation level.
- Grammar (docopt family, not coined): =viva instance/create <source: identifier|path>
  [target: path] [--slug=slug]= · semantic types closed set =path·slug·identifier·url= ·
  scope tokens =<ledger>/instances/<slug>= only for the five paladin scopes · =$VIVA_*=
  for env keys · abstract lines use scopes, walkthroughs use literals, never mixed.
- Derivation chain (sketch): =systems/ghost/typology.js= semantic types + =.flag()= →
  =belt/signature.js= fold =({nature,schema}) → grammar string= → =help.js= render →
  docs quote the render via shell channel. README = grammar-only fences; 50.01 = the
  four blocks with fixed carriers + the *tangle demo unit* (tangle fence authors a tiny
  package → Shell capture taps it — hermetic and self-proving).
- Three go-pieces offered, none go'd: ① grammar sweep over README+50.01 ② signature
  fold + help render (rides m44) ③ runner iteration.
