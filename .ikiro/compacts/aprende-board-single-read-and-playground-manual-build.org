** The strength×due scatter — a long polish loop
*** conjugations were missing — NOT a wiring bug, an axis CLIP
*"the splatter plot is not showing any conjugations. why?"* Ground-truthed the live db
(=testament/variant/mountpoint/daemon_brazilian/test-language.viva.db=, whose 298/233/17
byStatus exactly matched Finn's bar). 14 conjugation memories exist, all studied, all with
=nextAt= — but all ~61–63 days OVERDUE, and the Y floor was a hardcoded =symlog(-60)=. They
clipped off the bottom edge (so did the worst-overdue words). Fix: DATA-FIT bounds.
*"fix bounds."* → compute bounds + margin in SYMLOG space (even visual padding at any
magnitude), not day-space (±3 days is invisible at -61d):
#+BEGIN_SRC javascript
  const dueSym = board.filter(r => r.seen).map(r => symlog(r.nextDays));
  const timeLo = Math.min(symlog(-7),  ...dueSym) - 0.3;   // MARGIN in symlog units
  const timeHi = Math.max(symlog(20),  ...dueSym) + 0.3;
#+END_SRC

*** flip the axes
*"flip the x and y axis. time left right, confidence top bottom. and pour some braintokens
into how propper zoom should behave."* Swapped the value tuple to
=[symlog(nextDays), strength]=. X = time (overdue ← =now= → ahead; the =now= markLine is now
VERTICAL at =xAxis:0=, overdue wash fills left). Y = confidence (=type:"log"=, weak bottom /
strong top). Reason beyond the ask: confidence-as-vertical reads "weak stuff = bottom band".

*** zoom design (the braintokens)
Two independent, differently-scaled axes (log × symlog) → NO aspect lock, zoom each axis on
its own. =filterMode:"none"= stays (filtering would drop points AND the now-line/wash —
fatal for this chart). Only =DataZoomComponent= is registered in =subsystems/drapes/stage/
lib.js= (no toolbox → no box-zoom). So: =inside= zoom + =slider= rails (=brushSelect:true= →
drag a box on the rail to frame an edge band) + =minSpan:1= (no sub-pixel) + double-click
reset (=getZr().on("dblclick") → dispatchAction dataZoom start:0 end:100=).

*** edge zoom + trackpad pan (the math fix)
*"its really hard to zoom in on the edges."* → padded the confidence axis (=min 3e-5, max
1.6=) so the 1e-4 weak-pile and the ≈1 strong items lift off the boundary; added the slider
rails. Then *"two finger x-y movement isnt counted. only zoom. add that."* — first tried
echarts =moveOnMouseWheel:true=; Finn: *"your math is off. xy are correlated in weird
ways."* ROOT CAUSE: echarts feeds the SAME wheel delta to both inside zooms → any scroll
moves both axes. echarts has no clean 2D wheel-pan. Fix = MANUAL native =wheel= listener on
the container: =deltaX= pans the time window, =deltaY= the confidence window, each scaled to
its own visible span + clamped [0,100]; pinch (=event.ctrlKey=) is left to echarts
(=zoomOnMouseWheel:"ctrl"=). A =chart.on("datazoom")= resyncs local =zoom= state after
pinch/slider/drag/reset so wheel-pan never jumps; listener torn down on dispose.
