* the arc

brew for package registry architecture. study vivalence's nature. study my past

Synthesis: *"brew or straight.el" is not one model* — the pair agrees on tap
ergonomics and splits exactly where the open forks sit: fork D (version — brew
mints a new identity per major, straight's repo IS the version) and fork E
(store VCS — brew's cellar is artifacts, straight's store is clones). And the

package resolves =@vivalence/*= only under the host =--config= — the right
frame is =@vivalence/*= is the RUNTIME, not a dependency (straight packages
never vendor Emacs); the fix is completing that surface, not an import-map
generator.

The ramblings study surfaced desires m31 never carried: inline-literal

* the goal pinned

beef: /"first step is just I need to be able to pull, install, and load packages
via GitHub, via git... via any GitSource … also, not only Git, also, the local
file system … there's a tap or load or pull or install command that loads a
package And that gets pulled into the registry, uh, into the the ledger, which
loads into the registry, into PSF and VIP, and then it's accessible to the
system."/ Publish explicitly not the gate. Ghost + paladin first; the svelte
client rides the daemon proxy later.

* the untangling

beef, tangled, asked for the untangle. It came out as one law: *tap =
materialize → record*, where materialize is the ONLY place source kinds exist
(local path = no-op — /"if it's a link to the file system, then that's already
established, and we do nothing"/ — git = clone, s3 = future arm) and the record
never learns URLs — provenance lives in the clone's own =.jj=/=.git=. Then the
correction that finished the design: /"Mount is at runtime. It happens
automatically because of the way that our system is architectured. So the tap
has to do materialize and record. Very clean."/ Untap = record removal only —
the store keeps the working copy; =Pensieve.evict= fell out of the tap story
entirely and re-enters only on the live daemon.
