* the two follow-up rulings

** slurp — later wins on the edge too

I flagged that =slurp= replaced the EFFECT but kept the earlier EDGE, so a layer-② override
executed the new function while advertising the old valence.

#+begin_quote
Good catch and wrinkle number one absolutely later should win on metadata too. Try to find
an elegant way to do this. Have the connoisseur have a look, make it very functional and
elegant, and you know my style. Make me happy.
#+end_quote

On wrinkle two he pushed back and was right to:

#+begin_quote
I don't understand why that is a problem. I mean, those are stateless functions. ... What
am I not understanding?
#+end_quote

The functions ARE stateless — the TRIE is the state. =slurp= on collision recursed INTO the
shared library node and rebound its effect, so the singleton itself carried a mode's
override for every later request. One fix retires both: the collision DELETES the earlier
edge, keys by the LATER pattern, and mints a FRESH node from both sides — neither source
mutated.

* the live crash — the same law, twice

Beef pasted a vite trace: every kajuit route 500, =Cannot read properties of undefined
(reading 'array')= inside =Signature=, thrown from =belt/skill/buffer.js= at module eval.

Skills built their Vector at MODULE SCOPE. =Vector.open= → =new Pattern= → =Signature= ctor
calls =is.array= off the BARREL, and vite's SSR module runner evaluated the skill file
before the barrel was populated. *I had already hit the near-miss version of this earlier in
the same session* — the first cut imported =Vector=/=v= directly to dodge a TDZ error — and
treated it as a local workaround instead of a law. Deno never hits it; another module runner
does.

Fixed with the repo's own idiom (=schematics/prototypes/yield.js=): a memoized thunk. LAW,
now written down: *typology modules must not construct Vectors or touch =v= at module
scope.*

A second self-inflicted one: the first =slurp= rewrite added entries to the Map it was
iterating, and =tests/bench/smoke.test.js= looped forever. Beef spotted it before I did —
*"run tests against this change in the vector. this seems … possibly issuey"* — then
*"test stuck?"*. Snapshot iteration + self-slurp guard, three invariant tests.

* the import-doctrine question, measured

Beef, on the crash: *"is this something we fix by dogmatically applying the 'relative
imports within packages' doctrine?"*

*No — provably not, and the trace is the proof.* At crash time =belt/skill/buffer.js= was
ALREADY on relative imports (=../../../prototypes/vector.js=, =../../../schematics/v.js= —
I had swapped them earlier that session to dodge a TDZ error). It never fails in the leaf's
import line; it fails three frames deeper, and every hop goes through the barrel:

#+begin_example
prototypes/vector.js:1     import { Pattern, Signature }    from "@vivalence/typology";
prototypes/pattern.js:1    import { object, is, hash }      from "@vivalence/typology";
prototypes/signature.js:1  import { array, hash, is, cast } from "@vivalence/typology";
#+end_example

The relative import bought exactly ONE hop before rejoining the same cycle.

Measured across the package: *62 files import typology's own barrel* — prototypes 23/48 ·
gestalten 34/76 · entities 4/21 · specimen 3/2 · schematics 1/26.

** why it had never bitten before

Two conditions must coincide: a typology-internal module doing WORK at module scope, AND
that work reaching the barrel. Measured: before m26 there were *ZERO* module-scope
=new Vector/Aperture/Connection= constructions in =prototypes/= or =gestalten/=.
=belt/skill/*= was the first to arm condition one.

And *registry modules were never at risk* — 28 of them build =export const tools/emitter/
harness = new Vector()= at module scope right now. They sit DOWNSTREAM of the barrel, not
inside it, so it is fully evaluated before they run. The hazard belongs to modules the
barrel re-exports, nothing else.

** the ruling I did NOT make

Debarreling typology's internals would take the barrel off the critical path and is a real
cycle-smell fix — but it is a 62-file sweep across the HOLY layer, it does not close the bug
CLASS (internal cycles survive; module-scope work stays hostage to eval order), and it cuts
against the standing doctrine one layer up ([[feedback_import_through_barrel]]: kajuit
imports THROUGH the barrel, never deep paths). A package-internal exception would be a NEW
rule and beef's to state — I am not inventing one. Filed to =known-issues.org= as
=typology-internals-import-their-own-barrel — OPEN=, with the note: measure the actual cycle
set before touching 62 files.

Landed law instead, the one that closes the hazard: *typology-internal modules must not
construct Vectors or touch =v= at module scope — use a memoized thunk.*
