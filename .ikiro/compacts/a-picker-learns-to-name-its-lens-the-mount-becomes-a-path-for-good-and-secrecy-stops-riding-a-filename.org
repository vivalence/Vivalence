* the lens stack (turns 1, 3, 7, 8, 11)

lists; an undeclared =slug:dojo= stays literal.

* two laws about mounts (turns 20, 21, 27)

/"mount always means path. never not path. never slug. ghost interface might allow
instance slug but env var must be path."/ Slug→path now resolves in ONE place, split
by frame owner: =paladin.ledger.instances.shelf(slug)= (paladin owns the shelf) and
=ghost/belt/path.js instance(token)= (ghost owns the operator's cwd frame — =apps/nested=
is cwd-relative, NOT =paladin.source='s repo frame). Every writer routes through it;
=populate.js= now THROWS on a slug rather than resolving one — that tolerance was
exactly what let one get stored.

/"i dont see how it makes sense to have the information of the instance mount in the
mounted instance?!"/ — circular: you need the location to read the file. Location is
the LEDGER's knowledge (=use <slug>= → session · =--ledger= → =environment.json=).
Both =.env.example= templates stripped of every mount line.

/"the machine should be able to set it. but the instance can overwrite it. is thats
what currently is? if so, gucci."/ — yes: =flag › cwd › instance › .env › os ›
session › ledger=, first hit wins, =instance= sits above =os= and =ledger=.

* the secrecy callout and the env reduction (turns 27, 28)

/"i feel like we need to tie down, cleanup, make coherent… they are weird rn"/ →
/"does this make sense actually? is there a simpler, more coherent way? what would be

/"i feel like this is extremely shitty prototype design. on your end. you build this.

**=paladin.assign(bag, stratum)=** is now the ONE ingress — splits by KEY
(=SECRET_*= → secret bag, =VIVA_*=/=PUBLIC_VIVA_*= → env bag, rest ignored), returns
={held, secrets, ignored}=. os · cwd =.env= · =VIVA_ENV_FILE= · the instance's own
files all call it. No file and no caller decides secrecy.

/"i am good with the reduction, but i want to keep environemnt.json. we move it next to
.env. no reason really other than i like json/jsonc!"/ + /"rename to viva_service…"/ →
each scope carries =.env= BESIDE =environment.json=, both at the root, same stratum;
=environment/= the directory dies and takes =scope.environment= +
=VIVA_ENVIRONMENT_MOUNT= with it. =SERVICE_*= → =VIVA_SERVICE_*= (it was in no
namespace: no key filter on the jsonc path, filtered out on the =.env= path — the same

* five bugs, every one found by beef at a real prompt

1. **=instance/use= had never worked.** =ledger/init= wrote =export VIVA_PROCESS_ID="$$"=
   into =~/.config/viva/env= — which **=ghost.sh= sources**, so =$$= was ghost.sh's own
   pid, fresh every invocation. Selections were written under an id that never recurred.
   =ghost.sh= now takes =${VIVA_PROCESS_ID:-$PPID}= — the invoker is our parent.
2. **=registry/tap git@host:path=** — =path.pin= guards =://= but not the scp form, so
   it resolved into a cwd path and stopped being remote. The remote test now exists
   ONCE, at =paladin.clone.remote=, next to the thing that fetches. /"should work
   really."/
3. **=registry/tap v=** → raw =ENOENT readdir=. =vip.tap= stats first and names what it
   looked for.
4. **The instance's =.env= was never read.** =populate.env= reads os + =${cwd}/.env= +
   =VIVA_ENV_FILE=; =mount()= folded only =environment/*.jsonc=. It had worked by
   ACCIDENT — the deno tasks passed =--env-file=, putting secrets in the =os= stratum.
   The moment =instance/run= spawned a child inheriting only =VIVA_INSTANCE_MOUNT=, the
   lighthouse died on =JWT secret not configured=. /"…/.env doesnt get read?!"/
5. **=run undefined=54417=** — =ledger/process.js= builds its lock from
   ={instance, process}=; three readers invented =spec.type=/=spec.slug=.
