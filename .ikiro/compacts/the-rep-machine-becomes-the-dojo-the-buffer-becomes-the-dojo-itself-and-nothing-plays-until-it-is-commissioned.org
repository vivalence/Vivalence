* fit and resize — the first two, and a helper that outlives them

Row 6. The horizontal scroll was arithmetic: two fixed docks plus a 480px player floor. The
fix is not a media query but a clamp derived from the shell's own measured width (the
kajuit law: a buffer view lives in a pincer panel, so =window.innerWidth= lies). Pane
widths persist through =preferences(mode)= — the ONE generic helper this session left in
drapes — under =viva.mode.<slug>=, deliberately the same dot-namespace as
=viva.terminals=. By the end of the session that helper holds only pane widths and recent
setups; everything that is dojo STATE moved onto the buffer (row 31).

* commission — the mode stops launching itself

Rows 20–21. Both auto-launches were named from the code: =phase = queue.length ? "playing"
: "drawing"= sends a carried buffer straight to rep 1 and an empty one straight to a
=/draw=. beef: /"only launch into reps once its comissioned"/. Ship metaphor already runs
kajuit, so the phase is *commission*: =commissioning= (nothing aboard, console is the yard,
NO auto draw) → =commissioned= (Start ⏎, a gesture — which is exactly what the FOCUS LAW
says iOS needs to open the keyboard) → =playing= (locked) → =drawing= (continuous only) →
=done= (flip an axis → re-commissioned). Every door lands on the same Start card — emitter,
tool, tactic, console — because the buffer records no provenance and there is nothing to
branch on. /"change certain settings ad hoc, but only after i've already started"/ became
=types.LIVE= — one table read by console, =apply()= and provision alike.

Rows 22–25. Two screenshots, one law: =separate("he/she/it has")= produced =["he","she","it
has","she has"]= because it distributed tails across ADJACENT pairs. Fix in the belt (one

* the buffer is the dojo

Rows 30–31. Row 30 put scope and count in localStorage; row 31 corrected it: /"read/write
the data into buffer data … dont create a new buffer"/. The right shape came from tracing
the client spine, not from designing on paper: Frame remounts on object identity (=next
=== live=), and remote-repository =merge=/=cast= mutate the SAME instance — so a daemon
write followed by =cast(raw)= updates the buffer prop in place with no remount and the view
refreshes its own state. Two apertures, both returning the populated buffer: =/setup=
REPLACES the =types.SETUP= keys (JSON drops =undefined=; a full-write is the only way
=streak: off= lands — the same reason the old =persist()= wrote whole =data=) and resolves
symbols with =findByIdentifiers=; =/commission {buffer, knowables?}= draws from the buffer's
OWN setup into its literals, or takes authored knowables and clears them. The console emits
nothing any more; ad hoc lines and provision-authored pairs go through =/commission=.
=buffer.symbols= is the SCOPE — the selection itself, one home — read by =/commission=,
=continuous= and =/count= alike.
