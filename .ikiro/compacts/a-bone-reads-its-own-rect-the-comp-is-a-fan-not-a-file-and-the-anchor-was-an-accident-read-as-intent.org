* what happened, in one breath

A wake that became a design import, a quest, a live walk, a quality pass and one hard ruling. He pointed
the =DesignSync= MCP at his own Claude Design project and named one file to implement, then framed the
work himself in two lines — /"changes to the pincer direction layout top level tbone structure"/ and
/"changes to the cpanel"/ — and those two lines are M1 and M2 to this day. The first read said the comp
was a single design; the measured answer is that *=geometry.js= and =gesture.js= already ARE the comp* —
the axis flips at 90 and 270 in code that shipped months ago, and every one of the three bone components
hardcodes one axis anyway, so at those orientations the crown, shoulder and spine all render across their
45 px thickness. Seen, not inferred: the export served on localhost and driven at o=90. Then /"do another
pass. improve quality"/, and the pass found four things reading one file could not. The project is a
**fan** — three different panel-C designs and two different pincer interactions, generated from this repo
by a sync ledger that names the source files. The palette is not a palette question at all: 21 of 21 hexes
resolve into =dapper/lib/colors.js=, so the port is a token substitution. v3's own =norm=, lifted into node
and swept over 1 960 cases, holds seven invariants and **fails one** — every-pane-folded leaves bare
background, and =openPane= can reach it. And the wireframes carry a rule v3 drops, that terminal is an
anchor which never folds, docks or closes. I recommended keeping it. He killed it in one line:
/"this is horrible. terminal should absolutely dock adn close. bullshit"/ — and the interesting part is
*why* I recommended it, which is that I counted the live code's silence as a vote.

* the frame he gave, and what it turned out to mean (rows 2–3)

He named one file and said /"Implement"/, then split it himself. The split survived every later finding,
which is the tell that it was the right cut: M1 is the top-level t-bone, M2 is panel C, and nothing that
came after moved the boundary.

What M1 turned out to be is smaller and stranger than a redesign. =stores/bridge/geometry.js:122-217=
=bonesForOrientation= *already* flips each bone's axis:

| orientation | shoulder   | crown      | spine      |
|-------------+------------+------------+------------|
|      0 · 180 | horizontal | horizontal | vertical   |
|     90 · 270 | vertical   | vertical   | horizontal |

and each component hardcodes exactly one of those — =shoulder.svelte:39-55= a default-row flex,
=crown.svelte:61-73= =flex-direction: row= with =overflow-x=, =spine.svelte:119-140= =column= with
=padding: 56px 0 14px= and two column-only ornaments. =gesture.js= is the comp constant for constant
(the sync ledger says so outright: the comp ported it verbatim). So M1 changes no store logic at all. It
is one derived rule —

#+begin_src js
const vert = (r) => r.height > r.width;   // the comp, twice, in two files independently
#+end_src

— three components, a drag HUD kajuit never had, and two pieces of dead CSS.

* the quality pass, and the four things one file could not say (row 9)

** the project is a fan, not a file

=github.md= in the project is a sync ledger — /"repo: vivalence/Vivalence · path: systems/kajuit"/ — with a
screen map naming the repo files each comp was generated from. The comps are derivations of this tree, and
they disagree on purpose.

| file                                  | its question                     | its answer                                                        |
|---------------------------------------+----------------------------------+-------------------------------------------------------------------|
| =Pincer Panel C - Final v3=           | how do panes resize and leave?   | fold · strip · push-through · dock to a bar · tab back             |
| =Pincer C - Drag Handling Wireframes= | which drag model?                | FIVE side by side: seam grips · detents · shelf docking · flick · push-through |
| =Pincer C-Nav Variants=               | what when C is too NARROW for 3? | FIVE nav models: tabs · accordion · drawers · drill · bone          |

and two pincer interactions: v3's long-press radial (=gesture.js= verbatim) versus c-nav's tap-fan of four
side-chips plus a 3 px tick on the viket edge showing which side A is on. Both are in front of him; one
can ship. Nine siblings remain unread, and the three read this pass each moved a ruling.

** the palette is dapper's =paper=, measured 21/21

The ledger says the comp was recoloured to the dapper paper ladder, and it checks: =paper= 50→800,
=ink= 900/950, =aqua= 500/600, and v3's =ROLE= map is dapper's role ramps at their anchors. So M1 and M2 are
a **token substitution**, not a colour judgment, and every value must be written =var(--colors-…)= so
=nordic= — still the default — holds too. Five hexes in the c-nav sketch are NOT in dapper; that file is
off-token. This *corrects* the standing note on this surface, which said to keep iron-gray and not adopt
the comp's palette. That was true of the earlier navy comps. It is not true of these.

** the engine's invariants, run rather than asserted

v3's =norm= / =fitRun= / =push= lifted verbatim into node: =oi= over all 7 non-empty subsets × 8 fold masks
× 5 weight vectors × 7 areas = 1 960 =norm= cases, plus 260 =push= cases. Seven invariants hold — sums to
area, folded = exactly =BAR=, floors respected, closed = 0, =push= sums, never under =BAR=, monotone in the
delta. One fails, 470 cases:

#+begin_example
I1b ALL FOLDED leaves dead space  {"oi":[0],"area":100,"total":44,"dead":56}
#+end_example

=norm= returns early once nothing is unfolded, so the run measures =oi.length × BAR= and the rest of C
paints as bare background. =gripUp= and =toggleFold= guard it; =openPane= does not — dock all three, pull
one tab down under 84 px, and you are there. Writing the invariants as a list would have shipped a false
one; running them found a true defect instead.

** two dead CSS blocks in the bones

=shoulder.svelte:56-67= styles =.sep= AND guards it with =@container shoulder (max-width: 190px)=, but no
element carries the class — the container query guards nothing. =Tab.svelte:59-73= styles =.tab-pip= and
its keyframes; the markup renders only =.tab=, =.tab-title=, =.tab-close=. Both get deleted, not ported.
(=Tab.svelte:9-11= also carries three of his own TODO comments — noted in the quest so M1 cannot bury them.)

* the ruling, and the mistake under it (rows 10–11)

He quoted the wireframes' anchor back at me and killed it:

#+begin_quote
this is horrible. terminal should absolutely dock adn close. bullshit
#+end_quote

*Ruled: no anchor.* No privileged pane, no per-pane floor exception; every pane folds, docks and closes.
Carried through the quest in the same turn: the engine takes no anchor parameter, every header renders its
=✕=, and the all-docked empty state is REACHABLE and must be built. It also *promotes* the =norm= defect
from a curiosity to a requirement — with no anchor left to guarantee an unfolded pane, the guard has to
live inside =normalise= rather than at its three call sites.

The wireframes' =settle= graft survives it: the bump-to-=MIN= pass is anchor-free, and only its
=i !== ANCHOR= fold guard drops out, which restores exactly v3's behaviour.

*Why I recommended the anchor.* Two sources appeared to agree — the wireframes' prose, and =c.svelte=,
where E has no twig toggle and therefore cannot be closed. The second is not evidence. E has no toggle
because the twig design only ever hung toggles on the wings; there is no rail outside F to hang one on. I
read a **limitation of the old implementation as a decision**, and then cited it as corroboration for a
rule I had no independent reason to want. The rule that follows: before treating what the old code does as
intent, ask what the old code could have expressed. Silence from a design that had no way to speak is not
agreement. That is written into the quest's decision trail so it is not re-argued from the same evidence.
