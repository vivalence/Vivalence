* the mode↔cortex boundary — two of my own fixes were wrong before landing right

Beef caught a real interface smell in the compaction helpers: =cortex.resolve(type,
{via:"render"})= then =faculty.via.render(...)= — "that interface looks... i am sure
there are already or ought to be better ways of accessing specific faculties?!?"
Checked every live caller repo-wide (=cortex.js= internals ×3, =conversational.js= ×2
— both inside dead =/* ... */= blocks, no live callers outside =cortex.js= itself) —
confirmed genuinely awkward, not local to new code. Verified =resolve()='s existing
contract couldn't just return the callable directly: =cortex.test.js:84-88= legitimately
reads =.tune= off the SAME =via=-filtered resolve call. Added =Cortex.via(type, name,
tune)= — additive, one line, reuses =resolve()= untouched, zero test breakage —
refactored =cortex.js='s three internal sites to use it.

Beef then went further: "I don't understand why we're using Cortex here at all, that
is something that... is done on harness level... the modes interact with the
hallucinators in the cortex through the harness." First response conceded riddler's
case (called from the aperture, safe to route through =mode.harness=) but defended
keeping oracle's case on raw =cortex.via()=, citing a real recursion hazard: oracle's
compaction runs INSIDE =harness.branch("/dialogue")='s own middleware, and calling
=mode.harness.dialogue.render(...)= from there would re-enter the same branch.

Beef pushed once more, flatly: "I don't understand why we are using the cortex
directly anyways. This is something that should be handled by the harness." Tracing
it through properly found BOTH prior fixes wrong, not just the disputed one: the
"safe" riddler fix used =mode.harness.dialogue.render([...], {})= — wrong branch
entirely (=/dialogue= is exactly what =harnessed.js= scribes turns onto; calling it
for an internal summarization utility would have persisted two junk turns into the
REAL thread's history every compaction cycle) AND the wrong call signature (=dialogue=
takes ={parts, thread, tune}=, not the raw =(turns, config)= positional shape). The
actual fix, for both oracle and riddler: =mode.harness.object.render({turns, config})=
— =/object= carries no scribe/history-load coupling in =harnessed.js= (that coupling
is =/dialogue=-only, the same fact this whole session's fork-F thread turned on), so
it's side-effect-free, AND it's a different branch than =/dialogue= entirely — calling
it from inside oracle's =/dialogue= middleware doesn't recurse. Same entry point
riddler/oracle/aprende already use for their real feature, not a special utility path.
Verified after landing: =grep -rn "cortex" registry/= → zero live call sites anywhere
in the registry, one unrelated comment. =cortex.via()= itself stays, but only as an
internal =cortex.js= implementation shortcut — never as a surface modes are invited
to reach through.
