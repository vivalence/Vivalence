* the fourth no-default, and why a comp is two texts

Three times the night before, on the old screen. The fourth arrived on a screen I had just written from nothing, which is the part worth keeping: the rewrite did not inherit the bug, it re-derived it.

Mechanism: =/tree= read the whole domain, and =selected= fell back to =visible[0]=. Neither is a stored default — that is exactly why the greps of the previous three rounds would not have caught it. The scope was wrong, not the values.

The comp said so. Its =SCENE= constant is not decoration; it lists what its own queue committed, file by file. I read the markup, the palette, the five stage names, the ontology block — and treated the sample data as filler.

Fixed: =/tree { slugs }= reads only what this buffer's jobs minted, =[]= reads nothing, a missing list is refused; nothing auto-selected anywhere. Proven by opening a brand-new thread and buffer through the dock: =QUEUE 0 · SCENE 0 component · 0 assembly · 0 step · NODE — · nothing selected=.

Rule, filed as =user-intent-drift= n 5→6: *a comp is markup AND data; the data says what a fresh screen holds. Before building any screen from a comp, write one line per pane — "shows what, from where".*

* the untagged union

=NODE= carried three kinds with zero discriminator: =component?= set, =assembly?= set, or neither meaning "group". That predates me — =schematics.js:25= says /"a group (neither)"/ in its own description — and when I proposed writing group nodes for the blend's collections, I built on it rather than naming it.

beef: /"you want to sell me the ontology of node by the abssence of compontnt or assembly?? the fuck. this is not clena thinking. this is not clean schema design. this is not how we do things around here."/

He is right twice: the shape is wrong, and *leaning on an existing defect to justify new work is how a defect becomes load-bearing.* I offered two shapes — tag the node, or make grouping a property of the placement — and recommended the tag because the union was already broken and the alternative bought one format. /"a"/ · /"be thoughtful"/ · /"complete"/.

Radius, done in one pass: schematic · =resolve.js= · =Literal.place= (three new refusals) · =references()= · the fold tool's line renderer · both valences · four test files rewritten · the importer's writer and reader. 8 suites / 47 steps green.

* the file that lies, and the two-stager

The drone =.blend= declares =unit_settings.scale_length = 1.0= and =Frame_Top= measures 5.65 units. The file is wrong about itself by a factor of twenty.

My answer had been a query parameter with no UI, which I reported as "beef's call" — and he read the sentence back at me: /"your word on the unit (?unit= exists, no field); what?"/. Then the real order (145), dictated, and it is the best framing anyone has given this mode: /"this is probably not the only issue of this type. There is a class of problems that arise from transmuting between file types and encodings. And I want the solution to that entire space."/ Plus the shape: /"first we do dry parse and then the final parse with the embedding parse."/

The space, as mapped: *frame* (unit, up axis, handedness, origin, baked-vs-placed transforms) · *identity* (instancing rule, hierarchy, what's excluded, naming) · *fidelity* (tessellation tolerance, modifiers, precision, materials, animation pose) · *encoding* (text/binary variants, containers, external buffers, compression, extension ≠ magic).

The principle that covers all of it: *never decide silently, and show the consequence in human units rather than echoing the setting.* A wrong unit is invisible as =0.05=. It is obvious as =13.24 × 2.26 × 13.78 m=.

Built: =/parse= yields a =READING= — every object in the file's own units, what the file =declared=, what was skipped — and mints nothing. =fold.js= is pure and runs in the screen, so every knob's result is instant. =/commit { name, settings }= takes every setting made, by name, and refuses a missing one. The stage renders the dry parse before commit (148), so the unit is judged by eye and by number at once.
