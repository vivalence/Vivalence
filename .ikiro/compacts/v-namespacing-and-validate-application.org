** A1+A4 — specimen.matches(schema)

=subsystems/typology/specimen/index.js= — extended =@std/expect= with a =matches= matcher:

#+begin_src javascript
expect.extend({
  matches(ctx, schema) {
    const errors = [...schema.errors(ctx.value)];
    const id = typeof schema.$id === "string" ? schema.$id : "";
    return {
      pass: errors.length === 0,
      message: () =>
        errors.length === 0
          ? `expected value NOT to match schema ${id}`
          : `expected value to match schema ${id}:\n` +
            errors.map((e) => `  ${e.instancePath || "<root>"}: ${e.message}`).join("\n"),
    };
  },
});
#+end_src

Subtle: =@std/expect= passes matcher a CONTEXT object =({value, isNot, customTesters})= not the raw value. Took a debug round to find — first attempt did =schema.errors(received)= which validated the wrapper object instead of the actual value, producing nonsense "must have required properties type, slug" errors on perfectly-shaped manifests. Documented inline.

Usage: =expect(value).matches(v.primitives.Manifest)=. Failure message lists each error's path. Boolean =.check= remains as escape hatch.

Final shape:

#+begin_src javascript
export async function validate(paladin) {
  const errors = [];
  const collect = (label, value, schema) => {
    for (const e of schema.errors(value)) {
      errors.push(`${label}${e.instancePath || ""}: ${e.message}`);
    }
  };

  for (const daemon of paladin.variant.daemons)
    collect(`daemon[${daemon.slug}]`, daemon, v.primitives.circuitry.Daemon);
  for (const service of paladin.variant.services)
    collect(`service[${service.slug}]`, service, v.primitives.circuitry.Service);

  if (errors.length) throw new Error(`[paladin.validate]\n  ${errors.join("\n  ")}`);
}
#+end_src

Tests added to =tests/variant.test.js= ("integrate.validate enforces circuitry schemas"): happy path passes; daemon missing manifest → throws =/daemon.*manifest/=; service missing module → throws =/service.*module/=.
