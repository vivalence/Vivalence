* Decision: streams compose — fromm.sink/source, to/from everywhere

@beef: *"this is already solved by pipes and spans."* — killed my hand-rolled
drain/ring/listener loop. Then *"there is an elegant way here. some composition"*
and *"pipes can fan out"* → =to=/=from= went variadic.

Landed on the =fromm= gestalt (view-X-as-Y), after @beef: *"you missed the essence
of the signature of fromm() functios"* — every fromm export is
=(subject) => ({ get view() {…} })=. So:
- =fromm.sink(target).write= — any sink → push fn (=send=/=enqueue=/=set=/=getWriter=/fn).
- =fromm.source(origin).read= — any source → async iterable (ReadableStream/Queue/Pipe/array).
@beef chose =.write= / =.read= (act-duality) over =.push= / =.stream=.

=Pipe.to(...sinks)= / =Pipe.from(...sources)= / =Queue.to(...sinks)= dispatch through
=fromm=. The byte→line transform stays *inline* — @beef: *"keep lines inline then"*
(a local =lines()= in =process.js=, not a fromm export). =process.js= piped path:
=this.in.to(child.stdin)= + =this.out.from(lines(child.stdout), lines(child.stderr))=.

First home was =cast/flow.js=; @beef: *"rewrite ...flow.js to be in ...fromm"* —
=cast= is coercion, =fromm= is regard-as. Moved.

* Decision: lines are LOGS, not span branches

@beef: *"span doesnt fucking branch on lines???!! are you retarded?? holy shit his
is dumb."* (callout — see zettelkasten) — I wrote =out.tap(line => span.branch(line))=.
Wrong: a Span is a scoped lifecycle trace (ONE branch per process: subject=pid,
transitions spawn→ready→exit, timing). Stdout lines feed the subject's =logs= Pipe.
Two separate streams; never one-node-per-line.

Related: @beef commented out =this.seal()= in =Span.drain= — *"why do we seal on
drain?"*. =drain= conflated emit + terminal-seal, blocking streaming. Decouple:
=drain= = emit (repeatable), =seal= = stop the clock. Proven in the temp.js drain
practice (fork a track every 1000ms, =pipe.send(root)= streams snapshots, two sync
taps = two sinks console+file).

* Ascii video background (the stretch)

@beef: *"can we maybe build a more holistic client? ... render a asciart video type
in the background in low warm dark waving reds"* → *"i literally mean video. i have
a mp4. from there to background video. in ink. surely possible?!"*

Pipeline (=video_assets/asci/=): =ffmpeg= → downscaled raw frames (96×26, 12fps, 4s
loop) → =convert.js= → =frames.json= → =Field= player (=testament/temp.jsx=) cycles
frames, renders each row as colour RUNS (group same-colour cells; never per-char —
96×26 = 2.5k nodes would choke ink).

- charset: @beef *"lets keep 4 symbols. ^ is the lightest V the second lightest.
  then > for second heaviest and ≪ (U+226A) for heaviest."* — a *density* ramp by
  glyph ink-weight (=^ v > ≪=), NOT Sobel direction. (We researched edge/gradient
  ascii — atan2→directional chars, blur-before-Sobel — then @beef chose pure density.
  Prior art: Asciimatic, jave.de image2ascii survey.)
- guillemet question: @beef wanted a glyph reading as fused =<<= → =≪= (U+226A).
- colour: first cut used a luminance→fixed-red ramp; @beef: *"the reds are off. the
  colors dont match. but it moves."* The clip is a rocket reentry (magenta-pink core,
  orange-white plasma, purple sky), not dull red. Fix: extract RGB, colour each cell
  by its ACTUAL quantized video colour (66-colour palette); glyph still = density.
- overlay: @beef *"render an input field above that"* + *"center center"*. ink has no
  z-overlay → composite the input INTO the frame's =({char,fg,bg})= cell grid: paint
  a centered dark panel, write the centered input text, render runs by fg+bg. One true
  overlay, no layering. This is the Step-4 compositor route, proven.
