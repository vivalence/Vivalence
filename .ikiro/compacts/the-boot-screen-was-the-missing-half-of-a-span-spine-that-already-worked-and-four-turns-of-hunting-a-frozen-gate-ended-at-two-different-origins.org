* the shape of the spine

#+begin_src
Span.mark() ──record──> Pipe ──tap──> trace.chronicle.step ──> $telemetry ──> panels G/H
   emitter              channel            fold                  store         readers

Root =Span= owns =journal[]= + its own =channel=; branches delegate via =root=.
=.to(telemetry())= bridges a span's private pipe into the shared one — that is
the opt-in seam, and a span without =.to()= records fine and reaches nobody.
=ctx.span= is unset on every client =connection.call=, so each request mints its
own ROOT; =$telemetry.roots= is a flat request list, which is exactly panel G's
model.

* three renderer bugs the live DOM found

Compiling clean proved nothing. Every one of these needed the actual page.

1. *=response= overwrote =request=.* =shard.track.request()= builds its response
   mark from =ctx.response=, which carries no method and no url, so ={status:200}=
   replaced ={method,path}= wholesale. Traffic rows rendered as a bare =200 14ms=.
   Merge, don't replace.
2. *=trace.dictate= walks tree order, not time order* — root A's full open→close
   before root B's first record. Mixed with live-tapped records the stamps
   scrambled. Sort by =at=.
3. *Boot had no memory.* It tapped the live pipe only; measured =rowsBefore: 0=
   with 71 records already in the store. =/authority= was lost on every single
   boot because =hydrate(lighthouse)= runs in the layout's *script body*, before
   the child's markup renders and installs the tap. Fixed by folding
   =trace.dictate(story)= through the same =step= function before tapping —
   replay then live, one fold, bounded to the current boot by slicing from the
   last =/authority= open.

* open, needs go

- *=hydrate= writes ={}= over the token* — =lighthouse.js:197=. nanostores =effect=
  fires immediately on registration and =map({})= is truthy, so a freshly
  constructed Lighthouse writes ={"authority":{},"identity":{}}= into
  localStorage. Signature: =cached=true= with =access=false identity=null=.
  Guard: =if (authority?.access || identity?.id)=.
- *=STORAGE_KEY= stringifies a =Url= to =[object Object]=* — =lighthouse.js:6=.
  Every lighthouse shares one key, defeating the point of keying by URL.
- *=unsubscribePopulate= races =verify=* — it fires =populate()= immediately on
  subscribe (authority already hydrated), concurrent with =verify()=, whose
  =VERIFIED= clobbers =POPULATING=. So =gate → ready= lands before the daemons
  mount and the full-gate hold is defeated. The subscribe is redundant —
  =onLogin= calls =boot()=, which does verify→populate in order. Deleting it
  makes the sequence strictly ordered.
- *=console.warn= kept beside =mounting.fault=* in =dossier.js= — deliberate,
  flagged: =fault()= records only message + code, and the raw error object is
  worth more in devtools when a daemon boot breaks.
- *settle records never reach the screen* — settle runs after the gate flips;
  its notes land in panel G only.
