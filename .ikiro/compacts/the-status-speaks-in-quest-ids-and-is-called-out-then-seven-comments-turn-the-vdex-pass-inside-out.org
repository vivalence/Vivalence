* his seven comments, and the second cut (row 84)

Verbatim, each with what it changed:

- /"do we want the plain tools on vdex or an application of these tools? i think the latter. vdex
  should provide the functionality that fs tools provide. wrap for context and utility."/ → the
  =paladin.skills.fs= slurp is GONE. The vdex speaks in SLUGS, never paths: =index= · =find= ·
  =read= · =write= · =file= · =move= · =delete= · =open=. Each verb implemented ONCE in the aperture
  (where the App already calls it); the tools wrap =ctx.mode.call.<verb>= with the model-facing
  valence, the receipt and the refusal. Three faces, one body.
- /"not really a tool. more of an emitter."/ → =emitter/index.js= is new, the manifest gains
  =EMITTER=, the aperture's =/open= route goes and =/emit/open= replaces it; the tool =open= is a
  receipt over =ctx.mode.emit.open(...)=, the aprende =drill= shape. The trait binds the thread and
  flushes — none of that is written in the package any more.
- /"i think this is entirely garbage?. idea of boot is to update the literal. but does the literal
  need update? and can he process it? ie are literals subscribed to on the client? if so, we want to
  be precise with our subscription! not just load * when *."/ → they are, and the matcher speaks
  =$like=, so symbols are too. Precision on BOTH sides: the server syncs per PATH (a disk event
  names the file, only its row is written), the client applies each event to the row it names (swap ·
  add · drop by id) and refetches nothing. The only full pass left is the dataset install at boot.
- /"do we want prune on repository level???!?!?! not sure. and for sure not like this. way tooo
  narrow. one ontology key - static?!?! makes no sense and is very out of style. just implement
  inline for now."/ → inline in =boot.js=, through the em — and the reason it MUST be through the em
  came out while doing it: the domain's =prune()= methods were =nativeDelete=, which bypasses the ORM
  subscriber, so every removal was invisible to the twitch. The two methods (vdex was their only
  consumer) are deleted from the domain's =Literal.ts= / =Symbol.ts=.
- /"weird line. very unclear."/ (on =await line(daemon, mode, fresh ? await prune(…) : {literal: 0,
  symbol: 0})=) → three lines with the case named: =drain()= is null when the loader's stamp matched
  and nothing was scanned — the rows already ARE the tree, so there is nothing to prune against.
- /"wtf is daemon traits stamp???? what!"/ (twice) → gone, with the entire stamp comparison. Per-path
  sync needs no fingerprint: an unchanged file is an =assign= with no diff — no UPDATE, no event. Our
  own write's disk echo costs one stat and one read and emits nothing. The package never touches the
  loader's =installed=.
- /"shouldnt this watch files??!!! this should watch files and twitch changes to files onto
  literals... or is this not needed at all? this code is gibberish!"/ → it watches files now:
  =Deno.watchFs= on the real root (FSEvents reports =/private/…=, so the root is resolved once),
  events → the paths they name → =sync(paths)= → those rows → the twitch. A gone path takes every row
  under it; a folder is walked and reconciled; a file is upserted. Needed: without it an editor,
  Finder or git changes the JDex and the screen lies until the next boot.
