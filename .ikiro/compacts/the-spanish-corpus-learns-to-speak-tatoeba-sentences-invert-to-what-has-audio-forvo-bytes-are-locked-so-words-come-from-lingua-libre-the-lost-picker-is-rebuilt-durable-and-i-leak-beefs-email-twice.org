* sentences — tatoeba, and the inversion is real

Sourcing = Tatoeba =api_v0/search?from=spa&has_audio=yes=. Transport lesson, learned the hard way:
- **WebFetch is too lossy** — its small-model layer returned a *Latin* sentence ("Hispanice non loquor") for "No hablo español". Cannot trust it for audio_ids.
- **Chrome same-origin fetch** gives raw JSON (reliable) but the CDP eval caps at 45s and Tatoeba's API runs ~4-6s/request → only ~7 sentences per call. Impractical at scale.
- **Deno fetches the API directly** server-side (200, raw JSON, no cap). This is the way — the whole 100-sentence pull ran as one background Deno script.

Our hand-authored survival sentences mostly are NOT in Tatoeba verbatim → **inversion**: take the closest audio-bearing sentence and realign the literal to it. beef blessed the drift:
#+begin_quote
drift is fine
#+end_quote
#+begin_quote
were flexible on the literals
#+end_quote
The hard constraint, though:
#+begin_quote
i dotn want out of step audio-literal
#+end_quote
#+begin_quote
fix em
#+end_quote
So: =learning= text is always realigned to the audio (coherent — never out of step); =known= + =ANNOTATED= tokens on inverted sentences go stale and are **deferred to a stanza re-annotation pass** (per the tatoeba-harvest quest, ANNOTATED was always a separate stanza step). **Doctrine: audio↔learning coherence is the hard gate; token annotation is deferrable debt, but the displayed text must match the recording.** Voices: =arh= dominates Castilian, + =marcelostockle=, =ignacio=. Result: 80 sentences placed (57 new + 23 prior); 20 of the target-100 had no Castilian audio.

* words — forvo's bytes are locked, so open datasets, and beef bans TTS

Forvo has 100% Castilian coverage for every target word (scrape via same-origin fetch on forvo.com works — 809 Castilian candidates over 124 words). But **Forvo's audio BYTES are automation-locked**: CDN URLs 404, cross-origin fetch is CORS-blocked, and instrumented =Play()=/click capture yields NO network request (gesture-gated). Its only clean path is the paid API. Proven dead-end for scraping.

beef, on the fallback:
#+begin_quote
no tts
#+end_quote
So every word must be a REAL human recording. Open, Deno-downloadable source = **Wikimedia Commons / Lingua Libre** (=intitle:<word> intitle:spa= → =LL-Q1321 (spa)-<speaker>-<word>.wav=; parens in the search string break it, and quotes over-restrict — bare =intitle:= is correct), plus **Wiktionary =Es-<word>.ogg=** as a second candidate. beef also set the floor:
#+begin_quote
i want at least two candidates per word
#+end_quote

**The coverage wall (assessed before the big pull, which is what "assess" is FOR):** Lingua Libre is a finite, frequency-skewed set. Top-124 words hit ~88%; but past ~rank 150 it collapses — stratified sample of the deeper 401 new words showed ~21% lemma / ~8% conjugated coverage. So 500 words is NOT reachable open-source + no-TTS; realistic ceiling ~190 total. Function words (=el la de a no=) and =tener/estar/ir= conjugations are simply absent from open CC audio. beef's call: **ship what exists, flag the rest** (Forvo API would close it but is paywalled). First round landed 106 words placed; the 500-scale pull is still grinding at fold-time (deep-rank yield ~1-in-8, exactly as assessed).

* compile — surgical VOCALIZED, because floats break the round-trip

=place= = promote picked =candidates/<form>/<speaker>.mp3= → =freight/audio/words/<slug>.mp3= + inject =VOCALIZED.asset.path= into the literal. First attempt reserialized whole files — but the word dataset files carry =RANKED.fpm= floats like =309.0= that =JSON.parse→stringify= flattens to =309= (95 per file), so a full reserialize would reformat every float = huge noise. Switched to **per-literal surgical string insertion** (brace-match the traits array + trait object, insert only VOCALIZED, everything else byte-identical). =sentences.js= has no such floats → full reserialize round-trips there. Also moved =candidates/= OUT of =freight/= into =.harvest/= so the served cargo catalogue holds only final assets (BR kept candidates in a separate staging corpus; we have one dir). **Doctrine: never reformat a hand/tool-authored data file to change one field — surgically insert, or you flip 95 unrelated floats.**
