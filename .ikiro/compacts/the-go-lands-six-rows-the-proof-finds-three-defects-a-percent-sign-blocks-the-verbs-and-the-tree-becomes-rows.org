* the proof, and the three defects it found (row 88)

The rule that made this window worth its cost: a scratch suite ran against the package scenario BEFORE
the report went out. Every one of these was invisible to reading.

- *the fold is an UPDATE fact.* =LiteralSubscriber.beforeCreate= writes =symbol = {}= even when the new
  row's collection already holds three linked symbols — and it overwrites a =symbol= supplied at create.
  Only =beforeUpdate= folds from the collection. So =reconcile= touches every fresh row once
  (=assign({updatedAt})= + flush), which is exactly what the dataset installer's =linkPhase= does.
  Without it, every document the watcher saw arrive minted a coordinate that the next orphan sweep
  deleted.
- *the m:n cascades REMOVE both ways.* =kernel/Literal.ts:100= (=symbols=) and =Symbol.ts:60=
  (=literals=) both declare =cascade: [Cascade.REMOVE]=, and MikroORM cascades over whatever is
  INITIALIZED — so the blast radius is the identity map, not the schema. Measured: file → move →
  delete in one scope removed =vdex.area.10-19= · =vdex.category.12= · =vdex.format.md=. The same
  remove from a plain =find= is harmless. Every pass now rides =daemon.entities.em.fork()= with
  repositories by =getEntityName()= — the installer's own habit; the watcher then needs no request
  context at all, because the ORM subscriber belongs to the orm and twitches for a fork's flush
  (measured: one =/after/literal/update= for a changed file, none for unchanged bytes).
- *a row's refs carry no traits.* =load.js row()= names symbols by slug only; the STRUCTURAL + LABELED
  bodies live on =coordinates(path).symbols=. =upsert= was minting bare symbols (=traits: []=,
  =trait: {}=) and never followed a folder rename. It now mints from the coordinates, and a coordinate
  whose PATH moved takes the folder's new name while one that did not move keeps the name its NN.00
  index gave it.

Ledgered for beef: =runtime-literal-symbol-m-n-cascades-remove-both-ways= in =known-issues.org=,
symptom · cause · evidence · *no approach* — the cascade is runtime, and the direction is his. The same
three facts sit in memory as =project_mikro_m_n_cascade_remove_both_ways=.

* r1 — the percent sign that blocks the verbs (rows 88, 89)

=subsystems/paladin/skills/fs.js:10= resolves through =new URL(path, "file://" + base).pathname=. A
=pathname= is percent-ENCODED: =12.05 Roadmap.md= becomes =12.05%20Roadmap.md=, =ü= becomes
=%C3%BC=, and =a#b.md= is CUT at the =#=. Every Johnny.Decimal name carries a space, so =/file= wrote a
percent-named file, the per-path =sync= found nothing at the path it was given, =serve(null)= came back
and the tool refused; over the wire the same call 404s. Pre-existing — T1's =/write= had it too, and the
suite never wrote a spaced name.

The fix is one line (=normalize(join(base, path))=) plus one paladin test, measured over fourteen cases:
escapes still throw, ="." "" "/a.md" "sub/../a.md"= unchanged, ="sub//a.md"= collapses, spaces · unicode
· =#?= survive. It sits in the quest as its own row and waits on his go — repo code, and the diff was
shown rather than a row id.

Row 95 rejected the tree: /"i want the full index. not an abbreviation. rows. no indentation format.
agent/human optimized"/. So =index.js= was rewritten whole. Every coordinate and every document, one
row per line, no indentation, no depth fold, no budget. A coordinate row names a folder; a document row
is =slug · title= — the slug already carries the id and the format, so an agent greps the exact string
it will hand to =read= / =open= / =move=, and a human reads a list. An id that is ONE file speaks only
through its document row. A loose document sits directly under its category. =unfiled= closes it.
=· not readable= marks a format the mode does not serve. =under= still narrows to one branch.
