** the row must not know what the interface calls a title (159, 160, 161, 165)

First draft of the subscriber:

#+begin_src ts

#+end_src

Beef: /"those are specifics of the interface / businesslogic reaching into typology/entities.
nonono."/ Then, on the second draft: /"whats the logic. if labeled, do nothing. if not
labeled - deduce label from mode - thread buffer # number"/. The truth test is the traits array,
not a nested field:

#+begin_src ts
// systems/runtime/daemon/entities/userspace/Buffer.ts
async beforeCreate({ entity, em }) {
  if (entity.traits.includes(BufferTraitsEnum.LABELED)) return;
  const mode = await em.findOne(ModeEntity, entity.mode);
  entity.traits = [...entity.traits, BufferTraitsEnum.LABELED];
  entity.trait = { ...entity.trait, LABELED: { name: `${mode?.slug} #${entity.index}` } };
}
#+end_src

The label itself is a typology primitive, =v.primitives.Label= (=schematics/primitives/label.js=,
beside =Manifest=), =name= required, =description= optional, every =.desc= with an Example. The
interface speaks it: =generator_view_render= REQUIRES =label=, the emitter requires it, revise
takes it optionally and always WHOLE. The skill is four lines:

#+begin_src js
// systems/runtime/daemon/skills/buffer.js — the runtime's standard toolset, beside /buffer/update
const row = await ctx.daemon.entities.buffer.findOneOrFail({ id: ctx.input.id });
row.trait = { ...row.trait, LABELED: ctx.input.label };
await ctx.daemon.entities.em.flush();
return { message: `labeled ${named(row)}`, buffer: [row] };
#+end_src

The first skill merged field by field and refused an empty patch — /"way too complicated"/. A
label is a whole.

** one mint, one seat-taker (165, 166, 167, 169, 170)

/"they are the same function, on two object, doing slightly different things… something is off
here."/ =mode.generator.buffer= and =mode.app.buffer= both did =em.create= + thread bind +
=findByIdentifiers=; the emitter drain bound a third time. Mikro-first: the mint is a repository
verb, the seat is the thread's to give.

#+begin_src ts
// Buffer.ts — every query FIRST, the mint LAST
async create({ thread, literals, symbols, ...fields }) {
  const bound = thread ? await this.em.findOneOrFail(ThreadEntity, thread) : null;
  const buffer = super.create({ ...fields, ...(literals && { literals: await …findByIdentifiers(literals) }), ...(symbols && …) });
  bound?.bindBuffer(buffer);
  return buffer;
}
// Thread.ts — beef: "its a real utility. call it bindBuffer();"
bindBuffer(buffer) { buffer.thread = this; buffer.index = this.counter++; return buffer; }
#+end_src

=mode.generator= is =bundle · inspect · serve · tools= now; the tools and every emitter call
=ctx.daemon.entities.buffer.create= with the real row shape (=traits=, =trait=, =view=, =data=,
=thread=). =mode.app.buffer= survives only because =fill= is real work.

The order in =create= is a measured defect, not style: the first draft minted, THEN queried the
thread. Mikro's auto-flush fires on a query when pending changes touch it — the thread was dirty
from the first bind — so the second buffer was flushed with =index 0=, the subscriber named it
=#0=, and only afterwards did =bindBuffer= set =index 1=. Stored: index 1, name =#0=.
