`.mailmap` already lives at repo root and resolves display only. This workpackage upgrades from cosmetic-fix to actual-fix: commit hashes change, GitLab attribution re-resolves to the account that owns `beef@vivalence.org`, signed history (none currently signed) and audit trails align to one identity.

* Why now / why this not mailmap

Mailmap is read-time — it shapes `git log`, `jj log`, GitLab's "authored by" dropdown, blame UIs. It does NOT change:
- the underlying commit object's author bytes (so non-mailmap-aware tools still see variants)
- attribution on systems that key off raw email (CODEOWNERS, some MR approval rules, audit exports, OAuth-bound dashboards)
- what a future `git filter-repo` operator sees if they ever run cleanup later

Since: solo project, no external clones, no live MRs (verify), GitLab account-linkage available — the destructive rewrite is feasible *now* with low blast radius. Doing it later costs more (more commits to rewrite, more downstream refs).

* Tool

`git filter-repo --mailmap .mailmap`

- Standard rewrite (replaces deprecated `git filter-branch`).
- Reads existing `.mailmap`; rewrites both author and committer.
- Single pass, all refs, atomic at the ref level.
- No external dependencies once installed (`brew install git-filter-repo`).

* Blast radius (accepted by going ahead)

- **All ~391+ commit hashes change.** Every Finn-authored or Finn-committed commit; merge commits where Finn was committer; everything reachable from main and bookmarks.
- **Force-push required to GitLab origin.** `--force-with-lease` reduces (does not eliminate) overwrite risk.
- **Open MRs invalid.** Need close+reopen or rebase. (Should be zero — verify in pre-flight.)
- **CI build cache invalidates.** Pipeline rebuilds from scratch. No data loss; one slow pipeline run.
- **External clones desync.** Solo project — verify zero external clones exist (Codespaces, secondary machines, collaborators).
- **Signed commits.** None currently — verified via spot check needed in pre-flight. If any exist, signatures invalidate (cannot re-sign rewritten commits).
- **jj op log on remote graph resets.** Local jj op log preserves pre-rewrite ops (recovery path).
- **Existing tags re-point.** Lightweight tags follow refs; annotated tags get rewritten. None expected — verify `! git tag --list`.
- **`.git/logs/HEAD` reflog.** Pre-rewrite reflog still references old SHAs locally (recovery path) until `git reflog expire`.
