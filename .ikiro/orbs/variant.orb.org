* ORB variant manifest — testament/variant once quest lands

Target end state for =testament/variant/=. Multiple expressions of the
same deployment shown — pick by ergonomics, paladin resolves to identical
=paladin.variant= regardless.

** Conventions

- Env lives EXCLUSIVELY in =<variant>/environment/*.jsonc=. Paladin loads
  it (=populate.environment=) BEFORE importing the variant marker.
- Variant file uses =paladin.env.get("X")= / =paladin.secret.get("X")= for
  all env-sourced values. Cast to typed prototypes at the read site:
  =new Url(paladin.env.get("PUBLIC_VIVA_LIGHTHOUSE_REMOTE"))=.
- Hardcoded internal constants (db filenames, mode slugs, trait arrays)
  stay as literals — they're variant-internal identifiers, not config.
- *No =environment= export from the variant file.* Bootstrap-order: a
  variant cannot declare env it would then consume.

** A — fully inline (single file, self-contained)

Everything in one variant marker. No =circuitry/= subdir needed. Self-
referential URLs inlined; only system-env values use =paladin.env.get=.

** C — environment + mountpoint (NOT variant-file exports)

Environment and mountpoint are NOT declared in the variant file. Bootstrap
order rules it out: =paladin.env.get(...)= calls inside the variant body
resolve against env loaded BEFORE the variant is imported — so a variant
cannot declare env it would then consume.

They live as sibling subdirs of the variant marker:

#+BEGIN_SRC
<variant root>/
  test.viva.js                 the variant marker
  environment/
    variant.jsonc              non-secret env vars
    services.jsonc             service-specific env
    secrets.jsonc              SECRET_VIVA_* values (template in registry source)
  mountpoint/
    (whatever data the variant mounts)
#+END_SRC

Paladin's =populate.environment= reads =<variant>/environment/*.jsonc=
into =paladin.env= / =paladin.secret= BEFORE =resolve.variantManifest=
imports the marker. Mountpoint is a paladin scope, resolved as today.

Install copies the whole tree verbatim (=cp -r source dest=) — registry
source is responsible for shipping the right environment templates.

  if (typeof entry === "string") {
    if (entry.startsWith("./") || entry.startsWith("/") || entry.startsWith("../")) {
      const mod = await import("file://" + resolve(variantPath, entry));
      return mod;
    }
    const cake = await paladin.vip.accio({ owner: "@vivalence", type, slug: parseSlug(entry) });

  if (typeof entry === "object") return entry;
  return null;

** Differences in mechanics — summary

Variant file exports only: =manifest=, =path=, =runtime=, =clients=,
=services=, =daemons=.

| field | inline form | reference form (string) | omitted |
|-------+-------------+-------------------------+---------|
| =runtime= | =Object= literal | slug → =vip.accio= | =paladin.variant.runtime = {}= |
| =clients= | =Object<slug,Object>= | =Object<slug,String>= per entry → =vip.accio= | =paladin.variant.clients = {}= |
| =services= | =Array<Object>= | =Array<String>= (slug or path) or mixed | =paladin.variant.services = []= |
| =daemons= | =Array<Object>= | path string (=./x.viva.js=) OR slug string, or mixed | =paladin.variant.daemons = []= |
| =path= | n/a | string with =~/= expansion | =$VIVA_VARIANTS_ROOT/<slug>= |

NOT in variant file:
| field | source |
|-------+--------|
| environment | =<variant>/environment/*.jsonc= (populate.environment) |
| mountpoint | =<variant>/mountpoint/= (paladin scope) |

** Reference-form resolution rules

String references in =services=, =daemons=, =clients= are dispatched by prefix:

| prefix | meaning | resolver |
|--------+---------+----------|
| =./= , =../= , =/= | path | dynamic import from filesystem |
| =@scope/...= | registry slug | =paladin.vip.accio({owner, type, slug})= |
| (other) | error or implicit @vivalence/* (TBD) | TBD |

** Implementation plan — three milestones, each testable

Scope: collapse =resolve.circuitry= → =resolve.variant= into a single marker
resolver. =paladin.scope.variant= stays a directory; the variant FILE is
discovered inside it. References (slug/path strings) parked to M3.

What changes vs today:
- =paladin.scope.circuitry= scope: GONE.
- =VIVA_CIRCUITRY_MOUNT= env handling: GONE.
- =resolve.circuitry=: GONE.
- =resolve.variant=: REWRITTEN — reads single variant-typed cake's exports.
- =paladin.scope.{variant,environment,mountpoint}=: UNCHANGED (env + mountpoint
  branch off =paladin.scope.variant=).
- =paladin.variant.{runtime,clients,services,daemons}= compiled shape: UNCHANGED
  (downstream consumers in systems/runtime keep working).

*** M1 — single-marker resolver (inline form only)

Goal: =deno task runtime/run= boots against a single root variant file in
=testament/variant/test.viva.js= with the same end-state =paladin.variant=
shape it has today.

Changes:
- =subsystems/paladin/lifecycle/populate.js=: drop the =circuitry= entry from
  the second =paladin.scopes([...])= block. Leave =variant=, =environment=,
  =mountpoint= untouched.
- =subsystems/paladin/lifecycle/resolve.js=:
  - DELETE =export async function circuitry=.
  - REPLACE =export async function variant= with:
    1. =const cakes = await paladin.find.viva(paladin.scope.variant)=
       then read each via =paladin.read.viva=.
    2. Filter to root-only (=dirname(cake.source.absolute) === paladin.scope.variant.absolute=)
       — exclude any nested subdir hits.
    3. Filter to =manifest.type === "variant"=.
    4. Length === 1 invariant — throw on 0 or >1 with the variant root
       absolute in the error message.
    5. Read =marker.runtime= / =.clients= / =.services= / =.daemons=
       from that cake's exports.
    6. Build =paladin.variant.{runtime, clients, services, daemons}= via
       the SAME Mask + mount-branching logic that exists in the current
       =variant= function (lines 50-66 of =resolve.js=).
- =subsystems/paladin/lifecycle/integrate.js=: remove =paladin.scope.circuitry=
  from the =statements= mounts array.
- =testament/variant/test.viva.js=: AUTHOR as Form A (orb section =A=) —
  fully inline. Single file declaring manifest + runtime + clients +
  services + daemons. Use =paladin.env.get= / =paladin.secret.get= for
  env-sourced values, inline literals for variant-internal constants
  (db filenames, mode slugs, trait arrays).
- =testament/variant/circuitry/=: DELETE the directory and its two files
  (=test-system.viva.js=, =test-daemon.viva.js=) once the runtime boots
  against the new marker.

Test:
- =deno task runtime/run= must start and serve =VIVA_RUNTIME_SERVE=.
- Pre/post snapshot of =paladin.variant.{runtime, clients, services, daemons}=
  via the existing =console.log= sites — shape and contents must match.
- Existing runtime smoke tests (whatever currently asserts daemon-bootup)
  continue to pass.

Guardrails:
- No changes to =populate.environment=, =populate.veryimportantpackage=,
  =integrate.publish=, =integrate.secure= — those are downstream of the
  variant scope, not the variant FILE, and are unchanged.

*** M2 — paladin lifecycle test against synthetic variants

Goal: lock the resolver behavior with a hermetic test suite. No reliance
on =testament/variant/= or =deno task runtime/run= for correctness
verification.

New file: =subsystems/paladin/tests/variant.test.js=.

Cases (each owns a temp dir, hand-written =<slug>.viva.js=):
1. *happy path* — one inline form-A marker → all four fields populated,
   Mask-wrapped, mounts branched correctly.
2. *omitted fields* — marker exports only =manifest= + =runtime= →
   =paladin.variant.clients = {}=, =services = []=, =daemons = []=.
3. *no marker* — variant dir contains only non-variant-typed files →
   throws with the variant root path in the message.
4. *multiple markers* — two files at root with =manifest.type === "variant"=
   → throws with both paths in the message.
5. *wrong-typed file* — variant dir contains one =.viva.js= with
   =manifest.type === "daemon"= → treated as case 3 (no marker), throws.
6. *nested marker ignored* — a =manifest.type === "variant"= file inside
   a subdir (e.g. =./brazilian/brazilian.viva.js=) MUST be ignored —
   root-only invariant.

Each case constructs a minimal =paladin= harness (or uses the existing
test harness in =subsystems/paladin/tests/=) pointed at the temp dir.

Test:
- =deno task paladin/test= passes all 6 cases.
- Failure cases assert on the thrown error message containing the offending
  path(s).

Guardrails:
- No mocks of typology primitives (=cast.lookup=, =paladin.read.viva=) —
  the test exercises the real resolver against real filesystem.

*** M3 — reference-form resolution (slug + path strings)

Goal: a variant field may carry a string ref in place of an inline object.
Compiled =paladin.variant= shape is identical regardless of declaration.

Dispatch (orb section =Reference-form resolution rules=):
| prefix | meaning | resolver |
|--------+---------+----------|
| =./= , =../= , =/= | path | =paladin.read.viva(new Path(resolved))= |
| =@scope/...= | registry slug | =paladin.vip.accio(cast.lookup(string))= |

Changes:
- =subsystems/paladin/lifecycle/resolve.js= — in the new =variant=
  function, walk each field BEFORE Mask-wrapping:
  - =runtime=: if string → resolve to inline. Else inline.
  - =clients=: iterate keys; per value: if string → resolve; else inline.
    Key stays the slug.
  - =services=, =daemons=: =paladin.vip.accioMany(arr)= for slug-or-object
    mixed arrays. For path-form strings, branch into a separate filesystem
    resolver first (because =accioMany= expects slug/object, not path).
- All four field walkers funnel through a single =normalize(entry, type)=
  helper at the top of =resolve.js= that returns the resolved inline
  config. Mask + mount logic stays unchanged after normalization.

Test:
- Extend =variant.test.js= with:
  - form B (variant + colocated daemon file via =./brazilian.viva.js=) →
    compiled =paladin.variant.daemons[0]= matches the inline form-A
    counterpart exactly (deep-equal).
  - form D (mixed: one inline daemon, one path-ref daemon, one slug-ref
    service) → compiled shape identical to all-inline counterpart.
  - bad-ref cases: nonexistent path → throws with the path in message;
    unknown slug → throws via =vip.accio= error pass-through.
- vip.accio path tests need either (a) a real registry fixture or (b) a
  test-scoped =paladin.vip= stub. Prefer (a) — registry fixture in
  =subsystems/paladin/tests/fixtures/=.

Guardrails:
- No bare-slug normalization in M3 (=flashcard= → =@vivalence/game/flashcard=).
  Stays parked.
- =runtime= single-config invariant kept — if =runtime= is a slug, the
  resolved cake must export a =runtime= field that becomes the marker's
  =runtime=; if a slug ref ALSO exports its own =runtime= field that
  conflicts, error.
