#+TITLE: Wafer Lifecycle — Vector-based Process Composition
#+AUTHOR: Vivalence
#+DATE: 2026-04-04
#+STATUS: ACTIVE

* Intent

Unify all bootable systems (paladin, runtime, daemon, client, terminal) under a single compositional pattern using Vector as the lifecycle backbone. Middleware = lifecycle phases. The effect = the thing the process produces or keeps alive. Teardown = middleware unwind. No new primitives — existing Vector + steer + shape already support this.

** Desired End State

Every system component is expressed as a *wafer* — a Vector with named lifecycle branches (/construct/populate/resolve/integrate). Casting a wafer produces a process. The Die class hierarchy (Wafer/Die/Good) is replaced by vector factories and steer.invoke.

** Terminology

| Term    | What                                                      |
|---------+-----------------------------------------------------------|
| Wafer   | The vector. Lifecycle blueprint. Named branches + middleware. |
| Die     | The context inside middleware. (die, next) => { ... }     |
| Process | The live wafer in action. Invoked wafer with state.       |
| Cast    | The act: steer.invoke(wafer, signal) → exec(input) → result. |

** Two process types

- *Completing*: effect returns a product (paladin, daemon). exec() resolves.
- *Alive*: effect returns a deferred promise (runtime, terminal). exec() blocks until kill.

** Partial application

Named branches enable partial lifecycle traversal. Effects at branch points serve as exits.

#+begin_src
/construct/populate/base     → paladin with env+scopes, no variant
/construct/populate/resolve/integrate/full → complete paladin
#+end_src

** Host contract

Alive wafers receive an AbortController from input. abort.abort() triggers release.resolve() → effect unblocks → middleware unwinds in reverse. The host provides the kill signal; the wafer responds.

** No premature primitives

No sugar, no convenience wrappers, no constants. Each system is different. If something isolatable emerges during migration, extract it then. The pattern is the primitive.

* Architecture

** Alive wafer pattern

#+begin_src javascript
wafer.use(async (die, next) => {
  die.abort = die.input?.abort || new AbortController()
  die.release = deferred()
  die.abort.signal.addEventListener("abort", () => die.release.resolve())
  await next()
  await die.server?.shutdown()
})
#+end_src

Host kills child: ~abort.abort()~ → release resolves → effect unblocks → middleware unwinds in reverse. One line to kill, deterministic teardown order for free.

** Recursive cast — daemon inside runtime

#+begin_src javascript
resolve.use(async (die, next) => {
  for (const [slug, entry] of die.daemons) {
    entry.product = await steer.invoke(entry.wafer, LIFECYCLE)({
      aperture: die.aperture, latch: die.latch, abort: die.abort,
    })
  }
  await next()
})
#+end_src

Daemon effect mounts into parent and returns:

#+begin_src javascript
resolve.open("/integrate", async (die) => {
  die.input.aperture.branch(die.daemon.mount.nature).slurp(die.daemon.aperture)
  return die.daemon
})
#+end_src

** Terminal isolation — concurrent alive children

#+begin_src javascript
spawn: async (params) => {
  const terminalAbort = new AbortController()
  const ready = deferred()
  const handle = steer.invoke(terminal(params), LIFECYCLE)({
    dataspace: die.dataspace, abort: terminalAbort,
    onReady: (api) => ready.resolve(api),
  })
  const api = await ready.promise
  return { ...api, kill: () => terminalAbort.abort(), handle }
}
#+end_src

Each terminal gets fresh entity Maps. Client shares dataspace (read-only environment), terminal creates isolated entities (write-local state). Kill one, others survive. Client teardown cascades via abort on all terminals.

** onReady handshake (alive wafers)

Alive wafers can't return state (they block forever). Effect publishes API before blocking:

#+begin_src javascript
resolve.open("/integrate", async (die) => {
  die.input?.onReady?.({ id, buffer, entities, stall })
  return die.release.promise
})
#+end_src

** Paladin wafer (completing, first migration)

#+begin_src javascript
import { Vector } from "@vivalence/typology"
import { Paladin } from "./prototypes/paladin.js"
import * as populate from "./lifecycle/populate.js"
import * as resolve from "./lifecycle/resolve.js"
import * as integrate from "./lifecycle/integrate.js"

export function paladin() {
  const wafer = new Vector()

  wafer.use(async (die, next) => {
    die.paladin = new Paladin()
    await next()
  })

  wafer.branch("/construct")
    .use(async (die, next) => {
      await populate.env(die.paladin)
      await populate.scopes(die.paladin)
      await next()
    })
    .branch("/populate")
    .use(async (die, next) => {
      await populate.environment(die.paladin)
      await populate.veryimportantpackage(die.paladin)
      await populate.questions(die.paladin)
      await next()
    })
    .open("/base", async (die) => die.paladin)
    .branch("/resolve")
    .use(async (die, next) => {
      await resolve.circuitry(die.paladin)
      await resolve.variant(die.paladin)
      await next()
    })
    .branch("/integrate")
    .use(async (die, next) => {
      await integrate.statements(die.paladin)
      await integrate.publish(die.paladin)
      await integrate.questions(die.paladin)
      await next()
    })
    .open("/full", async (die) => die.paladin)

  return wafer
}
#+end_src

** Phase 3.5: Process Strategy + Die Namespace [DESIGNED]
New steer strategy for process wafers. Replaces direct (HTTP-oriented Context) with plain die object.

*** Process strategy

#+begin_src javascript
const process = (carry, effect, steps, signal) => async (die = {}) => {
  await carry(die, async () => {
    const result = await effect(die)
    if (result !== undefined) die.output = result
  })
  return die.output
}
#+end_src

Key difference from direct: no Context wrapping. Die IS the context — whatever the caller puts on it, middleware sees. The caller owns the die. The wafer enriches it.

*** Die namespace convention

| Field        | What                                                    | Who creates             |
|--------------+---------------------------------------------------------+-------------------------|
| die.good     | The product being constructed                           | Caller or root middleware |
| die.variant  | Cast-time configuration                                 | Caller                  |
| die.control  | Host lifecycle controls                                 | Caller + root middleware |
| die.output   | Effect return value (set by strategy)                   | Strategy                |
| die.signal   | Signal path (set by strategy)                           | Strategy                |

For alive wafers, die.control contains:
- abort: AbortController (provided by host or defaulted)
- release: deferred (wired to abort by root middleware)
- ready: deferred (optional, host-provided, resolved by effect when construction complete)

*** Cast = invoke + execute (separate steps)

#+begin_src javascript
// 1. Build the cast (binds wafer + path + strategy)
const cast = steer.invoke(daemon, "/construct/populate/resolve/full",
  (carry, effect) => async (die) => {
    await carry(die, async () => { die.output = await effect(die) })
    return die.output
  },
)

// 2. Execute the cast (separate — call when/where applicable)
const result = await cast({ good: new Daemon(connection), variant: { lighthouse } })
#+end_src

*** Two strategy shapes

Completing (daemon, lighthouse, paladin, client to /idle):
#+begin_src javascript
(carry, effect) => async (die) => {
  await carry(die, async () => { die.output = await effect(die) })
  return die.output
}
#+end_src

Alive (terminal, runtime, client to /full):
#+begin_src javascript
(carry, effect) => (die) => {
  die.control.release = deferred()
  die.control.abort.signal.addEventListener("abort", () => die.control.release.resolve())
  const handle = carry(die, async () => {
    die.control.ready?.resolve(die.good)
    await effect(die)
  })
  return { ready: die.control.ready?.promise, handle, kill: () => die.control.abort.abort() }
}
#+end_src

*** Plain vector export (no factory function)

Wafers are plain exported vectors, not factory functions. Vectors are stateless — middleware is just functions, branch structure is immutable. Each cast traverses the same vector with a fresh die.

* Decisions

- Named paths over patternless vectors. Partial application for free.
- AbortController as the host→process kill signal (standard, composable).
- Daemons are completing vectors (effect returns product, not alive).
- Terminals are alive vectors (effect blocks, host controls lifetime).
- Paladin is a completing vector — simplest, uniform.
- Integrate is middleware, not the effect. Effects (/base, /full) are pure returns.
- No new steer/shape/shard primitives. No sugar. No constants. Each system is different enough that premature abstraction would create things to work around.
- Fluent wafer construction — one chain, no stored sub-branches.
- Paladin class stays as product container. Die enriches die.good, effect returns die.good.
- Lifecycle functions keep their (paladin) => {} signature. Wafer composes them.
- Process strategy over direct: die is a plain object, no Context/Request/Response wrapping. Caller owns the die, wafer enriches it.
- die.good is the universal product field. External consumers name it (paladin, runtime, lighthouse), internally it's always die.good.
- die.control for host lifecycle: { abort, release, ready }. release is part of control (other side of abort). ready is host-provided deferred resolved by effect.
- die.variant for cast-time configuration. Domain-specific, not standardized.
- Cast creation and cast execution are separate steps. steer.invoke builds the cast, caller executes when/where applicable.
- Plain vector export, no factory functions. Vectors are stateless — reusable across casts.
- Completing cast: caller awaits result directly. Alive cast: caller gets { ready, handle, kill }.
- Circuit file circular import: paladin/mod.js must two-phase (cast /base, then ikiro directly) because circuit .viva.js files import @vivalence/paladin at module scope. Eliminating this requires changing the circuit file contract (future: declarative $env/$secret references).

* Gaps

- Process strategy not yet in typology — inline at each cast site for now. All four client wafers + paladin use identical completing strategy. Extract when stable.
- direct strategy should be renamed to request (HTTP-oriented) once process is stable.
- Lighthouse wafer export name collides with entities.lighthouse namespace. Currently accessed as entities.lighthouse.lighthouse. Rename export to resolve.
- Paladin wafer still uses factory function + die.input convention (not die.good/die.variant). Needs updating to plain vector + process strategy.
- Circuit file circular import prevents single-cast paladin mod.js. Three solutions designed: declarative env refs, circuit factory function, separate env module.
- localStorage .persist() on RemoteRepositories causes stale data across test runs. Tests must clear localStorage.
- Hot-reload: partial application enables it structurally. Middleware idempotency not yet addressed.
- Process system (long-running agent processes within daemons) — how do they fit as wafers?
- Alive strategy not yet used in production. Terminal wafer is completing. Alive pattern (abort/release/ready) designed and tested in typology but not applied to real wafers yet.
