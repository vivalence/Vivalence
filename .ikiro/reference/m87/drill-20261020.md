## 1 · precedent

10-16 (the first drill): Jupyter (output = mime bundle, the frontend picks by preference = our =negotiate=) · module federation (=remoteEntry= manifest, a hosted value) · Elm (view is data, total over the type) · Emacs (=display= property inline in the stream) · MCP resource (=uri · mimeType · text|blob=) · claude.ai artifact (versioned, revisable by id — the one that needs rows, and the one that matches /"revise"/).

10-20, Q0 (a client-hosted mode's views):

| system | a host-bundled module vs a served one |
|---|---|
| module federation | the host's own modules never appear in the remote manifest; =shared= dedupes by version |
| VS Code | an extension's webview assets ship inside the extension; the server knows nothing of them |
| Emacs | a package's resources resolve by =load-path=, no registry row |
| Jupyter | prebuilt labextensions are static; outputs still travel as mime bundles |

10-20, data × view × type (asked for by /"look at other systems … come up with different solutions entirely"/):

| system | the data | the type | the view | inline vs full | what it answers for us |
|---|---|---|---|---|---|
| Emacs | text; a buffer may visit a file (=buffer-file-name=) | major mode, one per buffer | a window shows a buffer; many windows, one buffer | the window's size | one buffer, many windows; storage is a column → ruling 31 |
| CLIM | an object | a presentation type, named, a lattice | =present(object, type, stream, view)=, a method on =(type, view)= | the =view= argument | views keyed by TYPE, never by object → =presents= |
| Glamorous Toolkit | an object | its class | =gtViewFor:= methods ON the class, many, tabbed | nested views | a type ships its own views, the tool merges them with built-ins → the renderer table |
| Jupyter | a mimebundle | the mime | the frontend picks by preference | — | our =Bundle= of today; no state type |
| Jupyter widgets | a model with a schema | =_model_name= | many views synced by comm | — | one model, N views, live sync = the mirror (m95 lock 8) |
| Datomic · Clojure spec | open maps | specs named, data unnamed; a map satisfies many | — | — | the type as a claim → V2, parked |
| HyperCard | a card | its background | one card, one background | — | data and layout born together = =App=, the knot (/"the buffer schema applies to two things"/) |
| Smalltalk MVC | a model | its class | N views observe one model | — | as widgets |

Findings: every mature system keys the view by the TYPE of the data, never by the datum (our m:n =buffer.artifacts= keyed by datum was the weirdness); nobody splits a view into two files for inline and full (CLIM passes =view=, GT nests, Emacs resizes) → =surface.place=.
