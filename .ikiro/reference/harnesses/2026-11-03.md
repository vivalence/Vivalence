## sources

### Claude Code docs: Best practices, "What you can stop doing" (live page, read 11-03)
https://code.claude.com/docs/en/best-practices
- A table of old advice now marked dead: ALL CAPS/IMPORTANT emphasis ("piling on emphasis mostly makes Claude over-apply the rule"), "think hard" keywords (effort is the control), "keep going / don't be lazy" lines, architecture or file-layout descriptions in CLAUDE.md, and subagents used to protect the context window.
- CLAUDE.md should hold only what Claude can't work out from the code: how to verify work, places where the code misleads, decisions that aren't in the repo, "Anything you've had to correct twice already".
- Two failed corrections → `/clear` plus a better prompt, not a third correction.
- `/doctor prompt-audit` flags instructions written for older models, stale paths, and contradictions.

### Claude Code docs: memory (live, read 11-03)
https://code.claude.com/docs/en/memory
- Target under 200 lines per CLAUDE.md. Imports don't cut context cost. Claude treats memory as context, never enforcement: "To block an action regardless of what Claude decides, use a PreToolUse hook".
- Path-scoped rules and loaded-on-demand files have a per-file cap: 40,000 chars at a 200K window, 150,000 chars at 1M on models after 4.6 (since v2.1.309). Past the cap Claude sees only the start of the file.
- Auto memory is on by default. It saves `feedback` memories ("corrections you give Claude") into `~/.claude/projects/<p>/memory/`; MEMORY.md loads its first 200 lines or 25KB.
- A symlink whose target is outside the working directory is treated as an external import. The `.ikiro` targets are inside the repo, so they are fine.
- `/doctor` checkup "cuts content Claude can derive from the codebase, such as directory layouts … keeps pitfalls, rationale, and conventions".

### Claude Code docs: context window / what survives compaction (live, read 11-03)
https://code.claude.com/docs/en/context-window
- Root CLAUDE.md, unscoped rules and auto memory are re-injected from disk.
- Rules with `paths:` reload only on demand: "If a rule must persist across compaction, drop the `paths:` frontmatter or move it to the project-root CLAUDE.md".
- Invoked skill bodies are re-injected at 5k tokens each, 25k in total, oldest dropped first. "Truncation keeps the start of the file, so put the most important instructions near the top".
- `SessionStart` hooks matching the `compact` source run, and their output is added to the compacted context.

### Claude Code docs: skills (live, read 11-03)
https://code.claude.com/docs/en/skills
- Keep SKILL.md under 500 lines. A loaded skill "stays in context across turns, so every line is a recurring token cost".
- Skills accept `paths` frontmatter and can carry their own hooks in frontmatter ("move the rule into a hook … define the hook in the skill's `hooks` frontmatter").
- Evals: baseline comparison in a fresh session, with the skill on and off. skill-creator offers a blind A/B "to confirm an edit is an improvement before committing it" and description tuning with should-trigger and should-not-trigger prompts.
- The listing budget is 1% of the context window. Each description is capped at 1,536 chars, and descriptions of the least-used skills are dropped first.

### Claude Code settings reference + changelog: idle compaction, transcript retention
https://code.claude.com/docs/en/settings-reference#idlecompaction · https://code.claude.com/docs/en/changelog
- 2.1.299 (2026-10-14): "a 200K+ token conversation left idle for about 54 minutes is compacted before its one-hour prompt cache expires". On by default; `"idleCompaction": false` turns it off. 2.1.314 (10-30) brought it to VS Code and Desktop.
- PreCompact matcher values are `manual` and `auto`. The ikiro compact-gate matches only `manual`.
- `cleanupPeriodDays` defaults to 30: "The sweep deletes transcripts without showing a message". Local check: the oldest remaining transcript in `~/.claude/projects/-Users-finn-vivalence-code-vivalence/` is from 2026-10-05, so every Jul–Sep transcript is already gone. Neither settings.json sets the key.
- 2.1.283 (2026-09-25): added `/doctor prompt-audit` "to audit your CLAUDE.md files, skills, agents and commands for prompting patterns written for older models".

### Claude Code docs: hooks reference (live, read 11-03)
https://code.claude.com/docs/en/hooks
- Events now include InstructionsLoaded ("When a CLAUDE.md or `.claude/rules/*.md` file is loaded into context … when files are lazily loaded"), PostToolBatch, PostCompact, PreModelSwitch/PostModelSwitch, TaskCompleted and SessionEnd.
- ikiro currently uses only PreToolUse, PreCompact(manual) and Stop.

### Claude Code docs: dynamic workflows (live, read 11-03)
https://code.claude.com/docs/en/workflows
- "A workflow moves the plan into code", with scripts saved under `.claude/workflows/` and rerunnable with `args`.
- "Project location: Claude Code refuses if `.claude`, `.claude/workflows`, or the target file is a symlink." The ikiro symlink pattern (`.claude/rules`, `.claude/skills` → `.ikiro`) cannot host a saved workflow.
- A workflow can have agents adversarially review each other's findings before reporting.

### Claude Code docs: scheduled tasks (routines) / desktop scheduled tasks / /loop / /goal (live, read 11-03)
https://code.claude.com/docs/en/routines · https://code.claude.com/docs/en/scheduled-tasks · https://code.claude.com/docs/en/goal
- Cloud scheduled tasks (formerly routines) clone the repo and run in the cloud, so they can't see local `~/.claude` transcripts or `~/.viva`. Desktop scheduled tasks and `/loop` run locally.
- `/goal` (2.1.139, 05-11) takes a completion condition that a model checks after each turn. The docs list it as the replacement for "keep going" prompting.

### Claude Code docs: subagents (live, read 11-03)
https://code.claude.com/docs/en/sub-agents
- Custom subagents load CLAUDE.md and project rules. Explore and Plan don't. Main-session auto memory never reaches subagents.
- A `memory` field gives a subagent its own persistent memory. Subagent transcripts are deleted after `cleanupPeriodDays`.
- "If a rule must [reach the subagent] … restate it in the prompt you give Claude when delegating". This matches ikiro's "a brief carries his rulings".

### Prompting Claude Opus 5.5 (platform docs; Opus 5.5 launched 2026-09-22)
https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5
- Effort is the main control: "Lowering effort reduces thinking … more reliably than prompt instructions do". Default effort is `medium`.
- Unattended runs: "Treat a text-only end of turn as a report rather than as proof the task is done". Keep a checklist, and send at most two or three automatic continuations.
- Multi-agent: a time budget (`elapsed 340s / 1200s`) speeds up teams.
- Chat: "treat that answer as done" reduces re-thinking. Mark pasted content with id-tagged blocks.

### Opus 5.5 migration guide (platform docs, 2026-09-22)
https://platform.claude.com/docs/en/models/opus-5-5/migration-guide
- "Instructions tuned for Claude Opus 5's behavior might no longer be needed".
- Thinking can't be disabled. "If you rebuild conversation history to update instructions, consider switching to a mid-conversation system message to preserve prompt cache hits."

### Prompting Claude Fable 5.1 (platform docs)
https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5-1
- A scope block: "don't quietly narrow, widen, or swap it". Pre-existing bugs are reported as follow-ups, never fixed in the change.
- A compaction-summary template that preserves "anything that was asked for, decided, agreed, ruled out … stated exactly" and keeps the user's words close to verbatim.
- An anti-"mannered prose" block, and a preference for surgical edits over whole-file rewrites.
- An autonomy block: "If it is a plan … a list of next steps … do that work now".

### Claude Platform: Dreams (Managed Agents, research preview; created-at sample 2026-04-29, models added 2026-10-01)
https://platform.claude.com/docs/en/managed-agents/dreams
- Problem statement: "over many sessions a memory store accumulates duplicates, contradictions, and stale entries".
- A dream reads the store plus 1–100 past transcripts and writes a NEW store: "duplicates merged, stale or contradicted entries replaced with the latest value, and new insights surfaced".
- "The input store is never modified, so you can review the output and discard it". Steering instructions are high-level only; "imperative directives that target specific lines … generally produce no change".
- This is Anthropic's own shape for the exact routine beef asked for: a non-destructive consolidation pass over transcripts with a review gate.
