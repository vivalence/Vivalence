#+TITLE: Buffer / Intent / Emitter Migration — Work Package
#+AUTHOR: Vivalence
#+DATE: 2026-03-20

* Intent

Two core entities migrate. Product becomes Buffer. Valence becomes Intent.
Three mode traits rename. BUFFERED becomes SELFEVIDENT. VALENTIC becomes
INTENTED. PRODUCER becomes EMITTER. The emitter pattern replaces the
production pipeline — modes emit buffers through a Vector compiled to both
a callable object and an HTTP aperture.

This touches every layer: typology entities, registry mode files, runtime
trait system, client entities. The database migration is handled by MikroORM
schema diffing. The client keeps its current =[...viva]= routing structure.

** Design Decisions (Settled)

1. Emitter returns buffer-shaped POJOs. Normalization is middleware on the
   emitter Vector, not a custom carry function for compile.object.
2. Buffers are always persisted. Session persistence requires it.
3. No producer/commissioner. Buffer has =mode= — the viewable mode whose
   view renders this buffer.
4. SELFEVIDENT is a marker trait. No runtime function.
5. Session has either mode, or mode and intent. Intent is associated with
   a mode, so session.mode always exists. Session keeps its traits.
6. Intent has =intent.data.mount= — a path telling the client where to call.
   INTENTED trait does DB upsert + symbol/literal relation resolution.
7. Client keeps =[...viva]= catch-all routing. No URL scheme change in this
   migration.
8. Buffer data is trait-keyed (=data.TRAIT_NAME=), consistent with Literal
   pattern. System-level buffer traits: FURNISHED, STATEFUL, DIALOGIC, AGENTIC.
   Domain-specific traits (recall direction, speed, etc.) are NOT system
   vocabulary — they live in domain trait definitions applied later.
9. Intent has traits (FURNISHED at minimum) and m:n relations with symbols
   and literals. Symbols carry seek scope. Literals carry pinned content.
   The INTENTED trait resolves symbol/literal slugs from the dataset to
   actual entities during upsert.
10. No client-side trait accessor methods in this migration. Mode views read
    buffer POJOs directly (=buffer.data.FURNISHED.recall=). Future: domain
    trait definitions transported to client via runtime serialization of
    =defineTrait= method descriptors.
11. Old =valentic.js= moved to =bak/=, not deleted.

** Tactic mode (test example)

#+begin_src javascript
import { Vector } from "@vivalence/typology";
import dataset from "./dataset/index.js";

export const manifest = {
  type: "tactic",
  slug: "test",
  traits: ["INTENTED", "EMITTER"],
};

export const emitter = new Vector().open("/introduction", async (ctx) => {
  const [sentence] = await ctx.daemon.call("/pick/literal/feed", {
    take: 1,
    seek: ctx.input.seek,
    blacklist: ctx.input.blacklist,
  });

  if (!sentence) return [];

  const tokens = (
    await Promise.all(
      sentence.data.ANNOTATED.tokens.map((token) => {
        return ctx.daemon.entities.literal.findOne(
          { slug: token.literal },
          { populate: ["memories"], populateWhere: { memories: { user: ctx.user.id } } },
        );
      }),
    )
  ).filter(Boolean);

  const buffers = [];

  if (!sentence.memory) {
    buffers.push(
      await ctx.daemon.modes.game.shadow.emit.literal({
        literal: sentence, recall: "KNOWN", speed: { rate: "SLOW" },
      }),
    );
  }

  for (const token of tokens) {
    if (!token.memory || token.memory.status === "UNKNOWN") {
      buffers.push(
        await ctx.daemon.modes.game.shadow.emit.literal({
          literal: token, recall: "LEARNING", speed: { rate: "SLOW" },
        }),
      );
    } else if (token.memory.status === "LEARNING") {
      buffers.push(
        await ctx.daemon.modes.game.flashcard.emit.literal({
          literal: token, recall: "LEARNING",
        }),
      );
    }
  }

  for (const token of tokens) {
    if (!token.memory || token.memory.status === "UNKNOWN") {
      buffers.push(
        await ctx.daemon.modes.game.write.emit.literal({
          literal: token, recall: "LEARNING",
        }),
      );
    }
  }

  if (!sentence.memory || sentence.memory.status === "UNKNOWN") {
    buffers.push(
      await ctx.daemon.modes.game.shadow.emit.literal({
        literal: { ...sentence }, recall: "LEARNING",
      }),
    );
  } else {
    buffers.push(
      await ctx.daemon.modes.game.write.emit.literal({
        literal: { ...sentence }, recall: "LEARNING",
      }),
    );
  }

  return buffers;
});

export { dataset };
#+end_src

Notes:
- No VIEWABLE, no SELFEVIDENT (tactic has no view and cannot open without intent)
- Emitter calls other modes' emitters: =ctx.daemon.modes.game.shadow.emit.literal(...)=
  instead of manually constructing product POJOs with raw mode IDs
- Returns flat buffer array. EMITTER trait middleware normalizes each.
- ProductionResult dropped — empty array replaces =.cast.exhausted()=

* Runtime Trait Changes

** EMITTER (replaces PRODUCER)

Normalization is middleware on the emitter Vector, not a custom carry
function. The carry for =compile.object= is the default strategy.

#+begin_src javascript
import { compiler } from "@vivalence/typology";

export const EMITTER = async (mode, daemon) => {
  if (!mode.cake.emitter) return;

  mode.cake.emitter.use(async (ctx, next) => {
    ctx.daemon = daemon;
    ctx.mode = mode;
    await next();
  });

  mode.cake.emitter.use(async (ctx, next) => {
    await next();
    const raw = ctx.output;
    const raws = Array.isArray(raw) ? raw.flat() : [raw];
    ctx.output = raws.map((r) => ({
      mode: r.mode ?? mode.entity.id,
      status: r.status ?? "PENDING",
      traits: r.traits ?? [],
      data: r.data ?? {},
      literals: r.literals ?? [],
      symbols: r.symbols ?? [],
    }));
  });

  mode.emit = compiler.object(mode.cake.emitter);
  mode.aperture.branch("/emit").slurp(mode.cake.emitter);
};
#+end_src

Three steps:
1. Context middleware injects daemon + mode
2. Normalization middleware shapes output into buffer POJOs (runs after effect)
3. Compile to callable object (default carry) AND mount on aperture for HTTP

** INTENTED (replaces VALENTIC)

Upserts intents from dataset. Resolves symbol and literal slugs to entities
and links via m:n relations.

#+begin_src javascript
export const INTENTED = async (mode, daemon) => {
  for (const intentPojo of mode.cake.dataset?.intent || []) {
    intentPojo.mode = { id: mode.entity.id };

    if (intentPojo.symbols) {
      const resolved = await Promise.all(
        intentPojo.symbols.map((slug) => daemon.entities.symbol.findOne({ slug })),
      );
      intentPojo.symbols = resolved.filter(Boolean);
    }

    if (intentPojo.literals) {
      const resolved = await Promise.all(
        intentPojo.literals.map((slug) => daemon.entities.literal.findOne({ slug })),
      );
      intentPojo.literals = resolved.filter(Boolean);
    }

    await daemon.entities.intent.ensure(intentPojo);
  }
  await daemon.entities.em.flush();
};
#+end_src

Current VALENTIC does upsert + per-valence routing + PRODUCTIVE delegation.
INTENTED does upsert + symbol/literal resolution only. The emitter aperture
(=/emit/...=) is handled by the EMITTER trait. The client calls the emitter
directly using =intent.data.FURNISHED.mount=.

Old =valentic.js= moved to =bak/=.

** Buffer: prototype → entity

Buffer stays in =prototypes/buffer.js= but gains =static hydrate()= for
constructing from server POJOs. Client augmentation (view, context, hooks)
preserved.

#+begin_src javascript
export class Buffer {
  constructor(context, view, hooks) {
    this.id = belt.id.v7();
    this.context = context;
    this.context.buffer = this;
    this.view = view;
    this.status = new Status();
    this.hooks = hooks || [];
  }

  static hydrate(pojo, mode, terminal) {
    const buffer = new Buffer(
      { terminal, ...pojo.data, ...pojo },
      mode.view,
    );
    buffer.serverId = pojo.id;
    buffer.mode = mode;
    return buffer;
  }
}
#+end_src

** populate.js changes

Three paths (same as current, renamed):

1. SELFEVIDENT mode (no intent):
   =mode.implements("SELFEVIDENT")= → create buffer ad hoc, push to stall

2. SELFEVIDENT intent:
   =intent.type === "SELFEVIDENT"= → create buffer from =intent.data=,
   hydrate with mode.view, push to stall

3. APPLICATIVE intent:
   =intent.type === "APPLICATIVE"= → =stall.withPull()= calls
   =mode.call("/emit" + intent.data.FURNISHED.mount, { ...intent.data.FURNISHED.mask, ... })= →
   server returns buffer POJOs → hydrate each with its mode's view

Key difference in path 3: buffers may reference different modes than the
intent's mode. The tactic creates flashcard/shadow/write buffers. Each
buffer's =mode= field points at the viewable mode. Client resolves view:
