#+TITLE: Buffer / Intent / Emitter Migration — Work Package
#+AUTHOR: Vivalence
#+DATE: 2026-03-18

* Intent

Two core entities migrate. Product becomes Buffer. Valence becomes Intent.
Three mode traits rename. BUFFERED becomes SELFEVIDENT. VALENTIC becomes
INTENTIONAL. PRODUCER becomes EMITTER. The emitter pattern replaces the
production pipeline — modes emit buffers through a Vector compiled to both
a callable object and an HTTP aperture.

This touches every layer: typology entities, registry mode files, runtime
trait system, client entities. The database migration is handled by MikroORM
schema diffing. The client keeps its current =[...viva]= routing structure.

** Design Decisions (Settled)

1. Emitter returns buffer or buffer-shaped POJO. Trait middleware fills gaps
   (mode ref, session, status). Can return single buffer or array.
2. Buffers are always persisted. Session persistence requires it.
3. No producer/commissioner. Buffer has =mode= — the viewable mode whose
   view renders this buffer. That's it.
4. SELFEVIDENT is a marker trait. No runtime function.
5. Session has either mode, or mode and intent. Intent is associated with
   a mode, so session.mode always exists.
6. Intent has =intent.data.mount= — a path telling the client where to call.
   INTENTIONAL trait does DB upsert only, no routing.
7. Client keeps =[...viva]= catch-all routing. No URL scheme change in this
   migration.

** Tactic mode (test example)

#+begin_src javascript
import { ProductionResult } from "@vivalence/typology";
import { Vector } from "@vivalence/vector";

import dataset from "./dataset/index.js";

const manifest = {
  type: "tactic",
  slug: "test",
  traits: ["INTENTIONAL", "EMITTER"],
};

const emitter = new Vector()
  .open("/introduction", async (ctx) => {
    const [sentence] = await ctx.daemon.call("/pick/literal/feed", {
      take: 1,
      seek: ctx.input.seek,
      blacklist: ctx.input.blacklist,
    });

    if (!sentence) return ProductionResult.cast.exhausted({ reason: "out of sentences" });

    const tokens = (
      await Promise.all(
        sentence.data.ANNOTATED.tokens.map((token) => {
          return ctx.daemon.entities.literal.findOne(
            { slug: token.literal },
            { populate: ["memories"], populateWhere: { memories: { user: ctx.user.id } } },
          );
        }),
      )
    ).filter(Boolean);

    const buffers = [];

    if (!sentence.memory) {
      buffers.push(
        await ctx.daemon.modes.game.shadow.emit.literal({
          literal: sentence, recall: "KNOWN", speed: { rate: "SLOW" },
        }),
      );
    }

    for (const token of tokens) {
      if (!token.memory || token.memory.status === "UNKNOWN") {
        buffers.push(
          await ctx.daemon.modes.game.shadow.emit.literal({
            literal: token, recall: "LEARNING", speed: { rate: "SLOW" },
          }),
        );
      } else if (token.memory.status === "LEARNING") {
        buffers.push(
          await ctx.daemon.modes.game.flashcard.emit.literal({
            literal: token, recall: "LEARNING",
          }),
        );
      }
    }

    for (const token of tokens) {
      if (!token.memory || token.memory.status === "UNKNOWN") {
        buffers.push(
          await ctx.daemon.modes.game.write.emit.literal({
            literal: token, recall: "LEARNING",
          }),
        );
      }
    }

    if (!sentence.memory || sentence.memory.status === "UNKNOWN") {
      buffers.push(
        await ctx.daemon.modes.game.shadow.emit.literal({
          literal: { ...sentence }, recall: "LEARNING",
        }),
      );
    } else {
      buffers.push(
        await ctx.daemon.modes.game.write.emit.literal({
          literal: { ...sentence }, recall: "LEARNING",
        }),
      );
    }

    return buffers;
  });

export { manifest, emitter, dataset };
#+end_src

Notes:
- No VIEWABLE, no SELFEVIDENT (tactic has no view and cannot open without intent)
- Emitter calls other modes' emitters: =ctx.daemon.modes.game.shadow.emit.literal(...)=
  instead of manually constructing product POJOs with raw mode IDs
- Returns flat buffer array. EMITTER trait middleware persists each.
- Dataset declares APPLICATIVE intent with =mount: "/introduction"=

* Runtime Trait Changes

** EMITTER (replaces PRODUCER)

#+begin_src javascript
export const EMITTER = async (mode, daemon) => {
  if (!mode.cake.emitter) {
    console.error("EMITTER mode missing emitter", { mode });
    return;
  }

  // 1. Add context middleware to the emitter Vector
  mode.cake.emitter.use(async (ctx, next) => {
    ctx.daemon = daemon;
    ctx.mode = mode;
    ctx.user = ctx.user; // from aperture auth middleware
    await next();
  });

  // 2. Compile to callable object on mode
  mode.emit = compile.object(mode.cake.emitter, emitterStrategy);

  // 3. Mount on aperture for HTTP access
  mode.aperture.branch("/emit").slurp(mode.cake.emitter);
};
#+end_src

The =emitterStrategy= wraps the effect return value into a buffer POJO:

#+begin_src javascript
const emitterStrategy = (apply, effect) => async (input) => {
  const ctx = { input };
  await apply(ctx, async (c) => {
    const raw = await effect(c);
    const raws = Array.isArray(raw) ? raw : [raw];
    c.output = raws.map(r => ({
      mode: r.mode ?? ctx.mode.entity.id,
      data: r.data ?? r,
      status: "PENDING",
      literals: r.literals ?? [],
      symbols: r.symbols ?? [],
      ...r,
    }));
  });
  return ctx.output;
};
#+end_src

** INTENTIONAL (replaces VALENTIC)

Simplified to DB upsert only. No routing.

#+begin_src javascript
export const INTENTIONAL = async (mode, daemon) => {
  for (const intentPojo of mode.cake.dataset.entities["intent"] || []) {
    intentPojo.mode = { id: mode.entity.id };
    await daemon.entities.intent.ensure(intentPojo);
  }
  await daemon.entities.em.flush();
};
#+end_src

Current VALENTIC does upsert + per-valence routing + PRODUCTIVE delegation.
INTENTIONAL does upsert only. The emitter aperture (=/emit/...=) is handled
by the EMITTER trait. The client calls the emitter directly using
=intent.data.mount=.

** Buffer: prototype → entity

Buffer moves from =prototypes/buffer.js= to =entities/buffer.js=. It gains
server-mirrored fields (id from server, mode, data, status, session) while
keeping client augmentation (view, context, hooks).

#+begin_src javascript
export class Buffer extends Entity {
  // Server-mirrored (from buffer entity POJO):
  // id, data, status, position, mode, session, literals, symbols

  // Client augmentation:
  view = null;
  context = {};
  hooks = [];

  static hydrate(pojo, mode, terminal) {
    const buffer = new Buffer(pojo);
    buffer.view = mode.view;
    buffer.context = { terminal, buffer, ...buffer.data };
    return buffer;
  }
}
#+end_src

Three paths (same as current, renamed):

1. SELFEVIDENT mode (no intent):

* Deferred Work

These emerged during design but are out of scope for this migration.

** Session-first URL scheme

Replace =[...viva]= catch-all with =/daemon/:slug/session/:id= routes.
Session becomes the URL subject. Enables session resumption, cleaner
routing, eliminates Vector-based populate.

Considerations:
- Session creation flow: navtree must create session before navigation
- Daemon landing page: =/daemon/:slug= shows modes/intents + active sessions
- UUID aesthetics: session IDs are long but functional
- Post-login redirect destination
- Whether to keep =/viva= prefix

** Client entity/prototype refactor

Split daemon.js (195 lines) into =daemon/Daemon.js= (class) +
=daemon/lifecycle.js= (phased orchestration). Each entity gets its own
directory with class + lifecycle. Buffer as proper entity (not prototype).
Daemon lifecycle becomes: manifest → connections → modes → intents → cargo.

** Session resumption

With persisted buffers, navigating to an existing session could load
pending/active buffers instead of generating new ones. Query:
=find({ session: id, status: { $nin: ["DONE", "STALE"] } })=.

** Emitter strategy refinement

The =emitterStrategy= for compile.object needs design:
- How does session context get injected? (from aperture auth middleware
  vs from programmatic caller)
- Persistence: does the strategy flush, or does the caller?
- Single-vs-array unwrapping convention
- Error/exhausted handling (ProductionResult patterns)

** SELFEVIDENT buffer persistence

For selfevident modes/intents, the buffer is created ad hoc. But since
"buffers are always persisted," someone must persist it. Options:
- Client POSTs to create buffer entity
- A minimal server endpoint handles it
- SELFEVIDENT modes get an implicit emitter

** Svelte component props

Game mode Svelte components (Flashcard.svelte, Write.svelte, Shadow.svelte)
receive =product= as a prop. This becomes =buffer= or the prop naming
changes to match the new context shape from Buffer.hydrate().

Currently: ={terminal, product, seek, recall, ...}=
Target: ={terminal, buffer, literal, recall, speed?, ...}=

The buffer context spreads =buffer.data= which already contains literal,
recall, speed — so the Svelte components may need minimal changes if they
read from the spread data rather than from product.data.BUFFERED.
